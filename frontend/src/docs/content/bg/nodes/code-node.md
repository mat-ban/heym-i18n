# Code

**Code** node изпълнява Python код, който Вие пишете, със собствен `requirements.txt`, и връща JSON. Всяко изпълнение получава чисто нов контейнер, който се унищожава при завършване на изпълнението, така че едно изпълнение никога не може да види или повлияе на друго.

## Преглед

| Свойство | Стойност |
|----------|-------|
| Входове | 1 |
| Изходи | 1 |
| Изход | `$nodeLabel.result` (каквото е върнала `main`), плюс `$nodeLabel.logs` и `$nodeLabel.install` |

## Параметри

| Параметър | Тип | Описание |
|-----------|------|-------------|
| `label` | string | Идентификатор на node (camelCase) |
| `codeSource` | string | Python код. Трябва да дефинира `main(params)` и да върне JSON-сериализируема стойност |
| `codeParameters` | expression | JSON обект, свързващ данни от workflow-а с кода. Изразите се изчисляват преди изпълнението на кода |
| `codeRequirements` | string | Съдържание на `requirements.txt`, по един пакет на ред. Празно пропуска инсталацията |
| `codeAllowNetwork` | boolean | Дали самият код може да достига до мрежата (по подразбиране `false`) |

## Функцията `main`

Вашият код трябва да дефинира `main` на най-горно ниво, която приема един аргумент:

```python
def main(params):
    name = params.name
    return {"message": f"Hello, {name}!", "length": len(name)}
```

Изразите на ниво модул се изпълняват, но само това, което `main` върне, става изход на node-а.

Редакторът показва номера на редовете, а бутонът за разгъване до **Format** отваря по-голям редактор, който се затваря с `Esc` — промените се прилагат докато пишете, така че няма какво да запазвате. Бутонът **Format** преформатира кода Ви с Ruff, запазвайки коментарите. Той също така поправя щетите по отстъпите, които обикновено причинява поставянето на код: равномерно отстъпен блок, табулации смесени с интервали и ред, отдалечен с един-два интервала от своя блок, се поправят, вместо да бъдат отхвърлени. Истинска синтактична грешка се докладва с нейния ред и колона. Форматирането се изпълнява в същия изолиран контейнер, в който се изпълнява node-ът — без мрежа, без backend среда — така че се нуждае от Docker точно както и изпълнението.

## Четене на параметри

`params` поддържа точкова нотация, включително през вложени обекти и списъци:

```python
def main(params):
    city = params.user.address.city
    first_order = params.orders[0].id
    return {"city": city, "first_order": first_order}
```

- `params["my key"]` чете ключове, които не са валидни Python идентификатори
- `params.get("maybe")` връща `None` вместо да хвърли грешка, когато ключът липсва
- `params.to_dict()` връща обикновения речник
- Четенето на ключ, който никога не е бил предоставен, хвърля грешка, назоваваща ключа и изброяваща наличните

## Изход

```json
{
  "result": { "message": "Hello, Heym!", "length": 4 },
  "logs": "",
  "install": { "ok": true, "tool": "none", "log": "" }
}
```

- `result` — върнатата стойност на `main`. Следващите nodes четат `$nodeLabel.result.message`
- `logs` — всичко, което кодът е изпратил към `print`, уловено отделно, така че никога да не повреди резултата
- `install` — кой инструмент е инсталирал зависимостите (`uv`, `pip` или `none`) и неговия изход

## Зависимости

Избройте пакетите в `requirements.txt` точно както бихте го направили локално:

```
requests==2.32.3
feedparser
```

Пакетите се инсталират с `uv` в временна директория преди изпълнението на кода; ако `uv` не може да се справи с даден пакет, Heym опитва отново с `pip`. Нищо не се кешира между изпълненията, така че тежките зависимости добавят няколко секунди към всяко изпълнение. Оставянето на `requirements.txt` празен пропуска изцяло стъпката по инсталиране и е значително по-бързо.

Пакети, които не предоставят wheel и се нуждаят от C компилатор, няма да се инсталират. Причината се появява в `install.log`.

## Мрежа

| Фаза | Мрежа |
|-------|---------|
| Инсталиране на зависимости | Винаги включена — pip и uv трябва да достигнат до PyPI |
| Изпълнение на Вашия код | Изключена по подразбиране. `codeAllowNetwork` я включва |

С изключен `codeAllowNetwork`, изходящо повикване като `requests.get(...)` се проваля с грешка за връзка. Това е предвиденото поведение по подразбиране: повечето Code nodes трансформират данни, които друг node вече е изтеглил. Предпочитайте изтеглянето с **HTTP** node и подаването на тялото чрез `codeParameters`.

## Пясъчник и ограничения

Вашият код се изпълнява като non-root потребител в контейнер с премахнати всички Linux capabilities, зададено `no-new-privileges` и read-only root файлова система. Той не получава Docker socket и нито една от тайните или средата на backend-а.

| Ограничение | Стойност |
|-------|-------|
| Памет | 512 MB |
| CPU | 1 |
| Процеси | 256 |
| Таймаут за инсталиране на зависимости | 120 секунди |
| Таймаут за изпълнение | 60 секунди |

Това са фиксирани свойства на пясъчника, а не конфигурация.

> **Docker е задължителен.** За разлика от Agent Python инструментите и уменията, Code node няма локален резервен режим и няма променлива на средата, която да го облекчи. Без достъпен Docker daemon node-ът се проваля с ясна грешка, вместо да изпълни кода Ви в backend процеса. При разработка с нативен `./run.sh`, стартирайте Docker преди да използвате този node. Вижте [Security → Code node sandbox](../reference/security.md#code-node-sandbox).

## Пример

Редове с резултати, генерирани от предходен node:

```python
def main(params):
    rows = params.rows
    total = sum(r.amount * r.weight for r in rows)
    return {"total": round(total, 2), "count": len(rows)}
```

Когато `codeParameters` е зададено на `{ "rows": "$fetchRows.result" }`, следващите nodes четат `$scoreRows.result.total`.
