# Converter

**Converter** node преобразува данни и файлове между формати без писане на код. Той е технологично неутрален, така че с времето могат да бъдат добавени още формати. Преобразува CSV, JSON и XML данни в двете посоки, изпълнява Tesseract OCR за извличане на текст от изображения и PDF файлове и презаписва съхранен файл в друг формат.

## Преглед

| Свойство | Стойност |
|----------|-------|
| Входове | 1 |
| Изходи | 1 |
| Изход | `$nodeLabel.result` (парсирани данни за `csvToJson` / `xmlToJson`, текст за `jsonToCsv` / `jsonToXml`, извлечен текст за `imageToText` / `pdfToText`, метаданни за нов файл за `fileConvert`) |

## Параметри

| Параметър | Тип | Описание |
|-----------|------|-------------|
| `label` | string | Идентификатор на node (camelCase) |
| `conversion` | string | `csvToJson` (CSV текст → масив от обекти за редове), `jsonToCsv` (масив от обекти/редове → CSV текст), `xmlToJson` (XML текст → обект), `jsonToXml` (обект → XML текст), `imageToText` (OCR на изображение), `pdfToText` (OCR на всяка избрана PDF страница) или `fileConvert` (презаписване на съхранен файл в друг формат) |
| `source` | expression | Данните за преобразуване. Оставете празно, за да използвате първия вход на node |
| `delimiter` | string | Едносимволен разделител на полета (по подразбиране `,`) |
| `hasHeader` | boolean | Само за `csvToJson` — третира първия ред като заглавен (по подразбиране `true`) |
| `trimValues` | boolean | Само за `csvToJson` — премахва интервали около имената на колони и стойностите на клетките (по подразбиране `true`) |
| `includeHeader` | boolean | Само за `jsonToCsv` — записва заглавен ред (по подразбиране `true`) |
| `converterColumns` | string | Само за `jsonToCsv` — незадължителен ред на колоните, разделен със запетаи |
| `converterFileId` | expression | Файлови преобразувания — файлът в Heym Drive за четене, напр. `$Upload.file.id` |
| `converterTargetFormat` | string | Само за `fileConvert` — изходен формат (`pdf`, `docx`, `html`, `md`, `txt`, `csv`, `epub`, `jpg`, `png`, `bmp`, `webp`) |
| `ocrLanguage` | string | Само за OCR — `auto` (по подразбиране), Tesseract код като `tur` или `custom` |
| `ocrLanguageCustom` | string | Само за OCR — езикови кодове, използвани когато `ocrLanguage` е `custom`, напр. `eng+tur` |
| `ocrEncoding` | string | Само за OCR — наборът от знаци, към който се нормализира текстът (по подразбиране `utf-8`) |
| `ocrNormalizeUnicode` | boolean | Само за OCR — прилага NFC нормализация (по подразбиране `true`) |
| `ocrPsm` | string | Само за OCR — режим на сегментиране на страници в Tesseract (по подразбиране `3`) |
| `ocrDpi` | number | Само за `pdfToText` — DPI за растеризация на страници (по подразбиране `300`) |
| `ocrPageRange` | expression | Само за `pdfToText` — `3` или `2-5`. Празно означава всяка страница |

## Поведение

- **`csvToJson`** парсира изходния CSV текст. При `hasHeader: true` всеки ред става обект с ключове от стойностите на заглавния ред; при `hasHeader: false` всеки ред става масив от стойности на клетките. Полета в кавички, вградени разделители и вградени нови редове се обработват съгласно RFC 4180. Водещ UTF-8 BOM (често срещан при експорти от Excel) се премахва, а дублираните имена на колони се правят уникални без презаписване на реална колона (`a, a, a_2` → `a`, `a_3`, `a_2`). Задайте `delimiter` на `\t`, за да парсирате стойности, разделени с табулация.
- **`trimValues`** (по подразбиране `true`) премахва околните интервали от имената на колони и стойностите на клетките, **включително вътре в полета в кавички** (`" padded "` → `padded`). RFC 4180 третира интервалите в кавички като данни, затова задайте `trimValues: false`, за да ги запазите точно.
- **`jsonToCsv`** създава CSV текст от масив от обекти (или масиви). Редът на колоните се взема от `converterColumns`, когато е предоставен, в противен случай се извежда от ключовете на първия обект. Стойности, съдържащи разделителя, кавички или нови редове, се поставят в кавички автоматично.
- **`xmlToJson`** парсира XML в обект. Атрибутите използват префикс `@`, а текстът, смесен с атрибути, използва `#text`; повтарящите се съседни елементи стават масиви. Разгръщането на XML entities е деактивирано.
- **`jsonToXml`** сериализира обект в XML документ. Обектът трябва да има точно един ключ на най-горно ниво, който става коренов елемент на XML. Използвайте същата конвенция `@attribute` и `#text` като при `xmlToJson`, за да създадете атрибути и текст заедно с дъщерни елементи.
- **`imageToText`** изпълнява Tesseract върху едно изображение (PNG, JPEG, TIFF, WebP, BMP).
- **`pdfToText`** растеризира всяка избрана страница при `ocrDpi` и я разпознава. Всяка страница преминава през OCR, така че цифров PDF с напълно добър текстов слой все още се препрочита от пикселите. Това поддържа еднакво поведение за сканирани и цифрови документи, за сметка на скоростта, затова стеснете `ocrPageRange` при дълги файлове.
- **`fileConvert`** презаписва изходния файл в друг формат и съхранява резултата като **нов** файл в Drive. Оригиналът никога не се променя. Документите преминават през pandoc, изображенията през Pillow, а JSON към CSV през Python csv writer. Изображение не може да стане документ и документ не може да стане изображение; за извличане на текст от изображение използвайте `imageToText`.

## Въвеждане на файла

Файловите преобразувания четат от Heym Drive, не от път или URL, така че файлът трябва първо да бъде съхранен. Три често срещани вериги:

- **[File upload trigger](./file-upload-trigger-node.md) → Converter** — насочете `converterFileId` към `$Upload.file.id`.
- **[Drive](./drive-node.md) (`downloadUrl`) → Converter** — изтеглете отдалечен файл в Drive, след което подайте `$Download.id`.
- **[Agent](./agent-node.md) → Converter** — skill, който записва файл, го предоставя като `$reportAgent._generated_files[0].id`.

`converterFileId` също приема цял файлов обект (`$Upload.file`) или URL за изтегляне от Heym; идентификаторът на файла се извлича от всяко от тях. Файлът трябва да е ваш или споделен с Вас от колега.
## Езици

`auto` (по подразбиране) първо стартира откриването на ориентация и писменост на Tesseract, след което избира най-подходящия инсталиран модел за откритата писменост. Моделите за писмености като `Latin` или `Cyrillic` разчитат всеки език, написан с тази писменост, поради което `auto` се справя с турска и английска фактура, без да е необходимо да се указва коя коя е.

Указването на езика все още е по-точно, когато го знаете. Използвайте един код (`tur`) или съединете няколко с `+` (`eng+tur`) за смесени документи — повече езици означава по-бавно и леко по-неточно разпознаване, затова дръжте списъка кратък. Кодовете работят само когато съответните езикови данни са инсталирани на backend-а; node-ът показва какво е налично, когато изберете липсващ такъв.

Всеки образ на Heym включва `osd`, английски, турски, немски, френски, испански, италиански, португалски, нидерландски, руски, арабски, опростен китайски, японски, корейски, както и моделите за писмености Latin, Cyrillic, Arabic, HanS, Japanese и Hangul.

## Кодиране

Разпознатият текст е UTF-8 и запазва всеки символ, който Tesseract е произвел. `ocrNormalizeUnicode` (включен по подразбиране) прилага NFC нормализация, така че буква, написана като `s` плюс комбинираща седила, се превръща в единично `ş` — струва си да остане включено, защото двете форми не са равни при сравнения или справки в база данни.

`ocrEncoding` има значение само когато нещо надолу по веригата не може да съхрани пълния диапазон на Unicode. Избирането на `cp1254` или `iso-8859-9` запазва турския текст непокътнат, като същевременно гарантира, че резултатът се побира в този charset; `latin-1` и `ascii` са по-тесни и заменят това, което не могат да представят, с `?`. Оставете го на `utf-8`, освен ако целева система не Ви принуди да го промените.

## Изход

`csvToJson`, `jsonToCsv`, `xmlToJson` и `jsonToXml` връщат `$label.result` и `$label.conversion`. OCR конверсиите добавят:

| Поле | Описание |
|-------|-------------|
| `$label.result` | Пълният извлечен текст, страниците съединени с празен ред |
| `$label.language` | Моделът, който действително е работил (полезно, за да видите какво е избрал `auto`) |
| `$label.encoding` | Charset-ът, към който е нормализиран текстът |
| `$label.page_count` | Брой разпознати страници |
| `$label.pages` | Масив от `{ page, text }` за обработка по страници |
| `$label.file` | `{ id, filename, mime_type, size_bytes }` на изходния файл |

`fileConvert` връща новия файл вместо това:

| Поле | Описание |
|-------|-------------|
| `$label.id` | UUID на новосъхранения файл |
| `$label.filename` | Конвертирано име на файл, базовото име е запазено, а разширението е сменено |
| `$label.mime_type` | MIME тип на новия файл |
| `$label.size_bytes` | Размер на новия файл |
| `$label.download_url` | URL за изтегляне от Drive за новия файл |
| `$label.source_file` | Метаданни на файла, който е бил конвертиран |

## Пример

```json
{
  "type": "converter",
  "data": {
    "label": "toRows",
    "conversion": "csvToJson",
    "source": "$userInput.body.text",
    "delimiter": ",",
    "hasHeader": true
  }
}
```

За вход `name,age\nAda,36`, node-овете надолу по веригата достъпват парснатите редове чрез `$toRows.result` (`[{ "name": "Ada", "age": "36" }]`).

Конвертиране на XML към JSON:

```json
{
  "type": "converter",
  "data": {
    "label": "xmlToObject",
    "conversion": "xmlToJson",
    "source": "$webhook.body"
  }
}
```

За `<person id="1"><name>Ada</name></person>`, `$xmlToObject.result` е `{ "person": { "@id": "1", "name": "Ada" } }`. За да създадете XML, подайте този обект към втори Converter node с `conversion: "jsonToXml"`.

Разчитане на сканирана фактура, качена чрез file upload trigger:

```json
{
  "type": "converter",
  "data": {
    "label": "readInvoice",
    "conversion": "pdfToText",
    "converterFileId": "$Upload.file.id",
    "ocrLanguage": "tur",
    "ocrEncoding": "utf-8",
    "ocrDpi": 300,
    "ocrPageRange": "1-3"
  }
}
```

[Agent](./agent-node.md) или [LLM](./llm-node.md) node надолу по веригата може след това да извлече структурирани полета от `$readInvoice.result`.

Превръщане на markdown отчет на agent в PDF:

```json
{
  "type": "converter",
  "data": {
    "label": "convertDoc",
    "conversion": "fileConvert",
    "converterFileId": "$reportAgent._generated_files[0].id",
    "converterTargetFormat": "pdf"
  }
}
```

Node-овете надолу по веригата четат `$convertDoc.download_url`, за да споделят PDF-а, или `$convertDoc.id`, за да продължат да работят с него в [Drive](./drive-node.md).

## Изисквания

OCR извиква `tesseract` и `pdftoppm` на poppler, а конвертирането на документи използва pandoc. И трите се доставят с всеки начин на стартиране на Heym, включително `run.sh`, docker-compose и единичния release образ, така че няма нищо за конфигуриране. Ограниченията за страници, таймаутите и максималният DPI са фиксирани платформени стойности, а не настройки.
