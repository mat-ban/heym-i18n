# Trigger за качване на файл

**Trigger-ът за качване на файл** (File Upload Trigger) е входна точка с нулев вход за workflow-и, които се нуждаят от **голям файл** (аудио, видео, архиви), който не може да бъде вграден като base64 в JSON заявка. Извикването на workflow-а връща предварително попълнен `curl` линк за качване с еднократна употреба; качването на файл на този линк стартира изпълнението с прикачен файл.

Използвайте го, когато извикващата страна — включително AI агент като Claude или ChatGPT, работещ в sandbox — трябва да предаде 20 MB гласов запис или 75 MB видео на Heym workflow.

## Преглед

| Свойство | Стойност |
|----------|-------|
| Входове | 0 |
| Изходи | 1 |
| Изход | `$nodeLabel.file.{id,name,mime,size,download_url}`, `$nodeLabel.uploaded_at` |

## Как работи

Node-ът работи в две фази:

1. **Създаване (Mint).** Когато workflow-ът бъде извикан по HTTP (`POST /api/workflows/{id}/execute`), като MCP инструмент или чрез бутона **Run Workflow** на canvas-а, изпълнението **не** изпълнява тялото. Вместо това се създава слот за качване с еднократна употреба и се връща:

   ```json
   {
     "file_upload_required": true,
     "curl": "curl -F 'file=@/path/to/your/file' 'https://your-host/api/file-intake/u/<token>'",
     "upload_url": "https://your-host/api/file-intake/u/<token>",
     "expires_at": "2026-06-25T13:00:00+00:00",
     "max_size_mb": 100,
     "allowed_types": ["audio/*"]
   }
   ```

2. **Качване + изпълнение.** Извикващата страна изпълнява `curl` с своя файл. Endpoint-ът за качване валидира слота, съхранява файла, изпълнява workflow-а **синхронно** и връща изхода на workflow-а в отговора на качването. Линкът е **еднократен** — второ качване връща `409`.

На canvas-а **Run Workflow** показва създадения `curl` в debug панела с бутон за копиране.

## Параметри

| Параметър | Тип | По подразбиране | Описание |
|-----------|------|---------|-------------|
| `ttlMinutes` | number | `60` | Колко дълго линкът за качване остава валиден (1–10080 минути / до 7 дни). |
| `maxSizeMb` | number | `100` | Максимален приет размер на файла. Твърдият таван е **100 MB**. |
| `allowedTypes` | string | (празно) | Опционален списък с разрешени MIME типове/разширения, разделени със запетая, напр. `audio/*, .wav`. Празно позволява всякакъв тип. |

## Изходни полета

| Израз | Описание |
|------------|-------------|
| `$nodeLabel.file.id` | UUID на съхранения файл (Drive файл). |
| `$nodeLabel.file.name` | Оригинално име на файла. |
| `$nodeLabel.file.mime` | Открит тип на съдържанието. |
| `$nodeLabel.file.size` | Размер в байтове. |
| `$nodeLabel.file.download_url` | Автентикиран URL за изтегляне за последващи nodes. |
| `$nodeLabel.uploaded_at` | ISO времеви печат на качването. |

## Пример

Workflow за транскрипция:

```
File Upload Trigger ("audio")  →  Transcribe ($audio.file)  →  LLM summary  →  Output
```

1. Агент извиква MCP инструмента на workflow-а и получава `curl`.
2. Агентът изпълнява `curl` със записа от своя sandbox.
3. Качването изпълнява workflow-а и отговорът на `curl` съдържа обобщението на транскрипцията.

## Сигурност

- URL-ът за качване съдържа token с висока ентропия — token-ът **е** разрешението, така че sandbox-нат агент не се нуждае от Heym удостоверения, за да качи. Само хешът на token-а се съхранява на сървъра.
- Създаването изисква нормална автентикация на workflow-а, така че само оторизирани извикващи страни могат да създават линкове за качване.
- Всяко създаване и всеки опит за качване (приет или отхвърлен — изтекъл, повторен, с превишен размер, неразрешен тип, непознат token) се записва в одитен журнал само за добавяне.
- Качванията са с наложена еднократна употреба, ограничени с TTL и с таван на размера; качвания с превишен размер се отхвърлят.

## Бележки

- Общите канали за извикване по HTTP, MCP и canvas остават само JSON; този node е поддържаният начин за приемане на multipart качвания на файлове.
- Каченият файл се съхранява като нормален Drive файл, така че всеки последващ node, който приема референция към файл (транскрипция, изпращане на прикачен файл по имейл и т.н.), може да консумира `$nodeLabel.file`.
