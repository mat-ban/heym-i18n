# Google Meet

Намерете свободни времеви интервали в Google Calendar и създавайте, актуализирайте или изтривайте покани за срещи с връзки към Google Meet, имейли на участници и избрани часове. Свързаният акаунт в Google е собственик на събитието; участниците получават покани по имейл.

## Свързване на вашия акаунт

1. В [Google Cloud Console](https://console.cloud.google.com) активирайте **Google Calendar API**.
2. Конфигурирайте екрана за съгласие за OAuth и създайте OAuth клиент за **Уеб приложение**. Добавете вашия акаунт в Google като тестов потребител, ако приложението е в тестов режим.
3. Регистрирайте `https://your-heym-domain/api/credentials/google-meet/oauth/callback` като оторизиран URI адрес за пренасочване. За локална разработка използвайте произхода на Heym във вашия браузър със същия път.
4. Отворете **Dashboard → Удостоверения → Нов → Google Meet (OAuth2)**, въведете име, Client ID и Client Secret, щракнете върху **Свързване** и влезте с Google.
5. Предоставете и двете разрешения: Събития в календара (`calendar.events`) и наличност в календара (`calendar.events.freebusy`). Изберете това удостоверение в node-а.

Токените се криптират в хранилището и се обновяват автоматично. Това е отделно удостоверение от Google AI, Sheets или Drive. Календарът трябва да поддържа конферентни разговори в Google Meet, за да бъде създаването успешно.

## Операции

| Операция | Поведение | Задължителни полета |
| --- | --- | --- |
| `read` | Връща свободните и заетите интервали за календар | Удостоверение |
| `create` | Създава планирано събитие с нова Meet конференция и покани по имейл | Заглавие, начален час, краен час |
| `update` | Актуализира посочените полета на събитието и уведомява гостите | ID на събитието и поне едно променено поле |
| `delete` | Изтрива събитието и уведомява гостите за анулирането | ID на събитието |

## Конфигурация

Текстовите полета по-долу приемат изрази. Всички полета, включително булевата опция за подробности, могат да бъдат предоставени от Agent, когато този node е прикачен като инструмент.

| Поле | По подразбиране | Предназначение |
| --- | --- | --- |
| `gmCalendarId` | `primary` | Основен календар на свързания акаунт или достъпен ID/имейл на календар |
| `gmTimeZone` | `UTC` | IANA часова зона, например `Europe/Sofia`, използвана за местни дати и времена на отговор |
| `gmStartDate` | Текущо време | Начало на обхвата за четене като ISO дата или datetime |
| `gmEndDate` | Първият ден от следващия месец в полунощ | Изключващ край на обхвата за четене; максималният обхват е 60 календарни дни |
| `gmIncludeBusyDetails` | `false` | Само за четене: включва заглавията на събитията и участниците в `busy_slots`; boolean |
| `gmEventId` | Празно | ID на събитие в календара за update/delete; използвайте върнатия `event_id`, а не Meet URL |
| `gmTitle` | Празно | Заглавие на поканата; задължително при `create` |
| `gmDescription` | Празно | Описание на поканата |
| `gmStartTime` | Празно | Начало на срещата, напр. `2026-11-10T14:00:00+02:00` |
| `gmEndTime` | Празно | Край на срещата; трябва да е след началото |
| `gmAttendees` | Празно | Имейли, разделени със запетая/точка и запетая/нов ред, или JSON масив от низове с имейли |
| `gmLocation` | Празно | Незадължително местоположение на срещата заедно с Meet конференцията |

### Свободни времеви интервали

Четенето по подразбиране обхваща периода от текущото време до **1-во число на следващия месец, 00:00 ч.** в избраната часова зона. Задайте `gmEndDate`, за да определите друг прозорец. Обхват над 60 дни или невалидна дата се отхвърля преди извикване на Google.

Резултатът се основава на API **free/busy** на Google. Заетите интервали се обединяват и изваждат от заявения прозорец. `available_slots` съдържа непрекъснати свободни интервали с времеви отпечатъци `start` и `end`.

```json
{
  "type": "googleMeet",
  "data": {
    "label": "Availability",
    "credentialId": "YOUR_GOOGLE_MEET_CREDENTIAL_ID",
    "gmOperation": "read",
    "gmCalendarId": "primary",
    "gmTimeZone": "Europe/Berlin",
    "gmStartDate": "2026-11-06",
    "gmEndDate": "2026-11-13"
  }
}
```

### Включване на подробности за заетите събития

В **Четене на свободни времеви интервали** активирайте **Включване на подробности за заетите събития** (`gmIncludeBusyDetails: true`), за да добавите заглавието и участниците към всеки зает слот. Тази опция е деактивирана по подразбиране.

```json
{
  "start": "2026-11-06T21:15:00+01:00",
  "end": "2026-11-06T21:30:00+01:00",
  "title": "Daily check-in",
  "attendees": [
    "colleague@example.com"
  ]
}
```

### Резервиране на среща

1. Стартирайте node `read` с удостоверението на собственика на workflow-а.
2. Показвайте `available_slots` във вашия интерфейс за резервации.
3. Предайте `email`, `startTime` и `endTime` като входни данни за workflow-а.
4. Стартирайте `create` със същото удостоверение. Посетитерят не се нуждае от акаунт в Google; неговият имейл се записва като участник.

```json
{
  "type": "googleMeet",
  "data": {
    "label": "Booking",
    "credentialId": "YOUR_GOOGLE_MEET_CREDENTIAL_ID",
    "gmOperation": "create",
    "gmCalendarId": "primary",
    "gmTimeZone": "Europe/Berlin",
    "gmTitle": "Meet with me",
    "gmDescription": "A meeting booked through Heym",
    "gmAttendees": "$input.email",
    "gmStartTime": "$input.startTime",
    "gmEndTime": "$input.endTime"
  }
}
```

## Изход

| Операция | Изходни полета |
| --- | --- |
| `read` | `available_slots`, `busy_slots`, `count`, `calendar_id`, `time_zone`, `start`, `end` |
| `create`, `update` | `event_id`, `meet_url`, `conference_status`, `event`, `calendar_id` |
| `delete` | `event_id`, `calendar_id`, `deleted: true` |

Използвайте `$Availability.available_slots` или `$Booking.meet_url` в следващите nodes. Всяка операция връща също `status: "success"` и своята съответна `operation`.
