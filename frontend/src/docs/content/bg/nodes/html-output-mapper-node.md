# HTML output mapper

Възелът **HTML output mapper** рендерира един HTML шаблон в страница. Използвайте го, когато извикващият е **браузър**, а не API клиент — workflow-ът отговаря с `text/html` вместо с JSON.

## Преглед

| Свойство | Стойност |
|----------|-------|
| Входове | 1 |
| Изходи | 0 (sink) |
| Runtime изход | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Параметри

| Параметър | Тип | Описание |
|-----------|------|-------------|
| `label` | string | Идентификатор на възела (camelCase) |
| `html` | string | Шаблонът на страницата. Изразите `$nodeLabel.field` се интерполират на място. |
| `statusCode` | number | HTTP статус за отговора (по подразбиране `200`) |
| `contentType` | string | Content type на отговора (по подразбиране `text/html; charset=utf-8`) |

## Webhook и поведение при изпълнение

Когато този възел е **единственият** терминален изход на workflow-а, execute endpoint-ът отговаря с рендерираната страница, конфигурирания статус код и конфигурирания content type — без JSON обвивка, без обвивка с label.

Две неща изключват това поведение:

- **Втори терминален възел.** При наличие на друг активен терминален възел в графа, Heym се връща към нормалната JSON карта по label и страницата пристига като string поле.
- **`X-Simple-Response: false`.** Този header изисква пълната обвивка с `status`, `node_results` и времена за изпълнение, което е и това, което използва canvas-ът на редактора. Изпращайте го, когато дебъгвате page workflow.

## Сервиране на страница към браузър

Задайте **request method** на workflow-а на `GET` в cURL диалога, така че обикновена навигация от браузър да достига до него. `GET` заявката не носи body, затова входните стойности идват от query string:

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Прочетете тези стойности с `$input.query.name`. Вижте [Webhooks](../reference/webhooks.md) за пълния договор за методите.

Workflow без trigger възел, чийто единствен терминален възел е този, показва **WEB** етикет в [Workflows tab](../tabs/workflows-tab.md).

## Използване като инструмент на агент

Не се поддържа. Този възел е терминален sink, затова не може да бъде прикачен към handle за инструменти на [Agent Node](./agent-node.md). Същото важи и за [JSON output mapper](./json-output-mapper-node.md).

## Ограничение за цикли

Същото правило като при [Output](./output-node.md): не поставяйте този възел в разклонение на итерация на цикъл — само след `done` разклонението на цикъла. Вижте [Loop](./loop-node.md).

## Пример

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
