# Plugin Node

**Plugin** node изпълнява персонализирано действие, предоставено от инсталиран plugin. Плъгините разширяват Heym с нови типове nodes — действия, интеграции с трети страни или всичко, изразимо чрез Python — без да се налага модифициране на основното приложение.

## Преглед

| Свойство | Стойност |
|----------|-------|
| Входове | 1 |
| Изходи | 1 |
| Изход | `$nodeLabel.<keys returned by the plugin>` |

Един plugin **пакет** (един zip файл) може да съдържа **множество nodes** — произволна комбинация от действия и triggers. Всеки node се появява в палитрата под **Plugins** със собствено име и описание. Плъзгането на node върху работната площ създава Plugin node, обвързан с този пакет (`pluginId`) и node (`pluginNodeKey`).

## Кога да се използва

Използвайте Plugin node, когато оператор е инсталирал plugin, който изпълнява необходимото Ви действие — например извикване на частен API, комуникация с вътрешна система или изпълнение на специализирана логика, написана за Вашата инсталация.

За плъгини от тип trigger, които стартират workflow, вижте [Plugin Trigger node](./plugin-trigger-node.md).

## Конфигурация

Формулярът за конфигурация на node се генерира от манифеста на plugin. Всяко поле, декларирано от plugin (`string`, `number`, `boolean` или `select`), се визуализира автоматично. Несекретните полета от тип string използват полето за изрази, а запазените стойности на конфигурацията от тип string, които започват с `$`, се разрешават преди изпълнението на plugin handler.

Секретните полета (като API ключове) са маскирани в потребителския интерфейс и никога не се записват в логовете.

## Как се изпълняват плъгините

Плъгините се доставят от Heym и се инсталират от оператор, поради което кодът на plugin е **доверен** и се изпълнява в процеса като вграден node, с пълен достъп до мрежата и библиотеките. Един plugin може да декларира pip `dependencies`, които се инсталират в инстанцията по време на инсталацията.

Инсталирането и премахването на плъгини е ограничено до оператори, чийто имейл е посочен в `HEYM_PLUGIN_ADMIN_EMAILS`, а цялата подсистема е управлявана от `HEYM_PLUGINS_ENABLED` (изключена по подразбиране). Вижте [Running & Deployment](../getting-started/running-and-deployment.md) за променливите на средата.

## Персонализирани икони

Един plugin може да доставя персонализирани SVG лога. Поставете `icon.svg` в основната директория на пакета, за да зададете стойност по подразбиране за всеки node, и/или задайте на даден node собствено `"icon": "<file>.svg"` в манифеста. Иконата се показва както върху картата в палитрата, така и върху node върху работната площ; nodes без икона използват глифа по подразбиране с форма на пъзел.

## AI Builder

Инсталираните плъгини са достъпни за AI асистента и chat canvas, така че можете да помолите Heym да „използва Acme CRM plugin за създаване на запис“ и той ще генерира Plugin node с правилните `pluginId` и `config`.

## Авторство на плъгини

За да създадете plugin пакет, вижте [Plugin Authoring](../reference/plugin-authoring.md) за структурата на zip файла, полетата на манифеста, сигнатурите на handler, иконите, зависимостите и модела на доверие по време на изпълнение.
