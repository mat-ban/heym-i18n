# Функции на Canvas

Редакторът на workflow предоставя няколко функции за отстраняване на грешки, тестване и организиране на nodes: **Run to Node**, **Data Pin**, **Execution Logs**, **Enable/Disable** и **Extract to Sub-Workflow**.

## Run to Node

Задръжте курсора върху който и да е node (с изключение на sticky note) и кликнете върху **Run** под него. Heym изпълнява този node и неговите upstream зависимости, като оставя downstream nodes и несвързаните разклонения непокътнати. Това използва режима за тестване на canvas, включително pinned outputs и нормалните branch conditions на workflow.

Ако избраният път има входни полета, панелът **Run** отдясно се отваря и фокусира първото поле. Въведете стойностите и след това кликнете върху **Run to _node label_** или натиснете **Ctrl+Enter** (Cmd+Enter на macOS). Режимът Generic body фокусира редактора на JSON body. Пътищата без входни полета се изпълняват незабавно, без да се отваря панелът. Pinned Input nodes използват повторно своя pinned output, без да искат входни данни.

Панелът запазва избраната цел за следващите изпълнения. Изберете **Run full workflow**, за да изчистите целта. Бутоните за изпълнение са деактивирани, докато има активно изпълнение. Цел вътре в loop спира изпълнението, когато този node бъде достигнат за първи път; избирането на node след loop изпълнява целия upstream loop.

## Data Pin

Data Pin Ви позволява да pin-нете output на node от последното изпълнение, така че да можете да тествате downstream nodes, без да изпълнявате отново pinned node.

### Къде да го намерите

- **Properties panel** – Изберете node и превъртете до секцията **Pinned Data**
- **Node badge** – Икона за pin се появява върху node, когато данните са pinned

### Действия

| Действие | Описание |
|--------|-------------|
| **Pin** | Pin-ва output от последното изпълнение на node (налично след изпълнение) |
| **Clear** | Премахва pinned данните |
| **Edit** | Редактирайте pinned JSON директно; кликнете Save, за да приложите |

### Поведение в режим на тестване

Когато изпълнявате workflow в режим на тестване, nodes с `pinnedData` пропускат изпълнението и използват pinned output вместо това. Използвайте това, за да:

- Тествате downstream логика, без да извиквате външни API-та
- Отстранявате грешки в изрази, които реферират output на node
- Итерирате върху prompts или условия с фиксирани примерни данни

Автоматичното довършване на изрази в редактора използва pinned данни, когато са налични, за да предложи полета.

## Execution Logs

**Debug panel** (долният drawer) показва execution logs в реално време по време на изпълнения на workflow. Можете също да отворите активно production изпълнение от диалога History или от Board card. Редакторът се прикачва към SSE потока на това изпълнение, възстановява резултатите от завършените nodes и продължава да показва анимации на nodes и logs, когато нови nodes започват и завършват.

### Какво показва

- **Node results** – Статус на всеки node (`success`, `error`, `skipped`, `running`), време за изпълнение и output
- **Final outputs** – Агрегирани outputs от [Output](../nodes/output-node.md) nodes
- **Agent progress** – За [Agent](../nodes/agent-node.md) nodes, стъпка по стъпка извиквания на инструменти и reasoning

### Действия

- **Copy as JSON** – Копира пълния execution log в clipboard
- **Open in JSON editor** – Отваря log-а в JSON Hero или JSON Editor Online за преглед
- **Download generated files** – Ако skill е генерирал файлове за изтегляне (`_generated_files`), се появява бутон Download. Единичен файл се изтегля директно; множество файлове отварят popup за избор.

### Разлика от Logs Tab

Debug panel показва logs от **изпълнение на workflow** (node results, outputs). [Logs Tab](../tabs/logs-tab.md) показва logs от **Docker контейнери** (backend, frontend, database). <!-- pragma: allowlist secret -->

## Enable / Disable

Можете да деактивирате nodes, така че да бъдат пропускани по време на изпълнение. Деактивираните nodes показват badge "off" и изглеждат затъмнени.

### Как да превключвате

| Метод | Описание |
|--------|-------------|
| **Properties panel** | Изберете node → икона Power (горе вдясно) |
| **Context menu** | Кликнете с десен бутон върху node(s) → Disable или Enable |
| **Keyboard** | Изберете node(s) → натиснете **D** (вижте [Keyboard Shortcuts](./keyboard-shortcuts.md)) |

### Multi-Select

Когато са избрани няколко nodes, Enable/Disable се прилага за всички тях. Context menu показва "Enable", ако някой избран node е деактивиран, "Disable", ако всички са активирани.

### Поведение по време на изпълнение

Nodes с `active: false` се пропускат. Downstream nodes не получават данни от пропуснатите nodes. Използвайте това, за да изключите временно nodes, без да ги изтривате.

За да включите или изключите node отвътре в workflow, вместо ръчно, използвайте [Disable Node](../nodes/disable-node.md) и [Enable Node](../nodes/enable-node.md).
## Граф на паметта на агента

[Agent](../nodes/agent-node.md) nodes с активирана **[постоянна памет](./agent-persistent-memory.md)** показват розов контрол **brain** върху node. Кликнете върху него, за да отворите редактора на графа на паметта: обектите се визуализират като анимиран, force-directed граф, групиран по тип обект, с търсими Source/Target pickers за добавяне на връзки и панел за връзки за прескачане между свързани обекти. Същият диалогов прозорец включва **Share memory with other agents** (workflow → agent → read или read/write) за [споделяне на памет между агенти](./agent-persistent-memory.md#sharing-with-other-agents). Докато диалоговият прозорец е отворен, undo/redo на основния canvas е отложено, така че редактирането на графа запазва собствената си история.

**Филтриране на графа.** В горния ляв ъгъл на canvas има контрол за търсене, свит до бутон за бърз достъп, докато не кликнете върху него или не натиснете **Ctrl/Cmd+F**. Той съвпада с името на обект, неговия тип и всеки ключ и стойност на атрибут, както и с типа на връзка (`parent_of`) и нейните свойства; съвпадаща връзка води със себе си и двата свои обекта. Всички термини, разделени с интервал, трябва да съвпадат. Съвпадащ обект води със себе си цялата си околност — всяка връзка, в която участва, и обекта от другата страна на всяка от тях — така че съвпадението никога не остава като несвързана точка. Съвпадаща връзка води само двата обекта, които свързва, и спира дотук, тъй като търсенето на тип връзка е въпрос за тази връзка, а не за всичко, към което са прикачени нейните краища. Всичко останало се скрива напълно — не се затъмнява — на canvas и в списъка **All edges**, а badge показва колко от общия брой обекти са останали. **✕** вътре в полето първо изчиства заявката, а при второ натискане затваря полето. Escape се развива по същия начин, отвътре навън: изчиства заявката, след това затваря полето за търсене, след това напуска разширения изглед на canvas и затваря диалоговия прозорец само когато никое от тези не е отворено. Изчистването възстановява пълния граф с всеки обект обратно на мястото му.

**Ръчно поставяне на обекти.** Плъзгането на обект го закрепва там, където го пуснете, така че автоматичното оформление подрежда останалата част от графа около него, вместо да го издърпва обратно. Плъзгането на избрания от Вас обект мести заедно с него и пряко свързаните с него обекти, запазвайки формата на клъстера; плъзгането на всеки друг обект мести само него. **Tidy layout** (бутонът с пръчката) освобождава всеки закрепен обект и стартира отново автоматичното оформление.

## Extract to Sub-Workflow

Преобразувайте избраните nodes в многократно използваем sub-workflow и ги заменете с [Execute](../nodes/execute-node.md) node.

### Как да използвате

1. Изберете един или повече nodes на canvas
2. Кликнете с десния бутон → **Extract to Sub-Workflow**
3. Въведете име (и незадължително описание) за новия workflow
4. Кликнете **Extract**

### Какво се случва

- Създава се нов workflow с избраните nodes
- Външните входове (edges отвън на селекцията) стават полета [Input](../nodes/input-node.md) на sub-workflow
- Външните изходи (edges към nodes извън селекцията) се съпоставят към [Output](../nodes/output-node.md) на sub-workflow
- Избраните nodes се заменят с един [Execute](../nodes/execute-node.md) node, който извиква новия workflow
- Входно/изходните съпоставяния се запазват автоматично

### Случаи на употреба

- Повторно използване на последователност от nodes в множество workflows
- Опростяване на сложен workflow чрез групиране на свързана логика
- Създаване на модулни, тестваеми sub-workflows

## Run with cURL

Бутонът **cURL** в лентата с инструменти на редактора (горе вдясно) отваря диалогов прозорец за съставяне и копиране на cURL команда за задействане на workflow чрез API.

- Изберете режима на тялото на заявката на workflow (`Defined` или `Generic`)
- Задайте типа автентикация (Anonymous, JWT или Header Auth)
- Конфигурирайте кеширането на отговори и ограничаването на честотата
- Превключете SSE streaming и персонализирайте началните съобщения за всеки node
- Редактирайте тялото на заявката
- В режим Generic панелът за изпълнение на canvas използва същото raw JSON тяло като диалоговия прозорец cURL
- Кликнете **Copy cURL**, за да копирате готовата за изпълнение команда

Вижте [Webhooks](./webhooks.md#run-with-curl-dialog) за пълни подробности за диалоговия прозорец и [SSE Streaming](./sse-streaming.md) за протокола за събития.
