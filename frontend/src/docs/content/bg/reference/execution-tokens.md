# Execution Tokens

Execution tokens са обхватно ограничени JWT, които предоставят достъп до execute и stream endpoint-ите на един workflow. Те Ви позволяват да извиквате workflow от външни системи, без да разкривате своя дълготраен потребителски session token.

## Защо да използвате Execution Tokens

Когато authentication на даден workflow е зададен на **JWT**, endpoint-ът обикновено изисква валидна потребителска сесия. Execution tokens Ви позволяват да:

- Споделите извикваем token с външни скриптове, CI pipelines или интеграции, без да споделяте своите идентификационни данни за акаунта.
- Ограничите разкриването — даден token е валиден само за един конкретен workflow.
- Отмените достъпа незабавно, без да променяте паролата си или да ротирате session tokens.
- Избирате между краткотрайни tokens (минути или часове) и дълготрайни tokens (до 10 години).

## Създаване на Token

Отворете диалога **Run with cURL** в редактора (лентата с инструменти в горния десен ъгъл). Когато authentication на workflow е зададен на **JWT Token**, диалогът показва мениджър на tokens:

1. Изберете **Short-lived** или **Long-lived (10yr)**.
2. За краткотрайни tokens въведете продължителността в секунди (минимум 60).
3. Натиснете **+ New Token**.

Token-ът се създава незабавно, добавя се към списъка и се избира автоматично, така че cURL командата се обновява, за да го включи.

## Списък с Tokens

Всеки ред с token показва:

| Колона | Описание |
|--------|-------------|
| Created | Timestamp на създаване |
| Status | **Expires:** дата, **Expired** или **Revoked** |
| Икона с око | Превключва видимостта на стойността на token-а |
| Бутон за отмяна | Маркира token-а като отменен (необратимо) |

Натиснете който и да е активен (неизтекъл, неотменен) ред, за да го изберете. Избраният token се вгражда в прегледа на cURL командата.

Изтеклите и отменените tokens остават видими в списъка, но не могат да бъдат избирани.

## Използване на Token

Копирайте стойността на token-а от списъка (натиснете иконата с око, за да я разкриете) и я включете като `Bearer` token:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "X-Trigger-Source: my-service" \
  -H "Authorization: Bearer <execution-token>" \
  "https://app.heym.ai/api/workflows/{workflow_id}/execute" \
  -d '{"message": "Hello"}'
```

Когато използвате **Copy cURL** в диалога с избран token, token-ът вече е вграден в командата — не е необходимо ръчно заместване.

## Обхват на Token

Всеки token носи следните JWT claims:

| Claim | Стойност |
|-------|-------|
| `sub` | User ID на създателя на token-а |
| `wid` | Workflow UUID — token-ът се отхвърля за всеки друг workflow |
| `scope` | `workflow:execute` — разграничава го от потребителски session token |
| `jti` | Уникален token ID, използван за проверки при отмяна |
| `exp` | Timestamp на изтичане |

Backend-ът проверява всички тях при всяка заявка: валидност на подписа, изтичане, съответстващ `wid` и че `jti` не е отменен.

## Отмяна

Натиснете бутона за отмяна (кръг с наклонена черта) до даден token, за да го отмените. Отмяната влиза в сила незабавно — последващите заявки, използващи този token, връщат `401`. Редът с token-а остава видим в списъка с етикет **Revoked**.

Няма възстановяване на отменен token. Създайте нов token, ако трябва да възстановите достъпа.

## API

Endpoint-ите за управление на tokens се удостоверяват с обичайната Ви сесия.

| Метод | Път | Описание |
|--------|------|-------------|
| `POST` | `/api/workflows/{id}/execution-tokens` | Създаване на token |
| `GET` | `/api/workflows/{id}/execution-tokens` | Списък на Вашите tokens за този workflow |
| `DELETE` | `/api/workflows/{id}/execution-tokens/{token_id}` | Отмяна на token |

**Тяло на заявката за създаване:**

```json
{ "ttl_seconds": 900 }
```

**Отговор при създаване:**

```json
{
  "id": "uuid",
  "token": "<full jwt>",
  "expires_at": "2026-04-30T15:22:00Z",
  "created_at": "2026-04-30T15:07:00Z",
  "revoked": false
}
```

Полето `token` се връща само веднъж при създаването. Съхранете го незабавно; последващите `GET` заявки връщат същия ред, но можете също да го разкриете в cURL диалога по всяко време.

## Обхват на видимост

Всеки потребител вижда само tokens, които е създал. Членове на екипа с достъп до споделен workflow не могат да виждат tokens на другите.
