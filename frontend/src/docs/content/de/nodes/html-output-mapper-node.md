# HTML-Ausgabe-Mapper

Der **HTML-Ausgabe-Mapper**-Knoten rendert eine einzelne HTML-Vorlage in eine Seite. Verwende ihn, wenn der Aufrufer ein **Browser** statt eines API-Clients ist — der Workflow antwortet dann mit `text/html` statt JSON.

## Übersicht

| Eigenschaft | Wert |
|----------|-------|
| Eingaben | 1 |
| Ausgaben | 0 (Senke) |
| Laufzeit-Ausgabe | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Parameter

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `label` | string | Knoten-Bezeichner (camelCase) |
| `html` | string | Die Seitenvorlage. `$nodeLabel.field`-Ausdrücke werden an Ort und Stelle interpoliert. |
| `statusCode` | number | HTTP-Status für die Antwort (Standard `200`) |
| `contentType` | string | Antwort-Content-Type (Standard `text/html; charset=utf-8`) |

## Webhook- und Ausführungsverhalten

Wenn dieser Knoten die **einzige** terminale Ausgabe des Workflows ist, antwortet der Execute-Endpoint mit der gerenderten Seite, dem konfigurierten Statuscode und dem konfigurierten Content-Type — kein JSON-Envelope, kein Label-Wrapper.

Zwei Dinge schalten das ab:

- **Ein zweiter terminaler Knoten.** Bei einem weiteren aktiven terminalen Knoten im Graphen fällt Heym auf die normale JSON-Map pro Label zurück, und die Seite kommt als String-Feld an.
- **`X-Simple-Response: false`.** Dieser Header verlangt das vollständige Envelope mit `status`, `node_results` und Timings, was der Canvas des Editors verwendet. Sende ihn, wenn du einen Seiten-Workflow debuggst.

## Eine Seite an einen Browser ausliefern

Setze die **Request-Methode** des Workflows im cURL-Dialog auf `GET`, damit eine einfache Browser-Navigation ihn erreicht. Eine `GET`-Anfrage trägt keinen Body, daher kommen die Eingaben aus dem Query-String:

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Lies diese Werte mit `$input.query.name`. Siehe [Webhooks](../reference/webhooks.md) für den vollständigen Methodenvertrag.

Ein Workflow ohne Trigger-Knoten, dessen einziger terminaler Knoten dieser Knoten ist, zeigt einen **WEB**-Chip im [Workflows-Reiter](../tabs/workflows-tab.md).

## Verwendung als Agent-Tool

Nicht unterstützt. Dieser Knoten ist eine terminale Senke und kann daher nicht an einen Tools-Handle eines [Agent-Knoten](./agent-node.md) angehängt werden. Dasselbe gilt für den [JSON output mapper](./json-output-mapper-node.md).

## Loop-Einschränkung

Dieselbe Regel wie bei [Output](./output-node.md): Platziere diesen Knoten nicht innerhalb eines Loop-Iterationszweigs — nur nach dem `done`-Zweig des Loops. Siehe [Loop](./loop-node.md).

## Beispiel

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
