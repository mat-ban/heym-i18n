# Γιατί το Heym

Το Heym είναι υποδομή για την εκτέλεση και τη διακυβέρνηση AI agents σε παραγωγή. Ένα self-hosted runtime καλύπτει κάθε στάδιο του κύκλου ζωής ενός agent.

Ένας prototype agent χρειάζεται ένα μοντέλο, ένα prompt και μερικά εργαλεία. Ένας production agent χρειάζεται επίσης triggers και επαναλήψεις, αποθηκευμένη κατάσταση όταν διακόπτεται για κάποιο άτομο, αρχείο κάθε κλήσης μοντέλου και εργαλείου, κόστος για κάθε εκτέλεση, δοκιμές πριν από κάθε αλλαγή, και σαφή όρια στο τι μπορεί να κάνει αυτόνομα. Το Heym τα συγκεντρώνει όλα αυτά σε ένα σημείο, ώστε το σύστημα που σχεδιάζετε στον καμβά να είναι το σύστημα που εκτελείται. Δημιουργήστε agentic συστήματα και, στη συνέχεια, εκτελέστε τα με σιγουριά.

## Ένα Runtime για τον Κύκλο Ζωής του Agent

| Στάδιο | Τι σας προσφέρει το Heym |

| **Orchestrate** | Συντονίστε agents, [sub-agents](../reference/agent-architecture.md), coding agents, RAG, browser automation και εργαλεία με ρητή ροή δεδομένων και [παράλληλη εκτέλεση](../reference/parallel-execution.md). |
| **Run** | Ξεκινήστε εκτελέσεις από [webhooks](../reference/webhooks.md), χρονοδιαγράμματα και event [triggers](../reference/triggers.md), με επαναλήψεις ανά κόμβο, [διαχείριση σφαλμάτων](../nodes/error-handler-node.md) και [κατανομή φόρτου](../reference/cluster.md) μεταξύ instances. |
| **Observe** | Επιθεωρήστε κάθε εκτέλεση μέσω [history](../reference/execution-history.md), [LLM traces](../tabs/traces-tab.md), κόστους σε USD ανά εκτέλεση, ζωντανών εκτελέσεων στον καμβά, [analytics](../tabs/analytics-tab.md), [alerts](../tabs/alerts-tab.md) και εξαγωγής [OpenTelemetry](../reference/opentelemetry.md). |
| **Evaluate** | Δοκιμάστε prompts και μοντέλα έναντι αναμενόμενων αποτελεσμάτων στα [Evals](../tabs/evals-tab.md), με βαθμολόγηση LLM-as-Judge και σύγκριση μοντέλων δίπλα-δίπλα. |
| **Control** | Κρατήστε τους ανθρώπους στον έλεγχο με [review checkpoints](../reference/human-in-the-loop.md) και [guardrails](../reference/guardrails.md), και διαχειριστείτε την πρόσβαση με κρυπτογραφημένα [credentials](../reference/credentials.md), [teams](../reference/teams.md), [single sign-on](../reference/sso.md) και [audit trail](../reference/audit.md). |
| **Expose** | Διαθέστε workflows μέσω REST και [SSE](../reference/sse-streaming.md), ως εργαλεία [MCP](../tabs/mcp-tab.md), ως chat UIs [Portal](../reference/portal.md) και ως widgets [dashboard](../tabs/dashboard-tab.md). |

## Build

### AI Assistant: Δημιουργία Workflow με Φυσική Γλώσσα

Ο [AI Assistant](../reference/ai-assistant.md) είναι ένα πάνελ συνομιλίας μέσα στον επεξεργαστή workflow. Περιγράψτε τι θέλετε, για παράδειγμα «δημιουργήστε ένα workflow που δέχεται είσοδο χρήστη, αναζητά στη βάση γνώσεών μου και απαντά χρησιμοποιώντας το GPT-4o», και ο assistant δημιουργεί nodes και edges που εφαρμόζονται άμεσα στον καμβά.

- Χρησιμοποιεί το δικό σας credential LLM (οποιοδήποτε υποστηριζόμενο μοντέλο)
- Υποστηρίζει **voice input** για σχεδιασμό workflow χωρίς τη χρήση χεριών
- Εφαρμόζει αυτόματα έγκυρο workflow JSON από την απάντηση του AI στον καμβά
- Μεταδίδει τις απαντήσεις σε πραγματικό χρόνο

Ο assistant λειτουργεί απευθείας μέσα στον επεξεργαστή και μεταδίδει nodes στον καμβά σε πραγματικό χρόνο, και ό,τι δημιουργεί παραμένει επεξεργάσιμο όπως τα nodes που τοποθετήσατε χειροκίνητα.

### Skills System

Τα Skills είναι φορητά πακέτα δυνατοτήτων, ένα αρχείο οδηγιών `SKILL.md` συν προαιρετικά Python scripts, που μπορούν να προστεθούν σε οποιοδήποτε Agent node.

- Οι οδηγίες του skill προστίθενται στην αρχή του system prompt του agent
- Τα Python αρχεία στο skill γίνονται callable tools
- Τα skills είναι επαναχρησιμοποιήσιμα σε workflows και κοινοποιήσιμα ως αρχεία `.zip`

Αυτό είναι ανάλογο με το να δίνετε στον agent σας μια περιγραφή θέσης εργασίας και μια εργαλειοθήκη σε μία κίνηση.

### Workflow Analyzer: Run-Aware Feedback

Το πάνελ [Workflow Analysis](../reference/workflow-analysis.md) είναι ένα run-aware εργαλείο τεκμηρίωσης και ανατροφοδότησης ενσωματωμένο στον επεξεργαστή. Κάντε κλικ στο **Analyze**, επιλέξτε ένα credential LLM και μοντέλο, και το Heym δημιουργεί μια επεξεργάσιμη αναφορά Markdown για το τρέχον workflow.

Σε αντίθεση με μια στατική σημείωση, ο analyzer εκτελεί πρώτα το workflow όταν αυτό είναι εφικτό και συμπεριλαμβάνει το αποτέλεσμα εκτέλεσης στο prompt. Η αναφορά καλύπτει τομείς βελτίωσης, τον σκοπό του workflow και μια βήμα προς βήμα εξήγηση του τι κάνουν τα nodes. Όταν υπάρχει ήδη μια αναφορά, το **Reanalyze** μεταδίδει μια ξεχωριστή προεπισκόπηση ώστε να μπορείτε να αποδεχτείτε τη νέα έκδοση ή να διατηρήσετε το τρέχον κοινόχρηστο έγγραφο.

## Orchestrate

### Ενσωματωμένοι Κόμβοι LLM και Agent

Ο [Agent Node](../nodes/agent-node.md) του Heym εκτελεί ένα στενά ενσωματωμένο βρόχο κλήσης εργαλείων με inline Python tools, συνδέσεις MCP και ένα φορητό σύστημα skills, όλα σχεδιασμένα για production agents.

Ο απλός [LLM node](../nodes/llm-node.md) του Heym επίσης ξεπερνά το μεμονωμένο βήμα prompt-response. Για υποστηριζόμενα OpenAI και OpenAI-compatible endpoints, μπορεί να μεταβεί σε **Batch API mode**, ώστε ένας κόμβος να υποβάλλει έναν πίνακα prompts σε ένα φθηνότερο provider-native batch request. Ο καμβάς τότε εκθέτει έναν ειδικό κλάδο `batchStatus` που ενεργοποιείται καθώς το batch περνά από καταστάσεις όπως `pending`, `processing` και `completed`.

Αυτό σημαίνει ότι ο LLM node μπορεί να κάνει δύο πράγματα ταυτόχρονα:

- Να εκτελέσει το κύριο batch request και να επιστρέψει τα τελικά per-item outputs στον κανονικό κλάδο
- Να ενεργοποιήσει λογική ειδοποίησης ή καταγραφής σε κάθε σημαντική ενημέρωση κατάστασης του batch, χωρίς να μετατρέψει τη ροή σε προσαρμοσμένο polling loop

Η batch εκτέλεση είναι ένα first-class LLM workflow primitive, με ελέγχους δυνατοτήτων provider και μοντέλου στο UI του κόμβου.

Ο **Agent Node** είναι ο πυρήνας της agent orchestration στο Heym:

- **Tool calling** – Ο agent επαναλαμβάνει τις κλήσεις εργαλείων σε βρόχο μέχρι να παραγάγει μια τελική απάντηση
- **Python tools** – Ορίστε προσαρμοσμένα εργαλεία inline με πλήρη Python· ο agent τα καλεί κατά το runtime
- **MCP connections** – Συνδεθείτε σε οποιονδήποτε [Model Context Protocol](https://modelcontextprotocol.io/) server (stdio ή SSE) και ο agent αποκτά αυτόματα όλα τα εργαλεία του
- **Skills** – Αποθέστε ένα αρχείο `.zip` ή `.md` σε έναν agent για να επεκτείνετε το system context του και να προσθέσετε Python tooling
- **Sub-workflow calls** – Ο agent μπορεί να καλέσει άλλα workflows του Heym ως εργαλεία, συνθέτοντας σύνθετη συμπεριφορά χωρίς προσαρμοσμένο κώδικα

Δείτε τα [Agent Node](../nodes/agent-node.md) και [Agent Architecture](../reference/agent-architecture.md) για την πλήρη αναφορά.

### Multi-Agent Orchestration

Το Heym υποστηρίζει ένα **orchestrator pattern** με first-class οπτικά primitives:

- Ένας agent λειτουργεί ως **orchestrator** (`isOrchestrator: true`) και του δίνεται ένα εργαλείο `call_sub_agent`
- Αναθέτει εργασίες σε ονομασμένους **sub-agents** στον ίδιο καμβά
- Οι sub-agents μπορούν οι ίδιοι να καλέσουν άλλους agents ή sub-workflows (μέγιστο βάθος: 5)
- **Παράλληλη εκτέλεση**: Όταν ο orchestrator καλεί πολλούς sub-agents σε έναν κύκλο, εκτελούνται παράλληλα για ταχύτερα αποτελέσματα

Αυτό επιτρέπει αρχιτεκτονικές όπως έναν planning agent που δρομολογεί εργασία σε έναν researcher, έναν coder και έναν summarizer, όλα συνδεδεμένα οπτικά χωρίς προσαρμοσμένο κώδικα orchestration.

Δείτε το [Agent Architecture](../reference/agent-architecture.md) για λεπτομέρειες εκτέλεσης.

### Coding Agents ως Κόμβοι Workflow

Το Heym παρέχει δύο κόμβους που εκτελούν έναν πραγματικό coding agent ως βήμα workflow, όχι ως chat completion:

- **[Codex Node](../nodes/codex-node.md)** – Εκτελεί το OpenAI Codex CLI σε ένα απομονωμένο workspace του Heym πάνω σε ένα αποθετήριο GitHub. Υποστηρίζει **Sign in with ChatGPT** (PKCE OAuth στη συνδρομή σας Plus/Pro, χωρίς κόστος API ανά token) ή ένα access token, κλωνοποιεί το repo, επιτρέπει στο Codex να επεξεργαστεί κώδικα και επιστρέφει `summary`, `diff`, `changedFiles` και ένα πρόχειρο `pullRequestUrl`.
- **[OpenCode Go Node](../nodes/opencode-go-node.md)** – Η ίδια ροή εργασίας αποθετηρίου μέσω του provider-agnostic gateway OpenCode (Kimi, DeepSeek, Qwen και άλλα), εκτελούμενη σε ένα **hardened throwaway container**: όλες οι δυνατότητες αφαιρεμένες, read-only root, όρια pid/memory/CPU. Το GitHub token παραμένει εκτός του sandbox: το Heym εκτελεί κάθε λειτουργία git και GitHub στην πλευρά του host, ώστε ο παραγόμενος κώδικας να μην μπορεί να διαρρεύσει push credentials.

Αυτό σημαίνει ότι ένα workflow μπορεί να διαλογεί ένα bug από ένα webhook, να παραδώσει το repo σε έναν coding agent, να περιμένει το πρόχειρο PR και να δημοσιεύσει τον σύνδεσμο στο Slack, πλήρως αυτοματοποιημένα, με όρια πόρων διαμορφώσιμα ανά deployment.

### Ενσωματωμένο RAG Pipeline

Το Heym περιλαμβάνει έναν [RAG / Vector Store Node](../nodes/rag-node.md) και μια διαχειριζόμενη καρτέλα [Vectorstores](../tabs/vectorstores-tab.md). Μπορείτε να:

- Επιλέξετε το vector backend σας: **Qdrant** (εξωτερικός server) ή **Postgres (pgvector)**, που αποθηκεύει vectors στη βάση δεδομένων του ίδιου του Heym χωρίς να χρειάζεται επιπλέον υπηρεσία
- Εισάγετε έγγραφα σε ένα vector store απευθείας από έναν κόμβο workflow
- Εκτελέσετε σημασιολογική αναζήτηση και να τροφοδοτήσετε τα αποτελέσματα σε έναν κόμβο LLM ή Agent
- Αναφέρετε αποτελέσματα με εκφράσεις όπως `$ragNode.results.map("item.payload.content").join("\n\n")`

Στο Heym, το RAG είναι δύο κόμβοι με πλήρη έλεγχο στα embeddings και την ανάκτηση.

### Browser Automation με Playwright

Ο [Playwright node](../nodes/playwright-node.md) είναι first-party browser automation στον καμβά.

- **Steps mode** – Συνθέστε οπτικά ενέργειες navigate, click, type, fill, screenshot, extract και scroll
- **AI steps με auto-heal** – Περιγράψτε μια ενέργεια σε φυσική γλώσσα και ένα LLM παράγει τις ενέργειες Playwright· οι αποτυχημένοι selectors μπορούν να διορθωθούν αυτόματα και τα παραγόμενα βήματα μπορούν να αποθηκευτούν στην cache για να παραλείπονται μελλοντικές κλήσεις LLM
- **Run Code mode** – Μεταβείτε τον κόμβο σε πλήρη Playwright Python για σύνθετες ροές (απενεργοποιημένο από προεπιλογή· εκτελείται στο hardened sandbox του Heym όταν ενεργοποιηθεί)
- **Authenticated sessions** – Επαναφέρετε cookies/`storageState` πριν από την εκτέλεση, επαληθεύστε τη σύνδεση με έλεγχο selector και καταφύγετε σε scripted βήματα σύνδεσης
- **Network capture** – Προαιρετικά συλλέξτε JSON responses, headers, cookies και browser storage μαζί με τα αποτελέσματα

Το Heym αντιμετωπίζει το browser ως έναν κανονικό κόμβο με τις ίδιες εκφράσεις, credentials και χειρισμό σφαλμάτων όπως όλα τα άλλα.

### Expression DSL

Το [Expression DSL](../reference/expression-dsl.md) του Heym παρέχει μια καθαρή, ισχυρή σύνταξη για την αναφορά δεδομένων ανάντη κόμβων:

- `$input.text` – Δεδομένα του Input node
- `$nodeName.field` – Το πεδίο εξόδου οποιουδήποτε ανάντη κόμβου
- `$global.variableName` – Μόνιμες καθολικές μεταβλητές
- Βοηθητικές συναρτήσεις πινάκων: `.first()`, `.map("field")`, `.join("\n")`

Οι εκφράσεις λειτουργούν σε κάθε πεδίο συμβολοσειράς, συμπεριλαμβανομένων των prompts, των HTTP headers, των συνθηκών και των τιμών set, ώστε τα δεδομένα να μετακινούνται μεταξύ βημάτων με σαφήνεια. Το DSL εξισορροπεί τη δύναμη και την αναγνωσιμότητα χωρίς να απαιτεί πλήρη γνώση JavaScript.

## Εκτέλεση

### Triggers, Επαναλήψεις και Διαδρομές Σφαλμάτων

Ένα workflow μπορεί να ξεκινήσει από πολλά σημεία. Οι κόμβοι [Input](../nodes/input-node.md) λαμβάνουν HTTP [webhooks](../reference/webhooks.md), ο [Cron](../nodes/cron-node.md) εκτελείται βάσει χρονοδιαγράμματος, και οι event [triggers](../reference/triggers.md) ξεκινούν εκτελέσεις από Telegram, Discord, Slack, γραμματοκιβώτια IMAP, ροές WebSocket, ουρές RabbitMQ, μεταφορτώσεις αρχείων και συμβάντα της πλατφόρμας Heym.

Τα σφάλματα αντιμετωπίζονται εντός του γράφου. Οποιοσδήποτε κόμβος μπορεί να επαναλάβει σε περίπτωση αποτυχίας με καθορισμένο αριθμό προσπαθειών και αναμονή μεταξύ τους, κάθε προσπάθεια καταγράφεται στο [execution history](../reference/execution-history.md), και ένας κόμβος [Error Handler](../nodes/error-handler-node.md) εκτελείται αυτόματα όταν αποτύχει ένας κόμβος, ώστε η ανάκτηση να αποτελεί μέρος του ίδιου του workflow.

### Παράλληλη Εκτέλεση DAG

Ο εκτελεστής workflow του Heym χρησιμοποιεί έναν scheduler κατευθυνόμενου άκυκλου γράφου (DAG). Ανεξάρτητοι κόμβοι εκτελούνται παράλληλα αυτόματα, χωρίς να απαιτείται ρύθμιση.

- Κόμβοι στο ίδιο επίπεδο εξάρτησης αποστέλλονται ταυτόχρονα σε ένα thread pool (`max_workers=8`)
- Μόλις ολοκληρωθεί οποιοσδήποτε κόμβος, οι επόμενοι κόμβοι του προγραμματίζονται
- Ο [Merge Node](../nodes/merge-node.md) συνδυάζει τα αποτελέσματα παράλληλων κλάδων
- Πολλαπλές εκτελέσεις workflow εκτελούνται ταυτόχρονα· κάθε εκτέλεση είναι πλήρως απομονωμένη

Ο παραλληλισμός είναι η προεπιλεγμένη συμπεριφορά, καθοριζόμενος από τη δομή του γράφου.

Δείτε [Parallel Execution](../reference/parallel-execution.md).

### Κλιμάκωση σε Πολλαπλά Στιγμιότυπα

Στρέψτε ένα δεύτερο στιγμιότυπο Heym στην ίδια βάση δεδομένων PostgreSQL και αυτό εντάσσεται ως worker. Οι εκτελέσεις στο παρασκήνιο μοιράζονται μεταξύ των στιγμιοτύπων με βάρη που ορίζετε εσείς, ένας εκλεγμένος leader διατηρεί τα χρονοδιαγράμματα, την αξιολόγηση ειδοποιήσεων και την ανάκτηση μετά από κατάρρευση μέσω failover, και κάθε εκτέλεση καταγράφει το στιγμιότυπο που την εκτέλεσε. Δείτε [Load Distribution](../reference/cluster.md).

### Agentic Πίνακας Kanban

Η [καρτέλα Board](../tabs/board-tab.md) είναι ένας ενσωματωμένος πίνακας Kanban όπου οι ίδιες οι στήλες εκτελούν workflows. Μια κάρτα είναι μια επίμονη agentic εργασία που μεταφέρει context, ιστορικό συνομιλίας, κατάσταση εκτέλεσης, εξόδους και εκτελέσεις workflow.

- **Αλυσίδες workflow στηλών** – Η μετακίνηση μιας κάρτας σε μια στήλη ενεργοποιεί την αλυσίδα workflow αυτής της στήλης· ένα **Agentic Kanban Model** (το διαπιστευτήριό σας + μοντέλο) αντιστοιχίζει το περιεχόμενο της κάρτας σε εισόδους workflow και μετατρέπει τις εξόδους πίσω σε αναγνώσιμο κείμενο
- **Συνημμένα κάρτας** – Αποθέστε αρχεία σε μια κάρτα· τα έγγραφα εξάγονται σε κείμενο και οι εικόνες περνούν σε μοντέλα με δυνατότητα όρασης πριν από κάθε εκτέλεση
- **Ζωντανός καμβάς εκτέλεσης** – Ανοίξτε την ενεργή εκτέλεση μέσα σε μια κάρτα και παρακολουθήστε την να εκτελείται στον πραγματικό καμβά workflow, κόμβο προς κόμβο
- **Κοινή χρήση με την ομάδα** – Μοιραστείτε πίνακες με χρήστες ή ομάδες με δικαιώματα ανάγνωσης/εγγραφής· οι αλυσίδες σε κοινόχρηστους πίνακες εκτελούνται με τα διαπιστευτήρια του ιδιοκτήτη, ώστε οι συνεργάτες να μη χρειάζονται ποτέ τα δικά τους
- **Ορατότητα αποτυχιών** – Οι αποτυχημένες κάρτες εμφανίζουν ένδειξη ιστορικού σφαλμάτων, και οι επόμενες εκτελέσεις μπορούν να παύσουν για να περιμένουν σχόλια

Ο πίνακας είναι μια εγγενής επιφάνεια της πλατφόρμας: κάρτες, workflows, διαπιστευτήρια και ζωντανές εκτελέσεις βρίσκονται όλα σε ένα μέρος.

### Heym Drive: Ενσωματωμένη Αποθήκευση Αρχείων

Η [καρτέλα Drive](../tabs/drive-tab.md) είναι ένας χώρος αποθήκευσης αρχείων ενσωματωμένος στην πλατφόρμα. Τα αρχεία που παράγονται από skills και workflows (PDF, DOCX, CSV, εικόνες) καταλήγουν εκεί αυτόματα, και τα συνημμένα των καρτών του πίνακα αποθηκεύονται επίσης εκεί.

- **Σύνδεσμοι κοινής χρήσης** – Δημόσιοι ή προστατευμένοι με κωδικό πρόσβασης (Basic Auth) σύνδεσμοι λήψης, με προαιρετική λήξη και όρια μέγιστου αριθμού λήψεων
- **Κοινή χρήση με την ομάδα** – Μοιραστείτε αρχεία με δυνατότητα μόνο ανάγνωσης με τις ομάδες σας, και αφαιρέστε όλες τις κοινοποιήσεις ομάδας με μία ενέργεια
- **Μαζικές ενέργειες** – Πολλαπλή επιλογή με εύρη shift-click, ομαδοποίηση επιλογών σε μία λήψη ZIP, ή εφαρμογή μίας ρύθμισης κοινής χρήσης/κωδικού πρόσβασης/διαγραφής σε πολλά αρχεία ταυτόχρονα
- **Πρόσβαση agent** – Τα skills μπορούν να επιλέξουν ανάγνωση αρχείων από το Drive, ώστε ένας agent να μπορεί να εργαστεί πάνω σε έγγραφα που παρήγαγαν εσείς ή άλλα workflows

Τα παραγόμενα artifacts αποκτούν μόνιμη, κοινόχρηστη θέση εντός της πλατφόρμας.

## Παρατήρηση

### LLM Traces

Η [Καρτέλα Traces](../tabs/traces-tab.md) παρέχει πλήρη παρατηρησιμότητα για κάθε κλήση LLM:

- Payloads αιτήματος και απόκρισης
- Χρονισμός ανά κλήση: `llm_ms`, `tools_ms`, `mcp_list_ms`
- Ονόματα κλήσεων εργαλείων, ορίσματα και αποτελέσματα
- Skills που μεταβιβάζονται στο μοντέλο

Το σύστημα traces είναι σχεδιασμένο ειδικά για την αποσφαλμάτωση agentic συμπεριφοράς, με πλήρη payloads αιτήματος και απόκρισης και χρονισμό ανά κλήση.

### Παρακολούθηση Κόστους Token LLM

Κάθε κλήση LLM στο Heym κοστολογείται αυτόματα. Η [Καρτέλα Traces](../tabs/traces-tab.md) εμφανίζει ανά trace τον αριθμό token εισόδου και εξόδου μαζί με κόστος σε USD σε πραγματικό χρόνο, που προέρχεται από συγχρονισμένο πίνακα τιμολόγησης.

- **Κόστος ανά trace** – Token εισόδου, token εξόδου και συνολικό κόστος σε USD εμφανίζονται σε κάθε γραμμή trace
- **Ανάλυση κόστους** – Κάρτες KPI και γράφημα κόστους ανά μοντέλο ενημερώνονται με το επιλεγμένο χρονικό εύρος (1h / 24h / 7d / 30d / All)
- **Πίνακας Κόστους LLM** – Ένας system table στην [Καρτέλα DataTable](../tabs/datatable-tab.md) ενημερώνεται από το Helicone κάθε 24 ώρες· μπορείτε να παρακάμψετε τις τιμές ή να προσθέσετε προσαρμοσμένες γραμμές για μοντέλα που δεν αναφέρονται ακόμη
- **Προειδοποίηση ελλιπούς τιμής** – Τα traces για μοντέλα χωρίς καταχώριση τιμολόγησης εμφανίζουν ενσωματωμένη προειδοποίηση με απευθείας σύνδεσμο στον πίνακα κόστους

Κάθε εκτέλεση φέρει το δικό της κόστος σε USD, αναλυμένο ανά μοντέλο.

### Άνοιγμα Παραγωγικών Εκτελέσεων σε Ζωντανό Canvas

Ένα production workflow παραμένει επιθεωρήσιμο αφού ξεκινήσει εκτός του editor. Ανοίξτε οποιαδήποτε καταχώριση **Running** από οποιοδήποτε παράθυρο History, ή ανοίξτε την ενεργή εκτέλεση μέσα σε μια κάρτα Agentic Kanban, και το Heym συνδέει τον κανονικό editor workflow σε αυτήν την ακριβή εκτέλεση.

- Οι κόμβοι που έχουν ήδη ολοκληρωθεί εμφανίζονται με τα αποτελέσματά τους αμέσως
- Ο τρέχων κόμβος και οι εκκρεμείς επόμενοι κόμβοι συνεχίζουν να πάλλονται καθώς η εκτέλεση προχωρά
- Το Debug panel λαμβάνει τα ίδια σταδιακά αποτελέσματα κόμβων όπως μια εκτέλεση που ξεκίνησε από το canvas
- Η τελική έξοδος και οι επισημάνσεις εκτέλεσης φτάνουν χωρίς polling ή έναρξη διπλότυπης εκτέλεσης
- Το κλείσιμο του editor αποσυνδέει μόνο τον observer· δεν ακυρώνει ποτέ το production workflow

Ο observer χρησιμοποιεί SSE που υποστηρίζεται από cross-worker execution snapshot, ώστε να λειτουργεί για webhook, schedule, chat, MCP, integration και Board triggers ακόμη και όταν ένας άλλος backend worker κατέχει την εκτέλεση.

### OpenTelemetry, Analytics και Alerts

Το Heym εκπέμπει [OpenTelemetry](../reference/opentelemetry.md) spans για κάθε εκτέλεση workflow, εκτέλεση κόμβου και κλήση εργαλείου Agent, εξαγόμενα μέσω OTLP/HTTP σε Jaeger, Grafana Tempo, Honeycomb, Datadog ή οποιοδήποτε άλλο συμβατό backend.

Η [Καρτέλα Analytics](../tabs/analytics-tab.md) παρακολουθεί αριθμούς εκτελέσεων, ποσοστό επιτυχίας, διάρκεια και τάσεις ανά workflow. Τα [Alerts](../tabs/alerts-tab.md) παρακολουθούν αριθμούς σφαλμάτων, διάρκεια εκτέλεσης, δαπάνη token ή USD και όγκο εκτελέσεων σε ένα χρονικό παράθυρο, και στη συνέχεια εκτελούν ένα notify workflow που επιλέγετε, ώστε μια ειδοποίηση να φτάνει στο Slack, το email, το Telegram ή οπουδήποτε αλλού μπορεί ένας κόμβος.

## Έλεγχος

### Human-in-the-Loop (HITL)

Το Heym διαθέτει ενσωματωμένο σύστημα [Human-in-the-Loop](../reference/human-in-the-loop.md) που επιτρέπει στους agents να παύουν την εκτέλεση, να ζητούν ανθρώπινη αξιολόγηση και να συνεχίζουν από το ακριβές σημείο όπου σταμάτησαν.

- **Σημεία ελέγχου agent** – Ενεργοποιήστε το `hitlEnabled` σε οποιονδήποτε κόμβο Agent για να του δώσετε ένα εργαλείο `request_human_review`. Ο agent αποφασίζει πότε μια απόφαση χρειάζεται ανθρώπινη εποπτεία και καλεί το εργαλείο με σύνοψη και προσχέδιο.
- **Δημόσια URLs αξιολόγησης** – Κάθε αίτημα αξιολόγησης δημιουργεί έναν ασφαλή σύνδεσμο μίας χρήσης στο `/review/{token}` (TTL 168 ωρών). Οι αξιολογητές μπορούν να **αποδεχτούν**, να **επεξεργαστούν & συνεχίσουν** ή να **αρνηθούν** χωρίς σύνδεση.
- **Στιγμιότυπα εκτέλεσης** – Το Workflow παγώνει την πλήρη κατάστασή του (ιστορικό συνομιλίας, μεταβλητές, αποτελέσματα εργαλείων) ώστε να συνεχίσει ακριβώς από εκεί που σταμάτησε αφού απαντήσει ο αξιολογητής.
- **Διακλάδωση ειδοποίησης** – Μια προαιρετική έξοδος `review` σας επιτρέπει να συνδέσετε μια ροή ειδοποιήσεων (Slack, email, Webhook) που ενεργοποιείται όταν ζητείται αξιολόγηση.
- **Πολιτικές έγκρισης εργαλείων MCP** – Οι γραπτές οδηγίες HITL ερμηνεύονται σε πεδία έγκρισης (`always` / `once` / `never`) ώστε ο agent να εγκρίνει αυτόματα εργαλεία χαμηλού κινδύνου και να κλιμακώνει τα υψηλού κινδύνου.
- **Πολλαπλά σημεία ελέγχου** – Μία μόνο εκτέλεση agent μπορεί να παύσει για αξιολόγηση πολλές φορές· κάθε σημείο ελέγχου είναι ανεξάρτητο.

Τα δημόσια URLs αξιολόγησης, η επεξεργασία-και-συνέχεια, η διακλάδωση ειδοποιήσεων και η συνέχεια βάσει στιγμιοτύπων λειτουργούν όλα από το ίδιο σημείο ελέγχου agent.

Δείτε το [Human-in-the-Loop](../reference/human-in-the-loop.md) για την πλήρη αναφορά.

### Guardrails LLM

Το Heym διαθέτει ενσωματωμένα [Guardrails](../reference/guardrails.md) τόσο σε κόμβους [LLM](../nodes/llm-node.md) όσο και σε κόμβους [Agent](../nodes/agent-node.md), ώστε να μπορείτε να αποκλείετε μη ασφαλές περιεχόμενο προτού μια απάντηση μοντέλου φτάσει σε επόμενα βήματα.

- **Διακόπτης ασφάλειας σε επίπεδο κόμβου** – Ενεργοποιήστε τα guardrails απευθείας στον κόμβο που παράγει ή επεξεργάζεται περιεχόμενο προς τον χρήστη
- **Ευρεία κάλυψη πολιτικών** – Αποκλείστε βία, ρητορική μίσους, σεξουαλικό περιεχόμενο, NSFW/υβριστικό λόγο, παρενόχληση, παράνομη δραστηριότητα, αιτήματα προσωπικών δεδομένων και απόπειρες prompt injection
- **Πολυγλωσσική ανίχνευση** – Εφαρμόστε τους ίδιους κανόνες ασφάλειας σε τουρκικά, αγγλικά, αραβικά, ισπανικά και άλλες γλώσσες
- **Εγγενής εναλλακτική διαδρομή Workflow** – Όταν ένα μήνυμα αποκλείεται, ο κόμβος εκπέμπει ένα τυποποιημένο σφάλμα Workflow που μπορείτε να δρομολογήσετε μέσω ενός [Error Handler](../nodes/error-handler-node.md)

Η πολιτική ασφάλειας βρίσκεται απευθείας μέσα στη διαμόρφωση των LLM και Agent και συνδέεται άμεσα με τη διακλάδωση Workflow και τη διαχείριση σφαλμάτων.

### Πρόσβαση, Διαπιστευτήρια και Έλεγχος

Οι agents ενεργούν με πραγματικά διαπιστευτήρια, επομένως η πρόσβαση αποτελεί μέρος της διακυβέρνησης. Τα [Credentials](../reference/credentials.md) είναι κρυπτογραφημένα σε κατάσταση ηρεμίας, αποκρύπτονται μετά τη δημιουργία και είναι κοινοποιήσιμα σε χρήστες ή [teams](../reference/teams.md), ενώ οι ομάδες μοιράζονται επίσης Workflows, μεταβλητές, vector stores και αρχεία Drive. Το [Single sign-on](../reference/sso.md) συνδέεται με οποιονδήποτε πάροχο OpenID Connect, συμπεριλαμβανομένων των Okta, Entra ID, Keycloak, Auth0 και Google. Το [ίχνος ελέγχου](../reference/audit.md) καταγράφει κάθε ενέργεια που σχετίζεται με την ασφάλεια μαζί με τον δράστη, τον στόχο και το αποτέλεσμα, και μεταδίδεται μαζί με τα logs του container σας στον συλλέκτη logs ή το SIEM που ήδη χρησιμοποιείτε.

### Self-Hosted, τα Δεδομένα σας ανήκουν σε Εσάς

Το Heym εκτελείται στην υποδομή σας. Τα Workflows, τα credentials, το ιστορικό εκτελέσεων και τα traces βρίσκονται στη δική σας βάση δεδομένων, και οι κλήσεις μοντέλων πηγαίνουν από τους servers σας στον πάροχο που επιλέγετε, ή σε ένα μοντέλο που φιλοξενείτε εσείς μέσω Ollama ή vLLM. Για agents που επεξεργάζονται ευαίσθητα έγγραφα, δεδομένα πελατών ή ιδιόκτητες βάσεις γνώσης, αυτό αποτελεί συχνά αδιαπραγμάτευτη απαίτηση.

Το Heym διατίθεται υπό την **Άδεια MIT με τον όρο Commons Clause**. Ο πηγαίος κώδικας είναι source-available: μπορείτε να τον χρησιμοποιείτε, να τον τροποποιείτε και να τον φιλοξενείτε μόνοι σας ελεύθερα. Ο όρος Commons Clause περιορίζει την πώληση του λογισμικού, συμπεριλαμβανομένης της παροχής επί πληρωμή φιλοξενίας ή υπηρεσιών συμβουλευτικής/υποστήριξης των οποίων η αξία προέρχεται ουσιαστικά από το Heym. Για εμπορική άδεια, enterprise αναπτύξεις ή επαγγελματική υποστήριξη, επικοινωνήστε στο [enterprise@heym.run](mailto:enterprise@heym.run).

## Expose

### APIs και Streaming

Τα Workflows είναι καλέσιμα μέσω HTTP στο `/api/workflows/{workflow_id}/execute`, το οποίο επιστρέφει JSON, και στο `/api/workflows/{workflow_id}/execute/stream`, το οποίο κάνει stream τα node events ως Server-Sent Events καθώς η εκτέλεση προχωρά. Και τα δύο μοιράζονται authentication, rate limiting και response caching σε επίπεδο workflow. Δείτε [Webhooks](../reference/webhooks.md) και [SSE Streaming](../reference/sse-streaming.md).

### Ενσωμάτωση MCP (Model Context Protocol)

Το Heym έχει εγγενή υποστήριξη [MCP](../tabs/mcp-tab.md) και στις δύο πλευρές:

- **Ως client**: Τα Agent nodes συνδέονται σε εξωτερικούς MCP servers (Filesystem, Browserbase, custom tools) μέσω stdio ή SSE και καταναλώνουν αυτόματα τα tools τους
- **Ως server**: Τα Workflows με ενεργοποιημένο το MCP γίνονται tools στον προεπιλεγμένο server στο `/api/mcp/sse`, ή σε named servers με δικό τους URL και API key, ώστε το Claude Desktop, το Cursor και άλλοι MCP clients να μπορούν να καλούν απευθείας τα Workflows σας στο Heym

Τα Agents μπορούν να καταναλώνουν πολλούς MCP servers ταυτόχρονα, και οποιοδήποτε workflow μπορεί να γίνει tool για έναν εξωτερικό MCP client.

### Portal: Δημοσίευση Workflows ως Chat UIs

Η λειτουργία [Portal](../reference/portal.md) μετατρέπει οποιοδήποτε workflow σε δημόσια διαθέσιμη διεπαφή chat στο `/chat/{slug}`:

- Προαιρετικό authentication με per-user credentials
- Streaming εκτέλεση (πρόοδος node σε πραγματικό χρόνο)
- Υποστήριξη μεταφόρτωσης αρχείων
- Ιστορικό συνομιλίας πολλαπλών γύρων

Οι ομάδες παραδίδουν εσωτερικά εργαλεία, chatbots για πελάτες και φόρμες με υποστήριξη AI από ένα workflow και ένα URL, χωρίς να χρειάζεται να γράψουν κώδικα frontend.

### Dashboards με Υποστήριξη Workflow

Η [καρτέλα Dashboard](../tabs/dashboard-tab.md) είναι μια επιφάνεια αναφορών που δημιουργεί ο χρήστης, όπου κάθε widget γραφήματος υποστηρίζεται από το δικό του κρυφό workflow Heym. Ένα widget μπορεί να καλεί APIs, να εκτελεί queries στο BigQuery, να αναζητά σε RAG/vector stores, να εκτελεί βήματα LLM, να μετασχηματίζει γραμμές και να ολοκληρώνεται με ένα [Chart Output node](../nodes/chart-output-node.md). Μπορείτε να δημιουργείτε widgets χειροκίνητα, να τα παράγετε με AI, να τα βελτιώνετε αργότερα, να κάνετε cache τα αποτελέσματα και να αναδιατάσσετε το πλέγμα οπτικά.

αλλά απαιτούν χειροκίνητη εγκατάσταση και κλήσεις API μετά την εκτέλεση (ανοιχτό αίτημα λειτουργίας από τον Μάιο 2026). Το Zapier δεν εκθέτει στους χρήστες αριθμό token ανά εκτέλεση ή κόστος σε USD· τα βήματα AI καταναλώνουν μόνο tasks. Ο πίνακας credits του Make.com αντικατοπτρίζει εν μέρει την κατανάλωση token για AI που φιλοξενείται από το Make (από τον Αύγουστο 2025) αλλά οι συνδέσεις με κλειδιά API τρίτων χρεώνονται ως 1 operation = 1 credit χωρίς μέτρηση token· δεν είναι διαθέσιμη ανάλυση κόστους σε USD ανά εκτέλεση ανά μοντέλο. ¹⁶ Το Heym εκπέμπει εγγενή spans OpenTelemetry (ένα ανά εκτέλεση workflow συν ένα ανά node) μέσω OTLP/HTTP προς οποιοδήποτε συμβατό backend, με διάδοση trace-context W3C και χωρίς κώδικα instrumentation, ρυθμιζόμενο μέσω μεταβλητών περιβάλλοντος `HEYM_OTEL_*` και απενεργοποιημένο από προεπιλογή. Το n8n διαθέτει τεκμηριωμένη ενσωμάτωση ιχνηλάτησης OpenTelemetry για εκτελέσεις workflow και node. Τα Zapier και Make.com δεν τεκμηριώνουν εξαγωγή OpenTelemetry των εκτελέσεων workflow/scenario τους από τον Ιούνιο 2026. ¹⁷ Το n8n τεκμηριώνει ένα dashboard Insights για μετρικές εκτέλεσης παραγωγής, το Zapier τεκμηριώνει Zap History συν Task Usage, και το Make.com τεκμηριώνει Scenario History· πρόκειται για επιφάνειες παρακολούθησης/ιστορικού, όχι προσαρμοσμένα widgets dashboard που υποστηρίζονται από αυθαίρετη λογική workflow όπως η καρτέλα Dashboard του Heym. ¹⁸ Το Heym Workflow Analyzer εκτελεί το workflow όταν είναι εφικτό, διαβάζει το αποτέλεσμα εκτέλεσης και παράγει μια κοινόχρηστη επεξεργάσιμη αναφορά Markdown που καλύπτει τομείς βελτίωσης, σκοπό και βήμα-προς-βήμα συμπεριφορά. Το n8n τεκμηριώνει το AI Workflow Builder για δημιουργία/βελτίωση/αποσφαλμάτωση workflows, το Zapier τεκμηριώνει AI troubleshooting για εκτελέσεις Zap με σφάλματα, και το Make.com τεκμηριώνει ιστορικό scenario συν βήματα συλλογισμού agent AI, αλλά η δημόσια τεκμηρίωσή τους δεν περιγράφει το ίδιο έγγραφο κοινόχρηστης ανάλυσης workflow με επίγνωση εκτέλεσης. ¹⁹ Το [n8n All executions](https://docs.n8n.io/workflows/executions/all-executions/) παραθέτει εκτελέσεις σε εξέλιξη και μπορεί να φορτώσει δεδομένα από προηγούμενη εκτέλεση στον editor, ενώ το [Zapier run statuses](https://help.zapier.com/hc/en-us/articles/20505304170637-Review-run-statuses-in-Zap-workflows) εκθέτει κατάσταση running στον editor του. Το [Make Scenario History](https://help.make.com/scenario-history) τεκμηριώνει λεπτομέρειες εκτέλεσης και logs. Η δημόσια τεκμηρίωσή τους, που ελέγχθηκε στις 18 Ιουλίου 2026, δεν περιγράφει την ακριβή ροή του Heym: άνοιγμα μιας αυθαίρετης εκτέλεσης παραγωγής σε εξέλιξη από το History ή από κάρτα Kanban, επαναφορά του τρέχοντος στιγμιοτύπου node, και συνέχιση λήψης animation node και Debug logs στον ίδιο καμβά. ²⁰ Τα nodes [Codex](../nodes/codex-node.md) και [OpenCode Go](../nodes/opencode-go-node.md) του Heym εκτελούν ένα πραγματικό CLI coding agent σε απομονωμένο χώρο εργασίας Heym πάνω σε αποθετήριο GitHub — clone, επεξεργασία, παραγωγή diff, push branch, άνοιγμα pull request — ως βήμα workflow πρώτης τάξης. Από τις 20 Ιουλίου 2026, κανένας ανταγωνιστής δεν τεκμηριώνει ισοδύναμη λειτουργία: το [OpenAI node](https://docs.n8n.io/integrations/builtin/app-nodes/n8n-nodes-langchain.openai) του n8n καλύπτει κλήσεις API chat/assistant, όχι coding agent σε επίπεδο αποθετηρίου, και η εγγενής υποστήριξη Codex παραμένει αίτημα της κοινότητας· το blog του ίδιου του Zapier τεκμηριώνει την αντίστροφη κατεύθυνση — [Codex να οδηγεί εργαλεία Zapier μέσω Zapier MCP](https://zapier.com/blog/automate-codex-zapier-mcp/) — όχι το Codex ως βήμα Zap· τα modules OpenAI του Make.com εκθέτουν ενέργειες completions/assistants/batch, όχι coding agent που κάνει clone αποθετηρίων και ανοίγει PRs. ²¹ Η [καρτέλα Board](../tabs/board-tab.md) του Heym είναι ενσωματωμένος agentic πίνακας Kanban του οποίου οι στήλες εκτελούν workflows και του οποίου οι κάρτες φέρουν context, ιστορικό συνομιλίας, κατάσταση εκτέλεσης και εκτελέσεις. Τα n8n ([ενσωμάτωση Kanban Tool](https://n8n.io/integrations/kanban-tool/)), Zapier ([ενσωματώσεις Kanban Tool](https://zapier.com/apps/kanbantool/integrations)) και Make.com ([ενσωμάτωση Kanban Tool](https://www.make.com/en/integrations/kanban-tool)) συνδέονται μόνο με εφαρμογές kanban τρίτων όπως Kanban Tool, Wekan ή NocoDB· κανένα δεν τεκμηριώνει ενσωματωμένο πίνακα που εκτελεί τα δικά του workflows, από τις 20 Ιουλίου 2026. ²² Το n8n αποθηκεύει δυαδικά δεδομένα εκτέλεσης εσωτερικά (προαιρετικά σε [εξωτερικό χώρο αποθήκευσης συμβατό με S3](https://docs.n8n.io/hosting/scaling/external-storage/)) αλλά δεν τεκμηριώνει χώρο αρχείων προς τον χρήστη με συνδέσμους κοινής χρήσης ή κοινή χρήση ομάδας, οπότε χαρακτηρίζεται περιορισμένο. Το [Files by Zapier](https://zapier.com/apps/files-by-zapier/integrations) του Zapier επεξεργάζεται αρχεία μόνο για τη διάρκεια μιας εκτέλεσης Zap και το [Storage by Zapier](https://help.zapier.com/hc/en-us/articles/8496293271053-Save-and-retrieve-data-from-Zaps) διατηρεί μικρές τιμές κειμένου, οπότε το Zapier χαρακτηρίζεται περιορισμένο. Τα [data stores](https://help.make.com/l6du-data-stores) του Make.com διατηρούν δομημένες εγγραφές και η [διαχείριση αρχείων](https://help.make.com/working-with-files) του μεταφέρει αρχεία μεταξύ εφαρμογών χωρίς μόνιμο ενσωματωμένο χώρο αποθήκευσης, οπότε το Make χαρακτηρίζεται μη διαθέσιμο. ²³ Το [node Playwright](../nodes/playwright-node.md) του Heym είναι αυτοματισμός περιηγητή πρώτου κατασκευαστή με λειτουργία οπτικών βημάτων, βήματα που παράγονται από AI και λειτουργία πλήρους κώδικα. Το n8n προσφέρει μόνο πακέτα κοινότητας όπως το [n8n-playwright](https://github.com/toema/n8n-playwright) με [αίτημα λειτουργίας για εγγενή nodes αυτοματισμού περιηγητή](https://community.n8n.io/t/front-end-web-mobile-app-test-automation-nodes/129796) που παραμένει ανοιχτό, οπότε χαρακτηρίζεται περιορισμένο. Οι Zapier Agents μπορούν να [περιηγούνται και να διαβάζουν σελίδες μέσω web browsing και επέκτασης Chrome](https://help.zapier.com/hc/en-us/articles/29025734470925-Use-Zapier-Agents-Chrome-extension) αλλά το Zapier δεν τεκμηριώνει βήμα αυτοματισμού περιηγητή με σενάριο, οπότε χαρακτηρίζεται περιορισμένο. Το Make.com τεκμηριώνει modules HTTP και εφαρμογές scraping τρίτων αντί για οποιοδήποτε εγγενές module αυτοματισμού περιηγητή, από τις 20 Ιουλίου 2026.
