# Κόμβος Agent

Ο κόμβος **AI Agent** είναι ένας κόμβος LLM με δυνατότητα κλήσης εργαλείων. Μπορεί να εκτελεί εργαλεία Python, να καλεί συνδεδεμένους κόμβους του καμβά ως εργαλεία, να συνδέεται με διακομιστές MCP, να χρησιμοποιεί δεξιότητες, προαιρετικά να λειτουργεί ως ενορχηστρωτής που αναθέτει σε άλλους κόμβους agent, να καλεί άλλα workflows ως εργαλεία και να διακόπτεται για [ανθρώπινη αξιολόγηση](../reference/human-in-the-loop.md).

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 1, συν προαιρετικό `review` όταν το HITL είναι ενεργοποιημένο |
| Έξοδος | `$nodeLabel.text`, `$nodeLabel.fieldName` (όταν η έξοδος JSON είναι ενεργοποιημένη) ή ένα εκκρεμές payload HITL κατά την αναμονή αξιολόγησης |

## Βασικές Παράμετροι

### Διαπιστευτήριο & Μοντέλο

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `credentialId` | UUID | Διαπιστευτήριο LLM (API key) από τις Ρυθμίσεις |
| `model` | string | Όνομα μοντέλου (π.χ. `gpt-4o`, `gemini-2.5-flash-lite`) |
| `fallbackCredentialId` | UUID (προαιρετικό) | Εφεδρικό διαπιστευτήριο όταν το κύριο αποτύχει |
| `fallbackModel` | string (προαιρετικό) | Εφεδρικό μοντέλο όταν το κύριο αποτύχει |

Προσθέστε διαπιστευτήρια στην καρτέλα [Διαπιστευτήρια](../tabs/credentials-tab.md). Η λίστα μοντέλων φορτώνεται από το επιλεγμένο διαπιστευτήριο. Εάν το κύριο διαπιστευτήριο ή μοντέλο επιστρέψει σφάλμα, ο κόμβος επαναλαμβάνει αυτόματα με το εφεδρικό διαπιστευτήριο και μοντέλο πριν αποτύχει.

### Prompts

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `systemInstruction` | string | System prompt για το AI. Υποστηρίζει [εκφράσεις](../reference/expression-dsl.md). |
| `userMessage` | string | Μήνυμα/prompt χρήστη. Προεπιλογή: `$input.text` |
| `jsonOutputEnabled` | boolean | Δομημένη έξοδος JSON |
| `jsonOutputSchema` | string | JSON Schema για δομημένη έξοδο |
| `extraBodyEnabled` | boolean | Αποστολή παραμέτρων αιτήματος ειδικών για τον πάροχο (προεπιλογή: `false`) |
| `extraBody` | string | Αντικείμενο JSON που συγχωνεύεται σε κάθε αίτημα API που κάνει ο agent |

Χρησιμοποιήστε `$input.text`, `$nodeName.field` και άλλη σύνταξη [Expression DSL](../reference/expression-dsl.md).

### Μοντέλα συλλογισμού (o1, o3)

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `temperature` | number | 0.0–2.0 (προεπιλογή: 0.7), για τυπικά μοντέλα |
| `reasoningEffort` | `"low"` \| `"medium"` \| `"high"` | Βάθος συλλογισμού για μοντέλα συλλογισμού |

Όταν χρησιμοποιείτε μοντέλο συλλογισμού (π.χ. o1, o3), το UI εμφανίζει **Reasoning Effort** αντί για Temperature. Για τυπικά μοντέλα, το **Temperature** ελέγχει τη δημιουργικότητα.

**Παράδειγμα εξόδου JSON:** Όταν χρειάζεστε δομημένα δεδομένα από τον agent (π.χ. ταξινόμηση, εξαγωγή), ενεργοποιήστε την έξοδο JSON και παρέχετε ένα schema. Ο agent επιστρέφει JSON που συμμορφώνεται με το schema· αποκτήστε πρόσβαση στα πεδία με το όνομά τους στην έξοδο του κόμβου:

```json
{
  "jsonOutputEnabled": true,
  "jsonOutputSchema": "{ \"type\": \"object\", \"properties\": { \"status\": { \"type\": \"string\", \"enum\": [\"APPROPRIATE\", \"INAPPROPRIATE\"] }, \"reason\": { \"type\": \"string\" } }, \"required\": [\"status\", \"reason\"] }"
}
```

Οι επόμενοι κόμβοι μπορούν να χρησιμοποιήσουν `$agentLabel.status`, `$agentLabel.reason` κ.λπ. Ίδια συμπεριφορά με την έξοδο JSON του [κόμβου LLM](../nodes/llm-node.md).

## Ανθρώπινη Αξιολόγηση (HITL)

Χρησιμοποιήστε το HITL όταν ένας agent μπορεί να χρειάζεται έγκριση σε συγκεκριμένες στιγμές πριν από σημαντικές ενέργειες.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `hitlEnabled` | boolean | Προσθέτει σημεία ελέγχου ανθρώπινης αξιολόγησης στον agent |
| `hitlSummary` | string | Κατευθυντήριες γραμμές έγκρισης που υποδεικνύουν στον agent πότε απαιτείται ανθρώπινη αξιολόγηση |

Όταν το HITL είναι ενεργοποιημένο, ο agent λαμβάνει ένα εργαλείο `request_human_review`. Χρησιμοποιήστε το system prompt και
αυτό το πεδίο κατευθυντήριων γραμμών για να εξηγήσετε ποιες κλήσεις εργαλείων, υπο-agents, υπο-workflows, ενέργειες MCP, δεξιότητες
ή παρενέργειες απαιτούν έγκριση. Ο agent μπορεί να καλέσει αυτό το εργαλείο μόνο όταν χρειάζεται, συμπεριλαμβανομένων πολλαπλών
φορών σε μία εκτέλεση.

Η σύνοψη που βλέπει ο αξιολογητής στη δημόσια σελίδα δημιουργείται από το αίτημα αξιολόγησης του agent κατά
την εκτέλεση. Εάν ο agent δεν παρέχει σύνοψη ρητά, το Heym παράγει μία από το σώμα αξιολόγησης
Markdown.

Για εργαλεία MCP, το Heym ζητά από το μοντέλο να ερμηνεύσει τις γραπτές οδηγίες HITL ως ένα από τρία
εύρη: `always`, `once` ή `never`. Αυτό σημαίνει ότι ελεύθερη διατύπωση όπως "για κάθε κλήση", "μόνο
μία φορά" ή "να μην ρωτάς ποτέ" κανονικοποιείται πριν εφαρμοστεί ο έλεγχος κατά την εκτέλεση.

Κάθε σημείο ελέγχου HITL δημιουργεί έναν σύνδεσμο δημόσιας αξιολόγησης μίας χρήσης στο `/review/{token}`. Ένας αξιολογητής μπορεί να:

- **Αποδεχτεί** το αρχικό κείμενο αξιολόγησης Markdown
- **Επεξεργαστεί & Συνεχίσει** με τροποποιημένο Markdown
- **Απορρίψει** και να συνεχίσει με `text: ""`

Όταν το HITL είναι ενεργοποιημένο, ο κόμβος εκθέτει επίσης μια λαβή εξόδου `review` στον καμβά. Συνδέστε αυτόν τον κλάδο σε κόμβους Slack, email ή άλλων ειδοποιήσεων εάν θέλετε να μεταδίδετε το URL αξιολόγησης και τη σύνοψη μόλις διακοπεί η εκτέλεση.

Η εκτέλεση μεταβαίνει σε κατάσταση `pending` μέχρι να απαντήσει ένας αξιολογητής. Το κείμενο αξιολόγησης είναι ένα μόνο σώμα Markdown και το εκκρεμές payload περιλαμβάνει επίσης κείμενο κοινόχρηστου συνδέσμου για εξωτερική παράδοση. Οι κόμβοι στον κλάδο `review` εκτελούνται αμέσως όταν δημιουργηθεί η διακοπή· η κανονική διαδρομή εξόδου συνεχίζει μόνο μετά την έγκριση. Μετά την έγκριση, το Heym συνεχίζει από το αποθηκευμένο στιγμιότυπο εκτέλεσης και ο agent συνεχίζει με το εγκεκριμένο context. Εάν ένα επόμενο βήμα χρειάζεται επίσης έγκριση, ο agent μπορεί να δημιουργήσει άλλο σημείο ελέγχου HITL. Ανατρέξτε στο [Human-in-the-Loop](../reference/human-in-the-loop.md) για τη μορφή του payload, τη συμπεριφορά του URL αξιολόγησης και τη σημασιολογία συνέχισης.

Το HITL είναι διαθέσιμο μόνο για έξοδο agent σε λειτουργία κειμένου. Στην v1 δεν μπορεί να συνδυαστεί με `jsonOutputEnabled`.
## Λειτουργία Orchestrator

Όταν είναι ενεργοποιημένη, ο agent μπορεί να αναθέτει εργασίες σε άλλους agent nodes του workflow. Εάν η **λειτουργία Orchestrator είναι απενεργοποιημένη**, ο agent **δεν μπορεί να δημιουργήσει συνδέσεις agent→agent** στον καμβά.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `isOrchestrator` | boolean | Όταν είναι `true`, ο agent αποκτά ένα εργαλείο `call_sub_agent` |
| `subAgentLabels` | string[] | Ετικέτες των agent nodes που μπορεί να καλέσει αυτός ο orchestrator |

Οι **Sub-agents** πρέπει να χρησιμοποιούν `$input.text` στο User Message τους, ώστε να λαμβάνουν το prompt του orchestrator.

Όταν ο orchestrator καλεί πολλαπλούς sub-agents σε έναν μόνο κύκλο, αυτοί εκτελούνται παράλληλα. Ανατρέξτε στην ενότητα [Agent Architecture](../reference/agent-architecture.md) για λεπτομέρειες.

## Sub-Workflows

Όταν έχει ρυθμιστεί, ο agent λαμβάνει ένα εργαλείο `call_sub_workflow` για την εκτέλεση άλλων workflows.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `subWorkflowIds` | string[] | IDs των workflows που μπορεί να καλέσει αυτός ο agent ως εργαλεία |

Επιλέξτε workflows στην ενότητα Sub-Workflows της διαμόρφωσης του agent. Ο agent θα τα καλέσει με `workflow_id` και `inputs` (αντικείμενο που αντιστοιχεί στα πεδία εισόδου του target workflow). Μέγιστο βάθος: 5 ένθετες κλήσεις sub-workflow.

## Εργαλεία Canvas Node

Μπορείτε να συνδέσετε έναν υποστηριζόμενο workflow node στη λαβή **tools** ενός agent, ώστε ο agent να μπορεί να καλέσει αυτόν τον node κατά την εκτέλεση. Αυτό μετατρέπει υπάρχουσες ενέργειες και μετασχηματισμούς του καμβά σε εργαλεία που μπορούν να κληθούν, χωρίς να χρειάζεται να γράψετε Python.

Χρησιμοποιήστε τα εργαλεία canvas node όταν θέλετε ο agent να αποφασίζει πότε θα εκτελεστεί ένας διαμορφωμένος node, διατηρώντας παράλληλα τα διαπιστευτήρια, τα στατικά πεδία και τις ρυθμίσεις που αφορούν το workflow στο UI του node.

### Πεδία που παρέχει ο agent

Τα πεδία σε έναν συνδεδεμένο tool node μπορούν να επισημανθούν με το εικονίδιο bot. Τα επισημασμένα πεδία γίνονται υποχρεωτικές παράμετροι του εργαλείου, τις οποίες ο agent πρέπει να παρέχει όταν καλεί τον node. Τα μη επισημασμένα πεδία παραμένουν σταθερά και διαβάζονται από τη διαμόρφωση του node.

Για παράδειγμα:

- Συνδέστε έναν Slack node σε έναν agent ως εργαλείο
- Διατηρήστε το διαπιστευτήριο σταθερό στον Slack node
- Επισημάνετε το `message` ως πεδίο που παρέχει ο agent
- Ο agent λαμβάνει ένα εργαλείο Slack όπου παρέχει μόνο το μήνυμα κατά την εκτέλεση

Εάν ο node δεν είναι συνδεδεμένος σε έναν agent ως εργαλείο, το εικονίδιο bot κρύβεται και ο node συμπεριφέρεται όπως ένα κανονικό βήμα workflow.

### Συμπεριφορά κατά την εκτέλεση

Όταν ο agent καλεί ένα εργαλείο canvas node, το Heym συγχωνεύει προσωρινά τα ορίσματα που παρέχει ο agent στα δεδομένα αυτού του node, εκτελεί τον node, επιστρέφει την έξοδο του node στον agent και στη συνέχεια επαναφέρει την αρχική διαμόρφωση του node. Οι tool nodes δεν εκτελούνται ως κανονικά βήματα workflow μέσω του κανονικού χρονοπρογραμματισμού· εκτελούνται μόνο όταν τους καλεί ο agent.

Τα εργαλεία canvas node είναι χρήσιμα με integration nodes όπως Slack, Telegram, HTTP, Send Email και nodes διαμόρφωσης δεδομένων όπως το [Set](./set-node.md). Trigger nodes, nodes ελέγχου ροής και terminal output mappers ([JSON output mapper](./json-output-mapper-node.md), [HTML output mapper](./html-output-mapper-node.md)) δεν μπορούν να χρησιμοποιηθούν ως εργαλεία agent.

## Εργαλεία Python

Ορίστε προσαρμοσμένα εργαλεία που μπορεί να καλέσει ο agent. Κάθε εργαλείο έχει:

| Πεδίο | Τύπος | Περιγραφή |
|-------|------|-------------|
| `name` | string | Όνομα εργαλείου (π.χ. `count_characters`) |
| `description` | string | Περιγραφή για το LLM |
| `parameters` | JSON Schema | Σχήμα OpenAI function-calling (μορφή αντικειμένου) |
| `code` | string | Κώδικας συνάρτησης Python |

Οι **Παράμετροι** πρέπει να είναι ένα αντικείμενο JSON, όχι συμβολοσειρά:

```json
{
  "type": "object",
  "properties": {
    "text": { "type": "string", "description": "Text to count" }
  },
  "required": ["text"]
}
```

**Παράδειγμα εργαλείου:**

```python
def count_characters(text: str) -> int:
    return len(text)
```

> **Sandbox.** Τα εργαλεία Python εκτελούνται ως μη αξιόπιστος κώδικας σε ένα ενισχυμένο, απομονωμένο Docker container από προεπιλογή (χωρίς δίκτυο, χωρίς Docker socket, read-only filesystem, non-root). Οι εισαγωγές περιορίζονται σε μια allowlist ασφαλών modules της standard library. Ανατρέξτε στην ενότητα [Security → Python Tool Sandbox](../reference/security.md#python-tool-sandbox) για τη διαμόρφωση (`HEYM_PYTHON_TOOL_SANDBOX`).

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `toolTimeoutSeconds` | number | Μέγιστα δευτερόλεπτα ανά εκτέλεση εργαλείου (προεπιλογή: 30) |
| `requestTimeoutSeconds` | number | Μέγιστα δευτερόλεπτα αναμονής για κάθε απάντηση μοντέλου πριν από το timeout (προεπιλογή: 60). Αυξήστε το για αργούς ή self-hosted providers (LiteLLM, vLLM, τοπικά μοντέλα) και για μεγάλες εκτελέσεις πολλαπλών βημάτων. |
## Συνδέσεις MCP

Συνδεθείτε σε διακομιστές [Model Context Protocol](https://modelcontextprotocol.io/) για να εκθέσετε τα εργαλεία τους στον agent.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `transport` | `"stdio"` \| `"sse"` \| `"streamable_http"` | Τύπος σύνδεσης |
| `timeoutSeconds` | number | Χρονικό όριο για αυτή τη σύνδεση (προεπιλογή: 30) |
| `label` | string | Προαιρετικό όνομα εμφάνισης |

**stdio** (τοπική διεργασία):

| Πεδίο | Περιγραφή |
|-------|-------------|
| `command` | Εντολή προς εκτέλεση (π.χ. `npx`) |
| `args` | JSON array (π.χ. `["-y", "@modelcontextprotocol/server-filesystem", "--path", "/tmp"]`) |
| `env` | JSON object μεταβλητών περιβάλλοντος που εισάγονται στη διεργασία (π.χ. `{"GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..."}`) |

Οι περισσότεροι διακομιστές stdio με κλειδιά API αυθεντικοποιούνται μέσω μεταβλητών περιβάλλοντος αντί για ορίσματα εντολών. Ορίστε το `env` ανά σύνδεση, ώστε κάθε node agent να μπορεί να χρησιμοποιεί διαφορετικό διαπιστευτήριο χωρίς να τροποποιείται το περιβάλλον του κεντρικού συστήματος.

Οι τιμές του `env` υποστηρίζουν [Expression DSL](../reference/expression-dsl.md), ώστε να μπορείτε να περνάτε εισόδους workflow ως διαπιστευτήρια αντί να ενσωματώνετε μυστικά απευθείας:

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "$userInput.pat" }
}
```

Η έκφραση `$userInput.pat` επιλύεται κατά τον χρόνο εκτέλεσης με βάση τα δεδομένα εισόδου του workflow, πριν από την εκκίνηση της διεργασίας MCP. Αυτό σας επιτρέπει να δέχεστε token από trigger ή input node αντί να τα ενσωματώνετε στον ορισμό του workflow.

Παράδειγμα — GitHub MCP με ενσωματωμένο token:

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxxxxxxxxx" }
}
```

Παράδειγμα — GitHub MCP με δυναμικό token από είσοδο workflow:

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "$userInput.pat" }
}
```

Παράδειγμα — GitHub MCP με διαπιστευτήριο GitHub του Heym:

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "$credentials.MyGitHubToken" }
}
```

Το ενσωματωμένο διαπιστευτήριο GitHub υποστηρίζει προς το παρόν αυθεντικοποίηση βάσει PAT. Εάν χρειάζεστε πρόσβαση σε οργανισμό, χρησιμοποιήστε ένα PAT με τα απαιτούμενα δικαιώματα οργανισμού/αποθετηρίου.

Παράδειγμα — Slack MCP:

```json
{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-slack"],
  "env": { "SLACK_BOT_TOKEN": "xoxb-...", "SLACK_TEAM_ID": "T0123456" }
}
```

**SSE** (απομακρυσμένος διακομιστής):

| Πεδίο | Περιγραφή |
|-------|-------------|
| `url` | URL του endpoint SSE. Υποστηρίζει εκφράσεις (π.χ. `$userInput.serverUrl`). |
| `headers` | JSON object για auth/προσαρμοσμένες κεφαλίδες. Οι τιμές υποστηρίζουν εκφράσεις. |

**Streamable HTTP** (απομακρυσμένος διακομιστής):

| Πεδίο | Περιγραφή |
|-------|-------------|
| `url` | URL του endpoint MCP (π.χ. `https://example.com/mcp`). Υποστηρίζει εκφράσεις. |
| `headers` | JSON object για auth/προσαρμοσμένες κεφαλίδες. Οι τιμές υποστηρίζουν εκφράσεις. |

## Δεξιότητες

Οι Δεξιότητες είναι οδηγίες SKILL.md μαζί με προαιρετικά αρχεία Python και συνοδευτικά assets. Επεκτείνουν το system context του agent και μπορούν να προσθέσουν εργαλεία Python.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `name` | string | Όνομα Δεξιότητας |
| `content` | string | Περιεχόμενο SKILL.md (οδηγίες) |
| `timeoutSeconds` | number | Χρονικό όριο για την εκτέλεση Python της Δεξιότητας (προεπιλογή: 30) |
| `driveFilesEnabled` | boolean | Ενεργοποιεί τον βοηθό `heym_drive` κατά τον χρόνο εκτέλεσης για αυτή τη Δεξιότητα (προεπιλογή: false) |
| `files` | array | Προαιρετικές εγγραφές `{ path, content, encoding, mimeType }` (π.χ. scripts `.py` ή δυαδικά assets αποθηκευμένα ως base64) |

Οι Δεξιότητες μπορούν να προστεθούν με απόθεση αρχείου `.zip` ή `.md` στην περιοχή Δεξιοτήτων.
Αφού αναπτύξετε μια κάρτα Δεξιότητας, αποθέστε οποιοδήποτε αρχείο σε αυτή τη Δεξιότητα για να επισυνάψετε ή να αντικαταστήσετε ένα συνοδευτικό αρχείο, συμπεριλαμβανομένων δυαδικών assets όπως PDF και εικόνες.
Χρησιμοποιήστε το κουμπί λήψης σε μια κάρτα Δεξιότητας για να εξαγάγετε αυτή τη Δεξιότητα ως αρχείο `.zip` για δημιουργία αντιγράφου ασφαλείας ή επαναχρησιμοποίηση σε άλλο workflow.

Ενεργοποιήστε το **Drive files** σε μια Δεξιότητα μόνο όταν ο κώδικας Python της χρειάζεται να διαβάζει αρχεία από το Heym Drive. Οι ενεργοποιημένες Δεξιότητες λαμβάνουν έναν παραγόμενο βοηθό `heym_drive.py` κατά τον χρόνο εκτέλεσης και μπορούν να καλούν τις `list_drive_files`, `get_drive_file`, `get_drive_file_path`, `read_drive_file`, `read_drive_text` ή `read_drive_base64` με ένα αναγνωριστικό αρχείου Drive ή ακριβές όνομα αρχείου. Η αναζήτηση με όνομα αρχείου χρησιμοποιεί το νεότερο προσβάσιμο αποτέλεσμα. Οι απενεργοποιημένες Δεξιότητες δεν λαμβάνουν τον βοηθό.

Κάθε κάρτα Δεξιότητας έχει τέσσερις ενέργειες στη σειρά κάτω από τον τίτλο:

| Κουμπί | Περιγραφή |
|--------|-------------|
| **Edit with AI** | Ανοίγει το Skill Builder για αναθεώρηση της Δεξιότητας από ένα prompt chat |
| **Download** | Εξάγει τη Δεξιότητα ως αρχείο `.zip` |
| **Remove** | Διαγράφει τη Δεξιότητα από αυτό το node agent |
| **History** | Ανοίγει το ιστορικό της Δεξιότητας που προέρχεται από το [Ιστορικό Επεξεργασίας](../reference/edit-history.md) |
### Ιστορικό δεξιοτήτων

Το ιστορικό δεξιοτήτων **δεν** αποθηκεύεται ξεχωριστά. Προκύπτει από τα στιγμιότυπα του Ιστορικού επεξεργασίας του workflow: κάθε αποθηκευμένη έκδοση του workflow περιλαμβάνει τον πλήρη πίνακα `skills` του node του agent.

Από το παράθυρο διαλόγου Ιστορικού μπορείτε να:

- **Προεπισκόπηση** ενός προηγούμενου στιγμιότυπου (SKILL.md και λίστα αρχείων)
- **Επεξεργασία** — φόρτωση ενός στιγμιότυπου στον επεξεργαστή δεξιοτήτων χωρίς επαναφορά ολόκληρου του workflow
- **AI Fine-tune** — άνοιγμα του Skill Builder με αυτό το στιγμιότυπο ως σημείο εκκίνησης
- **Επαναφορά** — επαναφορά μόνο αυτής της δεξιότητας από μια προηγούμενη έκδοση (οι άλλοι nodes παραμένουν ως έχουν)

Το ιστορικό ακολουθεί την ίδια διατήρηση 7 ημερών με το Ιστορικό επεξεργασίας του workflow. Η αποθήκευση του workflow μετά από επεξεργασίες δεξιοτήτων δημιουργεί νέες εγγραφές ιστορικού.

Η ενότητα Δεξιοτήτων περιλαμβάνει επίσης το **AI Build**:

- Κάντε κλικ στο **AI Build** για να δημιουργήσετε μια νέα δεξιότητα από ένα prompt στο chat
- Κάντε κλικ στο κουμπί sparkle σε μια υπάρχουσα δεξιότητα για να την αναθεωρήσετε με AI
- Αποθέστε αρχεία στο prompt composer για να τα επισυνάψετε στο σχόλιο fine-tune· αυτά τα αρχεία αποθηκεύονται επίσης ως συνοδευτικά assets της δεξιότητας
- Το modal μεταδίδει το κείμενο του assistant ενώ εμφανίζει ζωντανές προεπισκοπήσεις των αρχείων `SKILL.md` και `.py`
- Το **Download ZIP** εξάγει την τρέχουσα προεπισκόπηση χωρίς να την προσθέτει στον node
- Το **Save & Add** αποθηκεύει τα παραγόμενα αρχεία πίσω μέσω της ίδιας ροής ανάλυσης ZIP που χρησιμοποιείται από τις χειροκίνητες μεταφορτώσεις

Κατά την επεξεργασία με AI, το Heym στέλνει μόνο αρχεία δεξιοτήτων κειμένου `.md` και `.py` στον builder. Τα δυαδικά και άλλα μη επεξεργάσιμα συνημμένα διατηρούνται και κοινοποιούνται στον builder ως μεταδεδομένα διαδρομής, ώστε ο παραγόμενος κώδικας Python να διατηρεί σωστές τις σχετικές αναφορές αρχείων.
Επιλέξτε ένα συνημμένο αρχείο στο δεξιό πλαίσιο και ενεργοποιήστε το **Include this file in AI context** όταν το AI χρειάζεται να επιθεωρήσει ένα συνοδευτικό πρότυπο. Αρχεία κειμένου, PDF και DOCX εξάγονται στο πλαίσιο του prompt όταν είναι δυνατό· το Heym δεν εφαρμόζει ξεχωριστό όριο μεγέθους συνημμένου του Skill Builder πέραν του ορίου του σώματος αιτήματος της πλατφόρμας.

## Extra Body

Ορισμένοι providers δέχονται παραμέτρους αιτήματος που τα τυπικά πεδία συμβατά με OpenAI δεν
καλύπτουν, όπως η απενεργοποίηση της λειτουργίας σκέψης ενός μοντέλου. Επιλέξτε **Send extra request body** στις
ιδιότητες του node και εισαγάγετε ένα αντικείμενο JSON.

```json
{
  "extraBodyEnabled": true,
  "extraBody": "{ \"thinking\": { \"type\": \"disabled\" } }"
}
```

- **Απενεργοποιημένο από προεπιλογή.** Με το πλαίσιο επιλογής ανενεργό, δεν αποστέλλεται τίποτα επιπλέον.
- Εφαρμόζεται σε **κάθε** αίτημα στον βρόχο κλήσης εργαλείων, όχι μόνο στην πρώτη στροφή, καθώς και
  στην προσπάθεια του εφεδρικού μοντέλου. Δεν εφαρμόζεται στους ελέγχους guardrail, οι οποίοι χρησιμοποιούν ξεχωριστό μοντέλο.
- Πρέπει να είναι ένα **αντικείμενο** JSON. Ένας πίνακας, μια κλιμακωτή τιμή ή μη έγκυρο κείμενο αποτυγχάνει τον node με
  `Invalid extra body JSON` αντί να απορρίπτεται σιωπηλά.
- Οι εκφράσεις `$` επιλύονται πριν από την ανάλυση. Επειδή πρόκειται για κειμενική αντικατάσταση, μια επιλυμένη
  τιμή που περιέχει διπλό εισαγωγικό ή αλλαγή γραμμής παράγει μη έγκυρο JSON και αποτυγχάνει τον node.

Ίδιο πεδίο και συμπεριφορά με το extra body του [LLM node](./llm-node.md).

## Μόνιμη μνήμη (γράφος)

Προαιρετικός γράφος γνώσης **ανά node agent** αποθηκευμένος στη βάση δεδομένων. Όταν είναι ενεργοποιημένος, το Heym προσθέτει μια σύνοψη Markdown των απομνημονευμένων οντοτήτων και σχέσεων στη **system instruction** πριν από κάθε εκτέλεση (μόνο εάν ο γράφος δεν είναι κενός). Μετά από μια **επιτυχή** ολοκλήρωση του agent, μια εργασία στο παρασκήνιο εξάγει νέα διαρκή γεγονότα από τη συνομιλία και τα συγχωνεύει στον γράφο.

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `persistentMemoryEnabled` | boolean | Ενεργοποίηση φόρτωσης + εξαγωγής στο παρασκήνιο για αυτόν τον node του canvas |

Οι **Sub-agents** διατηρούν τον **δικό** τους γράφο (με κλειδί το node id τους), ξεχωριστό από τον orchestrator.

Χρησιμοποιήστε το ροζ χειριστήριο **brain** στον node (όταν η μνήμη είναι ενεργή ή εμφανίζεται η γραμμή του μοντέλου) για να ανοίξετε τον επεξεργαστή γράφου και την προαιρετική **κοινοποίηση μνήμης** (άλλα workflows/agents). Πλήρης συμπεριφορά, διαδρομές REST και λεπτομέρειες εξαγωγής JSON: [Agent Persistent Memory](../reference/agent-persistent-memory.md).

## Responses API και συνέχεια συλλογισμού

Ένα πλαίσιο επιλογής **Use Responses API** δρομολογεί τις κλήσεις του μοντέλου του agent μέσω του
[Responses API](https://platform.openai.com/docs/api-reference/responses) αντί για Chat
Completions. Είναι ανενεργό από προεπιλογή.

Έχει τη μεγαλύτερη σημασία σε ένα μοντέλο συλλογισμού όπως το `gpt-5` ή η σειρά `o`. Το Responses API επιστρέφει
τον συλλογισμό του μοντέλου μαζί με κάθε κλήση εργαλείου, και ο agent τροφοδοτεί αυτά τα στοιχεία συλλογισμού πίσω στην
επόμενη στροφή, ώστε το μοντέλο να διατηρεί την αλυσίδα σκέψης του σε έναν βρόχο εργαλείων πολλαπλών βημάτων αντί να
την αναπαράγει μετά από κάθε αποτέλεσμα εργαλείου. Ολόκληρος ο βρόχος εκτελείται στην ίδια διαδρομή, συμπεριλαμβανομένης
της παύσης και συνέχισης της [ανθρώπινης αξιολόγησης](#human-review-hitl), της [συμπίεσης πλαισίου](#context-compression)
και της τελικής απάντησης.

Η ίδια η συνομιλία παραμένει στο Heym. Το Heym στέλνει την πλήρη είσοδο σε κάθε στροφή και μεταφέρει τον
συλλογισμό ως κρυπτογραφημένο blob, ώστε τίποτα να μη διατηρείται στην πλευρά του provider μεταξύ των κλήσεων.
Τα στοιχεία συλλογισμού εντός ενός span που συνοψίζει η συμπίεση πλαισίου απορρίπτονται μαζί του, καθώς
ένα κρυπτογραφημένο blob δεν μπορεί να συνοψιστεί.

Λειτουργεί με ένα διαπιστευτήριο OpenAI, και με ένα προσαρμοσμένο διαπιστευτήριο του οποίου το gateway υποστηρίζει το
endpoint. Με ένα διαπιστευτήριο Google παραμένει απενεργοποιημένο.
## Συμπίεση Πλαισίου (Context Compression)

Όταν ένας agent εκτελεί πολλές επαναλήψεις εργαλείων με μεγάλα αποτελέσματα (web scraping, αναγνώσεις εγγράφων, έξοδοι υπο-workflow), το συσσωρευμένο ιστορικό μηνυμάτων μπορεί να προσεγγίσει το όριο του παραθύρου πλαισίου του μοντέλου. Το Heym συμπιέζει αυτόματα το ιστορικό της συνομιλίας κατά τη διάρκεια της εκτέλεσης για να αποτρέψει την υπερχείλιση του πλαισίου.

**Πώς λειτουργεί:**

1. Πριν από κάθε επανάληψη εργαλείου, το Heym εκτιμά τον τρέχοντα αριθμό token (~4 χαρακτήρες ανά token).
2. Εάν η εκτίμηση υπερβαίνει το **80%** του παραθύρου πλαισίου του μοντέλου, ενεργοποιείται η συμπίεση.
3. Το ιστορικό μηνυμάτων χωρίζεται σε διατηρούμενα και συμπιεσμένα τμήματα:
   - **Διατηρούμενα**: system prompt, πρώτο μήνυμα χρήστη, πιο πρόσφατο μήνυμα χρήστη
   - **Συμπιεσμένα**: όλα τα ενδιάμεσα (γύροι συλλογισμού του assistant, κλήσεις εργαλείων, αποτελέσματα εργαλείων)
4. Το μεσαίο τμήμα συνοψίζεται χρησιμοποιώντας το **ίδιο μοντέλο και διαπιστευτήριο** — δεν απαιτείται πρόσθετη διαμόρφωση.
5. Η συμπιεσμένη σύνοψη αντικαθιστά το μεσαίο τμήμα ως ένα μόνο μήνυμα assistant.

**Παρατηρησιμότητα:**

Τα συμβάντα συμπίεσης εμφανίζονται ως καταχωρήσεις `Context compressed (N messages → summary)` σε:
- Τη λίστα κλήσεων εργαλείων του **Debug panel** κατά τη ζωντανή εκτέλεση
- Την προβολή λεπτομερειών εκτέλεσης του **Execution history**
- Την **καρτέλα Traces** ως καταχώρηση trace `context.compression`

Η συμπίεση είναι αυτόματη και πάντα ενεργή για τους Agent nodes. **Δεν** εφαρμόζεται σε LLM nodes, στην καρτέλα Chat ή σε συνεδρίες του AI Assistant.
