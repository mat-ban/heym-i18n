# Μετατροπέας

Ο κόμβος **Μετατροπέας** μετατρέπει δεδομένα και αρχεία μεταξύ μορφών χωρίς να απαιτείται σύνταξη κώδικα. Είναι τεχνολογικά ουδέτερος, ώστε να μπορούν να προστίθενται περισσότερες μορφές με την πάροδο του χρόνου. Μετατρέπει δεδομένα CSV, JSON και XML προς αμφότερες τις κατευθύνσεις, εκτελεί Tesseract OCR για την εξαγωγή κειμένου από εικόνες και PDF, και ξαναγράφει ένα αποθηκευμένο αρχείο σε άλλη μορφή.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 1 |
| Έξοδος | `$nodeLabel.result` (αναλυμένα δεδομένα για `csvToJson` / `xmlToJson`, κείμενο για `jsonToCsv` / `jsonToXml`, εξαγόμενο κείμενο για `imageToText` / `pdfToText`, μεταδεδομένα νέου αρχείου για `fileConvert`) |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `label` | string | Αναγνωριστικό κόμβου (camelCase) |
| `conversion` | string | `csvToJson` (κείμενο CSV → πίνακας αντικειμένων γραμμών), `jsonToCsv` (πίνακας αντικειμένων/γραμμών → κείμενο CSV), `xmlToJson` (κείμενο XML → αντικείμενο), `jsonToXml` (αντικείμενο → κείμενο XML), `imageToText` (OCR σε εικόνα), `pdfToText` (OCR σε κάθε επιλεγμένη σελίδα PDF), ή `fileConvert` (ξαναγράφει ένα αποθηκευμένο αρχείο σε άλλη μορφή) |
| `source` | expression | Τα δεδομένα προς μετατροπή. Αφήστε το κενό για να χρησιμοποιηθεί η πρώτη είσοδος του κόμβου |
| `delimiter` | string | Διαχωριστικό πεδίου ενός χαρακτήρα (προεπιλογή `,`) |
| `hasHeader` | boolean | Μόνο για `csvToJson` — να αντιμετωπίζεται η πρώτη γραμμή ως επικεφαλίδα (προεπιλογή `true`) |
| `trimValues` | boolean | Μόνο για `csvToJson` — αφαιρεί τα κενά διάστημα γύρω από ονόματα επικεφαλίδων και τιμές κελιών (προεπιλογή `true`) |
| `includeHeader` | boolean | Μόνο για `jsonToCsv` — εγγράφει γραμμή επικεφαλίδας (προεπιλογή `true`) |
| `converterColumns` | string | Μόνο για `jsonToCsv` — προαιρετική σειρά στηλών χωρισμένη με κόμμα |
| `converterFileId` | expression | Μετατροπές αρχείων — το αρχείο Heym Drive προς ανάγνωση, π.χ. `$Upload.file.id` |
| `converterTargetFormat` | string | Μόνο για `fileConvert` — μορφή εξόδου (`pdf`, `docx`, `html`, `md`, `txt`, `csv`, `epub`, `jpg`, `png`, `bmp`, `webp`) |
| `ocrLanguage` | string | Μόνο για OCR — `auto` (προεπιλογή), κωδικός Tesseract όπως `tur`, ή `custom` |
| `ocrLanguageCustom` | string | Μόνο για OCR — κωδικοί γλώσσας που χρησιμοποιούνται όταν το `ocrLanguage` είναι `custom`, π.χ. `eng+tur` |
| `ocrEncoding` | string | Μόνο για OCR — σύνολο χαρακτήρων στο οποίο κανονικοποιείται το κείμενο (προεπιλογή `utf-8`) |
| `ocrNormalizeUnicode` | boolean | Μόνο για OCR — εφαρμογή κανονικοποίησης NFC (προεπιλογή `true`) |
| `ocrPsm` | string | Μόνο για OCR — λειτουργία κατάτμησης σελίδας Tesseract (προεπιλογή `3`) |
| `ocrDpi` | number | Μόνο για `pdfToText` — DPI ραστεροποίησης σελίδας (προεπιλογή `300`) |
| `ocrPageRange` | expression | Μόνο για `pdfToText` — `3` ή `2-5`. Κενό σημαίνει κάθε σελίδα |

## Συμπεριφορά

- **`csvToJson`** αναλύει το κείμενο CSV της πηγής. Με `hasHeader: true` κάθε γραμμή γίνεται αντικείμενο με κλειδιά τις τιμές της επικεφαλίδας· με `hasHeader: false` κάθε γραμμή γίνεται πίνακας τιμών κελιών. Πεδία σε εισαγωγικά, ενσωματωμένα διαχωριστικά και ενσωματωμένες αλλαγές γραμμής αντιμετωπίζονται σύμφωνα με το RFC 4180. Ένα αρχικό UTF-8 BOM (συνηθισμένο σε εξαγωγές Excel) αφαιρείται, και διπλότυπα ονόματα επικεφαλίδων γίνονται μοναδικά χωρίς να αντικαθίσταται πραγματική στήλη (`a, a, a_2` → `a`, `a_3`, `a_2`). Ορίστε το `delimiter` σε `\t` για ανάλυση τιμών χωρισμένων με tab.
- **`trimValues`** (προεπιλογή `true`) αφαιρεί τα περιβάλλοντα κενά διάστημα από ονόματα επικεφαλίδων και τιμές κελιών, **συμπεριλαμβανομένων των πεδίων σε εισαγωγικά** (`" padded "` → `padded`). Το RFC 4180 αντιμετωπίζει τα κενά διάστημα σε εισαγωγικά ως δεδομένα, οπότε ορίστε `trimValues: false` για να τα διατηρήσετε ακριβώς.
- **`jsonToCsv`** δημιουργεί κείμενο CSV από πίνακα αντικειμένων (ή πινάκων). Η σειρά στηλών λαμβάνεται από το `converterColumns` όταν παρέχεται, διαφορετικά συνάγεται από τα κλειδιά του πρώτου αντικειμένου. Τιμές που περιέχουν το διαχωριστικό, εισαγωγικά ή αλλαγές γραμμής περικλείονται αυτόματα σε εισαγωγικά.
- **`xmlToJson`** αναλύει XML σε αντικείμενο. Τα χαρακτηριστικά χρησιμοποιούν πρόθεμα `@` και το κείμενο αναμεμειγμένο με χαρακτηριστικά χρησιμοποιεί `#text`· επαναλαμβανόμενα αδελφά στοιχεία γίνονται πίνακες. Η επέκταση οντοτήτων XML είναι απενεργοποιημένη.
- **`jsonToXml`** σειριοποιεί ένα αντικείμενο σε έγγραφο XML. Το αντικείμενο πρέπει να έχει ακριβώς ένα κλειδί ανώτατου επιπέδου, το οποίο γίνεται το ριζικό στοιχείο XML. Χρησιμοποιήστε την ίδια σύμβαση `@attribute` και `#text` όπως στο `xmlToJson` για να παραγάγετε χαρακτηριστικά και κείμενο μαζί με θυγατρικά στοιχεία.
- **`imageToText`** εκτελεί το Tesseract σε μία εικόνα (PNG, JPEG, TIFF, WebP, BMP).
- **`pdfToText`** ραστεροποιεί κάθε επιλεγμένη σελίδα στο `ocrDpi` και την αναγνωρίζει. Κάθε σελίδα περνά από OCR, οπότε ένα ψηφιακό PDF με απολύτως καλό επίπεδο κειμένου εξακολουθεί να ξαναδιαβάζεται από pixel. Αυτό διατηρεί τα σαρωμένα και τα ψηφιακά έγγραφα με πανομοιότυπη συμπεριφορά, με κόστος την ταχύτητα, οπότε περιορίστε το `ocrPageRange` σε μεγάλα αρχεία.
- **`fileConvert`** ξαναγράφει το αρχείο πηγής σε άλλη μορφή και αποθηκεύει το αποτέλεσμα ως **νέο** αρχείο Drive. Το πρωτότυπο δεν τροποποιείται ποτέ. Τα έγγραφα περνούν από pandoc, οι εικόνες από Pillow, και το JSON σε CSV από τον συγγραφέα csv της Python. Μια εικόνα δεν μπορεί να γίνει έγγραφο και ένα έγγραφο δεν μπορεί να γίνει εικόνα· για να διαβάσετε κείμενο από εικόνα χρησιμοποιήστε το `imageToText`.

## Εισαγωγή του αρχείου

Οι μετατροπές αρχείων διαβάζουν από το Heym Drive, όχι από διαδρομή ή URL, οπότε το αρχείο πρέπει πρώτα να αποθηκευτεί. Τρεις συνήθεις αλυσίδες:

- **[Trigger μεταφόρτωσης αρχείου](./file-upload-trigger-node.md) → Μετατροπέας** — κατευθύνετε το `converterFileId` στο `$Upload.file.id`.
- **[Drive](./drive-node.md) (`downloadUrl`) → Μετατροπέας** — ανακτήστε ένα απομακρυσμένο αρχείο στο Drive και μετά περάστε το `$Download.id`.
- **[Agent](./agent-node.md) → Μετατροπέας** — μια δεξιότητα που γράφει ένα αρχείο το εκθέτει ως `$reportAgent._generated_files[0].id`.

Το `converterFileId` δέχεται επίσης ένα ολόκληρο αντικείμενο αρχείου (`$Upload.file`) ή ένα URL λήψης Heym· το id αρχείου εξάγεται από οποιοδήποτε από τα δύο. Το αρχείο πρέπει να είναι δικό σας ή ένα που μοιράστηκε μαζί σας συνεργάτης.
## Γλώσσες

Το `auto` (η προεπιλογή) εκτελεί πρώτα την ανίχνευση προσανατολισμού και γραφής του Tesseract και έπειτα επιλέγει το καλύτερο εγκατεστημένο μοντέλο για την ανιχνευθείσα γραφή. Τα μοντέλα γραφής όπως το `Latin` ή το `Cyrillic` διαβάζουν κάθε γλώσσα που γράφεται σε αυτή τη γραφή, γι' αυτό το auto χειρίζεται ένα τουρκικό και ένα αγγλικό τιμολόγιο χωρίς να του υποδειχθεί ποιο είναι ποιο.

Η ονομαστική δήλωση της γλώσσας είναι ωστόσο ακριβέστερη όταν τη γνωρίζετε. Χρησιμοποιήστε έναν μόνο κωδικό (`tur`) ή συνδυάστε πολλούς με `+` (`eng+tur`) για μικτά έγγραφα — περισσότερες γλώσσες σημαίνει βραδύτερη και ελαφρώς θορυβωδέστερη αναγνώριση, οπότε διατηρήστε τη λίστα σύντομη. Οι κωδικοί λειτουργούν μόνο όταν τα αντίστοιχα δεδομένα γλώσσας είναι εγκατεστημένα στο backend· ο node εμφανίζει τι είναι διαθέσιμο όταν επιλέξετε έναν κωδικό που λείπει.

Κάθε εικόνα του Heym περιλαμβάνει τα `osd`, αγγλικά, τουρκικά, γερμανικά, γαλλικά, ισπανικά, ιταλικά, πορτογαλικά, ολλανδικά, ρωσικά, αραβικά, απλοποιημένα κινεζικά, ιαπωνικά, κορεατικά, καθώς και τα μοντέλα γραφής Latin, Cyrillic, Arabic, HanS, Japanese και Hangul.

## Κωδικοποίηση

Το αναγνωρισμένο κείμενο είναι UTF-8 και διατηρεί κάθε χαρακτήρα που παρήγαγε το Tesseract. Το `ocrNormalizeUnicode` (ενεργό από προεπιλογή) εφαρμόζει κανονικοποίηση NFC, ώστε ένα γράμμα γραμμένο ως `s` συν ένα συνδυαζόμενο cedilla να γίνεται ένα ενιαίο `ş` — αξίζει να παραμείνει ενεργό, επειδή οι δύο μορφές δεν είναι ίσες σε συγκρίσεις ή αναζητήσεις βάσης δεδομένων.

Το `ocrEncoding` έχει σημασία μόνο όταν κάτι downstream δεν μπορεί να αποθηκεύσει το πλήρες εύρος Unicode. Η επιλογή `cp1254` ή `iso-8859-9` διατηρεί το τουρκικό κείμενο άθικτο ενώ εγγυάται ότι το αποτέλεσμα χωράει σε αυτό το σύνολο χαρακτήρων· τα `latin-1` και `ascii` είναι στενότερα και αντικαθιστούν ό,τι δεν μπορούν να αναπαραστήσουν με `?`. Αφήστε το σε `utf-8` εκτός εάν κάποιο σύστημα-στόχος σας αναγκάσει να το αλλάξετε.

## Έξοδος

Τα `csvToJson`, `jsonToCsv`, `xmlToJson` και `jsonToXml` επιστρέφουν `$label.result` και `$label.conversion`. Οι μετατροπές OCR προσθέτουν:

| Πεδίο | Περιγραφή |
|-------|-------------|
| `$label.result` | Το πλήρες εξαγόμενο κείμενο, με τις σελίδες να ενώνονται με μια κενή γραμμή |
| `$label.language` | Το μοντέλο που εκτελέστηκε πραγματικά (χρήσιμο για να δείτε τι επέλεξε το `auto`) |
| `$label.encoding` | Το σύνολο χαρακτήρων στο οποίο κανονικοποιήθηκε το κείμενο |
| `$label.page_count` | Αριθμός σελίδων που αναγνωρίστηκαν |
| `$label.pages` | Πίνακας `{ page, text }` για χειρισμό ανά σελίδα |
| `$label.file` | `{ id, filename, mime_type, size_bytes }` του αρχείου προέλευσης |

Το `fileConvert` επιστρέφει το νέο αρχείο αντ' αυτού:

| Πεδίο | Περιγραφή |
|-------|-------------|
| `$label.id` | UUID του νεοαποθηκευμένου αρχείου |
| `$label.filename` | Το όνομα του μετατρεπόμενου αρχείου, με το βασικό όνομα να διατηρείται και την επέκταση να αλλάζει |
| `$label.mime_type` | Ο MIME τύπος του νέου αρχείου |
| `$label.size_bytes` | Το μέγεθος του νέου αρχείου |
| `$label.download_url` | Το URL λήψης από το Drive για το νέο αρχείο |
| `$label.source_file` | Μεταδεδομένα του αρχείου που μετατράπηκε |

## Παράδειγμα

```json
{
  "type": "converter",
  "data": {
    "label": "toRows",
    "conversion": "csvToJson",
    "source": "$userInput.body.text",
    "delimiter": ",",
    "hasHeader": true
  }
}
```

Για είσοδο `name,age\nAda,36`, οι downstream nodes έχουν πρόσβαση στις αναλυμένες γραμμές μέσω του `$toRows.result` (`[{ "name": "Ada", "age": "36" }]`).

Μετατροπή XML σε JSON:

```json
{
  "type": "converter",
  "data": {
    "label": "xmlToObject",
    "conversion": "xmlToJson",
    "source": "$webhook.body"
  }
}
```

Για `<person id="1"><name>Ada</name></person>`, το `$xmlToObject.result` είναι `{ "person": { "@id": "1", "name": "Ada" } }`. Για να δημιουργήσετε XML, περάστε αυτό το αντικείμενο σε έναν δεύτερο node Converter με `conversion: "jsonToXml"`.

Ανάγνωση σαρωμένου τιμολογίου που ανέβηκε μέσω ενός trigger μεταφόρτωσης αρχείου:

```json
{
  "type": "converter",
  "data": {
    "label": "readInvoice",
    "conversion": "pdfToText",
    "converterFileId": "$Upload.file.id",
    "ocrLanguage": "tur",
    "ocrEncoding": "utf-8",
    "ocrDpi": 300,
    "ocrPageRange": "1-3"
  }
}
```

Ένας downstream node [Agent](./agent-node.md) ή [LLM](./llm-node.md) μπορεί έπειτα να εξαγάγει δομημένα πεδία από το `$readInvoice.result`.

Μετατροπή μιας αναφοράς markdown ενός agent σε PDF:

```json
{
  "type": "converter",
  "data": {
    "label": "convertDoc",
    "conversion": "fileConvert",
    "converterFileId": "$reportAgent._generated_files[0].id",
    "converterTargetFormat": "pdf"
  }
}
```

Οι downstream nodes διαβάζουν το `$convertDoc.download_url` για να μοιραστούν το PDF ή το `$convertDoc.id` για να συνεχίσουν να εργάζονται με αυτό στο [Drive](./drive-node.md).

## Απαιτήσεις

Το OCR καλεί εξωτερικά το `tesseract` και το `pdftoppm` του poppler, ενώ η μετατροπή εγγράφων χρησιμοποιεί το pandoc. Και τα τρία περιλαμβάνονται σε κάθε τρόπο εκτέλεσης του Heym, συμπεριλαμβανομένων των `run.sh`, docker-compose και της μεμονωμένης εικόνας έκδοσης, οπότε δεν υπάρχει τίποτα να ρυθμίσετε. Τα όρια σελίδων, τα timeouts και το μέγιστο DPI είναι σταθερές τιμές της πλατφόρμας και όχι ρυθμίσεις.
