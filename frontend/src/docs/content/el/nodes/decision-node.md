# Decision

Ο κόμβος **Decision** υποβάλλει ερωτήσεις συγκεκριμένου τύπου σε ένα μοντέλο αποφάσεων σχετικά με την τρέχουσα κατάσταση της εκτέλεσης και επιστρέφει πιθανότητες. Δεν παράγει κείμενο. Χρησιμοποιήστε τον όταν ένα workflow χρειάζεται μια κρίση στην οποία μπορεί να διακλαδωθεί — δρομολόγηση, διαλογή, κατάταξη, επαλήθευση ή έλεγχο πρόσβασης σε ένα βήμα που δεν μπορεί να αναιρεθεί.

Τα μοντέλα αποφάσεων (που ονομάζονται επίσης μοντέλα *System One*) είναι διαφορετικού τύπου μοντέλα από ένα LLM. Δεν υπάρχει prompt, ούτε system instruction, ούτε temperature, ούτε tool calling. Στέλνετε μια **state** μαζί με έναν χάρτη **questions**, και κάθε απάντηση επιστρέφεται ως αριθμός με μια κατανομή πιθανότητας πίσω της. Επειδή μια απάντηση αποτελείται από λίγα μόνο tokens, αυτά τα μοντέλα είναι γρήγορα και οικονομικά σε σύγκριση με το να ζητήσετε από ένα [LLM](./llm-node.md) να παράγει JSON και να το αναλύσετε.

Για παραγωγή κειμένου, χρησιμοποιήστε τον κόμβο [LLM](./llm-node.md). Για ένα μοντέλο που καλεί εργαλεία, χρησιμοποιήστε τον [Agent Node](./agent-node.md).

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 1 |
| Έξοδος | Η απάντηση του παρόχου αυτούσια — `$nodeLabel.answers.<id>`, `$nodeLabel.model`, `$nodeLabel.usage` |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `credentialId` | UUID | Ένα διαπιστευτήριο *Decision Model*. Όχι διαπιστευτήριο LLM. |
| `model` | string | Όνομα μοντέλου, για παράδειγμα `jev-latest` |
| `state` | expression | Τι πρέπει να διαβάσει το μοντέλο (προεπιλογή `$input.text`) |
| `questions` | array | Διατεταγμένες γραμμές ερωτήσεων· τουλάχιστον μία |
| `customBodyEnabled` | boolean | Αποστολή ενός χειροκίνητα γραμμένου request body αντί της φόρμας |
| `customBody` | expression (JSON) | Το body που αποστέλλεται όταν ο διακόπτης είναι ενεργός |
| `requestTimeoutSeconds` | number | Μέγιστος χρόνος αναμονής σε δευτερόλεπτα (προεπιλογή: 60) |

### State

Η **State** είναι η κατάσταση που κρίνει το μοντέλο. Δέχεται string, object ή array.

Ένα πεδίο που περιέχει ακριβώς μία έκφραση διατηρεί τον δικό του τύπο, οπότε το `$input` στέλνει το ίδιο το object αντί για το κείμενό του. Ένα πρότυπο με έκφραση μέσα του (`Ticket: $input.text`) μετατρέπεται σε string. Δώστε σε κάθε ερώτηση αρκετά στοιχεία για να απαντήσει: κείμενο πηγής, ταυτότητες, σχέσεις, πολιτικές και τρέχοντα γεγονότα.

## Τύποι ερωτήσεων

Κάθε ερώτηση έχει ένα `id`, έναν `type`, `instructions` και κριτήρια που εξαρτώνται από τον τύπο.

Το `id` είναι ο τρόπος με τον οποίο το workflow σας διαβάζει την απάντηση. **Δεν αποστέλλεται ποτέ στο μοντέλο**, οπότε ολόκληρο το νόημα πρέπει να βρίσκεται στις `instructions`. Γράφοντας `id: is_urgent` με `instructions: "Is it?"` δεν δίνετε στο μοντέλο τίποτα για να δουλέψει.

### Noul

Κατά πόσο ισχύει μια συνθήκη. Επιστρέφει την πιθανότητα η απάντηση να είναι ναι, από 0 έως 1.

Τα κριτήρια είναι προαιρετικά: τα **Yes means** και **No means** περιγράφουν τι καλύπτει κάθε πλευρά. Μια τιμή κοντά στο 0.5 σημαίνει ότι το μοντέλο βρίσκει το ναι και το όχι περίπου εξίσου πιθανά — όχι «μέτρια ένταση».

```json
{
  "id": "is_urgent",
  "type": "noul",
  "instructions": "Does this message convey urgency?",
  "criteriaTrue": "Explicitly time-sensitive or blocking work",
  "criteriaFalse": "No urgency expressed"
}
```

Διαβάστε το με `$triage.answers.is_urgent.noul`.

### Choice

Επιλέγει μία επιλογή από ένα σύνολο που ορίζετε. Επιστρέφει την επιλεγμένη επιλογή, την πλήρη κατανομή και μια βεβαιότητα που προκύπτει από αυτήν.

Προσθέστε μια επιλογή που καλύπτει το «κανένα από αυτά» όποτε τίποτα δεν μπορεί να ταιριάξει — το μοντέλο δεν μπορεί να επιλέξει μια επιλογή που δεν του προσφέρατε.

```json
{
  "id": "department",
  "type": "choice",
  "instructions": "Which team should handle this request?",
  "options": [
    { "key": "billing", "description": "Payments, invoicing, refunds" },
    { "key": "technical", "description": "Bugs, outages, integrations" },
    { "key": "other", "description": "Nothing above fits" }
  ]
}
```

Διαβάστε το με `$triage.answers.department.choice`, `.probabilities.billing` και `.confidence`.

### Score

Αξιολογεί την κατάσταση κατά μήκος μιας διατεταγμένης κλίμακας. Επιστρέφει μια σταθμισμένη με πιθανότητες τιμή που μπορεί να βρεθεί **μεταξύ** των επιπέδων, μαζί με το legend και την κατανομή.

Τα επίπεδα παρατίθενται από το χαμηλότερο πρώτα, τουλάχιστον δύο και το πολύ δέκα. Κάθε επίπεδο πρέπει να περιγράφει μια συγκεκριμένη κατάσταση και να στέκεται αυτόνομα.

```json
{
  "id": "frustration",
  "type": "score",
  "instructions": "How frustrated is the customer?",
  "levels": ["Calm", "Frustrated", "Very angry"]
}
```

Διαβάστε το με `$triage.answers.frustration.score`, `.legend` και `.confidence`.

## Generate with AI

Το **Generate with AI** μετατρέπει μια απλή πρόταση σε ένα προτεινόμενο πρότυπο state και ένα σύνολο γραμμών ερωτήσεων. Περιγράψτε τι θέλετε να κριθεί — «διαλογή ενός εισερχόμενου αιτήματος υποστήριξης: πόσο επείγον είναι, ποια ομάδα το αναλαμβάνει και πόσο απογοητευμένος ακούγεται ο πελάτης» — και ελέγξτε τι επιστρέφεται πριν το προσθέσετε στον κόμβο.

Η σύνταξη γίνεται από ένα LLM, οπότε ο διάλογος ζητά ένα διαπιστευτήριο LLM. Το μοντέλο αποφάσεων απαντά στις ερωτήσεις αργότερα, όταν εκτελείται το workflow. Τα παραγόμενα ids αποδιπλοποιούνται σε σχέση με τις γραμμές που διατηρεί ήδη ο κόμβος, οπότε η διπλή παραγωγή δεν αντικαθιστά ποτέ ένα υπάρχον κλειδί απάντησης.

Κάθε παραγωγή καταγράφεται στην καρτέλα [Traces](../tabs/traces-tab.md) κάτω από την πηγή **Decision Questions**, μαζί με τα traces `decision.systemone` που γράφει ο ίδιος ο κόμβος κατά τον χρόνο εκτέλεσης.
## Προσαρμοσμένο σώμα αιτήματος

Ενεργοποιήστε το **Προσαρμοσμένο σώμα αιτήματος** για να στέλνετε JSON που γράφετε εσείς αντί για τη φόρμα. Χρησιμοποιήστε το για ένα endpoint του οποίου το συμβόλαιο διαφέρει από αυτό που δημιουργεί η φόρμα.

Ο επεξεργαστής αρχικοποιείται από την τρέχουσα φόρμα και οι εκφράσεις εντός του επιλύονται πριν αποσταλεί το αίτημα. Όσο ο διακόπτης είναι ενεργός, το πεδίο State και οι γραμμές ερωτήσεων αγνοούνται. Η απάντηση περνά αμετάβλητη είτε έτσι είτε αλλιώς, οπότε ένα διαφορετικό συμβόλαιο απλώς παράγει διαφορετικό σχήμα για τις εκφράσεις σας.

## Έξοδος

Ο node επιστρέφει ακριβώς ό,τι επέστρεψε ο πάροχος. Τίποτα δεν μετονομάζεται ή επιπεδοποιείται.

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "is_urgent": { "type": "noul", "noul": 0.95 },
    "department": {
      "type": "choice",
      "choice": "billing",
      "probabilities": { "billing": 0.88, "technical": 0.12, "other": 0.0 },
      "confidence": 0.81
    },
    "frustration": {
      "type": "score",
      "score": 1.05,
      "legend": { "0": "Calm", "1": "Frustrated", "2": "Very angry" },
      "probabilities": { "0": 0.0, "1": 0.95, "2": 0.05 },
      "confidence": 0.92
    }
  },
  "usage": { "input_tokens": 296, "output_tokens": 20 }
}
```

## Διακλάδωση βάσει απάντησης

Ένας node [Switch](./switch-node.md) δρομολογεί βάσει της επιλεγμένης επιλογής και ένας node [Condition](./condition-node.md) μπορεί να στέλνει περιπτώσεις χαμηλής βεβαιότητας κάπου όπου θα τις δει κάποιος:

```
Input → Decision (triage) → Condition ($triage.answers.department.confidence > 0.7)
                              ├─ true  → Switch on $triage.answers.department.choice
                              └─ false → Send Email (human review)
```

Μια τυποποιημένη απάντηση εγγυάται το σχήμα, όχι την αλήθεια. Επιλέξτε κατώτατα όρια με βάση τα δικά σας δεδομένα και τις συνέπειες αντί να αντιγράψετε έναν αριθμό από ένα παράδειγμα.

## Διαπιστευτήριο

Δημιουργήστε ένα διαπιστευτήριο **Decision Model** στην καρτέλα [Διαπιστευτήρια](../tabs/credentials-tab.md) με:

- **Base URL** — το endpoint, για παράδειγμα `https://api.typesafe.ai`. Το Heym προσθέτει `/v1/systemone`.
- **API Key** — προαιρετικό. Endpoints που δεν χρειάζονται κλειδί μπορούν να μείνουν κενά.

Η επεξεργασία ενός διαπιστευτηρίου διατηρεί το αποθηκευμένο κλειδί όταν το πεδίο κλειδιού μείνει κενό· πληκτρολογήστε το ξανά μόνο για να το αντικαταστήσετε.

Το ίδιο διαπιστευτήριο μπορεί να αξιολογεί εκτελέσεις [Αξιολογήσεων](../tabs/evals-tab.md): με επιλεγμένο το **LLM-as-Judge**, επιλέξτε το ως κριτή και το μοντέλο αποφάσεων βαθμολογεί κάθε απάντηση έναντι της αναμενόμενης εξόδου.

Το Heym αποκλείει εξερχόμενα αιτήματα προς ιδιωτικές και loopback διευθύνσεις από προεπιλογή, οπότε ένα endpoint αποφάσεων που εκτελείτε εσείς σε `localhost` ή σε ιδιωτικό εύρος χρειάζεται `HEYM_HTTP_ALLOW_PRIVATE_URLS=true`.

Τα μοντέλα αποφάσεων δεν εμφανίζονται στους πίνακες τιμολόγησης LLM που συγχρονίζει το Heym, οπότε η στήλη **Cost** στις [Εκτελέσεις](../tabs/traces-tab.md) παραμένει κενή για αυτές τις κλήσεις. Οι μετρήσεις token καταγράφονται ακόμα και μπορείτε να προσθέσετε τη δική σας τιμή με μια παράκαμψη τιμολόγησης.

## Σφάλματα

| Κατάσταση | Τι συμβαίνει |
|-----------|--------------|
| Μη έγκυρο API key | Ο node αποτυγχάνει με μήνυμα που κατονομάζει το διαπιστευτήριο |
| Κακοσχηματισμένη ερώτηση | Το μήνυμα σε επίπεδο πεδίου του ίδιου του παρόχου μεταφέρεται στο σφάλμα του node |
| Περιορισμός ρυθμού ή υπερφόρτωση | Ο node αποτυγχάνει με μήνυμα που αναφέρει ότι η κατάσταση είναι παροδική — ενεργοποιήστε την [επανάληψη](../reference/features.md) για αυτόν τον node για να την ξεπεράσετε |
| Διπλότυπο ή κενό αναγνωριστικό ερώτησης | Ο node αποτυγχάνει πριν αποσταλεί οποιοδήποτε αίτημα |
