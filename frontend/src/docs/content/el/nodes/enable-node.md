# Ενεργοποίηση Κόμβου

Ο κόμβος **Enable Node** ενεργοποιεί ξανά έναν άλλο κόμβο. Κατά την εκτέλεσή του, θέτει το `active` του κόμβου-στόχου σε `true` και διατηρεί την αλλαγή. Αποτελεί το αντίστοιχο του [Disable Node](./disable-node.md): χρησιμοποιήστε το για να επανενεργοποιήσετε ένα trigger [Cron](./cron-node.md) ή οποιονδήποτε κόμβο που είχε απενεργοποιηθεί.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 1 |
| Έξοδος | `$nodeLabel.targetNode`, `$nodeLabel.enabled` |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `label` | string | Αναγνωριστικό κόμβου (camelCase) |
| `targetNodeLabel` | string | Ετικέτα του κόμβου προς ενεργοποίηση (π.χ. `hourlyCheck`) |

## Συμπεριφορά

- Ο στόχος αποθηκεύεται ως ενεργός, ώστε οι μελλοντικές εκτελέσεις και τα triggers να τον βλέπουν. Ένα επανενεργοποιημένο trigger Cron ενεργοποιείται ξανά στην επόμενη προγραμματισμένη ώρα του.
- Εάν ο στόχος βρίσκεται κατάντη του Enable Node και δεν έχει εκτελεστεί ακόμη, εκτελείται επίσης στην τρέχουσα εκτέλεση.
- Η ενεργοποίηση ενός κόμβου που είναι ήδη ενεργός δεν αλλάζει τίποτα· η έξοδος εξακολουθεί να αναφέρει `enabled: true`.
- Ο κόμβος αποτυγχάνει με σφάλμα όταν το `targetNodeLabel` είναι κενό ή κανένας κόμβος δεν φέρει αυτή την ετικέτα.

## Περίπτωση Χρήσης

Ξεκινήστε ένα trigger [Cron](./cron-node.md) κατά απαίτηση. Αποθηκεύστε τον κόμβο Cron απενεργοποιημένο και δώστε στο workflow ένα δεύτερο σημείο εισόδου, όπως ένα trigger [Input](./input-node.md). Ένα αίτημα προς αυτό το σημείο εισόδου εκτελεί τον Enable Node και ο Cron αρχίζει να ενεργοποιείται.

Ένα απενεργοποιημένο trigger δεν ξεκινά ποτέ εκτέλεση από μόνο του, επομένως ο Enable Node πρέπει να βρίσκεται πίσω από ένα σημείο εισόδου που μπορεί να εκτελεστεί.

## Παράδειγμα

```json
{
  "type": "enableNode",
  "data": {
    "label": "startCron",
    "targetNodeLabel": "hourlyCheck"
  }
}
```

Ροή: Input → Enable Node (στόχος: cron) → Output. Ο κόμβος Cron `hourlyCheck` αποθηκεύεται ως απενεργοποιημένος στο ίδιο workflow και εκτελεί τον δικό του κλάδο HTTP ελέγχου μόλις ενεργοποιηθεί.
