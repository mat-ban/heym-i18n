# Trigger Μεταφόρτωσης Αρχείου

Ο κόμβος **Trigger Μεταφόρτωσης Αρχείου** αποτελεί σημείο εισόδου μηδενικής εισόδου για workflows που απαιτούν ένα **μεγάλο αρχείο** (ήχο, βίντεο, αρχεία συμπίεσης) το οποίο δεν μπορεί να ενσωματωθεί ως base64 μέσα σε ένα αίτημα JSON. Η κλήση του workflow επιστρέφει έναν προσυμπληρωμένο, μίας χρήσης σύνδεσμο μεταφόρτωσης `curl`· η μεταφόρτωση ενός αρχείου σε αυτόν τον σύνδεσμο ξεκινά την εκτέλεση με το αρχείο συνημμένο.

Χρησιμοποιήστε τον όταν ένας καλών — συμπεριλαμβανομένου ενός AI agent όπως το Claude ή το ChatGPT που εκτελείται σε sandbox — πρέπει να παραδώσει μια ηχογράφηση φωνής 20 MB ή ένα βίντεο 75 MB σε ένα workflow του Heym.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 0 |
| Έξοδοι | 1 |
| Έξοδος | `$nodeLabel.file.{id,name,mime,size,download_url}`, `$nodeLabel.uploaded_at` |

## Πώς λειτουργεί

Ο κόμβος εκτελείται σε δύο φάσεις:

1. **Δημιουργία (Mint).** Όταν το workflow καλείται μέσω HTTP (`POST /api/workflows/{id}/execute`), ως εργαλείο MCP ή μέσω του κουμπιού **Run Workflow** στον καμβά, η εκτέλεση **δεν** εκτελεί το σώμα. Αντ' αυτού δημιουργεί μια υποδοχή μεταφόρτωσης μίας χρήσης και επιστρέφει:

   ```json
   {
     "file_upload_required": true,
     "curl": "curl -F 'file=@/path/to/your/file' 'https://your-host/api/file-intake/u/<token>'",
     "upload_url": "https://your-host/api/file-intake/u/<token>",
     "expires_at": "2026-06-25T13:00:00+00:00",
     "max_size_mb": 100,
     "allowed_types": ["audio/*"]
   }
   ```

2. **Μεταφόρτωση + εκτέλεση.** Ο καλών εκτελεί το `curl` με το αρχείο του. Το endpoint μεταφόρτωσης επικυρώνει την υποδοχή, αποθηκεύει το αρχείο, εκτελεί το workflow **σύγχρονα** και επιστρέφει την έξοδο του workflow στην απάντηση της μεταφόρτωσης. Ο σύνδεσμος είναι **μίας χρήσης** — μια δεύτερη μεταφόρτωση επιστρέφει `409`.

Στον καμβά, το **Run Workflow** εμφανίζει το `curl` που δημιουργήθηκε στον πίνακα εντοπισμού σφαλμάτων με κουμπί αντιγραφής.

## Παράμετροι

| Παράμετρος | Τύπος | Προεπιλογή | Περιγραφή |
|------------|-------|------------|-----------|
| `ttlMinutes` | number | `60` | Για πόσο χρόνο ο σύνδεσμος μεταφόρτωσης παραμένει έγκυρος (1–10080 λεπτά / έως 7 ημέρες). |
| `maxSizeMb` | number | `100` | Μέγιστο αποδεκτό μέγεθος αρχείου. Το ανώτατο όριο είναι **100 MB**. |
| `allowedTypes` | string | (κενό) | Προαιρετική λίστα επιτρεπόμενων MIME/επεκτάσεων χωρισμένη με κόμματα, π.χ. `audio/*, .wav`. Κενή τιμή επιτρέπει οποιονδήποτε τύπο. |

## Πεδία εξόδου

| Έκφραση | Περιγραφή |
|---------|-----------|
| `$nodeLabel.file.id` | UUID αποθηκευμένου αρχείου (ένα αρχείο Drive). |
| `$nodeLabel.file.name` | Αρχικό όνομα αρχείου. |
| `$nodeLabel.file.mime` | Ανιχνευμένος τύπος περιεχομένου. |
| `$nodeLabel.file.size` | Μέγεθος σε bytes. |
| `$nodeLabel.file.download_url` | Πιστοποιημένο URL λήψης για επόμενους κόμβους. |
| `$nodeLabel.uploaded_at` | Χρονική σήμανση ISO της μεταφόρτωσης. |

## Παράδειγμα

Ένα workflow μεταγραφής:

```
File Upload Trigger ("audio")  →  Transcribe ($audio.file)  →  LLM summary  →  Output
```

1. Ένας agent καλεί το εργαλείο MCP του workflow και λαμβάνει το `curl`.
2. Ο agent εκτελεί το `curl` με την ηχογράφηση από το sandbox του.
3. Η μεταφόρτωση εκτελεί το workflow και η απάντηση του `curl` περιέχει τη σύνοψη της μεταγραφής.

## Ασφάλεια

- Το URL μεταφόρτωσης ενσωματώνει ένα token υψηλής εντροπίας — το token **είναι** η δυνατότητα, επομένως ένας sandboxed agent δεν χρειάζεται διαπιστευτήρια Heym για να μεταφορτώσει. Μόνο το hash του token αποθηκεύεται στην πλευρά του διακομιστή.
- Η δημιουργία απαιτεί κανονικό έλεγχο ταυτότητας workflow, επομένως μόνο εξουσιοδοτημένοι καλούντες μπορούν να δημιουργήσουν συνδέσμους μεταφόρτωσης.
- Κάθε δημιουργία και κάθε απόπειρα μεταφόρτωσης (αποδεκτή ή απορριφθείσα — ληγμένη, επαναληφθείσα, υπερμεγέθης, μη επιτρεπόμενου τύπου, άγνωστο token) καταγράφεται σε αρχείο ελέγχου μόνο προσθήκης.
- Οι μεταφορτώσεις επιβάλλονται ως μίας χρήσης, με χρονικό όριο TTL και ανώτατο όριο μεγέθους· οι υπερμεγέθεις μεταφορτώσεις απορρίπτονται.

## Σημειώσεις

- Τα γενικά κανάλια κλήσης HTTP, MCP και καμβά παραμένουν αποκλειστικά JSON· αυτός ο κόμβος είναι ο υποστηριζόμενος τρόπος αποδοχής μεταφορτώσεων αρχείων multipart.
- Το μεταφορτωμένο αρχείο αποθηκεύεται ως κανονικό αρχείο Drive, επομένως οποιοσδήποτε επόμενος κόμβος που δέχεται αναφορά αρχείου (μεταγραφή, αποστολή συνημμένου email κ.λπ.) μπορεί να καταναλώσει το `$nodeLabel.file`.
