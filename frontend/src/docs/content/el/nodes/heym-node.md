# Heym

Ο κόμβος **Heym** διαβάζει τα δεδομένα του ίδιου του Heym: τα workflows στα οποία έχετε πρόσβαση, τη δομή ενός workflow και το ιστορικό εκτελέσεών του. Με αυτόν τον τρόπο δημιουργείτε meta-workflows — απογραφές instances, συνόψεις εκτελέσεων και αναφορές υγείας για τον ίδιο τον Heym.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 1 |
| Λειτουργίες | `listWorkflows`, `getWorkflow`, `getExecutionHistory` |
| Διαπιστευτήριο | Δεν απαιτείται |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `heymOperation` | Select | Ποια ανάγνωση θα εκτελεστεί |
| `heymWorkflowId` | UUID | Ορίστε το σε `all` στο `getExecutionHistory` για να διαβαστούν όλα τα προσβάσιμα Workflows. |
| `heymLimit` | String | Μέγιστος αριθμός γραμμών που θα επιστραφούν. **Αφήστε το κενό ή εισαγάγετε `0` για να επιστραφούν τα πάντα** — αυτή είναι η προεπιλογή. Υποστηρίζει εκφράσεις. |
| `heymStatus` | String | Προαιρετικό φίλτρο κατάστασης για το `getExecutionHistory`. Υποστηρίζει εκφράσεις. |
| `heymSinceDays` | String | Προαιρετικό διάστημα αναδρομής σε ημέρες για το `getExecutionHistory`. Υποστηρίζει εκφράσεις. |

Ο επιλογέας workflow είναι ένα αναζητήσιμο dropdown που εμφανίζει κάθε workflow στο οποίο έχετε πρόσβαση.

## Εύρος Πρόσβασης

Τα αποτελέσματα περιορίζονται στον **κάτοχο του workflow στο οποίο ανήκει ο κόμβος** — όχι σε όποιον ξεκίνησε την εκτέλεση. Το ορατό σύνολο είναι:

- workflows που ανήκουν στον κάτοχο,
- workflows που έχουν κοινοποιηθεί απευθείας στον κάτοχο,
- workflows που έχουν κοινοποιηθεί σε ομάδα στην οποία ανήκει ο κάτοχος.

Ο περιορισμός στον κάτοχο είναι αυτό που κάνει τον κόμβο να συμπεριφέρεται πανομοιότυπα είτε μια εκτέλεση ξεκίνησε χειροκίνητα, από cron, από portal ή από κάποιο συμβάν της πλατφόρμας. Ο περιορισμός στον εκτελούντα θα επέστρεφε κενά αποτελέσματα σε κάθε μη επιτηρούμενη εκτέλεση. Είναι ο ίδιος κανόνας που χρησιμοποιεί ήδη ο Heym για τα διαπιστευτήρια και τις καθολικές μεταβλητές.

Ένα workflow στο οποίο δεν έχετε πρόσβαση και ένα workflow που δεν υπάρχει παράγουν το ίδιο μήνυμα σφάλματος, ώστε ο κόμβος να μην μπορεί να χρησιμοποιηθεί για την ανίχνευση workflow ids.

## Λειτουργίες

### List Workflows

Επιστρέφει κάθε workflow στο οποίο έχει πρόσβαση ο κάτοχος, με τα πιο πρόσφατα ενημερωμένα πρώτα.

| Έκφραση | Περιγραφή |
|------------|-------------|
| `$nodeLabel.workflows` | Πίνακας με συνόψεις workflow |
| `$nodeLabel.workflows[0].id` | UUID του workflow |
| `$nodeLabel.workflows[0].name` | Όνομα του workflow |
| `$nodeLabel.workflows[0].description` | Περιγραφή ή `null` |
| `$nodeLabel.workflows[0].active` | Αν το workflow είναι ενεργό |
| `$nodeLabel.workflows[0].folder_id` | UUID φακέλου ή `null` |
| `$nodeLabel.workflows[0].updated_at` | Χρονική σήμανση ISO της τελευταίας αποθήκευσης |
| `$nodeLabel.workflows[0].node_count` | Πόσους κόμβους περιέχει το workflow |
| `$nodeLabel.total` | Πλήθος όλων των προσβάσιμων **πριν** εφαρμοστεί το όριο |

Το `total` είναι σκόπιμα το πλήθος χωρίς όριο, ώστε το `$inventory.total` να αναφέρει το πραγματικό μέγεθος ακόμη και όταν περιορίζετε τις γραμμές που επιστρέφονται. Καθαρίζοντας το **Limit**, ή ορίζοντάς το σε `0`, επιστρέφονται όλα τα workflows — που είναι και η προεπιλογή.

### Get Workflow

Επιστρέφει την ταυτότητα και τη μορφή ενός workflow.

| Έκφραση | Περιγραφή |
|------------|-------------|
| `$nodeLabel.id`, `$nodeLabel.name`, `$nodeLabel.description` | Ταυτότητα του workflow |
| `$nodeLabel.active`, `$nodeLabel.folder_id`, `$nodeLabel.updated_at` | Μεταδεδομένα του workflow |
| `$nodeLabel.node_count` | Αριθμός κόμβων |
| `$nodeLabel.nodes` | Πίνακας με `{ id, type, label, position, data }` |
| `$nodeLabel.edges` | Πίνακας με `{ id, source, target, sourceHandle, targetHandle }` |

Το `data` είναι η **πλήρης διαμόρφωση του κόμβου** — κάθε πεδίο όπως αποθηκεύτηκε. Αυτό είναι που καθιστά δυνατόν τον έλεγχο: δεν μπορείτε να σαρώσετε ένα workflow για ένα API key που κάποιος επικόλλησε σε κάποιο πεδίο, αν ο κόμβος αρνείται να εμφανίσει το πεδίο.

Αυτό δεν παρέχει πρόσβαση που ο καλών δεν είχε ήδη. Ο κόμβος περιορίζεται σε workflows που ο κάτοχος μπορεί να ανοίξει ούτως ή άλλως στον editor, και τα αποθηκευμένα μυστικά των διαπιστευτηρίων εξακολουθούν να μην βρίσκονται εδώ: τα δεδομένα του κόμβου περιέχουν μόνο **ids** διαπιστευτηρίων, ενώ τα ίδια τα μυστικά βρίσκονται κρυπτογραφημένα στον πίνακα διαπιστευτηρίων.

### Σάρωση για hardcoded secrets

```
cron → heym (listWorkflows) → loop → heym (getWorkflow) → agent → slack
```

Δώστε στον agent το `$detail.nodes` και ζητήστε του να επισημάνει οποιαδήποτε τιμή του `data` μοιάζει με ενεργό key ή token. Τα πεδία που αξίζει να παρακολουθείτε είναι τα ελεύθερου κειμένου — το `curl` σε κόμβους HTTP, τα `userMessage` και `systemInstruction` σε κόμβους LLM και Agent, και τα σώματα των Python tools — γιατί ένα credential id είναι ένα αβλαβές UUID, αλλά ένα επικολλημένο `sk-…` δεν είναι.
### Λήψη Ιστορικού Εκτελέσεων

Αφήστε το **Since (days)** κενό για να καλύψετε τα πάντα, το **Status filter** κενό για να συμπεριλάβετε κάθε status, και το **Limit** κενό ή `0` για να επιστραφούν όλες οι εγγραφές.

## Παράδειγμα Workflow

**Καθημερινή σύνοψη instance**

```
cron → heym (listWorkflows) → loop → heym (getExecutionHistory) → llm → sendEmail
```

- **Heym** `listWorkflows` με ετικέτα `inventory`
- **Loop** πάνω στο `$inventory.workflows`
- **Heym** `getExecutionHistory` με `heymWorkflowId` ορισμένο στο `id` του στοιχείου του loop, `heymSinceDays` σε `1`, και `heymLimit` σε `5`
- **LLM** μετατρέπει τις συλλεγμένες εκτελέσεις και τις μετρήσεις status σε αναγνώσιμη σύνοψη

## Σημειώσεις

- Δεν απαιτείται διαπιστευτήριο· ο node διαβάζει την ίδια βάση δεδομένων στην οποία εκτελείται το Heym.
- Το **Limit** είναι το ίδιο πεδίο για αμφότερες τις λειτουργίες λίστας, και σημαίνει το ίδιο και στις δύο: κενό ή `0` επιστρέφει τα πάντα.
- Ο node δέχεται κανονική είσοδο και μπορεί να προσαρτηθεί σε έναν Agent node ως εργαλείο, ώστε ένας agent να απαντά σε ερωτήσεις σχετικά με το instance του Heym σας — ή να το ελέγχει.
- Τα payloads του `getWorkflow` αυξάνονται με το workflow: μεγάλα prompts και σώματα Python tool ταξιδεύουν όλα μέσα στο `data`.
- Συνδυάστε το με το [Heym Trigger](./heym-trigger-node.md) για να αντιδράτε σε αλλαγές workflow καθώς συμβαίνουν, αντί να κάνετε polling σε χρονοδιάγραμμα.
