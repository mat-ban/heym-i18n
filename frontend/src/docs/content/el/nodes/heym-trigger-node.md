# Heym Trigger

Ο κόμβος **Heym Trigger** εκκινεί ένα workflow όταν η ίδια η πλατφόρμα Heym δημοσιεύει ένα συμβάν πλατφόρμας. Πρόκειται για έναν trigger node μηδενικής εισόδου για την αυτοματοποίηση του Heym με το Heym: αλλαγή ιχνών ελέγχου, ανακοινώσεις ανάπτυξης και συνόψεις υγείας της παρουσίας.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 0 |
| Έξοδοι | 1 |
| Έξοδος | `$nodeLabel.events`, `$nodeLabel.count`, `$nodeLabel.triggered_at` |
| Διαπιστευτήριο | Κανένα δεν απαιτείται |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `eventNames` | Πίνακας συμβολοσειρών | Ποια συμβάντα θα γίνουν συνδρομητικά. Αφήστε το κενό για να λαμβάνετε κάθε συμβάν. |

## Συμβάντα

| Συμβάν | Δημοσιεύεται όταν | Εμβέλεια |
|-------|----------------|-------|
| `heym.started` | Η πλατφόρμα Heym εκκινεί | Σε επίπεδο παρουσίας: κάθε συνδρομητής το λαμβάνει |
| `workflow.created` | Δημιουργείται ένα workflow | Μόνο οι συνδρομητές του κατόχου του workflow |
| `workflow.updated` | Αποθηκεύεται ένα workflow | Μόνο οι συνδρομητές του κατόχου του workflow |
| `workflow.deleted` | Διαγράφεται ένα workflow | Μόνο οι συνδρομητές του κατόχου του workflow |

Τα widgets του πίνακα ελέγχου αποθηκεύονται εσωτερικά ως workflows, αλλά δεν παράγουν ποτέ συμβάντα `workflow.*`.

## Η Παράδοση Είναι Ομαδοποιημένη

Το Heym αποστέλλει συμβάντα κάθε πέντε δευτερόλεπτα. **Κάθε συμβάν που διεκδικείται σε ένα πέρασμα αποστολής φτάνει σε μία μόνο εκτέλεση workflow**, ως πίνακας.

- Δημιουργήστε δύο workflows εντός πέντε δευτερολέπτων μεταξύ τους → **μία** εκτέλεση με δύο συμβάντα.
- Δημιουργήστε ένα workflow → **μία** εκτέλεση με πίνακα ενός στοιχείου.

Η μορφή δεν αλλάζει ποτέ, επομένως οι εκφράσεις κατάντη δεν χρειάζεται ποτέ να διακλαδίζονται ανάλογα με το αν έφτασε ένα ή πολλά συμβάντα. Όταν χρειάζεται να ενεργήσετε μία φορά ανά συμβάν, τοποθετήστε έναν κόμβο [Loop](./loop-node.md) πάνω από το `$nodeLabel.events`.

## Παράδοση Ακριβώς Μία Φορά

Κάθε συμβάν διεκδικείται ανά συνδρομητικό κόμβο μέσω ενός μοναδικού περιορισμού βάσης δεδομένων πριν παραδοθεί. Αυτό ισχύει σε κάθε uvicorn worker, κάθε container και κάθε μηχάνημα: η εκτέλεση του Heym σε δύο διακομιστές δεν παραδίδει ένα συμβάν δύο φορές. Εάν μια διεκδίκηση δεν μπορεί να καταγραφεί, το συμβάν δεν παραδίδεται καθόλου — ο σχεδιασμός αποτυγχάνει κλειστά αντί να ενεργοποιείται δύο φορές.

Δύο διαφορετικοί κόμβοι `heymTrigger` που είναι συνδρομητές στο ίδιο συμβάν το λαμβάνουν ο καθένας μία φορά· δεν ανταγωνίζονται για αυτό.

## Το Παράθυρο Αποστολής

Ο dispatcher εξετάζει μόνο συμβάντα που δημοσιεύτηκαν τα **τελευταία πέντε λεπτά**. Τα παλαιότερα συμβάντα παραμένουν στο αρχείο καταγραφής για επιθεώρηση αλλά δεν παραδίδονται ποτέ. Αυτό περιορίζει το τι συμβαίνει μετά από διακοπή λειτουργίας: η επαναφορά του Heym μετά από μία ώρα εκτός σύνδεσης δεν αναπαράγει τίποτα, αντί να ενεργοποιεί μία ώρα εκκρεμοτήτων ταυτόχρονα.

Τα συμβάντα διατηρούνται για **7 ημέρες** και στη συνέχεια διαγράφονται.

## Πεδία Εξόδου

| Έκφραση | Περιγραφή |
|------------|-------------|
| `$nodeLabel.events` | Πίνακας αντικειμένων συμβάντων, από το παλαιότερο πρώτα. Πάντα πίνακας. |
| `$nodeLabel.events[0].id` | UUID συμβάντος |
| `$nodeLabel.events[0].name` | Όνομα συμβάντος, για παράδειγμα `workflow.created` |
| `$nodeLabel.events[0].payload` | Σώμα συμβάντος |
| `$nodeLabel.events[0].workflow_id` | Αναγνωριστικό του υποκείμενου workflow, ή `null` για `heym.started` |
| `$nodeLabel.events[0].created_at` | Χρονική σήμανση ISO για το πότε δημοσιεύτηκε το συμβάν |
| `$nodeLabel.count` | Αριθμός συμβάντων σε αυτή την ομάδα |
| `$nodeLabel.triggered_at` | Χρονική σήμανση ISO για την εκτέλεση του workflow |

### Μορφές Payload

`workflow.created`, `workflow.updated`, `workflow.deleted`:

```json
{
  "workflow_id": "…",
  "name": "Nightly report",
  "owner_id": "…",
  "actor_user_id": "…",
  "updated_at": "2026-08-11T09:30:00+00:00"
}
```

`heym.started`:

```json
{ "version": "1.4.2", "started_at": "2026-08-11T09:30:00+00:00" }
```

Το `workflow.deleted` φέρει το όνομα που καταγράφηκε αμέσως πριν από τη διαγραφή, καθώς η γραμμή του workflow έχει εξαφανιστεί μέχρι τη στιγμή που διαβάζετε το συμβάν.

## Παράδειγμα Workflow

**Ίχνος ελέγχου αλλαγών workflow**

```
heymTrigger → heym (getWorkflow) → slack
```

- **Heym Trigger** με ετικέτα `platformEvents`, συνδρομητής στα `workflow.created`, `workflow.updated`, `workflow.deleted`
- Κόμβος **Heym** με `getWorkflow` και `heymWorkflowId` ορισμένο σε `$platformEvents.events[0].workflow_id`
- Μήνυμα **Slack**: `"$platformEvents.count workflow change(s), latest: $platformEvents.events[0].name"`

## Σημειώσεις

- Το `heym.started` ενεργοποιείται **μία φορά ανά εκκίνηση πλατφόρμας**, όχι μία φορά ανά worker, παρόλο που το Heym εκτελεί οκτώ workers ανά container. Τα containers που εκκινούν με διαφορά άνω των πέντε λεπτών δημοσιεύουν το καθένα ένα συμβάν.
- Οι εκτελέσεις που ενεργοποιούνται με αυτόν τον τρόπο εμφανίζονται στο ιστορικό με `trigger_source = "heym_event"`.
- Ορίστε το **Events** σε κανένα αντί να απαριθμήσετε και τα τέσσερα, εάν θέλετε να λαμβάνετε αυτόματα τύπους συμβάντων που προστίθενται σε μελλοντικές εκδόσεις.
