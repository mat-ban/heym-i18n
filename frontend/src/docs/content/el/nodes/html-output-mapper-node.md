# Αντιστοιχιστής εξόδου HTML

Ο κόμβος **Αντιστοιχιστής εξόδου HTML** αποδίδει ένα μεμονωμένο πρότυπο HTML σε μια σελίδα. Χρησιμοποιήστε τον όταν ο καλών είναι ένας **browser** και όχι ένας API client — το workflow απαντά με `text/html` αντί για JSON.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 1 |
| Έξοδοι | 0 (sink) |
| Έξοδος χρόνου εκτέλεσης | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `label` | string | Αναγνωριστικό κόμβου (camelCase) |
| `html` | string | Το πρότυπο της σελίδας. Οι εκφράσεις `$nodeLabel.field` παρεμβάλλονται επί τόπου. |
| `statusCode` | number | Κατάσταση HTTP για την απάντηση (προεπιλογή `200`) |
| `contentType` | string | Τύπος περιεχομένου απάντησης (προεπιλογή `text/html; charset=utf-8`) |

## Συμπεριφορά Webhook και εκτέλεσης

Όταν αυτός ο κόμβος είναι η **μοναδική** τερματική έξοδος του workflow, το endpoint εκτέλεσης απαντά με την αποδιδόμενη σελίδα, τον διαμορφωμένο κωδικό κατάστασης και τον διαμορφωμένο τύπο περιεχομένου — χωρίς περίβλημα JSON, χωρίς περιτύλιγμα label.

Δύο πράγματα το απενεργοποιούν:

- **Ένας δεύτερος τερματικός κόμβος.** Με έναν άλλο ενεργό τερματικό κόμβο στο γράφο, το Heym επιστρέφει στον κανονικό χάρτη JSON ανά label και η σελίδα φτάνει ως πεδίο string.
- **`X-Simple-Response: false`.** Αυτή η κεφαλίδα ζητά το πλήρες περίβλημα με `status`, `node_results` και χρόνους, το οποίο χρησιμοποιεί ο καμβάς του editor. Στείλτε την όταν κάνετε αποσφαλμάτωση ενός workflow σελίδας.

## Εξυπηρέτηση σελίδας σε browser

Ορίστε τη **μέθοδο αιτήματος** του workflow σε `GET` στο παράθυρο διαλόγου cURL, ώστε μια απλή πλοήγηση browser να το φτάνει. Ένα αίτημα `GET` δεν φέρει σώμα, οπότε οι είσοδοι προέρχονται από το query string:

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Διαβάστε αυτές τις τιμές με `$input.query.name`. Ανατρέξτε στο [Webhooks](../reference/webhooks.md) για το πλήρες συμβόλαιο μεθόδων.

Ένα workflow χωρίς κόμβο trigger του οποίου ο μοναδικός τερματικός είναι αυτός ο κόμβος εμφανίζει ένα chip **WEB** στην [καρτέλα Workflows](../tabs/workflows-tab.md).

## Χρήση ως εργαλείο Agent

Δεν υποστηρίζεται. Αυτός ο κόμβος είναι τερματικός sink, οπότε δεν μπορεί να προσαρτηθεί σε λαβή εργαλείων [Agent Node](./agent-node.md). Το ίδιο ισχύει για τον [Αντιστοιχιστή εξόδου JSON](./json-output-mapper-node.md).

## Περιορισμός βρόχου

Ίδιος κανόνας όπως στο [Output](./output-node.md): μην τοποθετείτε αυτόν τον κόμβο μέσα σε κλάδο επανάληψης βρόχου — μόνο μετά τον κλάδο `done` του βρόχου. Ανατρέξτε στο [Loop](./loop-node.md).

## Παράδειγμα

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
