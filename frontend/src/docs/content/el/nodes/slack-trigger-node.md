# Slack Trigger

Ο κόμβος **Slack Trigger** είναι ένα σημείο εισόδου μηδενικής εισόδου που λαμβάνει webhooks του Slack Events API και ξεκινά αυτόματα ένα workflow. Διαχειρίζεται την πρόκληση επαλήθευσης URL του Slack και επαληθεύει τις υπογραφές αιτημάτων με ένα signing secret.

## Επισκόπηση

| Ιδιότητα | Τιμή |
|----------|-------|
| Είσοδοι | 0 |
| Έξοδοι | 1 |
| Έξοδος | `$nodeLabel.event`, `$nodeLabel.headers`, `$nodeLabel.triggered_by`, `$nodeLabel.trigger_node_id` |

## Παράμετροι

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `credentialId` | UUID | Διαπιστευτήριο `slack_trigger` που περιέχει το signing secret |

## Οδηγός Ρύθμισης

### 1. Δημιουργία Διαπιστευτηρίου `slack_trigger`

1. Μεταβείτε στις **Settings → Credentials → New Credential**
2. Επιλέξτε τύπο **Slack Trigger (Signing Secret)**
3. Επικολλήστε το **Signing Secret** από την εφαρμογή Slack σας:
   - Στο Slack: **App settings → Basic Information → App Credentials → Signing Secret**
4. Αποθηκεύστε το διαπιστευτήριο

### 2. Προσθήκη του Κόμβου στο Workflow σας

1. Ανοίξτε τον καμβά του workflow
2. Σύρετε τον **Slack Trigger** από τον πίνακα κόμβων στον καμβά
3. Κάντε κλικ στον κόμβο για να ανοίξετε τον πίνακα Ιδιοτήτων
4. Επιλέξτε το διαπιστευτήριο `slack_trigger` σας
5. Αντιγράψτε το **Webhook URL** που εμφανίζεται στον πίνακα

### 3. Ρύθμιση της Εφαρμογής Slack σας

1. Στις ρυθμίσεις της εφαρμογής Slack σας μεταβείτε στο **Event Subscriptions**
2. Ενεργοποιήστε το **Enable Events**
3. Επικολλήστε το Webhook URL στο πεδίο **Request URL**
4. Το Slack στέλνει μια πρόκληση επαλήθευσης URL — το Heym απαντά αυτόματα εντός χιλιοστών του δευτερολέπτου
5. Το πεδίο γίνεται πράσινο: ✓ Verified
6. Εγγραφείτε στα **Bot Events** που χρειάζεστε (π.χ. `message.channels`, `reaction_added`)
7. Αποθηκεύστε τις αλλαγές σας και επανεγκαταστήστε την εφαρμογή στον χώρο εργασίας σας εάν σας ζητηθεί

## Πεδία Εξόδου

Αφού ενεργοποιηθεί ο κόμβος, οι επόμενοι κόμβοι μπορούν να έχουν πρόσβαση σε:

| Έκφραση | Περιγραφή |
|------------|-------------|
| `$nodeLabel.event` | Πλήρες αντικείμενο συμβάντος Slack |
| `$nodeLabel.event.type` | Τύπος συμβάντος (π.χ. `"message"`, `"reaction_added"`) |
| `$nodeLabel.event.text` | Κείμενο μηνύματος (όταν ισχύει) |
| `$nodeLabel.event.user` | Αναγνωριστικό χρήστη Slack που ενεργοποίησε το συμβάν |
| `$nodeLabel.event.channel` | Αναγνωριστικό καναλιού |
| `$nodeLabel.event.ts` | Χρονική σήμανση συμβάντος |
| `$nodeLabel.headers` | Εξυγιασμένες κεφαλίδες HTTP από το Slack |
| `$nodeLabel.triggered_by` | Ετικέτα πηγής trigger (`"Slack"`) |
| `$nodeLabel.trigger_node_id` | Αναγνωριστικό κόμβου καμβά που έλαβε το συμβάν Slack |

## Παράδειγμα Workflow

**Μήνυμα Slack → απάντηση LLM → αποστολή Slack:**

```
slackTrigger → llm → slack
```

- Ετικέτα **slackTrigger**: `slackEvent`
- Μήνυμα χρήστη **LLM**: `"Reply to this Slack message: $slackEvent.event.text"`
- Μήνυμα **Slack**: `$llm.text`

## Ασφάλεια

- Τα αιτήματα επαληθεύονται χρησιμοποιώντας **HMAC-SHA256** με το signing secret σας
- Χρονικές σημάνσεις παλαιότερες από **5 λεπτά** απορρίπτονται (πρόληψη επιθέσεων επανάληψης)
- Ευαίσθητες κεφαλίδες (`x-slack-signature`, `authorization`, κ.λπ.) αφαιρούνται πριν φτάσουν στους επόμενους κόμβους
- Εάν δεν έχει οριστεί διαπιστευτήριο, ο κόμβος εκτελείται χωρίς επαλήθευση — συνιστάται μόνο για τοπικές δοκιμές

## Σημειώσεις

- Το Heym απαντά με `200 OK` αμέσως και εκτελεί το workflow στο παρασκήνιο — αυτό ικανοποιεί την απαίτηση απόκρισης 3 δευτερολέπτων του Slack
- Το webhook URL προέρχεται από το αναγνωριστικό κόμβου και δεν αλλάζει ποτέ, ακόμη και μετά από μετονομασίες workflow
- Απαιτείται μόνο ένας κόμβος `slackTrigger` ανά workflow· χρησιμοποιήστε κόμβους **Switch** ή **Condition** στη συνέχεια για δρομολόγηση διαφορετικών τύπων συμβάντων
