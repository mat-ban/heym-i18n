# A2A

Το Heym παρέχει τον **Heym Agent** μέσω του πρωτοκόλλου Agent2Agent (A2A 1.0, σύνδεση JSON-RPC). Ο Heym Agent είναι ο μηχανισμός πίσω από την [καρτέλα Chat](../tabs/chat-tab.md)· οι πελάτες MCP έχουν πρόσβαση στον ίδιο agent ως το εργαλείο `heym_chat` (δείτε την [καρτέλα MCP / A2A](../tabs/mcp-tab.md)). Με ενεργοποιημένο το A2A, ένας άλλος agent μπορεί να του στείλει μια Task σε φυσική γλώσσα και να λάβει την απάντηση, έχοντας τις ίδιες δυνατότητες με το Chat.

## Ενεργοποίηση

1. Ανοίξτε την καρτέλα **MCP / A2A**.
2. Ενεργοποιήστε τον **Heym Agent** στον προεπιλεγμένο διακομιστή ή σε έναν επώνυμο διακομιστή και επιλέξτε τα διαπιστευτήρια και το μοντέλο του.
3. Επιλέξτε **Ενεργοποίηση A2A**. Η κάρτα εμφανίζει τη διεύθυνση URL της **Agent Card** και το **JSON-RPC Endpoint**.

Το A2A βασίζεται στον Heym Agent: η απενεργοποίηση του agent απενεργοποιεί επίσης το A2A.

## Endpoints

| | Προεπιλεγμένος διακομιστής | Επώνυμος διακομιστής |
|---|---|---|
| Agent Card | `{origin}/.well-known/agent-card.json` | `{origin}/api/a2a/servers/{server_id}/agent-card.json` |
| JSON-RPC | `POST {origin}/api/a2a` | `POST {origin}/api/a2a/servers/{server_id}` |

Η Agent Card δεν απαιτεί διαπιστευτήρια και δεν αναφέρει χρήστη, διακομιστή ή Workflow. Υπάρχει μόνο όσο είναι ενεργοποιημένο το A2A: η κάρτα τομέα εφόσον τουλάχιστον ένας χρήστης έχει ενεργοποιημένο το A2A για τον προεπιλεγμένο διακομιστή, και η κάρτα ενός επώνυμου διακομιστή όσο είναι ενεργό το A2A αυτού του διακομιστή. Διαφορετικά, η διεύθυνση απαντά με 404.

## Έλεγχος ταυτότητας

Στείλτε τα ίδια διαπιστευτήρια όπως για το MCP, αποκλειστικά σε κεφαλίδες:

- `X-MCP-Key: <key>`: το κλειδί του προεπιλεγμένου διακομιστή ή το κλειδί του επώνυμου διακομιστή
- `Authorization: Bearer <token>`: ένα OAuth Token από τον διακομιστή OAuth του Heym

Διαπιστευτήρια στο URL απορρίπτονται. Η Agent Card δηλώνει και τα δύο σχήματα, ώστε ένας πελάτης A2A να μπορεί να τα διαβάσει από την κάρτα.

## Μέθοδοι

| Μέθοδος | Περιγραφή λειτουργίας |
|---|---|
| `SendMessage` | Ξεκινά μια Task ή συνεχίζει μία που περιμένει είσοδο. Περιμένει την απάντηση εκτός εάν το `configuration.returnImmediately` είναι `true`. |
| `SendStreamingMessage` | Το ίδιο, ως ροή Server-Sent Events για την πρόοδο και το αποτέλεσμα της Task. |
| `GetTask` | Η κατάσταση, η απάντηση και το ιστορικό μιας Task (το `historyLength` περιορίζει το ιστορικό). |
| `ListTasks` | Οι δικές σας Tasks σε αυτόν τον διακομιστή, πρώτα οι νεότερες, φιλτραρισμένες κατά `contextId` ή `status`, με `pageSize` και `pageToken`. |
| `CancelTask` | Διακόπτει μια Task που εξακολουθεί να εκτελείται ή να περιμένει. |
| `SubscribeToTask` | Παρακολουθεί μια Task που βρίσκεται σε εξέλιξη. |
| `GetExtendedAgentCard` | Η κάρτα με το όνομα του διακομιστή και τα ανατεθειμένα σε αυτόν Workflows ως δεξιότητες. |

Οι ειδοποιήσεις push δεν προσφέρονται: η κάρτα δηλώνει `pushNotifications: false` και οι μέθοδοι push απαντούν με `PushNotificationNotSupportedError`. Τα αιτήματα χρησιμοποιούν το A2A 1.0· στείλτε `A2A-Version: 1.0`. Ονόματα μεθόδων του A2A 0.3 όπως το `message/send` απαντούν με `VersionNotSupportedError`.

## Tasks και συνομιλίες

Κάθε Task είναι μια συνομιλία στην καρτέλα Chat, επισημασμένη με εικονίδιο δικτύου. Το `contextId` της Task είναι αυτή η συνομιλία: στείλτε νέο μήνυμα με το ίδιο `contextId` και χωρίς `taskId` για να τη συνεχίσετε.

| Τι έκανε ο agent | Κατάσταση Task |
|---|---|
| Απάντησε | `TASK_STATE_COMPLETED`, με την απάντηση ως κείμενο και, αν αποθηκεύτηκαν, τους συνδέσμους προς Workflows και σουίτες αξιολόγησης ως δεδομένα |
| Υπέβαλε διευκρινιστική ερώτηση | `TASK_STATE_INPUT_REQUIRED`: απαντήστε με το ίδιο `taskId` |
| Χρειάζεται διαπιστευτήριο | `TASK_STATE_AUTH_REQUIRED`: το μήνυμα κατάστασης περιέχει σύνδεσμο προς τη σελίδα διαπιστευτηρίων του Heym. Ο χρήστης τον ανοίγει σε πρόγραμμα περιήγησης συνδεδεμένο στο Heym· η τιμή δεν περνά ποτέ μέσα από τον άλλο agent. Στη συνέχεια στείλτε ένα μήνυμα στην ίδια Task για να συνεχίσετε. |
| Απέτυχε | `TASK_STATE_FAILED`, με την αιτία |
| Ακυρώθηκε | `TASK_STATE_CANCELED` |

Ένα μήνυμα προς ολοκληρωμένη Task ή προς Task που εξακολουθεί να εκτελείται απορρίπτεται με `UnsupportedOperationError`. Τα μηνύματα δέχονται μέρη `text` και `data`, έως 20.000 χαρακτήρες συνολικά· τα μέρη αρχείων απορρίπτονται, επομένως στείλτε αρχεία ως συνδέσμους.

## Πρόοδος

Κατά την εκτέλεση μιας Task, η ροή στέλνει ενημέρωση κατάστασης για κάθε βήμα, με τη διατύπωση που εμφανίζει η καρτέλα Chat, για παράδειγμα `Running workflow "Invoice Parser"` ή `Testing the workflow · attempt 2/5`. Οι πελάτες MCP λαμβάνουν τα ίδια βήματα ως `notifications/progress` από το `heym_chat`.

## Παράδειγμα

```bash
curl -s https://heym.example.com/.well-known/agent-card.json

curl -s -X POST https://heym.example.com/api/a2a \
  -H "X-MCP-Key: $HEYM_MCP_KEY" \
  -H "A2A-Version: 1.0" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"SendMessage","params":{"message":{"messageId":"m1","role":"ROLE_USER","parts":[{"text":"List my workflows"}]}}}'
```

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "task": {
      "id": "…",
      "contextId": "…",
      "status": { "state": "TASK_STATE_COMPLETED", "timestamp": "2026-10-27T10:30:00.000Z" },
      "artifacts": [
        { "artifactId": "response", "name": "Heym Agent reply", "parts": [{ "text": "You have 12 workflows: …" }] }
      ]
    }
  }
}
```

## Περιορισμοί

- Η μέθοδος `CancelTask` διακόπτει αμέσως έναν τρέχοντα γύρο στην παρουσία Heym που τον εκτελεί, όπως ακριβώς το κουμπί Stop στην καρτέλα Chat. Σε άλλους κόμβους η Task επισημαίνεται ως ακυρωμένη και το καθυστερημένο αποτέλεσμα δεν καταγράφεται.
- Χωρίς ειδοποιήσεις push, χωρίς σύνδεση REST ή gRPC, χωρίς υπογεγραμμένες Agent Cards.
