# Μόνιμη Μνήμη Agent

Οι κόμβοι Agent μπορούν να διατηρούν ένα **γράφο γνώσης ανά κόμβο** αποθηκευμένο στη βάση δεδομένων: οντότητες (με τύπους και ιδιότητες) και σχέσεις μεταξύ τους. Όταν είναι ενεργοποιημένη, το Heym **εισάγει μια σύνοψη αυτού του γράφου στο system prompt** σε κάθε εκτέλεση (εφόσον ο γράφος δεν είναι κενός). Μετά από μια επιτυχή εκτέλεση, μια **εργασία εξαγωγής LLM** συγχωνεύει νέα γεγονότα από τη συνομιλία στον γράφο στο παρασκήνιο.

Οι υπο-agents και οι orchestrators χρησιμοποιούν ο καθένας τον γράφο που είναι συνδεδεμένος με **τον δικό του κόμβο canvas** από προεπιλογή. Μπορείτε επίσης να **παραχωρήσετε σε άλλους agents πρόσβαση ανάγνωσης ή ανάγνωσης/εγγραφής** στον γράφο αυτού του κόμβου (συμπεριλαμβανομένων agents σε **άλλα workflows** που σας ανήκουν)—δείτε [Κοινή χρήση με άλλους agents](#sharing-with-other-agents).

## Ενεργοποίηση

| Παράμετρος | Τύπος | Περιγραφή |
|-----------|------|-------------|
| `persistentMemoryEnabled` | boolean | Όταν είναι `true`, φορτώνει τον γράφο αυτού του κόμβου στο system prompt και προγραμματίζει εξαγωγή μετά την εκτέλεση για τον γράφο αυτού του κόμβου |
| `memoryShares` | array (προαιρετικό) | Παραχωρεί σε άλλους κόμβους agent πρόσβαση στον γράφο μνήμης **αυτού** του κόμβου· δείτε [Κοινή χρήση](#sharing-with-other-agents) |

Ενεργοποιήστε το στις ιδιότητες του κόμβου Agent (**Persistent memory (graph)**). Ένα ροζ εικονίδιο **εγκεφάλου** στον κόμβο ανοίγει τον επεξεργαστή γράφου όταν η μνήμη είναι ενεργοποιημένη (ή όταν εμφανίζεται ένα μοντέλο).

## Επεξεργαστής γράφου

Το παράθυρο διαλόγου αποδίδει τις οντότητες ως έναν κινούμενο, force-directed γράφο — χρωματιστούς κύκλους με μέγεθος ανάλογο του αριθμού συνδέσεων και ομαδοποιημένους ανά τύπο οντότητας — μαζί με επεξεργασία και πλοήγηση (προσαρμογή προβολής, τακτοποίηση διάταξης, συντομεύσεις πληκτρολογίου). Μπορείτε να **προσθέσετε, να επεξεργαστείτε ή να διαγράψετε** κόμβους και ακμές χειροκίνητα· οι επιλογείς σχέσης Source/Target είναι αναζητήσιμοι για γράφους με πολλές οντότητες. Η επιλογή ενός κόμβου εμφανίζει τις εξερχόμενες και εισερχόμενες συνδέσεις του, καθεμία από τις οποίες είναι κλικάριμη για μετάβαση σε αυτόν τον κόμβο. Οι αλλαγές εφαρμόζονται **μόνο** στον γράφο **αυτού** του agent (τον γράφο για τον κόμβο canvas του οποίου ανοίξατε τον εγκέφαλο).

## Κοινή χρήση με άλλους agents

Στο παράθυρο διαλόγου του γράφου μνήμης, η επιλογή **Share memory with other agents** σας επιτρέπει να συνδέσετε **peers** που μπορούν να καταναλώσουν αυτόν τον γράφο κατά την εκτέλεση:

1. Επιλέξτε ένα **workflow** (οποιοδήποτε workflow μπορείτε να ανοίξετε στον επεξεργαστή).
2. Επιλέξτε έναν κόμβο **agent** σε αυτό το workflow.
3. Ορίστε **Read only** ή **Read & write**.

| Δικαίωμα | Αποτέλεσμα |
|------------|--------|
| Read only | Όταν εκτελείται ο **peer** agent, αυτός ο γράφος συγχωνεύεται στο system prompt του peer (εφόσον έχει οντότητες). Καμία εξαγωγή σε αυτόν τον γράφο από την εκτέλεση του peer. |
| Read & write | Ίδια συμπεριφορά prompt όπως στην ανάγνωση, και μετά από μια **επιτυχή** ολοκλήρωση του peer, η συνήθης εξαγωγή μνήμης μπορεί επίσης να **συγχωνεύσει σε αυτόν τον (ιδιοκτήτη) γράφο** χρησιμοποιώντας το διαπιστευτήριο της εκτέλεσης του peer. |

Οι peers αποθηκεύονται ανά κόμβο ιδιοκτήτη ως καταχωρήσεις `memoryShares` με `peerWorkflowId` και `peerCanvasNodeId` (και `permission`). Παλαιότερα workflows ενδέχεται να παραλείπουν το `peerWorkflowId` για peers στο **ίδιο** workflow· ο επεξεργαστής το θεωρεί ως το τρέχον workflow.

Η **κοινή χρήση μεταξύ workflows** επιλύεται κατά την εκτέλεση σαρώνοντας workflows **που σας ανήκουν**. Εκτελέσεις χωρίς πιστοποιημένο περιβάλλον χρήστη επιλύουν μόνο κοινές χρήσεις που ορίζονται στο JSON του **τρέχοντος** workflow (ίδιος canvas).

## Συμπεριφορά κατά την εκτέλεση

### Ίδιος γράφος (`persistentMemoryEnabled`)

1. **Πριν την κλήση LLM** — Εάν ο γράφος έχει οντότητες, ένα block προσαρτάται στις οδηγίες συστήματος που εξηγεί ότι αυτά είναι γεγονότα από προηγούμενες εκτελέσεις (μπορεί να είναι ελλιπή· το τρέχον μήνυμα χρήστη υπερισχύει σε περίπτωση σύγκρουσης).
2. **Μετά από μια επιτυχή ολοκλήρωση** — Μια εργασία παρασκηνίου ζητά από το μοντέλο (ίδιο διαπιστευτήριο με την εκτέλεση του agent) δομημένο JSON (οντότητες + σχέσεις). Αυτό το payload συγχωνεύεται στη βάση δεδομένων (εφαρμόζεται αποδιπλοποίηση και καθαρισμός σχέσεων για ορισμένους τύπους, π.χ. ακμές τύπου employment).

### Peer που λαμβάνει κοινόχρηστους γράφους

Όταν εκτελείται ένας agent, το σύστημα βρίσκει κόμβους **ιδιοκτήτη** (σε οποιοδήποτε από τα workflows σας, όταν είναι εφικτό) των οποίων τα `memoryShares` δείχνουν στο workflow και τον κόμβο canvas αυτής της εκτέλεσης. Για κάθε αντιστοίχιση, ο γράφος αυτού του ιδιοκτήτη προσαρτάται ως ενότητα **shared memory** στο system prompt. Οι peers με **Read & write** προγραμματίζουν επιπλέον στόχους εξαγωγής για το workflow/γράφο του **ιδιοκτήτη** όταν η εκτέλεση πετύχει.

Η εξαγωγή **δεν** εκτελείται όταν η εκτέλεση αποτύχει ή καταλήξει σε κατάσταση εκκρεμότητας HITL.

## Workflow JSON (πεδίο `data`)

Αποθηκεύεται στον κόμβο agent όπως οι άλλες ρυθμίσεις:

```json
{
  "type": "agent",
  "data": {
    "label": "supportAgent",
    "persistentMemoryEnabled": true,
    "userMessage": "$input.text",
    "memoryShares": [
      {
        "peerWorkflowId": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
        "peerCanvasNodeId": "agent-peer-canvas-id",
        "permission": "read"
      }
    ]
  }
}
```

Το `permission` είναι `"read"` ή `"write"`. Παραλείψτε το `memoryShares` ή χρησιμοποιήστε `[]` όταν δεν υπάρχει κοινή χρήση.

Δείτε το [Workflow Structure](./workflow-structure.md) για την πλήρη μορφή του αντικειμένου κόμβου.
