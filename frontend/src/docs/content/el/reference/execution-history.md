# Ιστορικό Εκτελέσεων

Το ιστορικό εκτελέσεων καταγράφει τις εκτελέσεις workflow: εισόδους, εξόδους, αποτελέσματα κόμβων, κατάσταση και πηγή trigger. Χρησιμοποιήστε το για να παρακολουθείτε μια ενεργή εκτέλεση παραγωγής, να εξετάζετε προηγούμενες εκτελέσεις, να εντοπίζετε σφάλματα ή να επανεκτελείτε με τις ίδιες εισόδους μέσω **Bring to Canvas**.

## Επισκόπηση

Κάθε εκτέλεση αποθηκεύει:

| Πεδίο | Περιγραφή |
|-------|-------------|
| **Inputs** | Σώμα αιτήματος ή είσοδοι εκτέλεσης (π.χ. `text` για Input node) |
| **Outputs** | Έξοδοι σε επίπεδο workflow |
| **Node results** | Έξοδοι ανά κόμβο, κατάσταση και χρόνος εκτέλεσης |
| **Status** | `success`, `error`, `pending`, `skipped` ή `failed` (βλ. [Crash Recovery](#crash-recovery)) |
| **trigger_source** | Πώς ενεργοποιήθηκε η εκτέλεση (βλ. [Triggers](./triggers.md)) |

## Πρόσβαση στο Ιστορικό

| Τοποθεσία | Εύρος |
|----------|-------|
| Γραμμή εργαλείων **Editor** | Μόνο το τρέχον workflow |
| Κεφαλίδα προβολής **Docs** | Μόνο το τρέχον workflow |
| Κεφαλίδα **Dashboard** (καρτέλα Chat) | Όλα τα workflows + εκτελέσεις chat/assistant |
| Κεφαλίδα προβολής **Evals** | Όλα τα workflows + εκτελέσεις chat/assistant |

Κάντε κλικ στο κουμπί **History** (εικονίδιο ρολογιού) για να ανοίξετε το παράθυρο διαλόγου.

## Ιστορικό ανά workflow vs Όλο το Ιστορικό

- **Ανά workflow** (Editor, Docs): Εμφανίζει εκτελέσεις για το workflow που έχετε ανοιχτό. Χρησιμοποιήστε το **Clear history** για να αφαιρέσετε εκτελέσεις μόνο για αυτό το workflow.
- **Όλο το Ιστορικό** (Dashboard, Evals): Εμφανίζει εκτελέσεις από όλα τα workflows και τις συνεδρίες chat/assistant. Η κάλυψη αντιστοιχεί στην πρόσβαση workflow: workflows που σας ανήκουν, workflows που κοινοποιούνται απευθείας σε εσάς και workflows που κοινοποιούνται σε μια ομάδα στην οποία ανήκετε. Χρησιμοποιήστε το **Clear all history** για να αφαιρέσετε όλες τις εγγραφές που σας ανήκουν. Το ιστορικό για κοινόχρηστα workflows θα διατηρηθεί.

## Bring to Canvas

Το **Bring to Canvas** φορτώνει τις εισόδους και τις εξόδους κόμβων μιας επιλεγμένης εκτέλεσης στο τρέχον workflow.

### Τι φορτώνει

- **Inputs** → Πίνακας εισόδου εκτέλεσης (π.χ. `text` για Input node ή προσαρμοσμένα πεδία)
- **Node results** → Ο πίνακας αποτελεσμάτων εκτέλεσης εμφανίζει προηγούμενες εξόδους ανά κόμβο
- **Execution result** → Κατάσταση, έξοδοι και χρονισμός από την εκτέλεση

### Συμπεριφορά ανά περιβάλλον

- **Στον Editor** (ιστορικό ανά workflow): Εφαρμόζεται αμέσως στο ανοιχτό workflow και κλείνει το παράθυρο διαλόγου.
- **Από το Όλο το Ιστορικό** (Dashboard/Evals): Μεταβαίνει στον editor του workflow και στη συνέχεια εφαρμόζει τα δεδομένα όταν φορτωθεί ο editor. Διατίθεται μόνο για εκτελέσεις workflow—όχι για εκτελέσεις chat/assistant.

### Deep link εκτέλεσης

Το άνοιγμα ενός workflow στο `/workflows/{workflowId}/{executionId}` φέρνει αυτόματα αυτήν την εκτέλεση στον καμβά — το ίδιο όπως επιλέγοντας την εκτέλεση και επιλέγοντας **Bring to Canvas**. Αυτό καθιστά μια συγκεκριμένη προηγούμενη εκτέλεση κοινοποιήσιμη ως URL. Εάν η εκτέλεση δεν μπορεί να βρεθεί (λάθος ή διαγραμμένο id), ο editor επιστρέφει στη φόρτωση του απλού workflow.

### Περιπτώσεις χρήσης

- Επανεκτέλεση ενός workflow με τις ίδιες εισόδους
- Εντοπισμός σφάλματος σε μια αποτυχημένη εκτέλεση εξετάζοντας τις εισόδους και τις εξόδους κόμβων
- Σύγκριση εξόδων μεταξύ εκτελέσεων

## Ρωτήστε το AI

Και τα δύο παράθυρα διαλόγου ιστορικού διαθέτουν ένα κουμπί **Ρωτήστε το AI** (εικονίδιο σπινθήρα) δίπλα στον τίτλο τους. Ανοίγει την [καρτέλα Chat](../tabs/chat-tab.md#asking-about-a-run) σε μια νέα συνομιλία με το workflow και την επιλεγμένη εκτέλεση προσαρτημένα ως αφαιρούμενα τσιπ. Ρωτήστε γιατί η εκτέλεση ήταν αργή, τι απέτυχε ή ζητήστε από το Chat να διορθώσει το workflow. Το Chat διαβάζει ακριβώς αυτήν την εκτέλεση, συμπεριλαμβανομένης της ανίχνευσης ανά κόμβο και των σφαλμάτων.

Στο παράθυρο διαλόγου All History, το **Ρωτήστε το AI** εμφανίζεται μόνο όταν είναι επιλεγμένη μια εκτέλεση workflow· οι εκτελέσεις chat και βοηθού δεν το εμφανίζουν.

## Χρονολόγιο εκτέλεσης

Στις λεπτομέρειες της εκτέλεσης, το κουμπί **Χρονολόγιο** (εικονίδιο χρονομέτρου) δίπλα στο **Ανάπτυξη όλων** αντικαθιστά τη λίστα **Βήματα** με ένα χρονολόγιο διαστημάτων (spans). Ενώ εμφανίζεται το χρονολόγιο, το ίδιο κουμπί αναγράφει **Καταγραφές**· κάντε κλικ σε αυτό για να επιστρέψετε στη λίστα. Στο All History το κουμπί εμφανίζεται μόνο για εκτελέσεις workflow. Το χρονολόγιο σχεδιάζει μια γραμμή ανά κόμβο κατά τη στιγμή εκκίνησής του, ώστε να βλέπετε ποιος κόμβος πόση ώρα διήρκεσε και ποιοι εκτελέστηκαν παράλληλα. Τοποθετήστε τον δείκτη πάνω από μια γραμμή για τη διάρκειά της· κάντε κλικ σε αυτήν για να ανοίξετε τον ίδιο επιθεωρητή λεπτομερειών με το [χρονολόγιο εκτέλεσης](#execution-timeline-details) του επεξεργαστή. Η επιλεγμένη προβολή παραμένει όσο το παράθυρο διαλόγου είναι ανοιχτό.

Οι εκτελέσεις που καταγράφηκαν πριν από την αποθήκευση των χρόνων έναρξης των κόμβων διατάσσονται διαδοχικά κατά διάρκεια.

## Execution Highlights

Μετά από μια ζωντανή εκτέλεση — ή μετά το **Bring to Canvas** — εμφανίζεται ένα αναδιπλούμενο αναδυόμενο παράθυρο **Execution Highlights** στο **πάνω δεξιά μέρος του Καμβά**. Είναι ένας γρήγορος τρόπος να δείτε *τι παρήγαγε κάθε κόμβος*, παρατιθέμενο από πάνω προς τα κάτω με σειρά εκτέλεσης. Κλείστε το με το **✕**· ανοίγει ξανά στην επόμενη εκτέλεση.

### Τι εμφανίζεται

| Εγγραφή | Πηγή | Αυτόματο; |
|--------|--------|-------|
| **Input** | Οι παράμετροι εισόδου της εκτέλεσης (input/trigger node) | Ναι |
| **Output** | Το αποτέλεσμα του output node — ή, αν δεν υπάρχει, το μήνυμα του τελευταίου κόμβου | Ναι |
| **Agent / LLM** | Η έξοδος κάθε agent ή LLM node | Ναι |
| **Output** | Οποιοσδήποτε άλλος κόμβος με ενεργοποιημένο το **Highlight Node Output** | Προαιρετικό |

Κόμβοι που είναι ήδη αυτόματα επισημασμένοι (input / output / last / agent / llm) δεν εμφανίζονται ποτέ δύο φορές, ακόμη και αν ενεργοποιήσετε επίσης τον διακόπτη.

### Κάθε εγγραφή

- Εμφανίζει `Node — message…` με τους πρώτους **250 χαρακτήρες**· κάντε κλικ σε μια γραμμή για να την αναπτύξετε και να αποδώσετε το **πλήρες μήνυμα ως Markdown**, με κουμπί **Copy**.
- Ένας κόμβος που εκτελέστηκε πολλές φορές (π.χ. μέσα σε ένα loop) εμφανίζει `Node (N)` με επιλογέα `‹ i / N ›` — επιλέξτε ποια εκτέλεση να δείτε· ο επιλογέας κάθε κόμβου είναι ανεξάρτητος.

### Highlight Node Output

Κάθε κόμβος **εκτός από Agent και LLM** έχει ένα πλαίσιο ελέγχου **Highlight Node Output** στον πίνακα ιδιοτήτων του (προεπιλογή ανενεργό). Ενεργοποιήστε το για να προσθέσετε την έξοδο αυτού του κόμβου στο αναδυόμενο παράθυρο. Ένα μικρό σήμα ✦ εμφανίζεται στους επισημασμένους κόμβους στον καμβά. Στο [workflow DSL](./expression-dsl.md) αυτό είναι το πεδίο node-data `"highlight": true` (προεπιλογή `false`).

### Στους πίνακες ελέγχου

Οι κάρτες widget του Dashboard που εκτέλεσαν ένα workflow εμφανίζουν ένα κουμπί ✦ **Execution highlights** στην κεφαλίδα της κάρτας· κάντε κλικ σε αυτό για να ανοίξετε το ίδιο αναδυόμενο παράθυρο για την εκτέλεση αυτού του widget, με την σχεδιασμένη έξοδο του widget ως την κύρια εγγραφή.
## Εκτέλεση Εκτελέσεων

Και τα δύο παράθυρα διαλόγου ιστορικού εμφανίζουν τις **εκτελέσεις που βρίσκονται σε εξέλιξη** στην κορυφή της λίστας, πριν από τις προηγούμενες εκτελέσεις.

- Ένας περιστρεφόμενος δείκτης και η ετικέτα **Running** εμφανίζονται μαζί με την ώρα έναρξης
- Κάντε κλικ στο **Open live** για να συνδέσετε τον editor με αυτήν ακριβώς την εκτέλεση χωρίς επανεκκίνηση
- Ο καμβάς πρώτα επαναφέρει τους κόμβους που έχουν ήδη ολοκληρωθεί και έπειτα λαμβάνει
  `node_start`, `node_complete` και τελικά events εκτέλεσης μέσω SSE
- Ο τρέχων κόμβος πάλλεται στον καμβά, οι επόμενοι κόμβοι διατηρούν το animation εκκρεμότητας και
  το Debug panel προσθέτει κάθε αποτέλεσμα καθώς φτάνει—ακριβώς όπως μια εκτέλεση που ξεκίνησε από τον editor
- Κάντε κλικ στο **Cancel** για να σταματήσετε αμέσως την εκτέλεση
- Η ακύρωση από οποιοδήποτε παράθυρο διαλόγου (Editor ή Dashboard) κλείνει επίσης το ενεργό SSE stream σε οποιαδήποτε ανοιχτή καρτέλα καμβά για αυτό το workflow, ώστε η κατάσταση του editor να επαναφέρεται καθαρά
- Μετά την ακύρωση, η καταχώριση εκτέλεσης εξαφανίζεται στην επόμενη ανανέωση· πατήστε **Refresh** για να ενημερώσετε τη λίστα χειροκίνητα
- Εάν ακυρώσετε μια εκτέλεση που έχει ήδη ολοκληρωθεί, το αίτημα είναι no-op

Το live URL είναι `/workflows/{workflowId}/{executionId}`. Ο observer είναι read-only: η αποχώρηση
από τον editor αποσυνδέει μόνο αυτήν την καρτέλα του browser και δεν σταματά ποτέ το workflow. Τα ενεργά snapshots
κοινοποιούνται μέσω PostgreSQL, οπότε το άνοιγμα μιας εκτέλεσης λειτουργεί ακόμα και όταν το trigger και το αίτημα του editor
καταλήγουν σε διαφορετικούς backend workers.

## Ανάκτηση μετά από Crash

Εάν ο server επανεκκινηθεί (deploy, επανεκκίνηση container ή crash) ενώ εκτελείται ένα workflow, ο worker αυτής της εκτέλεσης σταματά στα μέσα της εκτέλεσης. Το Heym ανακτά αυτόματα αυτές τις διακοπείσες εκτελέσεις αντί να τις αφήνει κολλημένες ως **Running**.

- Στην επόμενη εκκίνηση, η εκλεγμένη leader διεργασία εντοπίζει ορφανές εκτελέσεις — άμεσα για ομαλή επανεκκίνηση ή εντός ~60 δευτερολέπτων για σκληρό crash (μόλις σταματήσουν ξεκάθαρα τα heartbeats).
- Οι ανακτημένες εκτελέσεις **επανεκτελούνται από την αρχή με τα ίδια inputs** (δεν συνεχίζονται από το σημείο που σταμάτησαν), χρησιμοποιώντας τον τρέχοντα ορισμό του workflow. Κατά την ολοκλήρωση καταγράφουν μια κανονική τελική καταχώριση (π.χ. `success`), ώστε το ιστορικό να εμφανίζει την εκτέλεση ως ολοκληρωμένη.
- Μια εκτέλεση επαναλαμβάνεται **μία φορά**. Εάν η προσπάθεια ανάκτησης διακοπεί επίσης — ή το workflow έχει στο μεταξύ διαγραφεί — η καταχώριση καταγράφεται ως `failed`.
- Αυτό λειτουργεί με τον ίδιο τρόπο σε single container και σε multi-worker deployments· μόνο ο leader εκτελεί ανάκτηση, οπότε μια εκτέλεση δεν ανακτάται ποτέ δύο φορές από διαφορετικούς workers.

### Διακόπτης Auto-recover

Το **Execution Log** (run) panel του editor διαθέτει ένα checkbox **Auto-recover**, **ενεργό από προεπιλογή** ανά workflow.

- **On**: οι διακοπείσες εκτελέσεις αυτού του workflow επανεκτελούνται όπως περιγράφεται παραπάνω.
- **Off**: οι διακοπείσες εκτελέσεις δεν επανεκτελούνται και καταγράφονται με κατάσταση `skipped`.

> Οι εκτελέσεις sub-workflow δεν ανακτώνται ανεξάρτητα — καθοδηγούνται εκ νέου από τη ανακτημένη γονική εκτέλεση. Triggers με δική τους redelivery (RabbitMQ, scheduled/cron, IMAP) μπορεί επίσης να κάνουν redeliver κατά την επανεκκίνηση, οπότε μια ανακτημένη εκτέλεση μπορεί περιστασιακά να εκτελεστεί δύο φορές.

## Εκκρεμής Ανθρώπινη Αξιολόγηση

Οι εκτελέσεις που παύουν για έγκριση [Human-in-the-Loop](./human-in-the-loop.md) εγγράφονται αμέσως στο ιστορικό με κατάσταση `pending`.

- Ο pending agent node αποθηκεύει ένα review payload που περιλαμβάνει `reviewUrl`, `draftText` και `expiresAt`
- Οποιοιδήποτε κόμβοι είναι συνδεδεμένοι στο `review` handle του agent μπορούν επίσης να εκτελεστούν πριν απαντήσει ο άνθρωπος, και τα αποτελέσματά τους αποθηκεύονται στην ίδια pending καταχώριση ιστορικού
- Τα παράθυρα διαλόγου ιστορικού εμφανίζουν τον σύνδεσμο αξιολόγησης ώστε οι κάτοχοι να μπορούν να τον αντιγράψουν ή να τον ανοίξουν
- Τα παράθυρα διαλόγου ιστορικού και το Debug panel του editor εμφανίζουν την τελική ανθρώπινη απόφαση αφού συνεχιστεί η εκτέλεση
- Όταν ένας αξιολογητής αποδεχτεί, επεξεργαστεί ή απορρίψει το draft, η ίδια καταχώριση ιστορικού ενημερώνεται με το τελικό αποτέλεσμα εκτέλεσης
- Εάν η ίδια εκτέλεση παύσει για HITL περισσότερες από μία φορές, η καταχώριση ιστορικού παραμένει ίδια ενώ κάθε checkpoint αποκτά τον δικό του one-time σύνδεσμο αξιολόγησης

Αυτό είναι ιδιαίτερα χρήσιμο για εκτελέσεις portal και μακρόβια workflows που μπορεί να περιμένουν ώρες ή ημέρες πριν συνεχίσουν.

## Αντιγραφή

Χρησιμοποιήστε το **Copy** δίπλα στα Inputs ή Outputs για να αντιγράψετε το JSON στο πρόχειρο.

## Εκκαθάριση Ιστορικού

- **Ανά workflow**: Στο παράθυρο διαλόγου ιστορικού του Editor, κάντε κλικ στο **Clear history** για να αφαιρέσετε τις εκτελέσεις του τρέχοντος workflow.
- **Όλο το Ιστορικό**: Στο παράθυρο διαλόγου ιστορικού του Dashboard/Evals, κάντε κλικ στο **Clear all history** για να αφαιρέσετε όλες τις εγγραφές εκτελέσεων που σας ανήκουν. Οι εκτελέσεις από κοινόχρηστα workflows διατηρούνται. Αυτή η ενέργεια δεν μπορεί να αναιρεθεί.

## Λεπτομέρειες χρονολογίου εκτέλεσης

Όταν το **Execution Log** του editor είναι ανοιχτό, κάντε κλικ στο κουμπί χρονομέτρου για να εμφανίσετε το χρονολόγιο εκτέλεσης. Επιλέξτε ένα span για να ανοίξετε έναν ενσωματωμένο επιθεωρητή λεπτομερειών που καταλαμβάνει την περιοχή των γραμμών. Εμφανίζει την κατάσταση του επιλεγμένου βήματος, τη διάρκεια, τον αριθμό προσπαθειών, πληροφορίες επανάληψης, σφάλματα, trace ID και μια συμπαγή προεπισκόπηση εξόδου. Οι έξοδοι αντικειμένων και πινάκων χρησιμοποιούν τον ίδιο viewer `JsonTree` όπως και το υπόλοιπο Debug panel· οι βαθμωτές τιμές χρησιμοποιούν προεπισκόπηση κειμένου. Όταν ένα βήμα παράγει εικόνες (στιγμιότυπα οθόνης Playwright, παραγόμενες εικόνες, αρχεία εικόνων ή εικόνες base64 στο σώμα του αιτήματος, που βρίσκονται οπουδήποτε στην έξοδο), εμφανίζονται ως μικρογραφίες πάνω από την έξοδο και το JSON εμφανίζει ένα σύντομο placeholder στη θέση του ακατέργαστου base64. Κάντε κλικ σε μια μικρογραφία για να την ανοίξετε σε lightbox· τα κουμπιά βελών ή τα πλήκτρα ←/→ περιηγούνται σε κάθε εικόνα της εκτέλεσης, με μετρητή όπως `2 / 5`. Χρησιμοποιήστε το **Open trace** για spans LLM και Agent όταν υπάρχει διαθέσιμο trace ID.
## Λεπτομέρειες node σε κινητή συσκευή

Σε ένα τηλέφωνο, ο editor εμφανίζει ένα δέντρο workflow πλήρους οθόνης αντί για τον ελεύθερο καμβά. Πατήστε έναν node του δέντρου με καταγεγραμμένο αποτέλεσμα για να ανοίξετε την εκτέλεσή του ως λεπτομέρεια πλήρους οθόνης. Η προβολή παρέχει ξεχωριστές καρτέλες **Input Data**, **Output Data** και **Errors**. Η καρτέλα output εμφανίζει το καταγεγραμμένο αποτέλεσμα και προσφέρει **Copy Output**· η καρτέλα input εμφανίζει τη διαμόρφωση του επιλεγμένου node, και η καρτέλα errors εμφανίζει το καταγεγραμμένο σφάλμα όταν ο node απέτυχε. Χρησιμοποιήστε το **Back to workflow** ή το κουμπί κλεισίματος για να επιστρέψετε στο δέντρο.

Ο καμβάς και τα παράθυρα διαλόγου ιστορικού του dashboard διατηρούν τα χειριστήρια εκτέλεσης σε μία σειρά και τοποθετούν τα διαθέσιμα φίλτρα tag και instance σε ένα responsive grid. Τα μενού φίλτρων τους χρησιμοποιούν τον ίδιο in-app selector, ώστε το επιλεγμένο σημάδι ελέγχου να έχει συνεπές περιθώριο και γραμμή βάσης με κάθε ετικέτα επιλογής.
