# Human-in-the-Loop

Το Human-in-the-loop (HITL) επιτρέπει σε έναν [Agent Node](../nodes/agent-node.md) να ζητά έγκριση σε συγκεκριμένες στιγμές, να αναμένει την απόφαση ενός ανθρώπου και στη συνέχεια να συνεχίζει το workflow από το ίδιο στιγμιότυπο εκτέλεσης.

## Τι Κάνει

- Προσθέτει ρητά σημεία ελέγχου έγκρισης σε έναν agent χωρίς τη δημιουργία ξεχωριστού workflow έγκρισης
- Δημιουργεί έναν μοναδικό δημόσιο σύνδεσμο αξιολόγησης στη διεύθυνση `/review/{token}`
- Επιτρέπει σε έναν αξιολογητή να επιλέξει `Accept`, `Edit & Continue` ή `Refuse`
- Σημειώνει την εκτέλεση ως `pending` μέχρι να φτάσει μια απόφαση
- Συνεχίζει τη σε παύση εκτέλεση και επιτρέπει στον agent να προχωρήσει μετά την έγκριση
- Υποστηρίζει πολλαπλά διαδοχικά σημεία ελέγχου HITL στην ίδια εκτέλεση agent

## Διαμόρφωση Agent

Ενεργοποιήστε το HITL στον πίνακα ιδιοτήτων του agent.

| Ρύθμιση | Περιγραφή |
|---------|-------------|
| `hitlEnabled` | Ενεργοποιεί την ανθρώπινη αξιολόγηση για αυτόν τον agent |
| `hitlSummary` | Κατευθυντήριες γραμμές έγκρισης για το πότε ο agent πρέπει να ζητά ανθρώπινη αξιολόγηση |

Το HITL προσθέτει ένα εργαλείο `request_human_review` στον agent. Χρησιμοποιήστε το system prompt και τις κατευθυντήριες γραμμές `hitlSummary` για να υποδείξετε στον agent ποιες ενέργειες χρειάζονται έγκριση. Όταν ο agent κρίνει ότι ένα σημείο ελέγχου χρειάζεται αξιολόγηση, στέλνει ένα μόνο κείμενο αξιολόγησης Markdown στον άνθρωπο. Η σύνοψη που βλέπει ο αξιολογητής δημιουργείται από το αίτημα του agent κατά τον χρόνο εκτέλεσης· αν ο agent την παραλείψει, το Heym παράγει μία από το σώμα Markdown. Στην v1, το HITL υποστηρίζει μόνο εξόδους agent σε λειτουργία κειμένου, επομένως δεν μπορεί να συνδυαστεί με το `jsonOutputEnabled`.

Για εργαλεία MCP, το Heym ζητά από το μοντέλο να ερμηνεύσει τις γραπτές οδηγίες HITL σε μία από τρεις περιοχές έγκρισης:

- `always` για φράσεις όπως "always", "on each" ή "for each"
- `once` για φράσεις όπως "once" ή "only one time"
- `never` για φράσεις όπως "never", "do not ask" ή "already approved"

Αυτή η ερμηνεία ελέγχει αν οι επαναλαμβανόμενες κλήσεις MCP θα σταματούν ξανά, θα παραμένουν εγκεκριμένες μία φορά ή θα παραλείπουν εντελώς την ανθρώπινη αξιολόγηση.

Όταν το HITL είναι ενεργοποιημένο, ο agent εκθέτει επίσης μια δεύτερη λαβή εξόδου στον καμβά με την ετικέτα `review`. Χρησιμοποιήστε αυτόν τον κλάδο για να στέλνετε το URL και τη σύνοψη της εκκρεμούς αξιολόγησης στο Slack, σε email, σε καταγραφή ή σε οποιαδήποτε άλλη ροή ειδοποιήσεων, ενώ η κύρια εκτέλεση αναμένει ένα άτομο.

## Ροή Αξιολόγησης

1. Ο agent φτάνει σε ένα βήμα που απαιτεί έγκριση και καλεί το `request_human_review`
2. Το Heym δημιουργεί ένα δημόσιο αίτημα αξιολόγησης και επιστρέφει ένα URL αξιολόγησης
3. Οποιοιδήποτε κόμβοι είναι συνδεδεμένοι στη λαβή `review` του agent εκτελούνται αμέσως με το εκκρεμές payload HITL
4. Η εκτέλεση του workflow μεταβαίνει σε `pending`
5. Ένας αξιολογητής ανοίγει το `/review/{token}` χωρίς σύνδεση
6. Ο αξιολογητής επιλέγει μία ενέργεια:
   - `Accept` συνεχίζει με το αρχικό Markdown
   - `Edit & Continue` συνεχίζει με το επεξεργασμένο Markdown
   - `Refuse` συνεχίζει με `decision: "refused"` και παραλείπει περαιτέρω ενέργεια του agent
7. Το Heym συνεχίζει το workflow από το αποθηκευμένο στιγμιότυπο και επιτρέπει στον agent να προχωρήσει με το εγκεκριμένο περιεχόμενο Markdown
8. Αν ένα μεταγενέστερο βήμα απαιτεί επίσης έγκριση, ο agent μπορεί να καλέσει ξανά το HITL και να δημιουργήσει άλλο εκκρεμές σημείο ελέγχου

Οι σύνδεσμοι αξιολόγησης λήγουν μετά από 168 ώρες αν δεν ανταποκριθεί κανείς.

## Δημόσια Σελίδα Αξιολόγησης

Η δημόσια σελίδα αξιολόγησης εμφανίζει:

- Το όνομα του workflow και την ετικέτα του agent
- Μια αυτόματα παραγόμενη σύνοψη αξιολογητή από το αίτημα αξιολόγησης του agent
- Το κείμενο αξιολόγησης Markdown πρώτα, ως κύριο περιεχόμενο
- Ένα πλαίσιο επεξεργασίας που ανοίγει μόνο αφού ο αξιολογητής κάνει κλικ στο `Edit`
- Μια ζωντανή προεπισκόπηση Markdown κατά την επεξεργασία
- Κουμπιά ενεργειών για `Accept`, `Edit & Continue` και `Refuse`

Μόλις υποβληθεί μια απόφαση, το token κλειδώνεται και δεν μπορεί να χρησιμοποιηθεί ξανά.

## Έξοδοι και Κατάσταση Εκτέλεσης

Ενώ αναμένεται αξιολόγηση, η έξοδος του agent περιέχει ένα εκκρεμές payload:

```json
{
  "decision": null,
  "summary": "Review the customer-ready reply before it is sent.",
  "draftText": "# Goal\n...\n\n# Planned Tool Calls / Actions\n- ...",
  "reviewUrl": "https://example.com/review/abc123",
  "requestId": "uuid",
  "expiresAt": "2026-03-29T10:00:00Z",
  "shareMarkdown": "Review the customer-ready reply before it is sent.\n\n[Open review page](https://example.com/review/abc123)"
}
```

Αφού ο αξιολογητής απαντήσει και το workflow συνεχιστεί, η τελική έξοδος του agent περιλαμβάνει τα μεταδεδομένα της απόφασης:

```json
{
  "text": "Final agent output after approval and execution",
  "decision": "accepted",
  "summary": "Review the customer-ready reply before it is sent.",
  "originalDraft": "# Goal\n...\n\n# Planned Tool Calls / Actions\n- ...",
  "requestId": "uuid"
}
```

Χρησιμοποιήστε το `$agentLabel.decision` σε μεταγενέστερους κόμβους για διακλάδωση σε αποτελέσματα accepted, edited ή refused.

## Κλάδος Αξιολόγησης στον Καμβά

Η λαβή εξόδου `review` είναι διαθέσιμη μόνο όταν το `hitlEnabled` είναι ενεργοποιημένο για έναν agent.

- Εκτελείται πριν φτάσει η ανθρώπινη απόφαση
- Λαμβάνει το εκκρεμές payload HITL, συμπεριλαμβανομένων των `summary`, `draftText`, `reviewUrl`, `shareText` και `shareMarkdown`
- Προορίζεται για βήματα ειδοποίησης ή παράδοσης, όπως Slack, email ή καταγραφή ελέγχου
- Εκτελείται μία φορά για κάθε σημείο ελέγχου HITL
- Δεν εκτελείται ξανά αφού απαντήσει ο αξιολογητής· μόνο η κανονική διαδρομή εξόδου του agent συνεχίζεται κατά τη συνέχιση
## Πού εμφανίζεται

- Το [Ιστορικό εκτελέσεων](./execution-history.md) εμφανίζει αμέσως τις εκτελέσεις με κατάσταση `pending` και αποθηκεύει το URL αξιολόγησης στα αποτελέσματα του node
- Οι απαντήσεις του chat στο [Portal](./portal.md) εμφανίζουν τον σύνδεσμο ανθρώπινης αξιολόγησης αντί για κενή απάντηση
- Ο πίνακας Debug και τα παράθυρα διαλόγου ιστορικού εμφανίζουν την τελική απόφαση HITL και το κείμενο που αξιολογήθηκε
- Το output handle της αξιολόγησης μπορεί να ειδοποιήσει εξωτερικά κανάλια ακόμη και όταν το workflow ενεργοποιήθηκε από cron, curl ή κίνηση από το portal
- Πολλαπλά σημεία ελέγχου HITL επαναχρησιμοποιούν την ίδια καταχώριση ιστορικού εκτέλεσης, δημιουργώντας παράλληλα έναν νέο σύνδεσμο αξιολόγησης μίας χρήσης για κάθε παύση

## Τρέχοντες περιορισμοί

- Το HITL είναι διαθέσιμο μόνο σε Agent nodes
- Το HITL χρησιμοποιεί την έξοδο κειμένου του agent και δεν υποστηρίζει έξοδο JSON στην έκδοση v1
- Μια σε παύση εκτέλεση συνεχίζεται από το αποθηκευμένο snapshot του workflow, όχι από την τελευταία επεξεργασμένη έκδοση του workflow
- Τα ένθετα sub-workflows δεν μπορούν να εισέλθουν σε κατάσταση εκκρεμούς HITL στην έκδοση v1· ζητήστε αξιολόγηση από τον γονικό agent πριν τα καλέσετε
