# Heym Incident Playbook (L0)

Χρησιμοποιήστε αυτό το playbook για να επιβεβαιώσετε ένα περιστατικό στο Heym, να εκτιμήσετε τον αντίκτυπο στους χρήστες, να επιλέξετε τη σοβαρότητα (severity) και να απευθυνθείτε στη σωστή διαδικασία αποκατάστασης και στον αρμόδιο υπεύθυνο.

Αναλυτικές διαδικασίες: [Heym Runbook (L1)](./operations-runbook.md)

Τελευταία αναθεώρηση: 2026-11-10. Πεδίο εφαρμογής: self-hosted Heym, μεμονωμένη παρουσία ή cluster, σε Docker Compose ή Kubernetes.

## Παράδοση ανάπτυξης (Deployment handover)

Συμπληρώστε αυτόν τον πίνακα για κάθε περιβάλλον προτού χρησιμοποιήσετε αυτά τα έγγραφα κατά την επιφυλακή (on-call). Τα ονόματα, τα URL, οι στόχοι χωρητικότητας και οι στόχοι ανάκτησης αφορούν τη συγκεκριμένη ανάπτυξη. Τα παραδείγματα του αποθετηρίου δεν αποτελούν κατάλογο παραγωγής.

| Στοιχείο | Τιμή στην ανάπτυξη |
| --- | --- |
| Περιβάλλον και δημόσιο URL του Heym | `<environment>`, `<public-url>` |
| Επιφυλακή πλατφόρμας και αναπληρωτής | `<rotation-or-contact>`, `<backup-contact>` |
| Κανάλι περιστατικού και σύστημα καταγραφής περιστατικών | `<channel>`, `<tracker-url>` |
| Επιφυλακή βάσης δεδομένων και αναγνωριστικό βάσης | `<contact>`, `<database-id>` |
| Υπεύθυνοι υποδομής, δικτύωσης και αποθήκευσης | `<contacts>` |
| Υπεύθυνος έκδοσης και σύστημα ανάπτυξης | `<contact>`, `<deployment-url>` |
| Πίνακας ελέγχου σφαλμάτων εφαρμογής, καθυστέρησης και διαθεσιμότητας | `<dashboard-url>` |
| Πίνακας ελέγχου CPU, μνήμης, δίσκου και επανεκκινήσεων κεντρικού υπολογιστή ή pod | `<dashboard-url>` |
| Πίνακας ελέγχου συνδέσεων, κλειδωμάτων, δίσκου και αναπαραγωγής PostgreSQL | `<dashboard-url>` |
| Αρχεία καταγραφής και προαιρετικό σύστημα ανίχνευσης OTel | `<logs-url>`, `<trace-url-or-disabled>` |
| Έργο/αρχεία Compose ή περιβάλλον/namespace Kubernetes | `<exact-target>` |
| Τοποθεσίες main, workers, βάσης δεδομένων και αποθήκευσης | `<services-or-deployments>`, `<storage-ids>` |
| Εγκεκριμένο workflow δοκιμής (smoke) και αναμενόμενο αποτέλεσμα | `<workflow-id>`, `<safe-input>`, `<expected-result>` |
| Διαδικασία αντιγράφων ασφαλείας βάσης και αρχείων, τελευταία δοκιμή επαναφοράς | `<procedure-url>`, `<test-date>` |
| Στόχοι χρόνου αποκατάστασης (RTO) και σημείου αποκατάστασης (RPO) | `<RTO>`, `<RPO>` |

Διατηρήστε τις επαφές και τους συνδέσμους των πινάκων ελέγχου στο περιορισμένης πρόσβασης επιχειρησιακό αντίγραφο της ανάπτυξης. Τα αποδεικτικά στοιχεία πρέπει να περιέχουν αναγνωριστικά, χρονοσφραγίδες, μετρήσεις και απαλειμμένα σφάλματα αντί για credentials ή payloads των workflows.

## Απογραφή πλατφόρμας

| Στοιχείο | Ευθύνη | Επίπτωση σε περιστατικό |
| --- | --- | --- |
| Frontend και κύριο backend (main) | UI, API, MCP, Portal, διαδραστική εκτέλεση | Ελέγξτε ξεχωριστά τη δημόσια διαδρομή και την κύρια διεργασία |
| PostgreSQL | Κατάσταση εφαρμογής, μητρώο εκτελέσεων, ουρά εκτέλεσης, θέσεις ταυτοχρονισμού, συντονισμός και ειδοποιήσεις | Μια διακοπή της βάσης δεδομένων μπορεί να σταματήσει τόσο την εξυπηρέτηση αιτημάτων όσο και την εκτέλεση στο παρασκήνιο |
| Παρουσίες worker, όταν είναι ενεργή η λειτουργία cluster | Επιλέξιμες εκτελέσεις παρασκηνίου σε ουρά | Οι υγιείς workers δεν αντικαθιστούν τα δημόσια endpoints της κύριας παρουσίας (main) |
| Εκλεγμένη διεργασία ηγέτη (leader) | Cron, αξιολόγηση ειδοποιήσεων, συντονισμός παρασκηνίου | Ένας συμβατός worker μπορεί να γίνει ηγέτης. Αυτό δεν αλλάζει τον ρόλο του σε main |
| Μόνιμος χώρος αποθήκευσης της main | Αρχεία Drive, εγκατεστημένα πρόσθετα και χώροι εργασίας πρακτόρων κώδικα | Επαναφέρετε τον χώρο αποθήκευσης μαζί με τη main. Η δρομολόγηση ingress σε έναν worker δεν τον επαναφέρει |
| Backend sandbox σε κάθε εκτελεστική παρουσία | Containers Docker ή pods Kubernetes για απομονωμένη εκτέλεση | Ένα προβληματικό backend sandbox μπορεί να επηρεάσει επιλεγμένους κόμβους ενώ το UI λειτουργεί |
| Εξαρτήσεις workflow | Πάροχοι μοντέλων, διακομιστές MCP, εξωτερικά API, αποθήκες δεδομένων και υπηρεσίες μηνυμάτων | Προσδιορίστε εάν αποτυγχάνει μια μεμονωμένη εξάρτηση ή ολόκληρη η πλατφόρμα |
| Προαιρετικός συλλέκτης OTel | Εξαγόμενα spans workflow, κόμβων και εργαλείων Agent | Η έλλειψη εξαγόμενων ανιχνεύσεων από μόνη της δεν αποδεικνύει αποτυχία εκτέλεσης |

Η ενσωματωμένη ουρά εκτελέσεων του Heym χρησιμοποιεί PostgreSQL. Το Redis, το RabbitMQ και οι χώροι αποθήκευσης διανυσμάτων μπορεί να αποτελούν εξαρτήσεις workflow. Δεν είναι υποχρεωτικές υπηρεσίες για την ενσωματωμένη ουρά.

Το `GET /api/health` αναφέρει μόνο την υγεία της διεργασίας και την έκδοση. Δεν ελέγχει την PostgreSQL, την ουρά, την εκλογή ηγέτη, τη χωρητικότητα των sandbox ή τον συγχρονισμό credentials. Μια θετική απάντηση είναι ένας μεμονωμένος έλεγχος, όχι εγγύηση συνολικής ετοιμότητας.

## Τα πρώτα πέντε λεπτά

| Βήμα | Ενέργεια | Απόφαση ή αποδεικτικό στοιχείο |
| --- | --- | --- |
| 1 | Επιβεβαιώστε την ειδοποίηση και ελέγξτε περιβάλλον, υπηρεσία και ώρα έναρξης | Καταγράψτε χρονοσφραγίδες UTC και την πιο πρόσφατη αλλαγή έκδοσης/διαμόρφωσης |
| 2 | Ελέγξτε το δημόσιο UI και το `/api/health`, έπειτα το άμεσο backend της main | Δημόσια αποτυχία με υγιές άμεσο backend υποδεικνύει πρόβλημα δρομολόγησης ή frontend |
| 3 | Ελέγξτε τη συνδεσιμότητα και την πίεση συνδέσεων της PostgreSQL | Δρομολογήστε αποτυχίες βάσης δεδομένων στο L1 πριν επανεκκινήσετε υπηρεσίες εφαρμογών |
| 4 | Ελέγξτε την κατάσταση containers/pods, CPU, μνήμη, δίσκο και πρόσφατα σφάλματα | Διαχωρίστε την αστοχία υποδομής, τον φόρτο και τα σφάλματα που αφορούν συγκεκριμένα workflows |
| 5 | Σε λειτουργία cluster, ελέγξτε **Ρυθμίσεις > Instances**, ουρές και ενδείξεις ηγέτη | Εντοπίστε απώλεια της main, μη διαθέσιμους/ασύμβατους workers ή εργασίες μόνο για τη main |
| 6 | Αντιστοιχίστε σοβαρότητα και ξεκινήστε ένα μέτρο μετριασμού από τον πίνακα δρομολόγησης | Για P1/P2, ανοίξτε αμέσως περιστατικό και καλέστε τον σχετικό υπεύθυνο |
| 7 | Επαληθεύστε την εκτέλεση ενός ασφαλούς workflow παραγωγής και παρακολουθήστε την ανάκαμψη | Επιβεβαιώστε ότι η ηλικία της ουράς, τα σφάλματα και οι πόροι βελτιώνονται. Ορίστε ώρα επόμενης ενημέρωσης |

Εάν μια έκδοση συμπίπτει χρονικά με την αποτυχία, ελέγξτε το [Ελαττωματική ανάπτυξη ή υποχώρηση διαμόρφωσης](./operations-runbook.md#bad-deployment-or-configuration-regression). Ελέγξτε τη συμβατότητα του σχήματος πριν από οποιαδήποτε επαναφορά (rollback).

## Σοβαρότητα και απόκριση

Αυτοί είναι αρχικοί στόχοι απόκρισης. Εφαρμόστε την πολιτική περιστατικών και τον επιχειρηματικό αντίκτυπο της ανάπτυξης εάν είναι αυστηρότεροι.

| Σοβαρότητα | Παραδείγματα | Απόκριση |
| --- | --- | --- |
| P1 | Η main δεν είναι διαθέσιμη σε όλους τους χρήστες. Η βάση δεν είναι διαθέσιμη ή αποτυγχάνουν οι εγγραφές. Εκτεταμένη αποτυχία εκτελέσεων. Κρίσιμη εισαγωγή μη διαθέσιμη σε όλα τα workflows | Άμεσος μετριασμός, φάκελος περιστατικού, επιφυλακή πλατφόρμας και εξαρτήσεων |
| P2 | Αυξανόμενη συσσώρευση στην ουρά. Απώλεια χωρητικότητας worker. Επικείμενη εξάντληση συνδέσεων. Ένα workflow υποβαθμίζει την κοινόχρηστη χωρητικότητα. Επανειλημμένα σφάλματα OOM | Άμεση έναρξη μετριασμού, στόχος περιορισμού εντός 15 λεπτών, καταγραφή περιστατικού |
| P3 | Μεμονωμένη αποτυχία workflow ή παρόχου. Περιορισμένος αντίκτυπος με υγιή χωρητικότητα πλατφόρμας | Υπεύθυνος workflow ή εξάρτησης, καταγεγραμμένη παρακολούθηση και σημείωση επιφυλακής |
| P4 | Πληροφοριακό σήμα, αναμενόμενη τάση χωρητικότητας, επαληθευμένος ψευδής συναγερμός | Επιβεβαίωση, τεκμηρίωση και προσαρμογή παρακολούθησης εάν χρειάζεται |

| Αυξανόμενη ουρά, εκτελέσεις σε αναμονή ή φαινομενικά κολλημένες | [Συσσώρευση στην ουρά (backlog)](./operations-runbook.md#queue-backlog-or-apparently-stuck-runs) |
| Παρουσία εκτός σύνδεσης ή ασύμβατη, αδρανής worker, πρόβλημα προγραμματιστή ή κατανομής | [Έλεγχοι λειτουργίας cluster](./operations-runbook.md#cluster-mode-checks) |
| Απώλεια της main ενώ οι workers παραμένουν υγιείς | [Η παρουσία main δεν είναι διαθέσιμη](./operations-runbook.md#main-instance-unavailable-while-workers-are-live) |

| Σφάλματα παρόχου Agent/LLM/MCP, κωδικός 429, αποτυχία credentials | [Αποτυχία μοντέλου ή ενοποίησης](./operations-runbook.md#model-credential-or-integration-failure) |
| Αποτυχίες sandbox για Code, Playwright, skill ή πράκτορα κώδικα | [Αποτυχία sandbox](./operations-runbook.md#sandbox-failure) |

## Κλιμάκωση

| Εύρημα | Εμπλοκή | Παροχή |
| --- | --- | --- |
| Επηρεάζονται πολλαπλές διεπαφές ή workflows | Επιφυλακή πλατφόρμας και επικεφαλής περιστατικού | Περιβάλλον, εύρος, ώρα έναρξης, μέτρα μετριασμού, επόμενη ενημέρωση |
| Βάση δεδομένων μη διαθέσιμη, κορεσμένη, κλειδωμένη ή χωρίς χώρο στο δίσκο | Επιφυλακή βάσης δεδομένων | ID βάσης, αριθμός συνδέσεων, μπλοκαρισμένα PID, απαλειμμένα σφάλματα, κατάσταση δίσκου |
| Αποτυχία pod/κόμβου, σύνδεση αποθήκευσης, χωρητικότητα sandbox | Υπεύθυνος υποδομής/αποθήκευσης | Περιβάλλον, namespace, φόρτος εργασίας, συμβάντα pod, πίεση πόρων |
| Η δημόσια διαδρομή αποτυγχάνει ενώ το άμεσο backend λειτουργεί | Υπεύθυνος δικτύου/ingress | Επηρεαζόμενες διαδρομές, κωδικοί κατάστασης, καθυστέρηση, σύγκριση με backend |
| Ένα μόνο workflow κυριαρχεί στον φόρτο ή αποτυγχάνει μεμονωμένα | Ιδιοκτήτης workflow | ID workflow/εκτέλεσης, πηγή trigger, ρυθμός, χρονικό παράθυρο, προσωρινά όρια |
| Συσχετισμένη αλλαγή ανάπτυξης ή διαμόρφωσης | Υπεύθυνος έκδοσης | Σύνοψη (digest) τρέχουσας εικόνας, ώρα ανάπτυξης, αναθεώρηση σχήματος, τελευταία καλή έκδοση |
| Όριο (quota), έλεγχος ταυτότητας ή διαθεσιμότητα παρόχου | Υπεύθυνος credential ή ενοποίησης | Πάροχος, μοντέλο/υπηρεσία, κωδικός κατάστασης, ID αιτήματος εάν είναι ασφαλές. Όχι μυστικά |

Εάν ο αντίκτυπος επιπέδου P1/P2 παραμένει μετά το πρώτο μέτρο μετριασμού, κλιμακώστε αμέσως με τα αποδεικτικά στοιχεία που έχουν ήδη συγκεντρωθεί. Μην περιμένετε την πλήρη ανάλυση βασικής αιτίας.

## Αναμενόμενη συμπεριφορά σε αστοχίες

| Αστοχία | Τι μπορεί να συνεχιστεί | Πρώτη ενέργεια |
| --- | --- | --- |
| PostgreSQL μη διαθέσιμη | Το στατικό frontend μπορεί να φορτώνει ακόμα | Επαναφέρετε τη διαδρομή της βάσης δεδομένων. Μην επανεκκινείτε κάθε παρουσία εφαρμογής |
| Main μη διαθέσιμη, workers υγιείς | Οι επιλέξιμες εργασίες παρασκηνίου και ο προγραμματισμός μπορούν να συνεχιστούν εάν ηγείται ένας συμβατός worker | Επαναφέρετε τη main με τον μόνιμο χώρο αποθήκευσής της. Τα δημόσια UI/API/MCP/Portal παραμένουν μη διαθέσιμα |
| Worker μη διαθέσιμος | Άλλες επιλέξιμες παρουσίες αναλαμβάνουν εργασίες από την ουρά καθώς επανακατανέμονται | Ελέγξτε την τοποθέτηση, την εφεδρική χωρητικότητα και την ανάκαμψη πριν προσθέσετε κίνηση |
| Διακοπείσα εκτέλεση | Οι επιλέξιμες ανακτήσιμες εκτελέσεις μπορούν να επανεκκινηθούν από την αρχή, μία μόνο φορά | Ελέγξτε την αυτόματη ανάκτηση και τις εξωτερικές παρενέργειες πριν από τη μη αυτόματη επανάληψη |
| Υπερφόρτωση εργασιών αποκλειστικά για τη main | Οι workers μπορούν να παραμείνουν αδρανείς | Μειώστε την προβληματική εισαγωγή ή αυξήστε τη χωρητικότητα της main. Οι αλλαγές βαρών δεν μετακινούν δεσμευμένη εργασία |
| Εσωτερικές ειδοποιήσεις μη διαθέσιμες | Η εξωτερική παρακολούθηση διαθεσιμότητας/βάσης/υποδομής μπορεί να συνεχίσει να λειτουργεί | Χρησιμοποιήστε παρακολούθηση εκτός Heym. Οι ειδοποιήσεις του Heym εξαρτώνται από την ίδια βάση και τον ίδιο προγραμματιστή |
| Sandbox ή πάροχος μη διαθέσιμος | Workflows χωρίς αυτήν την εξάρτηση μπορούν να λειτουργήσουν | Απομονώστε τα επηρεαζόμενα workflows και επιδιορθώστε την εξάρτηση |

## Ανάκαμψη και κλείσιμο περιστατικού

1. Επαληθεύστε τη δημόσια πρόσβαση, την πρόσβαση στη βάση δεδομένων, την προβλεπόμενη επιλεξιμότητα των παρουσιών και ένα ασφαλές workflow δοκιμής (smoke) σε λειτουργία παραγωγής. Μια δοκιμή στο πρόγραμμα επεξεργασίας δεν αποδεικνύει αποστολή σε workers.
2. Παρακολουθήστε τουλάχιστον 10 λεπτά σταθερών σφαλμάτων, καθυστέρησης, χρήσης πόρων και μείωσης της ηλικίας της ουράς. Παρακολουθήστε επίσης το επόμενο αναμενόμενο κρίσιμο πρόγραμμα ή έναν συμφωνημένο ισοδύναμο έλεγχο.
3. Συμφωνήστε τις αποτυχημένες, ανακτημένες, παραλειφθείσες, ληγμένες και εκκρεμείς εκτελέσεις με τους ιδιοκτήτες των workflows. Ελέγξτε τις εξωτερικές παρενέργειες πριν επαναλάβετε οτιδήποτε.
4. Επαναφέρετε σταδιακά τις προσωρινές παύσεις triggers, τα όρια και τα βάρη των workers. Αναθέστε έναν υπεύθυνο και χρόνο λήξης σε κάθε εναπομείναντα περιορισμό.
5. Ενημερώστε το περιστατικό με τον αντίκτυπο, το χρονοδιάγραμμα UTC, τις ενέργειες, τα αποδεικτικά στοιχεία και τους εκκρεμείς κινδύνους. Αναθέστε μια ανασκόπηση βασικής αιτίας (post-mortem) για P1/P2 και ενημερώστε και τα δύο έγγραφα εάν έλειπε κάποια διαδικασία.
