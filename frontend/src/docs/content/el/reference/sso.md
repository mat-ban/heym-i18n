# Ενιαία Σύνδεση (Single Sign-On)

Το Heym μπορεί να πιστοποιεί χρήστες μέσω οποιουδήποτε εξωτερικού παρόχου **OpenID Connect**. Ένας διαχειριστής εισάγει ένα issuer URL στη διαδρομή **Settings → SSO** και το Heym διαβάζει κάθε άλλο endpoint από το discovery document του εν λόγω παρόχου.

Κανένας πάροχος δεν είναι ενσωματωμένος στον κώδικα. Το Keycloak, το Okta, το Entra ID, το Auth0, η Google και οποιοσδήποτε άλλος πάροχος OIDC συνδέονται μέσω των ίδιων πεδίων, διότι το μόνο που γνωστοποιείται στο Heym είναι ο issuer.

Η σύνδεση με κωδικό πρόσβασης και η SSO λειτουργούν παράλληλα. Η σύνδεση με κωδικό πρόσβασης μπορεί να απενεργοποιηθεί μόλις επαληθευτεί η SSO.

## Πριν Ξεκινήσετε

Οι ρυθμίσεις SSO ισχύουν για ολόκληρο το instance, επομένως μόνο οι διαχειριστές του instance μπορούν να τις τροποποιήσουν. Οι διαχειριστές καθορίζονται μέσω μεταβλητής περιβάλλοντος και δεν αποθηκεύονται στη βάση δεδομένων:

```
HEYM_ADMIN_EMAILS=admin@example.com,ops@example.com
```

Μια κενή τιμή δεν εκχωρεί πρόσβαση σε κανέναν. Επανεκκινήστε το backend μετά την αλλαγή της. Οι λογαριασμοί αυτής της λίστας βλέπουν επίσης την καρτέλα **SSO** στις Ρυθμίσεις και διατηρούν πρόσβαση με κωδικό πρόσβασης ακόμη και όταν η σύνδεση με κωδικό πρόσβασης είναι απενεργοποιημένη — ανατρέξτε στην ενότητα [Απενεργοποίηση Σύνδεσης με Κωδικό Πρόσβασης](#disabling-password-sign-in).

## Καταχώριση του Heym στον Πάροχό σας

Στον πάροχο ταυτότητας, δημιουργήστε έναν **confidential client** (ονομάζεται επίσης app registration) με:

| Ρύθμιση | Τιμή |
|---------|-------|
| Protocol | OpenID Connect |
| Grant type | Authorization Code with PKCE |
| Client authentication | On — το Heym χρησιμοποιεί client secret |
| Redirect URI | Η ακριβής τιμή που εμφανίζεται στην καρτέλα SSO του Heym |
| Scopes | `openid email profile` |

Το Heym υπολογίζει το redirect URI από τη μεταβλητή `FRONTEND_URL` και το εμφανίζει σε κατάσταση μόνο για ανάγνωση στη φόρμα ρυθμίσεων με κουμπί αντιγραφής. Τελειώνει πάντα σε `/api/auth/sso/callback`. Αντιγράψτε το αντί να το πληκτρολογήσετε — ένα redirect URI που δεν ταιριάζει αποτελεί την πιο συχνή αιτία αποτυχίας ρύθμισης και οι πάροχοι το απορρίπτουν χωρίς εξήγηση.

Ο πάροχός σας πρέπει να επιστρέφει επαληθευμένη διεύθυνση email. Ανατρέξτε στην ενότητα [Αντιστοίχιση Λογαριασμού](#account-mapping).

## Ρύθμιση του Heym

Ανοίξτε τη διαδρομή **Settings → SSO**. Η καρτέλα εμφανίζεται μόνο για λογαριασμούς που περιλαμβάνονται στη μεταβλητή `HEYM_ADMIN_EMAILS`.

| Πεδίο | Τι κάνει |
|-------|--------------|
| **Enable single sign-on** | Εμφανίζει το κουμπί σύνδεσης στην οθόνη σύνδεσης. |
| **Issuer URL** | Το βασικό URL του παρόχου, για παράδειγμα `https://idp.example.com/realms/your-realm`. Το Heym προσθέτει το `/.well-known/openid-configuration` και διαβάζει τα υπόλοιπα από εκεί. |
| **Client ID** | Το αναγνωριστικό client από τον πάροχό σας. |
| **Client secret** | Αποθηκεύεται κρυπτογραφημένο. Αφήστε το πεδίο κενό για να διατηρηθεί η αποθηκευμένη τιμή — το Heym δεν επιστρέφει ποτέ ένα secret που κατέχει. |
| **Redirect URI** | Μόνο για ανάγνωση. Αντιγράψτε το στη λίστα επιτρεπόμενων του παρόχου σας. |
| **Scopes** | `openid email profile` από προεπιλογή. |
| **Sign-in button label** | Το κείμενο στο κουμπί της οθόνης σύνδεσης, για παράδειγμα "Sign in with Okta". |
| **Create an account on first sign-in** | Κατά πόσο άγνωστα άτομα αποκτούν αυτόματα λογαριασμό Heym. |
| **Allowed email domains** | Διαχωρισμένα με κόμμα. Κενή τιμή επιτρέπει οποιονδήποτε τομέα πιστοποιεί ο πάροχος. |
| **Disable password sign-in** | Απενεργοποιεί την πιστοποίηση με κωδικό πρόσβασης για ολόκληρο το instance. |

### Δοκιμάστε πρώτα τη σύνδεση

Η επιλογή **Test connection** ανακτά το discovery document και τα signing keys του παρόχου και έπειτα αναφέρει το token endpoint που εντόπισε. Μπορείτε να την εκτελέσετε σε έναν issuer που έχετε πληκτρολογήσει αλλά δεν έχετε ακόμη αποθηκεύσει, ώστε ένα λανθασμένο URL να κοστίζει ένα κλικ αντί για μια αποθήκευση.

Μια δοκιμή *καταγράφει* επιτυχές αποτέλεσμα μόνο όταν ο issuer που δοκιμάστηκε είναι αυτός που είναι ήδη αποθηκευμένος. Μια δοκιμή σε πρόχειρη κατάσταση σας ενημερώνει κατά πόσο το URL επιλύεται· δεν νομιμοποιεί μια διαμόρφωση που δεν έχει αποθηκευτεί. Η αλλαγή του issuer, του client ID, των scopes ή του secret διαγράφει το καταγεγραμμένο αποτέλεσμα για τον ίδιο λόγο.

## Πώς Λειτουργεί η Σύνδεση

1. Κάποιος κάνει κλικ στο κουμπί σύνδεσης στην οθόνη σύνδεσης.
2. Το Heym τον ανακατευθύνει στον πάροχο με ένα `state`, ένα `nonce` και ένα PKCE challenge.
3. Αυτός πιστοποιείται με τον πάροχο.
4. Ο πάροχος ανακατευθύνει πίσω στο callback του Heym με έναν authorization code.
5. Το Heym ανταλλάσσει τον code με tokens και επαληθεύει το ID token έναντι των δημοσιευμένων keys του παρόχου, ελέγχοντας την υπογραφή, το audience, τον issuer, τη λήξη και το nonce.
6. Το Heym επιλύει τον λογαριασμό και εκδίδει τη δική του συνεδρία, ακριβώς όπως κάνει μια σύνδεση με κωδικό πρόσβασης.

Όλα τα επόμενα του βήματος 6 παραμένουν αμετάβλητα: τα ίδια session cookies, οι ίδιες διάρκειες ζωής token, τα ίδια δικαιώματα.

## Αντιστοίχιση Λογαριασμού

Το Heym επιλύει έναν λογαριασμό με την εξής σειρά:

1. **`(issuer, subject)`** — η ταυτότητα που δήλωσε ο πάροχος σε προηγούμενη σύνδεση. Αυτή είναι αυθεντική και επιβιώνει από αλλαγή email στον πάροχο.
2. **Επαληθευμένο email** — ένας υπάρχων λογαριασμός Heym με αυτή τη διεύθυνση διεκδικείται και το subject του παρόχου καταγράφεται σε αυτόν από εκείνη τη στιγμή και έπειτα.
3. **Νέος λογαριασμός** — δημιουργείται εφόσον η επιλογή **Create an account on first sign-in** είναι ενεργοποιημένη και ο τομέας επιτρέπεται.

Ένα email θεωρείται επαληθευμένο μόνο όταν το ID token φέρει `email_verified: true`. Εάν αυτή η δήλωση είναι `false` ή απούσα, η σύνδεση απορρίπτεται. Η διεκδίκηση υπάρχοντος λογαριασμού — ή η δημιουργία νέου — βάσει μιας διεύθυνσης για την οποία ο πάροχος δεν εγγυάται αποτελεί οδό κατάληψης λογαριασμού, επομένως το Heym δεν το πράττει. Ένας πάροχος που δεν εκπέμπει ποτέ `email_verified` χρειάζεται να ρυθμιστεί ώστε να το κάνει.

Οι λογαριασμοί που δημιουργούνται με αυτόν τον τρόπο δεν έχουν κωδικό πρόσβασης. Συνδέονται αποκλειστικά μέσω του παρόχου.
## Απενεργοποίηση σύνδεσης με κωδικό πρόσβασης

Ο διακόπτης **Disable password sign-in** παραμένει μη διαθέσιμος έως ότου ισχύουν τρία πράγματα:

1. Το SSO είναι ενεργοποιημένο.
2. Έχει περάσει ένας έλεγχος σύνδεσης, ώστε ένας λανθασμένος issuer να μην μπορεί να κλειδώσει την πόρτα πίσω από τον εαυτό του.
3. Τουλάχιστον ένας λογαριασμός στο `HEYM_ADMIN_EMAILS` έχει πράγματι κωδικό πρόσβασης.

Όταν είναι ενεργοποιημένος, η αυθεντικοποίηση με κωδικό πρόσβασης απορρίπτεται σε όλες τις τρεις επιφάνειες που εκδίδουν ή δέχονται έναν: τη φόρμα σύνδεσης, την **εγγραφή** και τη σελίδα συγκατάθεσης MCP OAuth. Η εγγραφή μετράει επειδή εκδίδει κωδικό πρόσβασης· αν παρέμενε ανοιχτή, η ρύθμιση θα ήταν παρακάμψιμη από οποιονδήποτε μπορεί να φτάσει στο `/register`.

Οι λογαριασμοί που αναφέρονται στο `HEYM_ADMIN_EMAILS` εξαιρούνται από τις τρεις επιφάνειες. Όποιος μπορεί να επεξεργαστεί το αρχείο περιβάλλοντος μπορεί ήδη να ανακτήσει την εγκατάσταση, επομένως αυτή η εγγύηση βρίσκεται στον κώδικα και όχι στη μνήμη ενός διαχειριστή.

### Γιατί υπάρχει η τρίτη συνθήκη

Ένας διαχειριστής του οποίου ο λογαριασμός Heym δημιουργήθηκε *μέσω* SSO δεν έχει καθόλου κωδικό πρόσβασης. Η εξαίρεση θα του επέτρεπε να περάσει την πύλη, αλλά δεν θα είχε τίποτα για να συνδεθεί — επομένως η εγκατάσταση δεν θα είχε τρόπο επιστροφής αν ο πάροχος έπεφτε. Το Heym αρνείται να εισέλθει σε αυτή την κατάσταση και το δηλώνει.

Αν συναντήσετε αυτό το μήνυμα, συνδεθείτε μέσω SSO και δημιουργήστε έναν λογαριασμό με κωδικό πρόσβασης σε μία από τις διευθύνσεις διαχειριστή σας (η εγγραφή παραμένει ανοιχτή σε διευθύνσεις διαχειριστή ακριβώς για αυτόν τον λόγο), ή προσθέστε μια διεύθυνση που έχει ήδη κωδικό πρόσβασης στο `HEYM_ADMIN_EMAILS`.

### Ανάκτηση όταν ο πάροχος είναι εκτός λειτουργίας

Κατά σειρά προτίμησης:

1. **Συνδεθείτε με κωδικό πρόσβασης διαχειριστή έκτακτης ανάγκης.** Η οθόνη σύνδεσης κρύβει τη φόρμα κωδικού πρόσβασης όταν η σύνδεση με κωδικό πρόσβασης είναι απενεργοποιημένη, επομένως κάντε κλικ στο **Sign in with a password instead** κάτω από το κουμπί SSO για να την εμφανίσετε. Η φόρμα δεν αποτελεί παράκαμψη: κάθε διεύθυνση εκτός του `HEYM_ADMIN_EMAILS` εξακολουθεί να απορρίπτεται, και ενημερώνεται για τον λόγο.
2. **Προσθέστε τον εαυτό σας στο `HEYM_ADMIN_EMAILS`** στο αρχείο περιβάλλοντος και επανεκκινήστε το backend. Ένας λογαριασμός που έχει ήδη κωδικό πρόσβασης μπορεί τότε να συνδεθεί.
3. **Επανανοίξτε τη σύνδεση με κωδικό πρόσβασης απευθείας στη βάση δεδομένων**, αν κανένας διαχειριστής δεν έχει καθόλου κωδικό πρόσβασης:

   ```sql
   UPDATE sso_settings SET password_login_disabled = false;
   ```

   Δεν απαιτείται επανεκκίνηση· η ρύθμιση διαβάζεται ανά αίτημα.

Οι τελικοί χρήστες του Portal δεν επηρεάζονται. Αυθεντικοποιούνται σε ξεχωριστό κατάλογο — βλ. [Portal](./portal.md).

## Σφάλματα σύνδεσης

Μια αποτυχημένη σύνδεση επιστρέφει στην οθόνη σύνδεσης με ένα ευανάγνωστο μήνυμα. Το Heym δεν εμφανίζει ποτέ το ακατέργαστο κείμενο σφάλματος του παρόχου.

| Μήνυμα | Αιτία |
|---------|-------|
| That sign-in attempt expired | Η προσπάθεια διήρκεσε περισσότερο από δέκα λεπτά, ή ο browser απέρριψε το cookie συναλλαγής. Δοκιμάστε ξανά. |
| Could not reach the identity provider | Η ανακάλυψη ή η ανταλλαγή token απέτυχε. Ελέγξτε το issuer URL και ότι ο πάροχος είναι προσβάσιμος από το backend. |
| The provider's response could not be verified | Το ID token απέτυχε στην επικύρωση υπογραφής, audience, issuer, λήξης ή nonce. Συνήθως πρόκειται για αναντιστοιχία client ID. |
| The provider did not return an email address | Λείπει το scope `email`, ή ο πάροχος δεν παρέχει το claim. |
| Your email address is not verified | Ο πάροχος έστειλε `email_verified: false`, ή παρέλειψε το claim. |
| Your email domain is not allowed | Η διεύθυνση είναι εκτός των **Allowed email domains**. |
| No Heym account exists for you | Το **Create an account on first sign-in** είναι απενεργοποιημένο και κανένας λογαριασμός δεν αντιστοιχεί. Ένας διαχειριστής πρέπει να δημιουργήσει έναν. |
| Single sign-on is not configured | Το SSO είναι απενεργοποιημένο, ή λείπει το issuer, το client ID ή το secret. |

## Σημειώσεις ασφαλείας

- **Το client secret είναι κρυπτογραφημένο σε κατάσταση ηρεμίας** και δεν επιστρέφεται ποτέ από κανένα endpoint. Η φόρμα ρυθμίσεων αναφέρει μόνο αν έχει αποθηκευτεί ένα.
- **Ο επαληθευτής PKCE δεν εγκαταλείπει ποτέ το Heym.** Διατηρείται σε ένα βραχύβιο cookie `HttpOnly` αντί στην παράμετρο `state`, η οποία περνά από τον πάροχο σε κοινή θέα.
- **Γίνονται δεκτές μόνο ασύμμετρες υπογραφές.** Το `none` και οι συμμετρικοί αλγόριθμοι απορρίπτονται ανεξάρτητα από το τι διαφημίζει ο πάροχος.
- **Ο προορισμός μετά τη σύνδεση επικυρώνεται** ως διαδρομή ίδιας προέλευσης, ώστε το callback να μην μπορεί να χρησιμοποιηθεί ως ανοιχτή ανακατεύθυνση.
- **Κάθε σύνδεση καταγράφεται σε audit.** Οι επιτυχίες, οι αποτυχίες και οι απορρίψεις εμφανίζονται ως γραμμές `auth.sso_login`, και οι αλλαγές ρυθμίσεων ως `sso_settings.update` — βλ. [Audit Logging](./audit.md).

## Τι δεν υποστηρίζεται

- **SAML.** Το OIDC είναι το μόνο πρωτόκολλο.
- **Πολλαπλοί ταυτόχρονοι πάροχοι.** Μία εγκατάσταση συνδέεται με έναν πάροχο.
- **Αντιστοίχιση ομάδων ή ρόλων** από claims του παρόχου.
- **Single logout.** Η αποσύνδεση από το Heym δεν σας αποσυνδέει από τον πάροχο.
