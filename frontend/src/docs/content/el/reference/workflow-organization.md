# Οργάνωση Workflows

Το Heym σας επιτρέπει να οργανώνετε workflows σε φακέλους, να δημιουργείτε υποφακέλους και να προγραμματίζετε workflows για διαγραφή. Ανατρέξτε στην ενότητα [Workflows Tab](../tabs/workflows-tab.md) για μια επισκόπηση της διεπαφής.

## Φάκελοι και Υποφάκελοι

Οι φάκελοι σχηματίζουν ένα δέντρο. Κάθε φάκελος διαθέτει:

- **Name** – Εμφανιζόμενο όνομα
- **Parent** – Το `parent_id` συνδέεται με άλλον φάκελο· `null` σημαίνει ρίζα
- **Workflows** – Τα workflows μπορούν να μετακινηθούν σε φακέλους μέσω του `folder_id`

### API

| Endpoint | Σκοπός |
|----------|---------|
| `GET /folders` | Μόνο φάκελοι ρίζας |
| `GET /folders/tree` | Πλήρες δέντρο (children + workflows) |
| `GET /folders/{id}` | Μεμονωμένος φάκελος με τα περιεχόμενά του |
| `POST /folders` | Δημιουργία φακέλου (το `parent_id` είναι προαιρετικό) |
| `PUT /folders/{id}` | Ενημέρωση ονόματος ή `parent_id` |
| `DELETE /folders/{id}` | Διαγραφή φακέλου (cascade) |
| `PUT /folders/{folder_id}/workflows/{workflow_id}` | Μετακίνηση workflow σε φάκελο |
| `DELETE /folders/workflows/{workflow_id}/folder` | Αφαίρεση workflow από φάκελο |
| `GET /folders/{id}/export` | Λήψη φακέλου + όλων των υποφακέλων ως ZIP |

### Δομή Δέντρου

Η απόκριση του δέντρου περιλαμβάνει `children` και `workflows` ανά φάκελο. Τα κοινόχρηστα workflows μπορούν να εμφανίζονται σε έναν φάκελο μέσω του `WorkflowShare.folder_id`.

## Κοινοποίηση Workflows

Ανοίξτε την επιλογή **Share** στον επεξεργαστή workflow για να προσκαλέσετε χρήστες μέσω email ή να κοινοποιήσετε σε μια [ομάδα](./teams.md). Κάθε πρόσκληση και κάθε κοινοποίηση σε ομάδα φέρει ένα δικαίωμα πρόσβασης:

| Δικαίωμα | Τι μπορεί να κάνει ο συνεργάτης |
|------------|------------------------------|
| **Read** | Να ανοίξει το workflow, να το επιθεωρήσει, να δει το ιστορικό εκτελέσεων και να το εκτελέσει. Ο επεξεργαστής ανοίγει σε λειτουργία μόνο για ανάγνωση: η Αποθήκευση είναι απενεργοποιημένη και ο καμβάς δεν μπορεί να τροποποιηθεί. |
| **Write** | Όλα όσα επιτρέπει το Read, συν την επεξεργασία του καμβά, των ρυθμίσεων, του εγγράφου ανάλυσης και της μνήμης του agent. |

Το δικαίωμα εμφανίζεται δίπλα σε κάθε καταχώριση στο παράθυρο διαλόγου Share και μπορεί να αλλάξει οποιαδήποτε στιγμή από αυτό το αναπτυσσόμενο μενού, χωρίς να αφαιρεθεί και να προστεθεί εκ νέου η κοινοποίηση. Όταν ένας χρήστης φτάνει σε ένα workflow μέσω πολλαπλών διαδρομών (μια άμεση κοινοποίηση και μία ή περισσότερες ομάδες), υπερισχύει το **υψηλότερο** δικαίωμα. Οι κοινοποιήσεις που υπήρχαν πριν από την εισαγωγή των δικαιωμάτων είναι **Write**, και οι API clients που παραλείπουν το `permission` λαμβάνουν επίσης **Write**.

Οι ενέργειες που προορίζονται αποκλειστικά για τον κάτοχο δεν εξαρτώνται ποτέ από το δικαίωμα: η διαγραφή ενός workflow, η επαναφορά ή ο καθαρισμός εκδόσεων, ο καθαρισμός του ιστορικού, η διαχείριση κοινοποιήσεων και οι [ρυθμίσεις αποκλειστικά για τον κάτοχο](#owner-only-settings) παρακάτω παραμένουν στον κάτοχο ακόμη και για συνεργάτες με **Write**. Ένας συνεργάτης με **Read** που στέλνει μια επεξεργασία μέσω του API (`PUT /api/workflows/{id}`, το σημείωμα ανάλυσης, τη μνήμη του agent, τον καθαρισμό cache) ή μέσω του AI Assistant λαμβάνει `403` με το μήνυμα `You have read-only access to this workflow`.

Η κοινοποίηση ενός workflow παρέχει πρόσβαση στον καμβά, στο ιστορικό εκτελέσεων και στο έγγραφο ανάλυσης. **Δεν** κοινοποιεί αυτόματα:

- **Διαπιστευτήρια** που αναφέρονται από nodes στο workflow
- **Υπο-workflows** που καλούνται από nodes [Execute](../nodes/execute-node.md) ή agents

Οι παραλήπτες χρειάζονται αυτά τα διαπιστευτήρια και τα θυγατρικά workflows να κοινοποιηθούν σε αυτούς ξεχωριστά (ίδιοι χρήστες ή ομάδες). Κοινοποιήστε διαπιστευτήρια από την [Credentials tab](../tabs/credentials-tab.md)· ανατρέξτε στην ενότητα [Credentials Sharing](./credentials-sharing.md). Κοινοποιήστε κάθε υπο-workflow από το δικό του παράθυρο διαλόγου κοινοποίησης στον επεξεργαστή.

### Ρυθμίσεις αποκλειστικά για τον κάτοχο

Ολόκληρη η διαμόρφωση **Run with cURL** παραμένει στον κάτοχο μετά την κοινοποίηση. Οι συνεργάτες εξακολουθούν να ανοίγουν το παράθυρο διαλόγου και να αντιγράφουν την παραγόμενη εντολή, αλλά τα στοιχεία ελέγχου είναι μόνο για ανάγνωση.

Η αλλαγή οποιουδήποτε από αυτά ως μη κάτοχος απορρίπτεται με `403`:

- **Authentication** (`auth_type`) και **Header Key** (`auth_header_key`)
- Λειτουργία **Request Body** (`webhook_body_mode`) και **Request Method** (`http_method`)
- **Response Cache** (`cache_ttl_seconds`) και **Rate Limit** (`rate_limit_requests`, `rate_limit_window_seconds`)
- **SSE Streaming** (`sse_enabled`, `sse_node_config`)

Το **Header Value** (`auth_header_value`) συμπεριφέρεται διαφορετικά: είναι εντελώς κρυφό από τους συνεργάτες, και η εγγραφή ενός συνεργάτη αγνοείται αντί να απορρίπτεται. Ο επεξεργαστής αποδίδει το πεδίο με μάσκα, ώστε ένα `403` εκεί να έσπαγε μια συνηθισμένη αποθήκευση αντί να σηματοδοτεί επίθεση.

Ο λόγος που το block προορίζεται αποκλειστικά για τον κάτοχο είναι η αυθεντικοποίηση: το `Anonymous` επιτρέπει σε μη αυθεντικοποιημένους καλούντες να εκτελέσουν το workflow, και μια εκτέλεση χωρίς συνδεδεμένο καλούντα επιλύει τα διαπιστευτήρια και τις καθολικές μεταβλητές ως τον **κάτοχο**, όχι τον καλούντα. Το υπόλοιπο block είναι το δημοσιευμένο συμβόλαιο αιτήματος και τα στοιχεία ελέγχου κόστους του κατόχου, οπότε μετακινείται μαζί του.

Η επιλογή **On error, run workflow** (`error_workflow_id`) στο πάνελ **Properties** σε επίπεδο workflow προορίζεται αποκλειστικά για τον κάτοχο για τον ίδιο λόγο: το [error workflow](./features.md#error-workflow) εκτελείται με τα διαπιστευτήρια και τις καθολικές μεταβλητές της αποτυχημένης εκτέλεσης, τα οποία ανήκουν στον κάτοχο για εκτελέσεις που προκαλούνται από trigger και ανώνυμες εκτελέσεις. Οι συνεργάτες βλέπουν τη ρύθμιση μόνο για ανάγνωση, και η προσθήκη, αντικατάσταση ή εκκαθάρισή της ως μη κάτοχος απορρίπτεται με `403`.

Η επεξεργασία του καμβά, του ονόματος και της περιγραφής δεν επηρεάζεται.

### Execution tokens

Ένας συνεργάτης μπορεί να δημιουργήσει ένα execution token για ένα workflow που έχει κοινοποιηθεί σε αυτόν. Η εκτέλεση αποδίδεται σε **όποιον δημιούργησε το token**, οπότε χρησιμοποιεί τα διαπιστευτήρια και τις καθολικές μεταβλητές αυτού του χρήστη, όχι του κατόχου. Μόνο μια γνήσια ανώνυμη κλήση — `auth_type: anonymous` χωρίς καλούντα — εκτελείται στο πλαίσιο του κατόχου.

## Προγραμματισμένα για Διαγραφή

Τα workflows μπορούν να προγραμματιστούν για διαγραφή αντί να αφαιρεθούν αμέσως.

- **Πεδίο**: `scheduled_for_deletion` (nullable datetime)
- **Συμπεριφορά**: Όταν οριστεί, το workflow μετακινείται σε `folder_id = null` και εμφανίζεται στην ενότητα "Scheduled for Deletion".
### API

| Endpoint | Σκοπός |
|----------|---------|
| `PUT /workflows/{id}/schedule-deletion` | Ορίζει το `scheduled_for_deletion`, καθαρίζει το `folder_id` |
| `DELETE /workflows/{id}/schedule-deletion` | Καθαρίζει το `scheduled_for_deletion` (επαναφορά) |

### UI

- **Σύρετε στα απορρίμματα** – Αποθέστε workflows στην περιοχή "Scheduled for Deletion" για να τα προγραμματίσετε
- **Επαναφορά** – Αφαιρέστε από το πρόγραμμα
- **Άμεση διαγραφή** – Εικονίδιο απορριμμάτων για μόνιμη αφαίρεση

### Λογική καθαρισμού

Μια εργασία cron εκτελείται καθημερινά στις **23:59** (στη ρυθμισμένη ζώνη ώρας). Ένα workflow διαγράφεται μόνο όταν:

- **Όλοι οι start nodes** (κόμβοι χωρίς εισερχόμενες ακμές, εξαιρουμένων των sticky/errorHandler) έχουν `active === false`

Εάν οποιοσδήποτε start node είναι ακόμη ενεργός, το workflow παραμένει μέχρι την επόμενη εκτέλεση.

## Dashboard UI

- **Γραμμές φακέλων** – Νέος Φάκελος, αναδρομικό δέντρο φακέλων με ανάπτυξη/σύμπτυξη. Κάθε φάκελος φέρει
  προαιρετική περιγραφή κάτω από το όνομά του και ένα badge που μετρά τα workflows που περιέχει, συμπεριλαμβανομένων
  των υποφακέλων.
- **Ενέργειες φακέλου** – Νέος Υποφάκελος, Μετονομασία, Αλλαγή εικονιδίου, Λήψη ως ZIP και Διαγραφή βρίσκονται ενσωματωμένες
  σε κάθε γραμμή φακέλου· το μενού περιβάλλοντος με δεξί κλικ προσφέρει το ίδιο σύνολο, και τα τηλέφωνα εμφανίζουν ένα μόνο
  κουμπί μενού.
- **Κύρια περιοχή** – Root workflows (χωρίς φάκελο, χωρίς προγραμματισμό) και Scheduled for Deletion
- **Προεπισκόπηση απόθεσης φακέλου** – Το σύρσιμο ενός workflow επισημαίνει τον ακριβή φάκελο ή υποφάκελο και
  εμφανίζει την πλήρη διαδρομή του σε προεπισκόπηση μεγέθους κάρτας. Ένας συμπτυγμένος φάκελος αναπτύσσεται μετά από σύντομη παραμονή του δείκτη.
- **Σταθερή ανατροφοδότηση συρσίματος** – Η κάρτα προέλευσης χρησιμοποιεί drag ghost, και ο ενεργός στόχος απόθεσης παραμένει
  επιλεγμένος κατά την κύλιση ή τη διέλευση στοιχείων ελέγχου εντός του ίδιου φακέλου.
- **Έλεγχος προορισμού** – Ο τρέχων φάκελος εμφανίζεται ως **Already in Folder** και δεν δέχεται
  περιττή μετακίνηση.
- **Άλλες ζώνες απόθεσης** – Το Root και το "Scheduled for Deletion" επισημαίνονται όταν μπορούν να δεχτούν το
  workflow που σύρεται.
- **Απόθεση ZIP** – Αποθέστε ένα αρχείο ZIP στην περιοχή workflow για να εισαγάγετε δομή φακέλων σε επίπεδο root
