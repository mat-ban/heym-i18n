# Καρτέλα Chat

Η καρτέλα **Chat** παρέχει μια άμεση διεπαφή συνομιλίας με LLM. Χρησιμοποιήστε την για να δοκιμάσετε μοντέλα, να υποβάλετε ερωτήσεις, να εκτελέσετε υπάρχοντα workflows ή να δημιουργήσετε ένα νέο workflow από ένα αίτημα σε φυσική γλώσσα.

## Ρύθμιση

1. Επιλέξτε ένα [διαπιστευτήριο](./credentials-tab.md) (κλειδί API για OpenAI, Google κ.λπ.)
2. Επιλέξτε ένα μοντέλο από το αναπτυσσόμενο μενού (τα μοντέλα φορτώνονται από το επιλεγμένο διαπιστευτήριο)
3. Ξεκινήστε να πληκτρολογείτε για να στείλετε μηνύματα

Μπορείτε επίσης να ξεκινήσετε μια συνομιλία από το πλαίσιο συνομιλίας στην [καρτέλα Workflows](./workflows-tab.md). Αποστέλλει το πρώτο σας μήνυμα και ανοίγει τη νέα συνομιλία εδώ με την απάντηση να μεταδίδεται ήδη.

## Δυνατότητες

- **Πλαίσιο καθολικών μεταβλητών** – Οι [Καθολικές Μεταβλητές](../reference/global-variables.md) σας είναι διαθέσιμες στο LLM, ώστε να μπορείτε να ρωτήσετε ή να αναφερθείτε σε αποθηκευμένες τιμές
- **Πλαίσιο προτύπων χώρου εργασίας** – Τα κοινόχρηστα πρότυπα workflow και node στον χώρο εργασίας σας περιλαμβάνονται ως πλαίσιο, ώστε το Chat να μπορεί να απαντήσει σε ερωτήσεις σχετικά με τα διαθέσιμα πρότυπα
- **Μακροχρόνιος agent** – Το Chat συνεχίζει να λειτουργεί στο backend ακόμη και αν ο browser κλείσει, ώστε να μπορείτε να επιστρέψετε από άλλη συσκευή και να συνεχίσετε την ίδια συνομιλία
- **Δημιουργία workflow** – Ζητήστε από το Chat να δημιουργήσει ή να ρυθμίσει ένα workflow, και χρησιμοποιεί την ίδια μηχανή Workflow AI Builder με τον βοηθό του editor για να δημιουργήσει και να αποθηκεύσει το workflow
- **Δημιουργία εργασιών Kanban** – Ζητήστε φυσικά να προστεθεί μια εργασία ή να δημιουργηθεί μια κάρτα. Το Chat την προσθέτει στην πρώτη στήλη του ζητούμενου πίνακα· όταν έχετε πολλούς πίνακες και δεν κατονομάσετε κάποιον, το Chat παρουσιάζει έναν επιλογέα πίνακα πριν δημιουργήσει την κάρτα
- **Συνεχείς ερωτήσεις σε ουρά** – Στείλτε περισσότερα μηνύματα ενώ μια απάντηση μεταδίδεται. Τα μηνύματα σε ουρά διατηρούνται, μπορούν να επεξεργαστούν ή να διαγραφούν πριν ξεκινήσουν, και εκτελούνται με σειρά μετά την ενεργή απάντηση
- **Παύσεις σχεδιασμού** – Όταν το Chat χρειάζεται λεπτομέρειες σχεδιασμού, υποβάλλει ερωτήσεις διευκρίνισης και παύει τις συνεχείς ερωτήσεις σε ουρά μέχρι να απαντήσετε. Αφού ολοκληρωθεί η απάντηση σχεδιασμού, τα μηνύματα σε ουρά συνεχίζονται
- **Διαπιστευτήρια** – Όταν ένα workflow που δημιουργεί ή επεξεργάζεται το Chat χρειάζεται ένα διαπιστευτήριο, το Chat ρωτά ποιο να χρησιμοποιηθεί, προσφέρει να δημιουργήσει ένα νέο στη συνομιλία ή σας επιτρέπει να συνεχίσετε χωρίς αυτό. Μπορείτε επίσης να ζητήσετε από το Chat να δημιουργήσει ένα διαπιστευτήριο ή να ενημερώσει ένα που σας ανήκει· ανοίγει τη φόρμα διαπιστευτηρίου στη συνομιλία. Το μοντέλο βλέπει το όνομα και τον τύπο του διαπιστευτηρίου, ποτέ τις τιμές του, τόσο για διαπιστευτήρια που σας ανήκουν όσο και για εκείνα που έχουν κοινοποιηθεί σε εσάς. Οι κόμβοι LLM και Agent που προσθέτει το Chat εκτελούνται με το διαπιστευτήριο και το μοντέλο που έχουν επιλεγεί για το chat, συμπεριλαμβανομένων των κοινόχρηστων διαπιστευτηρίων· όταν το Chat επεξεργάζεται ένα workflow, οι υπάρχοντες κόμβοι LLM και Agent διατηρούν το διαπιστευτήριο και το μοντέλο τους. Δείτε [AI Assistant › Διαπιστευτήρια](../reference/ai-assistant.md#credentials)
- **Dashboards** – Ρωτήστε ποια [dashboards](./dashboard-tab.md) έχετε, τι περιέχει κάποιο από αυτά ή σε ποιο dashboard βρίσκεται ένα workflow. Ζητήστε από το Chat να προσθέσει ένα νέο widget σε ένα dashboard (τοποθετεί ένα κενό widget εκεί, στη συνέχεια δημιουργεί και δοκιμάζει το workflow του), να τοποθετήσει ένα υπάρχον workflow σε ένα dashboard ως widget, να μετονομάσει ή να διαγράψει ένα widget ή να τακτοποιήσει τη διάταξη ενός dashboard. Το Heym Work εμφανίζει αυτά τα dashboards ως τις σελίδες του. Δείτε [Dashboard › Από το Chat και το MCP](./dashboard-tab.md#από-το-chat-και-το-mcp)
- **Πίνακες δεδομένων** – Όταν ένα workflow που δημιουργεί ή επεξεργάζεται το Chat αποθηκεύει εγγραφές, το Chat ρωτά ποιον [πίνακα δεδομένων](./datatable-tab.md) να χρησιμοποιήσει ή προσφέρει τη δημιουργία ενός με τις απαραίτητες στήλες. Μπορεί επίσης να επιθεωρεί γραμμές, να προσθέτει ή να αφαιρεί στήλες και να εισάγει, να ενημερώνει ή να διαγράφει γραμμές απευθείας σε πίνακες που σας ανήκουν ή μπορείτε να επεξεργαστείτε. Δώστε του ένα όνομα πίνακα ή έναν σύνδεσμο DataTable. Η αφαίρεση στηλών και η εκκαθάριση όλων των γραμμών ζητούν επιβεβαίωση· η προσθήκη στηλών διατηρεί τα υπάρχοντα δεδομένα. Δείτε [Βοηθός AI › Πίνακες δεδομένων](../reference/ai-assistant.md#data-tables)
- **Μετάδοση απαντήσεων** – Δείτε την έξοδο του μοντέλου καθώς μεταδίδεται
- **Διακοπή απάντησης** – Διακόψτε την τρέχουσα απάντηση που μεταδίδεται ανά πάσα στιγμή· η διακοπή καθαρίζει επίσης τα μηνύματα σε ουρά για αυτή τη συνομιλία
- **Απόδοση Markdown** – Οι απαντήσεις υποστηρίζουν μορφοποίηση markdown, συμπεριλαμβανομένων ενσωματωμένων εικόνων
- **Εμφάνιση εικόνων** – Οι εικόνες που ενσωματώνονται στις απαντήσεις (π.χ. από τη δημιουργία εικόνων LLM) εμφανίζονται ενσωματωμένες· κάντε κλικ σε οποιαδήποτε εικόνα για να την δείτε σε πλήρη οθόνη. Πατήστε **Esc** ή το κουμπί επιστροφής (κινητό) για να κλείσετε την προβολή πλήρους οθόνης
- **Αντιγραφή μηνυμάτων** – Αντιγράψτε οποιοδήποτε μήνυμα στο πρόχειρο
- **Εκκαθάριση chat** – Ξεκινήστε μια νέα συνομιλία
- **Φωνητική εισαγωγή** – Χρησιμοποιήστε το κουμπί μικροφώνου για μετατροπή ομιλίας σε κείμενο (υποστηρίζεται από τον browser). Όταν σταματήσει η εγγραφή, το Heym μπορεί να καθαρίσει ελαφρώς το μεταγραμμένο κείμενο πριν το στείλετε
- **Προγραμματισμένα workflows** – Ρωτήστε πότε εκτελούνται τα cron workflows (σήμερα, αυτή την εβδομάδα, αυτόν τον μήνα ή ένα προσαρμοσμένο εύρος ημερομηνιών). Ο βοηθός χρησιμοποιεί τα ίδια δεδομένα χρονοδιαγράμματος με την καρτέλα [Scheduled](./scheduled-tab.md) και μπορεί να περιορίσει τα αποτελέσματα σε workflows που σας ανήκουν ή να συμπεριλάβει αυτά που κοινοποιούνται σε εσάς
- **Ιστορικό εκτελέσεων workflow** – Ρωτήστε για ένα workflow ("πόσες φορές εκτελέστηκε η ημερήσια αναφορά;", "απέτυχε;", "πότε εκτελέστηκε τελευταία φορά;"). Το Chat αναζητά το workflow με το ID του και απαντά από τον αριθμό εκτελέσεων, την ανάλυση κατάστασης, την πρώτη και τελευταία ώρα εκτέλεσης και τη μέση διάρκεια. Ρωτήστε γιατί απέτυχε μια εκτέλεση ή τι επέστρεψε και το Chat ανοίγει αυτή τη μεμονωμένη εκτέλεση για να διαβάσει τις εισόδους, τις εξόδους και τα σφάλματα ανά node
- **Πού αποτυγχάνουν οι εκτελέσεις και γιατί είναι αργές** – Ρωτήστε πού αποτυγχάνουν τα workflow σας ή γιατί είναι αργά και το Chat κατονομάζει τα workflow που εκτελέστηκαν περισσότερο, απέτυχαν περισσότερο και είναι πιο αργά, καθώς και τους τύπους κόμβων που καταναλώνουν τον περισσότερο χρόνο (μέσος όρος ανά κλήση και σύνολο), αποτυγχάνουν περισσότερο και εκτελούνται περισσότερο, τους ίδιους αριθμούς με την καρτέλα [Analytics](./analytics-tab.md). Οι τύποι κόμβων καταμετρώνται για εκτελέσεις από την έκδοση που εισήγαγε τα αναλυτικά στοιχεία κόμβων. Ρωτήστε για την τελευταία ώρα, 3 ή 6 ώρες, 24 ώρες, 7 ή 30 ημέρες ή για όλο το διάστημα· τα ωριαία παράθυρα ξεκινούν στην αρχή της ώρας, επομένως «η τελευταία ώρα» στις 15:20 καλύπτει από τις 14:00 μέχρι τώρα.
- **Ζωντανή κατάσταση εκτέλεσης** – Ρωτήστε τι εκτελείται αυτή τη στιγμή και το Chat απαντά με τον αριθμό, τα ονόματα των workflows, πόσο διαρκεί κάθε εκτέλεση, σε ποιο node βρίσκεται και έναν σύνδεσμο απευθείας στη ζωντανή εκτέλεση
## Χρήση του Chat από έναν MCP Client

Ο μηχανισμός Chat μπορεί να προσεγγιστεί και εκτός του προγράμματος περιήγησης. Ενεργοποιήστε τον **Heym Agent** στην [καρτέλα MCP / A2A](./mcp-tab.md) και οι πελάτες MCP (Claude, Cursor και οποιοδήποτε άλλο εργαλείο συμβατό με MCP) αποκτούν ένα ενιαίο εργαλείο `heym_chat` που εκτελεί τον ίδιο μηχανισμό με όλες τις δυνατότητές του. Επιλέξτε επίσης **Ενεργοποίηση A2A** ώστε άλλοι agents να μπορούν να του στέλνουν εργασίες μέσω [A2A](../reference/a2a.md)· αυτές οι συνομιλίες εμφανίζουν ένα εικονίδιο δικτύου στη λίστα.

Οι συνομιλίες αυτές καταλήγουν στο ιστορικό αυτής της καρτέλας, επισημασμένες με ένα εικονίδιο plug στη λίστα συνομιλιών. Ανοίξτε μία για να διαβάσετε τι ζήτησε ο client, να δείτε τις κάρτες εργαλείων που ενεργοποιήθηκαν και να συνεχίσετε τη συζήτηση μόνοι σας. Η απάντηση σε μια ερώτηση διευκρίνισης λειτουργεί με τον ίδιο τρόπο είτε η σειρά ξεκίνησε εδώ είτε από έναν MCP client.

Μέσω MCP, το Chat δεν παραθέτει, δεν επιλέγει και δεν δημιουργεί διαπιστευτήρια. Τα workflows που δημιουργεί αφήνουν τα πεδία διαπιστευτηρίων κενά, και η απάντηση ονομάζει τους κόμβους που χρειάζονται διαπιστευτήριο, ώστε να τα ορίσετε στον editor.

Οι πίνακες δεδομένων λειτουργούν επίσης μέσω MCP: το Chat μπορεί να επεξεργάζεται απευθείας στήλες και γραμμές, να δημιουργεί πίνακες και να τους συνδέει σε workflow. Οι ερωτήσεις για πίνακες και οι επιβεβαιώσεις διαγραφής φτάνουν ως κείμενο στο αποτέλεσμα· απαντήστε με το ίδιο `conversation_id`.

## Όριο Πλαισίου

Το chat διατηρεί έως 25 πρόσφατα μηνύματα στο πλαίσιο. Τα παλαιότερα μηνύματα περικόπτονται για να παραμείνουν εντός των ορίων του μοντέλου.

## Δημιουργία Workflows

Όταν ζητάτε από το Chat να δημιουργήσει, να κατασκευάσει, να παράγει ή να ρυθμίσει ένα workflow, αυτό δημιουργεί ένα νέο αποθηκευμένο workflow με παραγόμενο όνομα και περιγραφή. Η απάντηση περιλαμβάνει μια προεπισκόπηση read-only του καμβά με τους παραγόμενους κόμβους και τις συνδέσεις, καθώς και έναν σύνδεσμο **Open workflow** που ανοίγει τον editor του workflow σε νέα καρτέλα του browser. Χρησιμοποιήστε το κουμπί **Run** της κάρτας προεπισκόπησης όταν θέλετε να εκτελέσετε το workflow.

Τα σχόλια συνέχειας στην ίδια συνομιλία επεξεργάζονται αυτό το workflow αντί να δημιουργήσουν ένα άλλο. Για παράδειγμα, αφού το Chat δημιουργήσει ένα workflow, μπορείτε να πείτε "add an approval step", "change the output format" ή "şöyle yap" και το Chat ενημερώνει το αποθηκευμένο workflow και ανανεώνει την προεπισκόπηση.

Αυτό είναι ιδανικό για αιτήματα όπου θέλετε η εργασία να γίνει ως επαναχρησιμοποιήσιμη αυτοματοποίηση, όχι απλώς ως μεμονωμένη απάντηση.

## Δημιουργία Εργασιών Kanban

Ζητήστε από το Chat σε καθημερινή γλώσσα, για παράδειγμα, "Add a task called Fix login bug" ή
"Create a new card Update documentation on the Launch board." Μπορείτε να συμπεριλάβετε μια
περιγραφή στο ίδιο αίτημα. Το Chat δημιουργεί πάντα την κάρτα στην πρώτη στήλη του επιλεγμένου
board.

Εάν ο χώρος εργασίας σας έχει πολλά boards και δεν προσδιορίσετε κάποιο, το Chat διακόπτεται με έναν
επιλογέα board μονής επιλογής. Επιλέξτε ένα board για να ολοκληρωθεί η δημιουργία της κάρτας. Δεν
απαιτείται slash command ή ειδική μορφή μηνύματος.

## Ερώτηση για το Τι Εκτελείται

Ρωτήστε σε καθημερινή γλώσσα — "what is running;", "how many workflows are active right now;",
"which node is the nightly report on;" — και το Chat αναφέρει την τρέχουσα εικόνα:

- **Πόσες** εκτελέσεις βρίσκονται σε εξέλιξη, χωρισμένες σε running και awaiting human review
- **Σε ποια workflows** ανήκουν, ονομαστικά
- **Πόσο καιρό** διαρκεί κάθε εκτέλεση (για παράδειγμα `1m 35s`, `3h 25m`)
- **Ποιος κόμβος** εκτελείται αυτή τη στιγμή, με την ετικέτα του στον καμβά, καθώς και ο τελευταίος κόμβος που ολοκληρώθηκε
- **Έναν σύνδεσμο** προς κάθε ενεργή εκτέλεση, που ανοίγει τον καμβά με αυτή την εκτέλεση σε αναπαραγωγή

Οι εκτελέσεις που έχουν παυθεί για [Human-in-the-Loop](../reference/human-in-the-loop.md) ή Codex review αναφέρονται ως
σε αναμονή για εσάς, όχι ως running. Πρόκειται για τα ίδια δεδομένα με το badge ενεργών εκτελέσεων στην κεφαλίδα,
οπότε το Chat και το badge δεν διαφωνούν ποτέ. Για εκτελέσεις που έχουν ήδη ολοκληρωθεί, ζητήστε πρόσφατες εκτελέσεις
αντί αυτού — αυτό διαβάζει το [Execution History](../reference/execution-history.md).

## Εργασία με το Evals

Το Chat μπορεί να δημιουργεί, να τροποποιεί και να εκτελεί τις σουίτες στο [Evals](./evals-tab.md), τόσο σουίτες prompt όσο και σουίτες agent:

- **Σουίτα prompt**: «δημιούργησε μια σουίτα prompt για το prompt απάντησης υποστήριξης με 8 περιπτώσεις δοκιμής και σύγκρινε το gpt-4o με το gpt-4.1-mini». Το Chat συντάσσει τις περιπτώσεις δοκιμής με τις αναμενόμενες απαντήσεις τους, επιλέγει μια μέθοδο βαθμολόγησης και αποθηκεύει τη σουίτα.
  - Πριν δημιουργήσει τη σουίτα, καθορίζει ποιο διαπιστευτήριο LLM και ποια μοντέλα θα χρησιμοποιηθούν. Με ακριβώς ένα διαπιστευτήριο LLM, χρησιμοποιεί αυτό και το αναφέρει· διαφορετικά ρωτά.
  - Για τη βαθμολόγηση LLM-as-Judge, ρωτά επίσης εάν ένας ξεχωριστός κριτής θα πρέπει να αξιολογήσει τις απαντήσεις.
- **Σουίτα agent**: «έλεγξε ότι ο agent υποστήριξης αναζητά πάντα στα έγγραφα και δεν στέλνει ποτέ email». Το Chat εντοπίζει τον agent και αποθηκεύει τους ελέγχους εργαλείων και τα όρια. Όταν το ζητήσετε, εκτελεί το workflow, δημιουργώντας διαφορετική είσοδο για κάθε εκτέλεση.
  - Οι εκτελέσεις σουίτας agent είναι πραγματικές εκτελέσεις workflow, επομένως οι παρενέργειές τους συμβαίνουν κανονικά. Το Chat αναφέρει πόσες εκτελέσεις ξεκινά.
- **Baseline**: Το Chat μπορεί να επεξεργαστεί τη γραμμή βάσης ενός agent με τρεις τρόπους:
  - Να την αναφέρει από τις πιο πρόσφατες εκτελέσεις του agent.
  - Να την κατασκευάσει από εκτελέσεις που ξεκινά το ίδιο («εκτέλεσέ το 5 φορές και χρησιμοποίησέ το ως baseline»).
  - Να αποθηκεύσει αριθμούς που του δίνετε («όρισε το baseline σε 3 δευτερόλεπτα p95 και 0,01 $ ανά εκτέλεση»).
- **Εκτελέσεις**: Το Chat περιμένει έως και ένα λεπτό για μια εκτέλεση και στη συνέχεια αναφέρει το αποτέλεσμα:
  - Για μια σουίτα prompt: τον αριθμό επιτυχιών κάθε μοντέλου και τις περιπτώσεις που απέτυχαν.
  - Για μια σουίτα agent: το ποσοστό επιτυχίας, τους αποτυχημένους ελέγχους και την απόκλιση από τη γραμμή βάσης.
  - Μια μεγαλύτερη εκτέλεση συνεχίζεται στο Evals· ζητήστε από το Chat να την ελέγξει ξανά.

Αφού το Chat δημιουργήσει ή αλλάξει μια σουίτα, η απάντηση εμφανίζει μια κάρτα με το όνομα της σουίτας, τον τύπο της και ένα κουμπί **Άνοιγμα στο Evals**, όπως η κάρτα ενός αποθηκευμένου workflow. Μέσω MCP, το αποτέλεσμα του `heym_chat` παραθέτει τον σύνδεσμο κάθε σουίτας που αποθηκεύτηκε σε αυτήν την κλήση.

Το ίδιο λειτουργεί από έναν πελάτη MCP μέσω του `heym_chat` (δείτε [Χρήση του Chat από έναν πελάτη MCP](#χρήση-του-chat-από-έναν-πελάτη-mcp)). Τα εργαλεία αξιολόγησης παραμένουν εντός του `heym_chat`· οι πελάτες MCP δεν τα βλέπουν ως ξεχωριστά εργαλεία.

Ο Βοηθός AI του επεξεργαστή δεν δημιουργεί σουίτες.

- **Σουίτα prompt**: «δημιούργησε μια σουίτα prompt για το prompt απάντησης υποστήριξης με 8 περιπτώσεις δοκιμής και σύγκρινε το gpt-4o με το gpt-4.1-mini». Το Chat συντάσσει τις περιπτώσεις δοκιμής με τις αναμενόμενες απαντήσεις τους, επιλέγει μια μέθοδο βαθμολόγησης και αποθηκεύει τη σουίτα.
  - Πριν δημιουργήσει τη σουίτα, καθορίζει ποιο διαπιστευτήριο LLM και ποια μοντέλα θα χρησιμοποιηθούν. Με ακριβώς ένα διαπιστευτήριο LLM, χρησιμοποιεί αυτό και το αναφέρει· διαφορετικά ρωτά.
  - Για τη βαθμολόγηση LLM-as-Judge, ρωτά επίσης εάν ένας ξεχωριστός κριτής θα πρέπει να αξιολογήσει τις απαντήσεις.
- **Σουίτα agent**: «έλεγξε ότι ο agent υποστήριξης αναζητά πάντα στα έγγραφα και δεν στέλνει ποτέ email». Το Chat εντοπίζει τον agent και αποθηκεύει τους ελέγχους εργαλείων και τα όρια. Όταν το ζητήσετε, εκτελεί το workflow, δημιουργώντας διαφορετική είσοδο για κάθε εκτέλεση.
  - Οι εκτελέσεις σουίτας agent είναι πραγματικές εκτελέσεις workflow, επομένως οι παρενέργειές τους συμβαίνουν κανονικά. Το Chat αναφέρει πόσες εκτελέσεις ξεκινά.
- **Baseline**: Το Chat μπορεί να επεξεργαστεί τη γραμμή βάσης ενός agent με τρεις τρόπους:
  - Να την αναφέρει από τις πιο πρόσφατες εκτελέσεις του agent.
  - Να την κατασκευάσει από εκτελέσεις που ξεκινά το ίδιο («εκτέλεσέ το 5 φορές και χρησιμοποίησέ το ως baseline»).
  - Να αποθηκεύσει αριθμούς που του δίνετε («όρισε το baseline σε 3 δευτερόλεπτα p95 και 0,01 $ ανά εκτέλεση»).
- **Εκτελέσεις**: Το Chat περιμένει έως και ένα λεπτό για μια εκτέλεση και στη συνέχεια αναφέρει το αποτέλεσμα:
  - Για μια σουίτα prompt: τον αριθμό επιτυχιών κάθε μοντέλου και τις περιπτώσεις που απέτυχαν.
  - Για μια σουίτα agent: το ποσοστό επιτυχίας, τους αποτυχημένους ελέγχους και την απόκλιση από τη γραμμή βάσης.
  - Μια μεγαλύτερη εκτέλεση συνεχίζεται στο Evals· ζητήστε από το Chat να την ελέγξει ξανά.

Αφού το Chat δημιουργήσει ή αλλάξει μια σουίτα, η απάντηση εμφανίζει μια κάρτα με το όνομα της σουίτας, τον τύπο της και ένα κουμπί **Άνοιγμα στο Evals**, όπως η κάρτα ενός αποθηκευμένου workflow. Μέσω MCP, το αποτέλεσμα του `heym_chat` παραθέτει τον σύνδεσμο κάθε σουίτας που αποθηκεύτηκε σε αυτήν την κλήση.

Το ίδιο λειτουργεί από έναν πελάτη MCP μέσω του `heym_chat` (δείτε [Χρήση του Chat από έναν πελάτη MCP](#χρήση-του-chat-από-έναν-πελάτη-mcp)). Τα εργαλεία αξιολόγησης παραμένουν εντός του `heym_chat`· οι πελάτες MCP δεν τα βλέπουν ως ξεχωριστά εργαλεία.

Ο Βοηθός AI του επεξεργαστή δεν δημιουργεί σουίτες.

## Ερωτήσεις σχετικά με μια εκτέλεση

Επιλέξτε μια εκτέλεση Workflow στο [Execution History](../reference/execution-history.md#ask-ai), από το πρόγραμμα επεξεργασίας ή από το All History, και κάντε κλικ στο **Ρωτήστε το AI** δίπλα στον τίτλο του διαλόγου. Το Chat ανοίγει μια νέα συνομιλία με δύο τσιπ πάνω από το πλαίσιο μηνύματος:

- **Workflow:** το όνομα του Workflow
- **Execution:** τους πρώτους χαρακτήρες του αναγνωριστικού της επιλεγμένης εκτέλεσης

Αφαιρέστε ένα τσιπ με το **×** του για να το παραλείψετε. Στη συνέχεια, κάντε την ερώτησή σας, για παράδειγμα «γιατί αυτή η εκτέλεση διήρκεσε τόσο πολύ;», «τι απέτυχε εδώ;» ή «μπορείτε να το διορθώσετε;». Τα υπόλοιπα τσιπ προσαρτώνται σε αυτό το μήνυμα με τα πλήρη αναγνωριστικά, ώστε το Chat να διαβάζει απευθείας τις εισόδους, τις εξόδους και το ίχνος ανά κόμβο της εκτέλεσης αντί να αναζητά το Workflow. Για να διορθώσει το Workflow, το Chat αποθηκεύει, εκτελεί δοκιμές και επαληθεύει την αλλαγή όπως περιγράφεται στη [Δημιουργία Workflows](#dimiourgia-workflows).

Το απεσταλμένο μήνυμα εμφανίζει τα τσιπ κάτω από την ερώτησή σας. Ανήκουν μόνο σε αυτό το μήνυμα· οι επόμενες ερωτήσεις στην ίδια συνομιλία διατηρούν το περιβάλλον από το ιστορικό.

## Ερώτηση για τις Ειδοποιήσεις

Το Chat μπορεί να απαντήσει σε ερωτήσεις σχετικά με τις [ειδοποιήσεις](./alerts-tab.md) που έχετε ορίσει:

- **Τι υπάρχει** — "what alerts do I have;", "is there an alert on the invoice workflow;",
  "which alerts are firing right now;"
- **Πώς έχει ρυθμιστεί μία** — "what is the threshold on the cost alert;", "how is that configured;"
- **Γιατί και πότε ενεργοποιήθηκε** — "why did the cost alert fire;", "when did this last trigger;"

Για μια ερώτηση "why did it fire", το Chat διαβάζει το αρχείο ενεργοποίησης και παραθέτει την πραγματική παρατηρούμενη
τιμή, το όριο και το ακριβές παράθυρο που αξιολογήθηκε, καθώς και τη σχετική λεπτομέρεια:
αναγνωριστικά αποτυχημένων εκτελέσεων και μηνύματα σφάλματος για ειδοποιήσεις σφαλμάτων, δαπάνη ανά μοντέλο για ειδοποιήσεις κόστους ή
την ανάλυση ανά πηγή trigger για ειδοποιήσεις πλήθους εκτελέσεων. Αναφέρει τι ίσχυε όταν ενεργοποιήθηκε η ειδοποίηση
αντί να επαναϋπολογίζει το παράθυρο, επειδή το παράθυρο έχει παρέλθει και ένας νέος υπολογισμός
μπορεί να δώσει διαφορετική απάντηση.

## Κλήσεις εργαλείων και μέγεθος context

Κάθε φορά που ο βοηθός καλεί ένα εργαλείο (εκτέλεση workflow, παράθεση εκτελέσεων, δημιουργία νέου workflow), εμφανίζεται μια αναδιπλούμενη κάρτα στη συνομιλία. Η κάρτα αναπτύσσεται αυτόματα όσο εκτελείται το εργαλείο, εμφανίζοντας τα ακριβή ορίσματα. Όταν το εργαλείο ολοκληρωθεί, η κάρτα συμπτύσσεται σε σύνοψη μίας γραμμής με τον χρόνο εκτέλεσης. Κάντε κλικ σε οποιαδήποτε κάρτα για να αναπτύξετε ξανά τα ορίσματα και τη σύνοψη της απάντησης.

Ένα μικρό κυκλικό badge κάτω από το πεδίο εισαγωγής εμφανίζει την τρέχουσα χρήση context ως ποσοστό του παραθύρου του μοντέλου (π.χ. `12% · ~9.2k`). Τοποθετήστε τον δείκτη πάνω από το badge για να δείτε ανάλυση: system prompt, AGENTS.md, workflows block, user rules, ιστορικό και το πρόχειρο κείμενό σας. Όταν η χρήση ξεπεράσει το 80%, ο δακτύλιος γίνεται πορτοκαλί· στο 95% γίνεται κόκκινος.

Εάν η χρήση πλησιάσει το όριο, το Heym συμπιέζει αυτόματα τα παλαιότερα μηνύματα σε μια σύντομη σύνοψη χρησιμοποιώντας τον ίδιο μηχανισμό που χρησιμοποιούν οι κόμβοι agent. Μια κάρτα "Context compressed" εμφανίζεται ενσωματωμένη για να δείξει τι συνέβη.
