# Καρτέλα MCP / A2A / A2A

Η καρτέλα **MCP** ρυθμίζει την ενσωμάτωση του Model Context Protocol (MCP), και ως διακομιστές [Agent2Agent](https://github.com/google/A2A) (A2A 1.0) στους οποίους άλλοι agents μπορούν να αναθέτουν εργασίες. Το MCP επιτρέπει σε AI clients (Claude, ChatGPT, Gemini, Cursor και οποιοδήποτε εργαλείο συμβατό με MCP) να καλούν τα workflows σας στο Heym ως εργαλεία.

Το Heym υποστηρίζει δύο λειτουργίες: έναν **default server** που εκθέτει όλα τα workflows με ενεργοποιημένο MCP κάτω από ένα μοναδικό endpoint, και **named servers** που παρέχουν σε κάθε λογική ομάδα workflows το δικό της αποκλειστικό URL και API key.

Και οι δύο λειτουργίες μπορούν να εκθέσουν δύο είδη εργαλείων: μεμονωμένα **workflows** και το **Heym chat tool** — ολόκληρη τη μηχανή της [Καρτέλας Chat](./chat-tab.md) πίσω από ένα εργαλείο `heym_chat`.

## Default MCP Server

Ο default server είναι πάντα διαθέσιμος στη διεύθυνση `{origin}/api/mcp/sse`. Όλα τα workflows με ενεργοποιημένο MCP εμφανίζονται εδώ ως εργαλεία.

### MCP API Key

- Τα keys αποθηκεύονται ως SHA-256 digests, επομένως το Heym δεν μπορεί να σας εμφανίσει ένα υπάρχον key. Η καρτέλα αναφέρει αν έχει οριστεί κάποιο, όχι ποιο είναι.
- **Generate** / **Regenerate** – Το νέο key εμφανίζεται μία φορά, αμέσως μετά τη δημιουργία του. Αντιγράψτε το τότε· η επαναφόρτωση της καρτέλας το αποκρύπτει οριστικά.
- Χρησιμοποιήστε αυτό το key κατά τη σύνδεση του Claude Desktop, του Cursor ή άλλων MCP clients με το Heym
- Χάσατε ένα key; Δημιουργήστε το ξανά. Το προηγούμενο key σταματά να λειτουργεί αμέσως.

### Μέθοδοι Σύνδεσης

- **API Key** – Χρησιμοποιήστε το MCP API key για προγραμματιστικές συνδέσεις. Η καρτέλα μπορεί να αντιγράψει ένα έτοιμο προς χρήση JSON config και περιλαμβάνει κουμπί **Add to Cursor** για ρύθμιση του Cursor με ένα κλικ.
- **Claude** – Η καρτέλα εμφανίζει το URL του MCP server και τα βήματα ρύθμισης για το Claude. Αφήστε τα πεδία OAuth Client ID και Secret κενά· το Claude καταχωρείται αυτόματα και πιστοποιείται μέσω Heym OAuth.
- **ChatGPT** – Η καρτέλα εμφανίζει το URL του MCP server και τα βήματα ρύθμισης για μια εφαρμογή ChatGPT. Ενεργοποιήστε το Developer mode, δημιουργήστε μια εφαρμογή με το URL και επιλέξτε OAuth· το ChatGPT εγγράφεται αυτόματα.
- **Gemini** – Η καρτέλα εμφανίζει το URL του MCP server και τα βήματα ρύθμισης για μια προσαρμοσμένη εφαρμογή Gemini: στο gemini.google.com, μεταβείτε στα **Settings → Connected Apps → Add a custom app**, επικολλήστε το URL και αφήστε το **Advanced features** κλειστό· το Gemini εγγράφεται αυτόματα και πραγματοποιεί έλεγχο ταυτότητας μέσω Heym OAuth. Μόλις συνδεθεί, το Heym λειτουργεί επίσης στην εφαρμογή Gemini για κινητά.

### Διακόπτης MCP Workflow

Κάθε workflow μπορεί να εκτεθεί ως εργαλείο MCP:

- **Enable** – Τα εργαλεία του workflow γίνονται διαθέσιμα σε όλους τους clients που είναι συνδεδεμένοι στον default server
- **Disable** – Το workflow δεν εκτίθεται

Οι κάρτες workflow εμφανίζουν την περιγραφή και μια προεπισκόπηση των ονομάτων πεδίων εισόδου, ώστε να βλέπετε τι αναμένει κάθε εργαλείο πριν το ενεργοποιήσετε.


### Εκτελέσεις σε ουρά και heym_execution_status

Ένα workflow με [όριο ταυτόχρονης εκτέλεσης](../reference/webhooks.md#concurrency-limit-and-queued-runs) μπορεί να είναι απασχολημένο όταν το καλεί ένας client. Η κλήση επιστρέφει αμέσως ένα αποτέλεσμα που δεν αποτελεί σφάλμα:

```json
{
  "status": "queued",
  "execution_id": "6f1c0c2e-...",
  "queue": { "position": 2, "size": 5, "running": 1, "limit": 1 },
  "next_step": "Call heym_execution_status with this execution_id every 5-10 seconds until status is success, error, cancelled or expired."
}
```

Ο client υποβάλλει ερωτήματα στο εργαλείο `heym_execution_status` με αυτό το `execution_id`. Επιστρέφει το ίδιο σώμα με το [URL κατάστασης](../reference/webhooks.md#status-url): `queued` με την τρέχουσα θέση, `running`, και στη συνέχεια `success` ή `error` με τα αποτελέσματα. Εντοπίζει μόνο εκτελέσεις workflows που εκθέτει ο ίδιος server. Το εργαλείο παρατίθεται στον προεπιλεγμένο server και σε κάθε επώνυμο server μόνο εφόσον τουλάχιστον ένα από τα workflows του διαθέτει όριο ταυτόχρονης εκτέλεσης. Όταν η ουρά είναι πλήρης, η κλήση επιστρέφει σφάλμα "Concurrency queue is full".
## Heym Agent

Η ενότητα **Heym Capabilities** μετατρέπει τη μηχανή της Καρτέλας Chat σε ένα μοναδικό εργαλείο MCP με όνομα `heym_chat`. Ενεργοποιήστε το στον default server, σε οποιονδήποτε named server ή και στα δύο — κάθε επιφάνεια διατηρεί τον δικό της διακόπτη και επιλογή μοντέλου.

Όταν είναι ενεργό, το `heym_chat` εμφανίζεται στο `tools/list` μαζί με τα εργαλεία των workflows σας. Ένας MCP client στέλνει ένα μήνυμα σε φυσική γλώσσα και η μηχανή του Heym αναλαμβάνει από εκεί, με τις ίδιες δυνατότητες που έχει η Καρτέλα Chat:

- Δημιουργία ενός workflow, δοκιμαστική εκτέλεση με ενδεικτικές εισόδους, διόρθωση και ολοκλήρωση όταν μια εκτέλεση επιτύχει (δείτε [Λειτουργία κατασκευής](#build-mode))
- Επιθεώρηση και εκτέλεση των υπαρχόντων workflows σας
- Αναφορά analytics, πρόσφατων εκτελέσεων και επερχόμενων χρονοδιαγραμμάτων cron
- Εξήγηση του πού αποτυγχάνουν τα workflows και γιατί είναι αργά: τα workflows που εκτελέστηκαν συχνότερα, απέτυχαν περισσότερο και είναι πιο αργά, καθώς και οι τύποι κόμβων με τον περισσότερο χρόνο, σφάλματα και κλήσεις τις τελευταίες 1, 3 ή 6 ώρες, 24 ώρες, 7 ή 30 ημέρες ή διαχρονικά
- Αναφορά του ιστορικού εκτέλεσης ενός workflow: πόσες φορές εκτελέστηκε, πλήθος καταστάσεων, πότε εκτελέστηκε και, κατόπιν αιτήματος, τα inputs, τα outputs και τα σφάλματα ανά node μιας μεμονωμένης εκτέλεσης
- Αναφορά του τι εκτελείται αυτή τη στιγμή: πόσες εκτελέσεις είναι ενεργές, τα ονόματα των workflows τους, πόσο καιρό εκτελείται η καθεμία, σε ποιο node βρίσκεται αυτή τη στιγμή και έναν σύνδεσμο προς τη ζωντανή εκτέλεση
- Καταγραφή boards, δημιουργία καρτών και ανάγνωση λεπτομερειών κάρτας στην [Καρτέλα Board](./board-tab.md)
- Καταγραφή των dashboards (σελίδες του Heym Work) και των widgets τους, εντοπισμός του dashboard στο οποίο ανήκει ένα workflow, προσθήκη νέου widget και δημιουργία του workflow του, τοποθέτηση υπάρχοντος workflow ως widget, μετονομασία ή διαγραφή widgets ή τακτοποίηση διάταξης (βλ. [Dashboard › Από Chat και MCP](./dashboard-tab.md#from-chat-and-mcp))
- Επιθεώρηση πινάκων δεδομένων και γραμμών, δημιουργία πινάκων, προσθήκη ή αφαίρεση στηλών, εισαγωγή, ενημέρωση ή διαγραφή γραμμών και σύνδεση πινάκων σε workflows
- Δημιουργία, επεξεργασία και εκτέλεση σουιτών αξιολόγησης prompts και agents ([Eval suites](./evals-tab.md#from-chat-and-mcp)), συμπεριλαμβανομένης της γραμμής βάσης ενός agent: καταγεγραμμένη, κατασκευασμένη από εκτελέσεις ή αριθμητικά καθορισμένη. Το αποτέλεσμα παραθέτει τον σύνδεσμο Evals κάθε αποθηκευμένης σουίτας.
- Δημιουργία ή ενημέρωση των διαπιστευτηρίων σας στην ειδική σελίδα του Heym (δείτε [Διαπιστευτήρια](#διαπιστευτήρια))
- Ανάγνωση teams και global variables και αναζήτηση στην τεκμηρίωση
- Έγκριση, επεξεργασία ή απόρριψη εκκρεμών ελέγχων human-in-the-loop

Οι δυνατότητες που προστίθενται στην Καρτέλα Chat αργότερα γίνονται διαθέσιμες μέσω του `heym_chat` αυτόματα — δεν υπάρχει διακόπτης ανά δυνατότητα προς συγχρονισμό.

Αυτές οι δυνατότητες εκτελούνται εντός του `heym_chat`: το `tools/list` εμφανίζει το `heym_chat` και τα εργαλεία των workflows σας, ποτέ τα εσωτερικά εργαλεία του chat όπως αυτά των σουιτών αξιολόγησης.

### Λειτουργία κατασκευής

Το `heym_chat` εκτελεί πάντα τη μηχανή Chat σε λειτουργία κατασκευής (build mode). Σε μία κλήση ο βοηθός μπορεί να αποθηκεύσει ένα νέο workflow, να το εκτελέσει με ρεαλιστικές ενδεικτικές εισόδους, να διαβάσει την αναφορά εκτέλεσης, να διορθώσει ό,τι απέτυχε και να το εκτελέσει ξανά, έως πέντε δοκιμαστικές εκτελέσεις ανά κλήση. Όταν η τελευταία εκτέλεση της τελευταίας αποθήκευσης επιτύχει, ολοκληρώνει με μια σύνοψη μίας πρότασης και η απάντηση τελειώνει με `Verified: the latest test run of the saved workflow passed.`

Όταν μια κλήση δημιουργεί ή επεξεργάζεται ένα workflow, η απάντηση παραθέτει το καθένα με τον πλήρη σύνδεσμο του προγράμματος επεξεργασίας, όπως `https://heym.example.com/workflows/<id>`, και οι σύνδεσμοι μέσα στην απάντηση του βοηθού είναι επίσης πλήρεις σύνδεσμοι. Χρησιμοποιούν τη ρυθμισμένη διεύθυνση Heym (`FRONTEND_URL`) και ανοίγουν για συνδεδεμένα άτομα που έχουν πρόσβαση σε αυτό το workflow.

- Οι δοκιμαστικές εκτελέσεις είναι πραγματικές εκτελέσεις. Οι παρενέργειές τους συμβαίνουν κανονικά και εμφανίζονται στο ιστορικό εκτελέσεων του workflow όπως κάθε άλλη εκτέλεση.
- Οι αποθηκεύσεις ακολουθούν τη διαδρομή του επεξεργαστή: μια αλλαγή στο γράφημα διατηρεί το προηγούμενο γράφημα στο **Edit History** του workflow.
- Για να αλλάξετε ένα workflow που κατασκεύασε νωρίτερα, συνεχίστε το νήμα με το ίδιο `conversation_id`. Ο βοηθός ενημερώνει αυτό το workflow αντί να δημιουργήσει νέο και αλλάζει μόνο workflows που μπορείτε να επεξεργαστείτε.
- Όταν εξαντληθούν οι πέντε δοκιμαστικές εκτελέσεις, ο βοηθός σταματά και εξηγεί τι εξακολουθεί να αποτυγχάνει.

Οι πίνακες δεδομένων είναι διαφορετικοί. Ένας πίνακας δεν περιέχει μυστικά, επομένως το `heym_chat` μπορεί να καταγράψει τους πίνακές σας, να ρωτήσει ποιον πρέπει να χρησιμοποιήσει ένα workflow και να δημιουργήσει έναν νέο με τις στήλες του. Δεν διαβάζει και δεν γράφει ποτέ γραμμές.

### Διαπιστευτήρια

Το `heym_chat` βλέπει τα διαπιστευτήρια που σας ανήκουν και εκείνα που έχουν κοινοποιηθεί σε εσάς, κατά όνομα και τύπο, όπως ακριβώς και η καρτέλα Chat. Όταν ένα workflow που δημιουργεί χρειάζεται διαπιστευτήριο, ρωτά ποιο να χρησιμοποιήσει ως ερώτηση στο αποτέλεσμα. Απαντήστε με το ίδιο `conversation_id`.

Για να προσθέσετε ένα διαπιστευτήριο ή να ενημερώσετε ένα δικό σας, ο βοηθός ανοίγει τη φόρμα διαπιστευτηρίων του Heym σε μια σελίδα Heym, `/credentials/setup/<id>`. Συνδέεστε στο Heym εκεί, εισάγετε το κλειδί ή συνδέετε τον λογαριασμό και αποθηκεύετε. Η τιμή πηγαίνει απευθείας στο Heym: ο MCP client και το μοντέλο του μαθαίνουν μόνο το όνομα και τον τύπο του διαπιστευτηρίου. Μην επικολλάτε κλειδιά στον MCP client· ζητήστε τη φόρμα.

| Client | Τι συμβαίνει |
|--------|--------------|
| Υποστηρίζει εξαγωγή MCP URL | Ο client σας ζητά να ανοίξετε τη σελίδα Heym. Η κλήση περιμένει όσο συμπληρώνετε τη φόρμα (έως δέκα λεπτά) και μετά συνεχίζει με το νέο διαπιστευτήριο. |
| Οποιοσδήποτε άλλος | Το αποτέλεσμα φέρει τον σύνδεσμο και ζητά από τον client να καλέσει ξανά το `heym_chat` με `wait_for_credential_form`. Αυτή η κλήση περιμένει έως πέντε λεπτά όσο συμπληρώνετε τη φόρμα και μετά συνεχίζει τη συνομιλία. Εάν ο client δεν περιμένει, αποθηκεύστε τη φόρμα και απαντήστε με το ίδιο `conversation_id`· η επόμενη κλήση θα γνωρίζει ότι η φόρμα αποθηκεύτηκε και ποιο διαπιστευτήριο δημιουργήθηκε. |

Η σελίδα ανοίγει μόνο για τον λογαριασμό Heym που ξεκίνησε το αίτημα, επομένως ένας προωθημένος σύνδεσμος είναι άχρηστος σε οποιονδήποτε άλλον. Μια φόρμα παραμένει ανοιχτή για 24 ώρες και μπορείτε να την απορρίψετε από τη σελίδα. Μόλις την αποθηκεύσετε ή την απορρίψετε, το βήμα στη συνομιλία της καρτέλας Chat εμφανίζει το αποτέλεσμα.


### Διαπιστευτήριο και μοντέλο

Το `heym_chat` εκτελεί τη μηχανή στον λογαριασμό σας στο Heym, επομένως χρειάζεται δικό του διαπιστευτήριο LLM:

| Πεδίο | Συμπεριφορά |
|-------|----------|
| **Credential** | Επιλέξτε οποιοδήποτε διαπιστευτήριο OpenAI, Google ή Custom στο οποίο έχετε πρόσβαση. Προσυμπληρώνεται από το προτιμώμενο διαπιστευτήριο στις [Ρυθμίσεις](../reference/user-settings.md) όταν δεν έχετε επιλέξει κάποιο. |
| **Model** | Φορτώνεται από το επιλεγμένο διαπιστευτήριο. Προσυμπληρώνεται από το προτιμώμενο μοντέλο σας όταν το διαπιστευτήριο ταιριάζει. |

Εάν λείπει οποιοδήποτε από τα δύο, το εργαλείο εξακολουθεί να εμφανίζεται στο `tools/list`, αλλά κάθε κλήση επιστρέφει σφάλμα που σας ενημερώνει να ολοκληρώσετε τη ρύθμιση σε αυτή την καρτέλα.


Οι κόμβοι LLM και Agent σε ένα workflow που δημιουργεί το `heym_chat` εκτελούνται με αυτό το διαπιστευτήριο και μοντέλο, συμπεριλαμβανομένου ενός διαπιστευτηρίου που έχει κοινοποιηθεί σε εσάς, ώστε οι δοκιμαστικές εκτελέσεις να λειτουργούν χωρίς επιπλέον βήμα ρύθμισης. Όταν το `heym_chat` επεξεργάζεται ένα workflow, οι κόμβοι LLM και Agent που έχουν ήδη διαπιστευτήριο το διατηρούν μαζί με το μοντέλο τους.
### Ορίσματα και ιστορικό

| Όρισμα | Απαιτείται | Περιγραφή |
|----------|----------|-------------|
| `message` | Ναι | Η οδηγία ή η ερώτηση, σε φυσική γλώσσα. |
| `conversation_id` | Όχι | Ένα `conversation_id` από προηγούμενο αποτέλεσμα `heym_chat`, για συνέχιση αυτού του νήματος. |
| `wait_for_credential_form` | Όχι | Με `conversation_id`: αναμονή μέχρι ο χρήστης να αποθηκεύσει ή να απορρίψει τη φόρμα διαπιστευτηρίων που άνοιξε το νήμα και μετά αποστολή του `message`. |

Κάθε κλήση καταγράφεται στο ιστορικό της [Καρτέλας Chat](./chat-tab.md) ως κανονική συνομιλία, σημειωμένη με εικονίδιο βύσματος στη λίστα συνομιλιών. Τα μηνύματα, οι κάρτες εργαλείων και οι παύσεις διευκρίνισης εμφανίζονται ακριβώς όπως μια συνομιλία που ξεκινήσατε εσείς, και μπορείτε να ανοίξετε το νήμα και να συνεχίσετε να μιλάτε στον browser. Κάθε αποτέλεσμα επιστρέφει το `conversation_id` του, ώστε ο MCP client να συνεχίζει το ίδιο νήμα αντί να ανοίγει νέο σε κάθε κλήση.

Όταν ο βοηθός χρειάζεται διευκρίνιση, κάνει παύση και το αναφέρει· απαντήστε με τις απαντήσεις χρησιμοποιώντας το ίδιο `conversation_id`.
### Ενεργοποίηση A2A

Ενώ ο Heym Agent είναι ενεργοποιημένος, η κάρτα εμφανίζει το πλαίσιο ελέγχου **Ενεργοποίηση A2A**. Επιλέξτε το και άλλοι agents θα μπορούν να στέλνουν εργασίες στον Heym Agent μέσω του πρωτοκόλλου Agent2Agent (A2A 1.0). Στη συνέχεια, η κάρτα εμφανίζει τη διεύθυνση URL της **Agent Card** και το **JSON-RPC endpoint**, το καθένα με κουμπί αντιγραφής, καθώς και μια εντολή `curl` για τη λήψη της κάρτας. Το A2A χρησιμοποιεί το ίδιο κλειδί και σύνδεση OAuth με το MCP. Η απενεργοποίηση του agent απενεργοποιεί επίσης το A2A. Δείτε το [A2A](../reference/a2a.md) για μεθόδους, καταστάσεις εργασιών και ένα παράδειγμα.

### Πρόοδος

Μια εκτεταμένη κλήση του `heym_chat` αναφέρει τη δραστηριότητα του agent ως πρόοδο MCP (`notifications/progress`), με τις ίδιες διατυπώσεις που εμφανίζονται στην καρτέλα Chat, για παράδειγμα `Δοκιμή του workflow · προσπάθεια 2/5`. Οι πελάτες που επαναφέρουν το χρονικό όριο κατά την αναφορά προόδου συνεχίζουν να περιμένουν όσο εργάζεται ο agent.

## Ονομαστικοί MCP Servers

Οι ονομαστικοί servers σάς επιτρέπουν να τμηματοποιείτε τα workflows σε απομονωμένα MCP endpoints. Κάθε server διαθέτει το δικό του URL και API key, ώστε διαφορετικοί AI clients, ομάδες ή περιπτώσεις χρήσης να μπορούν να συνδέονται ακριβώς στα workflows που χρειάζονται.

### Δημιουργία Ονομαστικού Server

1. Πληκτρολογήστε ένα όνομα στο πεδίο εισαγωγής στο κάτω μέρος της καρτέλας MCP (π.χ. **CRM Tools**)
2. Κάντε κλικ στο **Create** — μια νέα κάρτα server εμφανίζεται αμέσως
3. Κάντε κλικ στην κάρτα για να την αναπτύξετε

### Ρυθμίσεις ανά Server

Κάθε κάρτα server εμφανίζει:

| Ρύθμιση | Περιγραφή |
|---------|-------------|
| **SSE Endpoint** | Μοναδικό URL: `{origin}/api/mcp/servers/{uuid}/sse` |
| **API Key** | Ανεξάρτητο key, εμφανίζεται μία φορά κατά τη δημιουργία ή την εκ νέου δημιουργία του. Αντιγράψτε το αμέσως· αποθηκεύεται hashed και δεν μπορεί να αποκαλυφθεί αργότερα |
| **How to connect** | Το **Copy JSON** αντιγράφει το έτοιμο προς επικόλληση MCP config· το **Add to Cursor** το εγκαθιστά με ένα κλικ |
| **Heym Capabilities** | Ενεργοποιήστε ή απενεργοποιήστε τον Heym Agent (`heym_chat`) για αυτόν τον διακομιστή και επιλέξτε credential και μοντέλο |
| **Ενεργοποίηση A2A** | Ο αποκλειστικός διακόπτης A2A αυτού του διακομιστή, με δική του Agent Card στο `{origin}/api/a2a/servers/{uuid}/agent-card.json` |
| **Ενεργοποίηση A2A** | Ο αποκλειστικός διακόπτης A2A αυτού του διακομιστή, με δική του Agent Card στο `{origin}/api/a2a/servers/{uuid}/agent-card.json` |
| **Assigned Workflows** | Ενεργοποιήστε/απενεργοποιήστε ποια από τα workflows σας εκθέτει αυτός ο server |

### Ανάθεση Workflow

Η ανάθεση workflow είναι ανά server και ανεξάρτητη από τον διακόπτη του προεπιλεγμένου server. Ένα workflow μπορεί να είναι ενεργοποιημένο στον προεπιλεγμένο server και σε πολλούς ονομαστικούς servers ταυτόχρονα, ή σε κανέναν.

Η εναλλαγή ενός workflow το μετακινεί στην κορυφή της λίστας ανατεθέντων, ώστε η γραμμή που μόλις αλλάξατε να παραμένει ορατή αντί να κάνει scroll μακριά.

### Έλεγχος Ταυτότητας

Οι ονομαστικοί servers υποστηρίζουν τις ίδιες μεθόδους ελέγχου ταυτότητας με τον προεπιλεγμένο server:

- **X-MCP-Key header** – Περάστε απευθείας το API key του server (API clients, Cursor). Μόνο header: τα keys δεν γίνονται δεκτά ως παράμετρος query `?key=`, επειδή τα URLs καταλήγουν σε access logs, proxy logs και ιστορικό προγράμματος περιήγησης.
- **Claude, ChatGPT και Gemini OAuth** – Προσθέστε το URL του server στους συνδέσμους ή στις προσαρμοσμένες εφαρμογές του client· αφήστε τα διαπιστευτήρια κενά και ο client θα εγγραφεί μέσω OAuth αυτόματα. Το bearer token πρέπει να μεταφέρεται στο header `Authorization`, όχι ως `?token=`.
- **Session token** – Εκδίδεται κατά τη διάρκεια του SSE handshake· περιορίζεται στον συγκεκριμένο server, ώστε tokens από έναν ονομαστικό server να μην μπορούν να αποκτήσουν πρόσβαση σε άλλον. Αυτή η βραχύβια παράμετρος `?session=` δεν επηρεάζεται.

### Διαγραφή Ονομαστικού Server

Κάντε κλικ στο εικονίδιο **X** στην κεφαλίδα της κάρτας server. Η διαγραφή αφαιρεί τον server και όλες τις αναθέσεις workflow του· τα ίδια τα workflows δεν επηρεάζονται.

## SSE Endpoint

| Server | Endpoint |
|--------|----------|
| Default | `{origin}/api/mcp/sse` |
| Named | `{origin}/api/mcp/servers/{server-uuid}/sse` |

Και τα δύο endpoints υποστηρίζουν το SSE transport (GET, MCP spec 2024-11-05) και το Streamable HTTP transport (POST, MCP spec 2025-03-26). Τα Claude, ChatGPT και Gemini χρησιμοποιούν OAuth 2.1 / PKCE για ασφαλή σύνδεση και στα δύο.
