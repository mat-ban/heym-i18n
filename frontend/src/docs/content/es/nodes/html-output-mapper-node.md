# Mapeador de salida HTML

El nodo **Mapeador de salida HTML** renderiza una única plantilla HTML en una página. Úselo cuando el llamador sea un **navegador** en lugar de un cliente de API: el workflow responde con `text/html` en lugar de JSON.

## Descripción general

| Propiedad | Valor |
|----------|-------|
| Entradas | 1 |
| Salidas | 0 (sumidero) |
| Salida en tiempo de ejecución | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Parámetros

| Parámetro | Tipo | Descripción |
|-----------|------|-------------|
| `label` | string | Identificador del nodo (camelCase) |
| `html` | string | La plantilla de la página. Las expresiones `$nodeLabel.field` se interpolan en su lugar. |
| `statusCode` | number | Estado HTTP de la respuesta (por defecto `200`) |
| `contentType` | string | Tipo de contenido de la respuesta (por defecto `text/html; charset=utf-8`) |

## Comportamiento del Webhook y de la ejecución

Cuando este nodo es la **única** salida terminal del workflow, el endpoint de ejecución responde con la página renderizada, el código de estado configurado y el tipo de contenido configurado: sin envoltura JSON, sin wrapper de label.

Dos circunstancias lo desactivan:

- **Un segundo nodo terminal.** Con otro terminal activo en el grafo, Heym recurre al mapa JSON normal por label y la página llega como un campo de tipo string.
- **`X-Simple-Response: false`.** Esa cabecera solicita la envoltura completa con `status`, `node_results` y tiempos, que es lo que utiliza el canvas del editor. Envíela cuando esté depurando un workflow de página.

## Servir una página a un navegador

Establezca el **método de solicitud** del workflow en `GET` en el diálogo de cURL para que una navegación simple de navegador lo alcance. Una solicitud `GET` no lleva cuerpo, por lo que las entradas provienen de la cadena de consulta:

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Lea esos valores con `$input.query.name`. Consulte [Webhooks](../reference/webhooks.md) para el contrato completo de métodos.

Un workflow sin nodo trigger cuyo único terminal es este nodo muestra un chip **WEB** en la [pestaña Workflows](../tabs/workflows-tab.md).

## Uso como herramienta de Agent

No compatible. Este nodo es un sumidero terminal, por lo que no puede adjuntarse a un handle de herramientas del [Nodo Agent](./agent-node.md). Lo mismo aplica al [Mapeador de salida JSON](./json-output-mapper-node.md).

## Restricción de bucle

La misma regla que en [Output](./output-node.md): no coloque este nodo dentro de una rama de iteración de bucle, solo después de la rama `done` del bucle. Consulte [Loop](./loop-node.md).

## Ejemplo

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
