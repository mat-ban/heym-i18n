# Mappeur de sortie HTML

Le nœud **Mappeur de sortie HTML** restitue un modèle HTML unique sous forme de page. Utilisez-le lorsque l'appelant est un **navigateur** plutôt qu'un client API — le Workflow répond alors avec `text/html` au lieu de JSON.

## Vue d'ensemble

| Propriété | Valeur |
|----------|-------|
| Entrées | 1 |
| Sorties | 0 (puits) |
| Sortie d'exécution | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Paramètres

| Paramètre | Type | Description |
|-----------|------|-------------|
| `label` | string | Identifiant du nœud (camelCase) |
| `html` | string | Le modèle de page. Les expressions `$nodeLabel.field` sont interpolées sur place. |
| `statusCode` | number | Statut HTTP de la réponse (par défaut `200`) |
| `contentType` | string | Type de contenu de la réponse (par défaut `text/html; charset=utf-8`) |

## Comportement du Webhook et de l'exécution

Lorsque ce nœud est la **seule** sortie terminale du Workflow, l'endpoint d'exécution répond avec la page restituée, le code de statut configuré et le type de contenu configuré — sans enveloppe JSON, sans wrapper de label.

Deux éléments désactivent ce comportement :

- **Un second nœud terminal.** Avec un autre terminal actif dans le graphe, Heym revient à la table JSON habituelle par label et la page arrive sous forme de champ string.
- **`X-Simple-Response: false`.** Cet en-tête demande l'enveloppe complète avec `status`, `node_results` et les timings, ce qu'utilise le canvas de l'éditeur. Envoyez-le lorsque vous déboguez un Workflow de page.

## Servir une page à un navigateur

Définissez la **méthode de requête** du Workflow sur `GET` dans la boîte de dialogue cURL afin qu'une simple navigation depuis un navigateur puisse l'atteindre. Une requête `GET` ne transporte pas de corps, les entrées proviennent donc de la chaîne de requête :

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Lisez ces valeurs avec `$input.query.name`. Consultez [Webhooks](../reference/webhooks.md) pour le contrat complet des méthodes.

Un Workflow sans nœud Trigger dont l'unique terminal est ce nœud affiche un badge **WEB** dans l'onglet [Workflows](../tabs/workflows-tab.md).

## Utilisation comme outil d'Agent

Non pris en charge. Ce nœud est un puits terminal, il ne peut donc pas être rattaché à une poignée d'outils d'un [Nœud Agent](./agent-node.md). Il en va de même pour le [Mappeur de sortie JSON](./json-output-mapper-node.md).

## Restriction de boucle

Même règle que pour [Output](./output-node.md) : ne placez pas ce nœud à l'intérieur d'une branche d'itération de boucle — uniquement après la branche `done` de la boucle. Consultez [Loop](./loop-node.md).

## Exemple

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
