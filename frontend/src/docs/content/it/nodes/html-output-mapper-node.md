# Mapper di output HTML

Il nodo **Mapper di output HTML** renderizza un singolo template HTML in una pagina. Lo si utilizzi quando il chiamante è un **browser** anziché un client API — il workflow risponde con `text/html` invece che con JSON.

## Panoramica

| Proprietà | Valore |
|----------|-------|
| Input | 1 |
| Output | 0 (sink) |
| Output a runtime | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## Parametri

| Parametro | Tipo | Descrizione |
|-----------|------|-------------|
| `label` | string | Identificatore del nodo (camelCase) |
| `html` | string | Il template della pagina. Le espressioni `$nodeLabel.field` vengono interpolate sul posto. |
| `statusCode` | number | Stato HTTP per la risposta (predefinito `200`) |
| `contentType` | string | Tipo di contenuto della risposta (predefinito `text/html; charset=utf-8`) |

## Comportamento del Webhook e dell'esecuzione

Quando questo nodo è l'**unico** output terminale del workflow, l'endpoint di esecuzione risponde con la pagina renderizzata, lo status code configurato e il content type configurato — nessun envelope JSON, nessun wrapper di label.

Due condizioni disattivano tale comportamento:

- **Un secondo nodo terminale.** Con un altro terminale attivo nel grafo, Heym ricade sulla normale mappa JSON per label e la pagina arriva come campo stringa.
- **`X-Simple-Response: false`.** Tale header richiede l'envelope completo con `status`, `node_results` e le tempistiche, ovvero ciò che utilizza il canvas dell'editor. Lo si invii quando si esegue il debug di un workflow di pagine.

## Servire una pagina a un browser

Impostare il **metodo di richiesta** del workflow su `GET` nella finestra cURL affinché una semplice navigazione da browser possa raggiungerlo. Una richiesta `GET` non trasporta body, quindi gli input provengono dalla query string:

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

Leggere tali valori con `$input.query.name`. Per il contratto completo sui metodi, si veda [Webhooks](../reference/webhooks.md).

Un workflow privo di nodo Trigger il cui unico terminale è questo nodo mostra un chip **WEB** nella [scheda Workflows](../tabs/workflows-tab.md).

## Utilizzo come strumento di un Agent

Non supportato. Questo nodo è un sink terminale, pertanto non può essere collegato a un handle degli strumenti di un [Nodo Agent](./agent-node.md). Lo stesso vale per il [Mapper di output JSON](./json-output-mapper-node.md).

## Restrizione sui loop

Stessa regola di [Output](./output-node.md): non collocare questo nodo all'interno di un ramo di iterazione di un loop — solo dopo il ramo `done` del loop. Si veda [Loop](./loop-node.md).

## Esempio

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
