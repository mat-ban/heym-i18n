# Plugin

**Plugin** ノードは、インストール済みのプラグインが提供するカスタムアクションを実行します。プラグインは、コアアプリケーションを変更することなく、新しいノードタイプ（アクション、サードパーティ統合、あるいは Python で表現可能なあらゆる処理）で Heym を拡張します。

## 概要

| プロパティ | 値 |
|----------|-------|
| 入力 | 1 |
| 出力 | 1 |
| 出力値 | `$nodeLabel.<keys returned by the plugin>` |

プラグインの**パッケージ**（1 つの zip）には、**複数のノード**を同梱できます。アクションと Trigger を任意に組み合わせることが可能です。各ノードは **Plugins** 配下のパレットに、それぞれの名前と説明とともに表示されます。ノードをキャンバスにドラッグすると、そのパッケージ（`pluginId`）とノード（`pluginNodeKey`）に紐づいた Plugin ノードが作成されます。

## 使用する場面

必要なアクションを実行するプラグインをオペレーターがインストール済みである場合に、Plugin ノードを使用します。たとえば、プライベート API の呼び出し、社内システムとの連携、あるいはご利用のデプロイメント向けに書かれた独自ロジックの実行などが該当します。

Workflow を開始するトリガー型のプラグインについては、[Plugin Trigger ノード](./plugin-trigger-node.md)をご参照ください。

## 設定

ノードの設定フォームは、プラグインのマニフェストから生成されます。プラグインが宣言した各フィールド（`string`、`number`、`boolean`、または `select`）は自動的にレンダリングされます。シークレットではない文字列フィールドは式入力に対応しており、`$` で始まる保存済みの文字列設定値は、プラグインハンドラーの実行前に解決されます。

シークレットフィールド（API キーなど）は UI 上でマスクされ、ログに書き出されることはありません。

## プラグインの実行方法

プラグインは Heym によって配布され、オペレーターによってインストールされるため、プラグインのコードは**信頼済み**として扱われ、組み込みノードと同様にインプロセスで実行され、ネットワークおよびライブラリへのフルアクセスを持ちます。プラグインは、インストール時にインスタンスへインストールされる pip の `dependencies` を宣言できます。

プラグインのインストールおよび削除は、メールアドレスが `HEYM_PLUGIN_ADMIN_EMAILS` に記載されているオペレーターに限定されており、サブシステム全体は `HEYM_PLUGINS_ENABLED` によって制御されます（デフォルトでは無効）。環境変数については、[Running & Deployment](../getting-started/running-and-deployment.md)をご参照ください。

## カスタムアイコン

プラグインはカスタム SVG ロゴを同梱できます。パッケージのルートに `icon.svg` を配置すると、すべてのノードのデフォルトアイコンを設定できます。また、マニフェスト内でノードごとに `"icon": "<file>.svg"` を指定して、個別のアイコンを持たせることも可能です。アイコンはパレットのカードとキャンバス上のノードの両方に表示されます。アイコンが指定されていないノードは、デフォルトのパズルピースのグリフにフォールバックします。

## AI Builder

インストール済みのプラグインは AI アシスタントおよびチャットキャンバスに公開されるため、「Acme CRM プラグインを使ってレコードを作成して」と Heym に依頼すると、適切な `pluginId` と `config` を持つ Plugin ノードを生成します。

## プラグインの作成

プラグインパッケージを構築するには、zip のレイアウト、マニフェストフィールド、ハンドラーのシグネチャ、アイコン、依存関係、およびランタイムの信頼モデルについて解説した[Plugin Authoring](../reference/plugin-authoring.md)をご参照ください。
