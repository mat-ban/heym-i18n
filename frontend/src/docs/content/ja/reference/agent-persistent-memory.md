# Agent 永続メモリ

Agent ノードは、データベースに保存される**ノード単位のナレッジグラフ**を保持できます。これはエンティティ（型とプロパティを持つ）とそれらの間のリレーションシップで構成されます。有効化すると、Heym は**各実行時にそのグラフのサマリーをシステムプロンプトに注入します**（グラフが空でない場合）。実行が成功した後、**LLM 抽出ジョブ**がバックグラウンドで会話から得られた新しいファクトをグラフにマージします。

サブエージェントとオーケストレーターは、デフォルトでそれぞれ**自身のキャンバスノード**に紐づけられたグラフを使用します。また、**他のエージェントにこのノードのグラフへの読み取りまたは読み取り/書き込みアクセスを付与**することもできます（所有する**他の Workflow** 内のエージェントを含む）。詳細は[他のエージェントとの共有](#sharing-with-other-agents)を参照してください。

## 有効化

| パラメータ | 型 | 説明 |
|-----------|------|-------------|
| `persistentMemoryEnabled` | boolean | `true` の場合、このノードのグラフをシステムプロンプトに読み込み、このノードのグラフに対する実行後の抽出をスケジュールします |
| `memoryShares` | array（任意） | 他の Agent ノードに**この**ノードのメモリグラフへのアクセスを付与します。[共有](#sharing-with-other-agents)を参照してください |

Agent ノードのプロパティ（**Persistent memory (graph)**）で有効化します。メモリが有効な場合（またはモデルが表示されている場合）、ノード上のピンク色の**brain**アイコンからグラフエディターを開けます。

## グラフエディター

ダイアログはエンティティをアニメーション化された force-directed グラフとして描画します。接続数に応じてサイズが変わる色付きの円で表現され、エンティティ型ごとにクラスタリングされます。さらに編集とナビゲーション（fit view、tidy layout、キーボードショートカット）も可能です。ノードとエッジは手動で**追加、編集、削除**できます。Source/Target のリレーションシップピッカーは、エンティティが多いグラフでも検索可能です。ノードを選択すると、その送信接続と受信接続が表示され、それぞれをクリックするとそのノードにジャンプできます。変更は**この**エージェントのグラフ（brain を開いたキャンバスノードのグラフ）にのみ適用されます。

## 他のエージェントとの共有

メモリグラフのダイアログで、**Share memory with other agents** を使用すると、実行時にこのグラフを消費できる**ピア**をアタッチできます。

1. **Workflow** を選択します（エディターで開ける任意の Workflow）。
2. その Workflow 内の **agent** ノードを選択します。
3. **Read only** または **Read & write** を設定します。

| 権限 | 効果 |
|------------|--------|
| Read only | **ピア**エージェントの実行時に、このグラフがピアのシステムプロンプトにマージされます（エンティティがある場合）。ピアの実行からこのグラフへの抽出は行われません。 |
| Read & write | プロンプトの動作は read と同じで、さらにピアが**正常に**完了した後、通常のメモリ抽出がピア実行の credential を使用して**この（オーナーの）グラフにマージ**される場合があります。 |

ピアはオーナーノードごとに `memoryShares` エントリとして保存され、`peerWorkflowId` と `peerCanvasNodeId`（および `permission`）を持ちます。古い Workflow では、**同じ** Workflow 内のピアに対して `peerWorkflowId` が省略されている場合があります。エディターはそれを現在の Workflow として扱います。

**クロス Workflow 共有**は、実行時に**所有する** Workflow をスキャンして解決されます。認証されたユーザーコンテキストを持たない実行では、**現在の** Workflow の JSON（同じキャンバス）で定義された共有のみが解決されます。

## 実行時の動作

### 自身のグラフ（`persistentMemoryEnabled`）

1. **LLM 呼び出しの前** — グラフにエンティティがある場合、これらが以前の実行からのファクトであることを説明するブロックがシステムインストラクションに追加されます（不完全な可能性があり、競合時は現在のユーザーメッセージが優先されます）。
2. **正常に完了した後** — バックグラウンドジョブがモデル（エージェント実行と同じ credential）に対して構造化 JSON（エンティティ + リレーションシップ）を要求します。その Payload はデータベースにマージされます（一部の型、例えば雇用関係スタイルのエッジでは、重複排除とリレーションシップのクリーンアップが適用されます）。

### 共有グラフを受け取るピア

エージェントが実行されると、システムは `memoryShares` がこの実行の Workflow とキャンバスノードを指している**オーナー**ノード（可能な場合は所有する任意の Workflow 内）を検索します。各マッチについて、そのオーナーのグラフがシステムプロンプト内の**共有メモリ**セクションとして追加されます。**Read & write** のピアはさらに、実行が成功したときに**オーナー**の Workflow/グラフに対する抽出ターゲットをスケジュールします。

抽出は、実行がエラーになった場合や HITL の pending 状態で終了した場合は**実行されません**。

## Workflow JSON（`data` フィールド）

他の設定と同様に Agent ノードに永続化されます。

```json
{
  "type": "agent",
  "data": {
    "label": "supportAgent",
    "persistentMemoryEnabled": true,
    "userMessage": "$input.text",
    "memoryShares": [
      {
        "peerWorkflowId": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
        "peerCanvasNodeId": "agent-peer-canvas-id",
        "permission": "read"
      }
    ]
  }
}
```

`permission` は `"read"` または `"write"` です。共有を行わない場合は `memoryShares` を省略するか `[]` を使用します。

ノードオブジェクトの完全な形状については、[Workflow Structure](./workflow-structure.md)を参照してください。
