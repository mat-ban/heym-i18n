# AI アシスタント

**AI Assistant** は、Debug パネルから開くチャットパネルで、エディターの右下に表示されます。ヘッダーをドラッグして移動し、辺または角をドラッグして幅や高さを変更できます。360×480 ピクセルより小さくなることはありません。位置とサイズはこのブラウザーに記憶されます。ヘッダーの **Reset position and size** をクリックすると、パネルが右下に戻ります。自然言語を使用して Workflow を作成または変更できます。希望する内容を記述すると、AI がノードとエッジを生成し、キャンバスに適用します。

エディター外でのドキュメントに関する質問には、[Chat with Heym](./chat-with-heym.md) をご利用ください。このサーフェスは、Workflow の生成ではなく、ページを認識した製品ヘルプに最適化されています。

## パネルを開く

1. エディターで Workflow を開きます
2. 下部にある **Debug パネル**（実行結果エリア）を探します
3. パネルツールバーの **AI** ボタン（Sparkles アイコン）をクリックします
4. AI Assistant パネルが右下に開きます。ヘッダーをドラッグして移動するか、辺または角をドラッグして幅や高さを変更できます。

エディター内のどこでも `Ctrl + I` / `Cmd + I` を押すと、パネルを開いたり閉じたりできます。このショートカットは、テキスト入力にフォーカスがある状態でも機能します。詳細は[キーボードショートカット](./keyboard-shortcuts.md)をご覧ください。

単一のノードを操作するには、キャンバス上でそのノードにカーソルを合わせ、上部にある **AI** をクリックします。パネルはそのノードに焦点を当てて開きます。[単一ノードの変更](#changing-one-node) を参照してください。

## パネルを閉じる

**X** ボタンをクリックするか、`Ctrl + I` / `Cmd + I` を押すか、Debug パネルツールバーの **AI** ボタンを切り替えます。ヘッダーはパネルをドラッグするためのもので、閉じるためのものではありません。

## 設定

メッセージを送信する前に、以下を選択します：

| 設定 | 説明 |
|---------|-------------|
| **Credential** | [Credentials](../tabs/credentials-tab.md) からの LLM 認証情報（API キー） |
| **Model** | モデル名（例：`gpt-4o`、`gemini-2.5-flash`） |

認証情報は [Credentials Tab](../tabs/credentials-tab.md) で追加します。モデルリストは、選択した認証情報から読み込まれます。

## Agent モードと Ask モード

パネルには 2 つのモードがあり、パネルヘッダーの **Agent / Ask** チップで切り替えます。

| モード | デフォルト | 動作 |
|------|---------|-----------|
| **Agent** | ✓ | キャンバスを構築および変更します。AI は Workflow の JSON ブロックを生成し、応答が完了すると自動的にキャンバスに適用されます。 |
| **Ask** | | 質問に回答するだけです。キャンバスには一切触れません。Workflow、Heym の機能について質問したり、キャンバスの更新をトリガーせずにアドバイスを得たりする場合に使用します。 |

モードはいつでも切り替えられます。モードを変更しても会話はクリアされません。

Agent モードでは、メッセージフィールドの下にある **YOLO mode** ボックスにより、アシスタントが構築したものを実行して修正します。詳細は [YOLO Mode](#yolo-mode) をご覧ください。

## チャットの使用

- 入力欄にリクエストを入力します（例：「ユーザー入力を受け取り、LLM に送信する Workflow を作成する」）
- **Enter** を押して送信します（Shift+Enter で改行）
- AI が応答をストリーミングします。**Agent** モードでは、応答に \`\`\`json コードブロック内の Workflow が含まれている場合、自動的に解析されてキャンバスに適用されます。**Ask** モードでは、キャンバスは変更されません。
- **Clear** を使用して会話をリセットします
- メッセージにカーソルを合わせてコピーアイコンをクリックすると、Workflow の JSON を含め、表示されているテキストをコピーできます
- メッセージボックスの上の線をドラッグすると、ボックスを高くできます。入力エリアはパネルの 60% まで拡大でき、ページをリロードするとデフォルトの高さに戻ります

## Workflow の自動適用

AI の応答に、\`\`\`json コードブロック内の有効な Workflow JSON ブロック（`nodes` と、オプションで `edges` を含む）が含まれている場合、Heym は以下を実行します：

1. 応答から JSON を解析します
2. 現在のキャンバスを新しいノードとエッジに置き換えます
3. ノードのレイアウトを整理します
4. Workflow を未保存としてマークします

解析に失敗した場合は、**Retry** ボタンが表示され、応答を再生成できます。

## 単一ノードの変更

キャンバス上のノードにカーソルを合わせ、その上にある **AI** をクリックします。パネルは Agent モードでそのノードに焦点を当てて開き、変更対象のノードを示します：

| ノードの状態... | パネルの表示 |
|---|---|
| 現在の実行で結果がない場合 | **Modifying Node:** ノードのアイコンと名前を含むコンパクトな行。アシスタントはノードの設定のみから編集します。出力を確認する必要がある場合は、まずノードを実行してください |
| 現在の実行で結果がある場合 | **Modifying Node: (Has Node Output)** ノード自体の上部：アイコン、名前と種類、最後のステータスと所要時間、失敗した場合はエラー。アシスタントはノードの編集時にその出力とエラーを確認します |

ラベルにカーソルを合わせると、パネルがどの状態にあるか確認できます。

パネルがどちらの状態にあっても、アシスタントはノードのヘッダーにある本アイコンの背後にあるノードドキュメントページも読み取ります。このページを使用してノードのオプションを理解し、それらに関する質問に答えます。

メッセージの下にある3つのオプションからリクエストを開始します：

| オプション | 動作 |
|---|---|
| **Change this node as ...** | 文章を完成できるように、メッセージボックスに *このノードを次のように変更:* と入力します |
| **Fix error in this node ...** | *このノードのエラーを修正。* と入力します。アシスタントは前回の実行からこのノードのエラーを読み取ります |
| **Other** | 空のメッセージボックスにフォーカスします |

テキストを編集して **Send** を押します。アシスタントはこのノードのみを返し、Heym はその場で更新します。ノードはその id、種類、名前を保持するため、他のノードの `$checkLinkedIn.result` などの式は引き続き機能します。他のノード、接続、レイアウトは変更されず、**Undo** で以前の設定に戻すことができます。

リクエストがノード内に収まらない場合（たとえば、別のノードタイプや新しいノードが必要な場合）、アシスタントは編集する代わりに変更する必要がある内容を示します。ノードカードの **X** でノードフォーカスを閉じると、ワークフロー全体を再度編集できます。パネルを閉じるとフォーカスもクリアされます。

[YOLO モード](#yolo-mode) はフォーカスされたノードで機能します。アシスタントはノードを変更し、ワークフローを実行し、実行が成功するまでノードを修正します。**Ask** モードでは、フォーカスによって質問の対象となるノードがアシスタントに伝えられ、キャンバスは変更されません。

## YOLO Mode

**YOLO mode** を使用すると、アシスタントが構築したものをテストできます。メッセージフィールドの下にある **YOLO mode** ボックスをチェックしてから、リクエストを送信します。このボックスは Agent モードでのみ表示されます。デフォルトではオフで、ページをリロードするとオフに戻ります。横にある情報アイコンにカーソルを合わせると、簡単な概要が表示されます。

YOLO mode をオンにすると、アシスタントは Workflow を適用した後で停止しません：

1. Workflow をキャンバスに適用します。
2. 最初の実行前に、テスト入力を求めます。カードには Workflow の入力フィールドが一覧表示され、アシスタントが提案する値が入力されています。それらを編集して **Run** を押します。以降の実行ではこれらの値が再利用されます。カードは、入力フィールドが変更された場合、またはアシスタントが異なるテストデータを必要とする場合にのみ再表示されます。
3. **Run** ボタンとまったく同じように、キャンバス上の Workflow を実行します。未保存の変更は最初に保存され、ノードが点灯し、実行は Debug パネルと [Execution History](./execution-history.md) に表示されます。
4. 結果を読み取ります。実行が要求どおりに行われた場合は、**Verified** と短いサマリーで終了します。そうでない場合は、Workflow を修正して再度実行します。

1 メッセージにつき最大 **5 回** 実行します。**Stop** をいつでも押すと、ループを終了し、進行中の実行を停止できます。

各返信は、発生したステップを表示します：
- `Applying changes to canvas`；
- `Running workflow · attempt 2/5`、各ノードの `Executing <node>` 行付き；
- 最終的な判定。

各実行後、*Attempt 1 result sent · error in 1.2s* のような短い行が表示され、結果がアシスタントに返されたことを示します。
### 他の Workflow の実行

YOLO モードでは、アシスタントは他の Workflow の結果が必要な場合にそれらを実行することもできます。たとえば、[Execute](../nodes/execute-node.md) ノードから呼び出す前に、その Workflow が何を返すかを確認できます。これらの実行は `Running workflow "<name>"...` ステップとして表示され、Execution History にトリガーソース `ai_assistant` として記録されます。編集中の Workflow は常にキャンバス上でテストされます。

### 早期に停止する場合

| 状況 | 発生する内容 |
|---|---|
| アシスタントが判断、情報、Credential、またはデータテーブルを必要とする場合 | 通常の質問カードで確認します。回答するとループが継続します。 |
| 実行が[human review](./human-in-the-loop.md)を待機する場合 | ループが停止します。レビューを承認してから、メッセージを送信してください。 |
| Workflow がファイルアップロードを待機する場合 | ループが停止します。YOLO モードではアップロードトリガーの実行をテストできません。 |
| より新しいバージョンの Workflow が別の場所で保存された場合 | ループが停止します。保存の競合を解決してから、メッセージを送信してください。 |

> **実行は実際に行われます。** Workflow 内のメール、メッセージ、API 呼び出しは試行のたびに実際に送信され、DataTable ノードは実際の行を書き込みます。すべての実行で Workflow が保存されるため、以前のバージョンは[Edit History](./edit-history.md)に残ります。

## Voice Input

対応ブラウザでは、**Voice** ボタンで音声テキスト変換を有効にできます。クリックで録音を開始し、もう一度クリックで停止します。文字起こしされたテキストは、送信前に文法修正のために AI へ送信されます。

## Agent Node と AI Assistant の比較

| | Agent Node | AI Assistant |
|---|------------|---------------|
| **目的** | Workflow 内の LLM ノード。実行時に動作 | 自然言語で Workflow を構築するチャット UI |
| **場所** | キャンバスノード | デバッグパネル → フローティングパネル |
| **タイミング** | 実行時 | 編集中 |

ツールと MCP を使用して LLM 呼び出しを実行する Workflow ノードについては、[Agent Node](../nodes/agent-node.md)を参照してください。

## 仕組み（AI Builder DSL）

AI Assistant は、ノード、エッジ、式を記述する **workflow DSL**（ドメイン固有言語）によって動作します。メッセージを送信すると、次の処理が行われます。

1. メッセージ、[User Rules](./user-settings.md)、および現在の Workflow（存在する場合）がバックエンドへ送信されます。
2. バックエンドが**システムプロンプト**を構築します。これには以下が含まれます。
   - 完全な workflow DSL（ノードタイプ、式構文、ルール、例）
   - 「User Custom Rules」として追加された User Rules
   - 既存の Workflow を編集している場合は、現在の Workflow JSON
   - Execute ノードを使用する場合は、利用可能な Workflow のリスト
   - 所有する Credential の名前、タイプ、ID（値は含まれません）
   - 使用可能なデータテーブルの名前、ID、説明、列（行は含まれません）
3. モデルが単一の Workflow JSON ブロック（`nodes` と `edges` を含む）を返します。フロントエンドがそれを解析し、キャンバスに適用します。

### Credentials

Workflow が Credential を必要とする場合、アシスタントは構築前に確認します。適合するタイプの Credential がある場合は、**Create a new credential** とともにそれらを一覧表示します。ない場合は、作成するかどうかを確認します。どの質問でも、Credential なしで続行することもできます。

作成を選択すると、パネル内に Credential フォームが開き、適切なタイプと推奨名が事前設定されます。値は直接 Heym に送信され、アシスタントは名前とタイプのみを認識します。OAuth Credential（Google Sheets、Google Drive、BigQuery、Linear、Notion）はポップアップで接続され、ポップアップがブロックされた場合に備えて認可ページへのリンクが表示されます。Credential が保存されると、カードにその名前が表示され、作成ボタンがオフになります。**Submit answers** を押すと、アシスタントが新しい Credential をノードに設定します。

Credential のみをリクエストすることも（「create a GitHub credential」）、所有する Credential の変更を依頼することもできます（「update my sheet credential」、「reconnect my Google Sheets」）。アシスタントは同じカードで応答します。作成の場合は空のフォームが開き、更新の場合はその Credential のフォームがシークレットをマスクした状態で開きます。

アシスタントは専用ノードを優先します。Google Sheet へのタブ追加など、操作をカバーするノードがない場合は、HTTP リクエストを使用し、選択した Credential のヘッダー行を書き込みます。[HTTP › Authenticating with Credentials](../nodes/http-node.md#authenticating-with-credentials)を参照してください。

Workflow がなくても実行できる確認質問は、入力欄に **Optional** と表示され、スキップできます。

DSL は camelCase ラベル、統一された式ルール、ノード固有のフィールドを強制します。フィールド値が単一の `$expr` の場合、バックエンドはネイティブ型を保持します。値が散文と `$refs` を混在させる場合、結果は文字列になります。単一 `$` ルールは引き続き適用されます。括弧内に `$` は使用できません。[Settings](./user-settings.md)の User Rules はこのシステムプロンプトに注入されるため、設定は AI が生成するすべての Workflow に適用されます。

現在の Workflow に Agent skills が含まれている場合、AI Assistant はその Workflow コンテキストに各 skill の `SKILL.md` のみを含めます。添付された `.py` ファイルとバイナリの skill アセットはリクエスト前に除去されるため、skill に大規模な実装が含まれていても、ビルダーはモデルのコンテキスト制限内に収まります。
### データテーブル

Workflow がレコードを保存、格納、または検索する際に、別のストアを指定していない場合、アシスタントは [DataTable](../nodes/datatable-node.md) ノードを使用します。テーブルに名前を付けており、そのテーブルが Workflow に必要なカラムを持っている場合は、アシスタントはそれを利用します。そうでない場合は、どのテーブルを使用するかを尋ねます。カードには該当するテーブルが一覧表示され、それぞれの説明とカラム型が示され、さらに **Create a new table** として提案された名前とカラムが表示されます。共有されているテーブルも提示されますが、読み取り専用のテーブルは読み取り専用としてのみ提示されます。

新しいテーブルを選択し、**Submit answers** を押してください。カードがテーブルを作成し、アシスタントがその id をノードに設定し、正確なカラム名を使用します。例えば「create a table for my leads」のように、テーブルを単独で依頼することもできます。

アシスタントはテーブル名、説明、カラムを参照しますが、行（rows）を参照することはありません。既存のテーブルのカラムを変更することもありません。テーブルに Workflow が必要とするカラムがない場合、そのカラム名を提示し、代わりに新しいテーブルを提案します。カラムの追加は [DataTable tab](../tabs/datatable-tab.md) で行ってください。
