# Drive

Drive タブは、スキルによって生成されたすべてのファイルを表示、管理、共有するための中心的な場所を提供します。

## Drive へのアクセス

ダッシュボードの **Drive** タブに移動します。Workflow のスキルによって生成されたすべてのファイルが、作成日順にここに表示されます。

## ファイル一覧

ファイル一覧には以下が表示されます：

- **Name** - タイプ別アイコン付きの元のファイル名
- **Type** - ファイルの MIME タイプ（例：pdf、csv、docx）
- **Size** - 人間が読みやすい形式のファイルサイズ
- **Source** - ファイルを生成したノードのラベル
- **Date** - ファイルが作成された日時
- **Actions** - ダウンロード、共有、削除のボタン

## 一括操作

自身が所有する各ファイルには、行の先頭にチェックボックスがあります。チームを通じて共有されたファイルは読み取り専用であり、選択できません。複数のファイルを選択すると（Shift キーを押しながらクリックすると連続した範囲を選択でき、ヘッダーのチェックボックスでページ全体を選択できます）、一覧の上に一括操作バーが表示されます。次に **Bulk actions** をクリックすると、選択したすべてのファイルに同じ設定を適用する単一のダイアログが開きます：

- **Share all with my teams** / **Remove team sharing** — 選択したすべてのファイルのチーム共有を一括で切り替えます
- **Create share link for each file** — 同じ有効期限、パスワード、最大ダウンロード数の値を使用して、選択したすべてのファイルに共有リンクを作成します

ダイアログには、適用されたファイル数が表示されます。自身が所有していないファイルはスキップされます。一覧の下部にある 1 ページあたりの行数セレクター（25 / 50 / 100 / **All**）を使用すると、1 ページにより多くのファイルを読み込めるため、Drive 全体にわたって選択できます。

## ファイルの共有

**Share** アイコンをクリックすると、共有ダイアログが開きます。ファイルごとに異なる設定で複数の共有リンクを作成でき、オプションで現在のチームとファイルを共有できます。

### パブリックリンク（Token ベース）

パスワードなしで共有リンクを作成します。リンクを知っている人は誰でもファイルをダウンロードできます。

### パスワード保護リンク（Basic Auth）

共有を作成する際にパスワードを設定します。ダウンロード URL は HTTP Basic Authentication を使用します。リンクを開くと、ブラウザがユーザー名（`file`）とパスワードの入力を求めます。

### リンクオプション

- **Expires (hours)** - オプションで有効期限を設定できます
- **Max downloads** - オプションでダウンロード数を制限できます
- 両方を組み合わせて、最大限の制御が可能です

### チームとの共有

**Share with my teams** を有効にすると、現在所属しているすべてのチームに読み取り専用アクセスを付与します。チームメンバーは Drive からファイルを表示およびダウンロードでき、読み取り指向の Drive ノード操作を使用できますが、ファイルを削除したり、パブリックリンクを作成または失効させたり、パスワード/TTL/ダウンロード制限を変更できるのはファイルの所有者のみです。

この設定はファイル固有です。後で別のチームに参加または作成した場合は、再度共有を切り替えるか、Drive ノードの `shareWithMyTeams` 操作を実行してそのチームを追加してください。Workflow 内でファイルからチーム共有を削除するには `unshareWithMyTeams` を使用します。

### 共有の管理

共有ダイアログには、既存のすべての共有リンクが以下とともに表示されます：
- 現在のダウンロード数
- 有効期限のステータス
- Basic Auth が有効かどうか
- コピーと失効のボタン

## チャットと Portal 内のファイルリンク

スキルが Portal チャットまたは Quick Drawer を通じた Workflow 実行中にファイルを生成すると、ダウンロードリンクが応答内に自動的に表示されます。ユーザーはクリックして直接ダウンロードできます。

## ストレージ

生成されたファイルは、サーバーのファイルシステム上の `data/files/` に保存されます。Docker デプロイメントでは、永続化のためにボリュームとしてマウントされます。

## Workflow からのファイル管理

[Drive ノード](../nodes/drive-node.md)を使用すると、Workflow 内からプログラムで Drive ファイルを管理できます。以下の用途に使用します：

- ファイルを**一覧表示**し、ファイル名、MIME タイプ、サイズ、ソース、ダウンロード URL などのメタデータを返す
- ユーザーに配信された後にファイルを**削除**する
- **チームとの共有または共有解除**を行い、チーム共有が存在する間のみチームメンバーがファイルを読み取りおよびダウンロードできるようにする
- ダウンロードリンクに**パスワードを設定**する
- **TTL を設定**し、N 時間後にリンクを失効させる
- **最大ダウンロード数**の制限を設定する

ファイルを別の形式に変換するのは [Converter ノード](../nodes/converter-node.md)の役割であり、`conversion: "fileConvert"` を使用します。Drive ファイルを読み取り、変換結果を新しいファイルとして保存します。

ファイルはスキル出力の ID で参照します：`$agentLabel._generated_files[0].id`

設定の詳細については、[Drive ノードのドキュメント](../nodes/drive-node.md)を参照してください。

## スキルからの Drive ファイルの読み取り

Agent スキルは、スキルカードの **Enable Drive files** 設定で Drive 読み取りを有効にできます。有効にすると、スキルランタイムに生成された `heym_drive.py` ヘルパーが含まれます。スキルコードは、`read_drive_text`、`read_drive_file`、`read_drive_base64`、`get_drive_file`、`get_drive_file_path`、`list_drive_files` などのヘルパーをインポートできます。

Drive 読み取りは、Workflow 実行者がアクセスできるファイル（所有ファイルおよびチームを通じて実行者と共有されたファイル）に限定されます。正確な検索にはファイル ID を使用するか、ユーザーがファイル名でファイルを指定する場合は正確なファイル名を使用します。ファイル名検索は、その名前を持つアクセス可能な最新のファイルを返します。`list_drive_files(filename="...")` はすべての一致を返します。

## クリーンアップ
失効した共有 Token は毎日自動的にクリーンアップされます。ファイル自体は、Drive タブを通じて手動で削除されるまで保持されます。**Clear All** を使用すると、すべてのファイルとその共有リンクを 1 回の操作で削除できます。
