# 式評価ダイアログ

式評価ダイアログは、式を利用できるフィールドのための拡張エディターです。式入力の隣にある展開ボタンから開くことができ、より広いワークスペース、オートコンプリート、ライブバックエンドプレビュー、および出力の閲覧を一か所で提供します。

## ダイアログを開く

- Properties パネル内の式フィールドの隣にある展開ボタンをクリックします。
- 複数行フィールドでは、ボタンは入力欄の内側に表示されます。
- 単一行フィールドでは、ボタンは入力欄の右側に表示されます。

## ダイアログのレイアウト

- ダイアログは、およそ **80vw × 80vh** の中央配置モーダルとして開きます。
- フィールドラベルが判明している場合、ヘッダーには **Evaluate — {field name}** が表示されます。
- エディターは、オートコンプリート、フィールド間のナビゲーション、および通常の **Apply** / **Cancel** アクションを維持します。
- プレビューは、入力が止まってから約 **300 ms** 後に自動的に更新されます。
- `Ctrl` / `Cmd` + `Enter` を押すと、現在のテキストをフィールドに適用してダイアログを閉じます（**Apply** と同じ動作です）。

## Output セクション

Output エリアは、エディターでの入力が止まった後に自動的に更新されます。

### 評価

| 式の種類 | 結果 |
|---|---|
| 単一の `$expr`（フィールド全体） | ネイティブ値が保持されます |
| 単一の裸のドットパス（フィールド全体、`$` なし、埋め込み改行なし） | `$` + そのパスと同じです（評価のためにバックエンドで正規化されます） |
| `$refs` が埋め込まれたテキスト | 最終結果は常に文字列になります |
| リテラルテキスト（`$` なし、単一のドットパスでもない） | そのまま返されます |

**例**

| 入力 | 結果 |
|---|---|
| `$input.items` | `[1, 2, 3]` |
| `input.items`（値全体がこのパスの場合、`$input.items` と同じです） | `[1, 2, 3]` |
| `Hello $input.name` | `Hello John` |
| `$input.count + 1` | `6` |
| `just text` | `just text` |

評価コンテキストは、次の順序で構築されます。

- 上流ノードの **Pinned data**
- キャンバスからの **Last run outputs**
- 上流データが利用できない場合は `null`

現在のノードに上流の依存関係があるものの、それらのいずれにも Pinned data または最近の実行結果がない場合、ダイアログはまずコンテキストを構築するためにテスト実行を実行し、その後で現在のテキストを評価します。

### Output Path Picker

バックエンドの結果がオブジェクトまたは配列の場合、Output エリアは生の JSON の代わりにインタラクティブなパスピッカーを表示できます。

- 行をダブルクリックすると、そのパスを現在の `$node.path` 参照に追加します。
- 展開可能な行をシングルクリックすると、ブランチを開いたり閉じたりします。
- 組み込みのクエリボックスを使用して、キー、値、およびパス文字列を検索できます。

## オートコンプリート

- `$` を入力すると、上流ノード、ビルトイン、およびメソッドの候補が開きます。
- `Tab` または `Enter` を押すと、選択した候補を挿入します。
- `↑` / `↓` を使用して、候補リスト内を移動します。

### 回答例

`$…` 参照をドットで続けると、各候補行にはその候補が生成する回答が、行の右側に太字で表示されます。

- `$set.listItems.first().toString().u` と入力すると、`upper`、`urlEncode`、`urlDecode`、および `unescape` が一覧表示され、それぞれに評価結果が付きます。そのため、名前ではなく結果に基づいて選択できます。
- `$node.text.toJson()` と入力すると、JSON 文字列をオブジェクトまたは配列にパースします。`.toJson()` の後では、last-run または pinned の出力が利用可能な場合、オートコンプリートはパースされたキー（たとえば `repoUrl`）を提示できます。
- 結果は、ダイアログのプレビューが使用するのと同じ pinned data および last-run outputs に対してバックエンドで評価されるため、フィールドが生成する内容と一致します。
- 単独で成立する候補のみが評価されます。つまり、引数なしのメソッド（`upper()`、`first()`、`keys()`、`toJson()`）および単純なプロパティ（`length`、`year`）です。先に引数を必要とする候補 — `map`、`filter`、`sort`、`replace` — は空白のままになります。
- 候補が回答を生成しない場合、行は空白のままになります。これは、エラー、`null`、またはその値に適用されないメソッドの場合です。
- 回答は 1 行に短縮されます。短縮された回答にホバーすると、その続きを確認できます。

## Build with AI

**Build with AI** ボタンは、Workflow が読み込まれているときに評価ダイアログの右上隅に表示されます。これをクリックするとネストされたモーダルが開き、希望する式をプレーンテキストで記述して LLM に生成させることができます。

### 仕組み

1. 評価ダイアログのツールバーで **Build with AI** をクリックします。
2. ドロップダウンから LLM credential とモデルを選択します。
3. 希望する内容をプレーンテキストで入力します — たとえば、*「API レスポンスから顧客名を取得する」* のように記述します。
4. **Generate** をクリックします。モーダルはバックエンドを呼び出し、バックエンドは [Expression DSL](./expression-dsl.md) のシステム Prompt と、コンテキストとして最後の Workflow 実行出力を使用して、単一の式文字列を返します。
5. 生成された式は、同じキャンバスデータに対して即座に評価されるため、適用する前に結果を確認できます。
6. **Apply** をクリックすると、エディターの内容が生成された式に置き換えられます。再試行する場合は **Regenerate** をクリックします。

### 使用されるコンテキスト

ジェネレーターは、キャンバス上の最後のテスト実行によるノード出力を受け取ります。Workflow がまだ実行されていない場合、LLM はノードラベルと DSL の規則に基づいて、可能な範囲で最善の式を生成します。

### 要件

- LLM credential（OpenAI、Google、または Custom）が [Credentials](./credentials.md) タブで設定されている必要があります。
- Workflow がエディターで開かれている必要があります。

## キーボードショートカット

| ショートカット | アクション |
|---|---|
| 入力の一時停止（約 300 ms） | バックエンドプレビューを更新 |
| `Ctrl` / `Cmd` + `Enter` | 適用してダイアログを閉じる |
| `Escape` | まずオートコンプリートを閉じ、それ以外の場合はダイアログを閉じる |
## メソッド引数におけるネストされた `$`

dialog / backend の評価では、動的なキーが必要な場合、`.get($other.field)` のような呼び出し内にネストされた `$` を含む別の参照を渡すことができます。また、`.get(...)` 内でベアパス（例えば `other.field`）を使用することもできます。backend は同様に解決します。保存された Workflow フィールドは引き続き [Expression DSL](./expression-dsl.md) のルールに従う必要があります。evaluate API は利便性のため、完全な行のベアドットパスも受け付けます（上記の表を参照してください）。

## ナビゲーション

Set および Execute のマッピングエディターでは、**Prev** / **Next** ボタンが表示されるため、ダイアログを閉じずにフィールド間を移動できます。
