# ファイル分析

ファイル分析を使用すると、Chat、[Agent ノード](../nodes/agent-node.md)、および [Code ノード](../nodes/code-node.md) は、隔離された Python サンドボックス内で [Drive](./drive.md) からの大容量ファイルを開いて分析できます。PDF、スプレッドシート、CSV、DOCX、JSON などのファイルは最初に検査された後、選択的に読み取られるため、200 ページの契約書や 100 万行のワークブックをモデルのコンテキスト全体に収める必要がありません。

## 動作の仕組み

各呼び出しは、ネットワークアクセスを持たない新しいコンテナで実行されます。必要なファイルは読み取り専用でコピーされ、コードが実行された後、コンテナは破棄されます。同一セッションの呼び出し間では小さな作業フォルダが保持されるため、後続のステップで前のステップが保存した結果から再開できます。

| パス | 内容 |
|------|--------|
| `/input` | このセッションの Drive ファイル（読み取り専用） |
| `/work` | セッション中保持される作業領域（例: `/work/sales.pkl`） |
| `/work/out` | ここに書き込まれたファイルは呼び出し後に Drive に保存され、リンクとして返されます |

サンドボックスには pandas、openpyxl、xlrd、pdfplumber、pypdf、python-docx、langdetect がプリインストールされており、[変換ノード](../nodes/converter-node.md) が使用する Tesseract OCR も備わっています。

## ツール

モデルは 3 つのツールと、Chat 内の 4 つ目のツールを組み合わせて動作します:

| ツール | 機能 |
|------|----------|
| `list_files` | 開くことができる Drive ファイルを一覧表示します: 名前、タイプ、サイズ、日付 |
| `inspect_file` | 短いサンプルとともに、ファイルのタイプ、メタデータ、構造を返します |
| `run_python` | 指定されたファイルに対して Python を実行し、コンソール出力を返します |
| `clear_workspace` | Chat のみ: 会話の作業フォルダを削除します |

`inspect_file` は要約に必要な情報のみを読み取ります:

| タイプ | 要約内容 |
|-----|-----------------|
| PDF | ページ数、タイトルと作成者、テキスト抽出可否、言語、ページサイズ、1 ページ目のテキストと表。スキャンされた PDF は OCR で読み取られます（最大 5 ページ） |
| XLSX / XLS | 行数と列数を含むシート、実際のヘッダー行、データ型、pandas の `read_hint`、名前付き範囲、先頭行 |
| CSV / TSV | エンコーディング、区切り文字、行数、型付きの列、先頭行 |
| DOCX | 見出しのアウトライン、表、単語数と文字数、作成者と日付 |
| JSON | ルートタイプ、キー、配列の長さ、ネストの深さ、サンプルレコード |

`run_python` 内で `heym_files` モジュールを使用してファイルを開きます:

```python
import heym_files
import pandas as pd

df = pd.read_excel(heym_files.path("q3.xlsx"), sheet_name="Summary", usecols=["Region", "Amount"])
print(df.groupby("Region").Amount.sum())
df.to_csv(f"{heym_files.out_dir()}/by-region.csv", index=False)
```

## Chat での利用

[Chat タブ](../tabs/chat-tab.md)、Heym Work の Chat、または MCP の `heym_chat` ツールを通じて、PDF、スプレッドシート、DOCX、CSV、JSON ファイル、画像（PNG、JPG、GIF、WebP）、または任意のプレーンテキストファイルを添付できます。1 つのメッセージで最大 10 個のファイルを添付できます。各ファイルは Drive に保存され、名前と ID のみがメッセージに含まれます。Chat はファイルを検査し、質問に必要な部分を読み取り、表や抜粋で回答します。

## ワークフローでの利用

実行では、自分自身のファイルのみが開かれます: [ファイルアップロード Trigger](../nodes/file-upload-trigger-node.md) を通じてアップロードされたファイル、ノードが Drive に書き込んだファイル、および同一実行内で [Drive ノード](../nodes/drive-node.md) が **Get** ステップで取得したファイルです。

- **Agent ノード**: エージェントの入力またはメッセージに対象ファイルが含まれている場合、そのファイルに対する上記のツールが自動的に付与されます。
- **Code ノード**: **Files** を `$Upload.file.id` などの式に設定します。ファイルはマウントされ、`params.files` に一覧表示されます。

## 制限事項

| 制限項目 | 値 |
|-----------|------|
| 1 回の呼び出しあたりのメモリ | 2 GB |
| 1 回の呼び出しあたりの実行時間 | 120 秒 |
| セッションあたりの作業フォルダ | 2 GB |
| 1 回の呼び出しあたりの出力ファイル数 | 20 個、各最大 100 MB |
| モデルに返されるコンソール出力 | 20,000 文字 |
| 1 回の呼び出しあたりのファイル数 | 20 個 |

## セキュリティ

- サンドボックスにはネットワークがなく、Heym の設定やシークレットへのアクセス権を持たず、非特権ユーザーとして実行されます。
- ファイルはサンドボックスの内部でのみ解析されます。
- Chat では、アクセス権は Drive に従います: 自分が所有するファイルおよびチームと共有されているファイルを開くことができます。
- Chat でのファイル開封は監査ログに記録されます。
- ファイルの内容は純粋なデータとして厳格に扱われ、ファイル内に記述された指示は実行されません。

## 要件

ファイル分析には、Heym インスタンス上のサンドボックスバックエンド（Docker または [Kubernetes](../getting-started/running-and-deployment.md#kubernetes)）が必要です。
