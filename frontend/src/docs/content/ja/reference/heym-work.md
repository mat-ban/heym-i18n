# Heym Work

**Heym Work** は、Heym を基盤として構築されたビジネスチーム向けの第2のインターフェースです。ユーザーは自身の言葉で業務内容を説明し、いくつかの質問に答えるだけで、Heym が構築・テストした workflow を利用できます。専用に設計されたページで業務を進め、レビューを処理し、実行者名が明記された各実行履歴を確認できます。Heym はすべてのジョブをバックグラウンドで実行します。

Heym Work は Heym の横で独立したコンテナとして動作し、Heym チームからの個別ライセンスが必要です。詳細の確認およびトライアルのお申し込みは [heym.run/enterprise](https://heym.run/enterprise) をご覧ください。2分間の概要ツアーについては [Heym Work 紹介動画](https://youtu.be/5Z2gGo6bcpU) をご視聴ください。

## ビジネスチームが得られる機能

| 領域 | 機能概要 |
|------|----------|
| **Chat** | テキスト入力または音声で業務内容を伝えます。Heym が必要な情報を確認し、workflow を構築してテストした上で「検証済み」として登録します。 |
| **ページ** | ピン留めされたウィジェットページ：数値、グラフ、ステータスバッジ付きテーブル、ファイルドロップエリア、承認機能。テーブル行をクリックして専用の詳細ページを開くことができます。 |
| **承認** | [Human-in-the-Loop](./human-in-the-loop.md) ステップからのレビューが「アクティビティ」およびページ上に表示され、「承認」「変更要求」「却下」の操作が可能です。 |
| **アクティビティ** | 実行開始者および実行インスタンスが記録されたすべての実行履歴。 |
| **ロール** | オーナー、エディター、ビューアー。ユーザーは Heym で設定済みの [Single Sign-On](./sso.md) を使用してログインします。 |
| **業界別エディション** | 法務、教育、金融、物流、エネルギー、Eコマース向けエディションには、業界特化のページ、サンプルデータ、専用 workflow があらかじめ用意されています。 |

## Heym Work の接続設定

最初のコマンド入力からホーム画面の表示まで、セットアップの全工程は [インストール動画](https://youtu.be/zXGfg1HPSLk) でご確認いただけます。

接続は **設定 → Heym Work** から設定します。このタブは `HEYM_ADMIN_EMAILS` に登録されているインスタンス管理者のみに表示されます。

| 項目 | 機能概要 |
|------|----------|
| **Heym Work アドレス** | Heym Work が動作している URL（例: `https://work.example.com`）。ログイン後のリダイレクト先となります。**保存** をクリックします。 |
| **連携キー** | **キー生成** をクリックすると、Heym Work が Heym へのリクエストごとに使用するキーが発行されます。コピー用ボタンと共に1度だけ表示されます。Heym にはそのハッシュ値のみが保存されます。 |
| **Heym Work を有効化** | 接続を有効にします。あらかじめアドレスとキーの設定が必要です。 |
| ステータス | Heym Work から最後に報告された **最終確認日時**、**Work バージョン**、**ライセンス** が表示されます。 |

続いて Heym Work のアドレスを開き、初期セットアップを完了します：

1. **ライセンス**: Heym チームから発行されたライセンスキーを入力します。
2. **Heym**: Heym のアドレスと連携キーを入力します。
3. **オーナー**: Heym Work オーナーとして登録されたアカウントでログインします。

ホーム画面が開き、チームですぐに利用を開始できます。

### キーのローテーション

**キーをローテーション** をクリックすると連携キーが置き換えられます。新しいキーが Heym Work 側に入力されるまで Heym Work は停止し、ログイン中のすべてのユーザーがログアウトされます。キーの漏洩が疑われる場合や、キーを知る担当者が離職した場合に使用してください。

### 接続の無効化

**Heym Work を有効化** のスイッチをオフにすると接続が切断されます。その後 Heym Work を利用する際は再度 Heym キーが求められます。いずれの場合も、Heym 自体はすべての workflow、スケジュール、Webhook の実行を継続します。

## セキュリティモデル

- **すべての変更は Heym を経由します。** Heym Work は表示する情報を Heym のデータベースから読み込み、キーで保護された通信経路を通じてすべてのアクションを Heym に送信し、Heym が自身のアクセス権限ルールを適用します。Heym Work は独自のデータを独立した `heym_work` スキーマに保管します。
- **キーはハッシュ化されて保存されます。** Heym は提示されたキーのハッシュ値を検証し、平文のキー自体を保存することは一切ありません。
- **認証は Heym が管理します。** [SSO](./sso.md) が有効な場合、ユーザーは所属組織の Identity Provider を介して Heym 経由でログインします。
- **すべての操作が監査されます。** 接続の保存やキーのローテーションは、`work_integration.update` および `work_integration.key_rotate` のログとして [監査ログ](./audit.md) に記録されます。

## ライセンス体系

Heym Work の利用には、Heym チームが発行する専用のライセンスキーが必要です。Heym Work は毎日、ライセンス ID、インストール ID、過去30日間のアクティブユーザー数、総メンバー数、過去24時間の実行回数、Heym および Heym Work のバージョン情報を heym.run に送信します。Workflow の内容、入力データ、出力結果、認証情報は常にローカルサーバー内にとどまります。

日次同期が30日間失敗すると14日間の猶予期間に入り、その後 Heym Work の画面でオーナーにキーの再入力が求められます。トライアルは指定期日まで有効で、Heym チームによる延長時に再開されます（1インストールにつき1回のみ利用可能）。Heym 本体はこの期間中も停止することなく稼働し続けます。インターネット接続のない閉域網では、enterprise@heym.run から提供されるオフラインライセンスをご利用いただけます。
