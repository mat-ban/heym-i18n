# Quick Drawer

**クイックドロワー**は、Workflow を素早く実行するための右側パネルです。ダッシュボードの [Workflows タブ](../tabs/workflows-tab.md)、Docs、Evals などの認証済みページに表示されます。

## アクセス

- 画面右中央の固定された **Quick / Workflows** トリガーをクリックします
- [コンテキストショーケース](./contextual-showcase.md) も利用可能な場合、その **Page Guide** トリガーは Quick Workflows の上に配置されます
- ドロワーは右側から開き、現在のページをわずかに縮小しながら左へシフトします
- モバイルでは、クイックドロワーは非表示になります
- ドロワーは、Workflow エディター、ログイン/登録、ポータル、HITL レビューページでは表示されません

## Workflow の検索

ドロワー上部のフィルターフィールドを使用して、以下の条件で Workflow を検索できます：

- Workflow 名
- Workflow の説明

検索は大文字と小文字を区別せず、リストは即座に更新されます。

## Workflow のピン留め

Workflow をピン留めすると、ドロワーの上部に固定されます。

- ピン留めされた Workflow は、全リストの上にある専用セクションに表示されます
- 新しくピン留めしたものは先頭に追加されます
- ピンの順序はブラウザストレージに保存され、リロード後も維持されます

## Workflow の実行

Workflow を選択すると、その入力フォームが開きます。

- 入力フィールドはドロワーの順序で縦に表示されます
- **Run Workflow** をクリックして、選択した Workflow を実行します
- **Stop Workflow** をクリックして、ドロワーから実行中の処理をキャンセルします
- 入力フィールドがない Workflow も直接実行できます
- [File Upload Trigger](../nodes/file-upload-trigger-node.md) で始まる Workflow では、代わりにドロップゾーンが表示されます。ファイルをドロップするか、クリックしてファイルを選択してください。ゾーンには Trigger が受け付けるファイル形式とサイズが表示され、それ以外のファイルはアップロード前に拒否されます。ファイルが選択されるまで **Run Workflow** は無効のままになります。

ドロワーは他の Heym 実行サーフェスと同じ Workflow 実行 API を使用するため、出力とランタイムの動作は一貫しています。

ドロワーから実行を停止すると、アクティブなバックエンド実行もキャンセルされます。これには、その Workflow 実行における進行中の Playwright ブラウザジョブも含まれます。

## 進捗と結果

実行を開始すると、ドロワーに以下が表示されます：

- ノードの開始時と終了時のストリーミングステップ進捗
- 最終ステータス：`success`、`error`、または `pending`
- コンパクトな JSON パネルでの最終出力
- `Quick Drawer` タグが付いた履歴エントリ

`pending` は、Workflow が人によるレビューなど、後続のアクションを待機していることを意味します。

Quick Drawer の実行は本番実行であるため、[同時実行制限](./webhooks.md#concurrency-limit-and-queued-runs)が設定された Workflow では待機させられる場合があります。実行が順番待ちの間、ステータスには **Waiting in queue (2/5)** と表示されます。実行が開始されると "running" に変わり、終了時にステップごとの進行状況なしで結果が表示されます。キュー内で有効期限が切れた実行、または待機中にキャンセルされた実行は `error` として終了します。

ファイル実行は Trigger の使い捨てアップロードリンクを経由して行われます。ドロワーが Workflow にリンクを要求し、そのリンクへファイルをアップロードして、完了時に結果を表示します。ファイル実行では最終ステータスと出力が表示されますが、ステップごとの進捗は表示されず、履歴には同じく `Quick Drawer` タグが付与されます。1つのリンクにつき1ファイルのみ受け付けるため、選択したファイルは実行ごとにクリアされます。

## ブラウザストレージ

クイックドロワーは、個人設定を `localStorage` に保存します：

- ピン留めされた Workflow ID
- 最後に選択した Workflow

このバージョンでは、ドロワーは入力値を**保存しません**。

## スコープ

クイックドロワーは、意図的に軽量な実行サーフェスとして設計されています。

- 含まれるもの：検索、ピン留め、選択、入力（ファイルを含む）、実行、進捗、結果
- 含まれないもの：Workflow の作成、編集、フォルダー管理、キャンバス操作
