# セキュリティ

Heym プラットフォームのセキュリティプラクティスと設定について説明します。

## パスワードポリシー

登録時およびパスワード変更時のすべてのパスワードは、以下の要件を満たす必要があります。

| ルール | 要件 |
|------|-------------|
| 最小文字数 | 8文字 |
| 大文字 | 少なくとも1つの大文字（A～Z） |
| 小文字 | 少なくとも1つの小文字（a～z） |
| 数字 | 少なくとも1つの数字（0～9） |

これらのルールはフロントエンドとバックエンド（Pydantic バリデータ）の両方で適用されます。要件を満たさないパスワードを含むリクエストは、データベースへの書き込みが行われる前に `422 Unprocessable Entity` レスポンスで拒否されます。

**有効なパスワードの例：** `MyWorkflow7!`

## セッション管理

- アクセストークンは `localStorage` ではなく **HttpOnly** Cookie に保存されます。これにより、JavaScript（XSS Payload を含む）が Token を読み取ることを防ぎます。
- リフレッシュ Token は `/api/auth/refresh` パスにスコープが限定されており、他の Endpoint には送信できません。
- `/api/auth/refresh` の呼び出しごとにリフレッシュ Token が **ローテーション** されます。古い Token は即座に失効し、新しい Token が発行されます。使用済みのリフレッシュ Token を再利用すると `401` が返されます。

## レート制限

以下の Endpoint には IP ごとのレート制限が適用されます。

| Endpoint | 制限 | 禁止期間 |
|----------|-------|--------------|
| `POST /api/auth/login` | 10 リクエスト / 60 秒 | 15 分 |
| `POST /api/auth/register` | 5 リクエスト / 60 秒 | 10 分 |
| `POST /register`（OAuth クライアント） | 5 リクエスト / 60 秒 | 10 分 |
| ポータルログイン | 3 回の試行 | 24 時間 |

`REDIS_URL` が設定されている場合、レート制限はすべてのバックエンドワーカー間で共有されます。設定されていない場合は、ワーカープロセスごとに制限が適用されます。

## 認証情報の暗号化

[認証情報](../tabs/credentials-tab.md)パネルに保存されるすべての API キー、Webhook URL、Bearer Token は、データベースに書き込まれる前に AES-256（Fernet）を使用して保存時に暗号化されます。キーは `ENCRYPTION_KEY` 環境変数から導出されます。`run.sh` および `deploy.sh` スクリプトは、値が空の場合に強力な値を自動生成します。`ENCRYPTION_KEY` が空または既知のプレースホルダーのままの場合、アプリケーションは起動を拒否します。

## MCP API キー

MCP API キーは、`/api/mcp/sse` Endpoint に接続する外部 MCP クライアントの認証に使用されます。SSE 接続が確立されると、短命（1時間）のセッション Token が発行され、実際の API キーの代わりにメッセージ Endpoint の URL に埋め込まれるため、サーバーアクセスログにキーが記録されることを防ぎます。セットアップについては [MCP タブ](../tabs/mcp-tab.md) を参照してください。

## OAuth / PKCE

OAuth 2.0 認可サーバー（MCP クライアントで使用）は、PKCE（`S256`）付きの `authorization_code` グラントのみをサポートします。同意フォームは 10 分間有効な HMAC-SHA256 CSRF Token を使用します。同意ページに表示されるすべての値は HTML エスケープされます。

## 実行 Token

[実行 Token](./execution-tokens.md) は、外部システムから Workflow の実行 Endpoint を呼び出すためのスコープ付き JWT です。ユーザーセッション Token とは異なり、以下の特徴があります。

- **単一 Workflow スコープ** — Token は他の Workflow では拒否されます。
- **個別に失効可能** — Token を失効させても、発行元ユーザーのセッションには影響しません。
- **短期または長期** — 60 秒から 10 年までの TTL を選択できます。

Token は同じアプリケーションシークレット（`SECRET_KEY`）で署名され、すべてのリクエストで署名、有効期限、`wid` クレームの一致、失効ステータスが確認されます。セットアップと API リファレンスについては [実行 Token](./execution-tokens.md) を参照してください。

## コンテンツの安全性

LLM ノードおよび Agent ノードで [Guardrails](./guardrails.md) を使用して、安全でない、またはポリシーに違反するユーザーメッセージがモデルに到達する前にブロックします。Guardrails は 9 つのコンテンツカテゴリ（暴力、ヘイトスピーチ、性的コンテンツなど）をサポートし、感度レベルを設定できます。

## Python ツールサンドボックス

[Agent ノード](../nodes/agent-node.md) 上のユーザー定義 Python ツールは、信頼されていないコードを実行します。デフォルトでは、Heym は各ツールを以下の構成を持つ堅牢化された使い捨て Docker コンテナ内で実行します。

- ネットワークアクセスなし
- 読み取り専用のルートファイルシステムと小さな `tmpfs` 作業ディレクトリ
- すべての Linux ケイパビリティが削除され、`no-new-privileges` が設定された非 root ユーザー
- 厳格な CPU、メモリ、PID 制限
- **Docker ソケット**がマウントされていないため、ツールはホストの Docker デーモンに到達できません

実行バックエンドは `HEYM_PYTHON_TOOL_SANDBOX` 環境変数で制御されます。

| 値 | 動作 |
|-------|----------|
| `auto`（デフォルト） | 堅牢化された Docker コンテナ内で実行します。Docker が利用できない場合、実行は **フェイルクローズ** します — OS 分離なしで信頼されていないコードを暗黙的に実行することはありません。 |
| `docker` | `auto` と同じですが、フォールバックしません。 |
| `subprocess` | インポート許可リストで保護されたローカルのインプロセスサブプロセスで実行します。これは **セキュリティ境界ではありません**。信頼されたコードまたはローカル開発のみを目的としています。`run.sh` はネイティブ開発用にこれを選択します。 |

`HEYM_PYTHON_TOOL_IMAGE` を設定してサンドボックスイメージを固定できます。空の場合、Heym は実行中のバックエンドイメージを自動検出します。インプロセス制限（インポート許可リストと属性・イントロスペクションフィルタリング）は多層防御として適用されますが、コンテナが実際の分離境界です — マルチユーザーおよび本番環境へのデプロイでは、デフォルトの `auto`（または `docker`）モードを維持してください。

## Skill Sandbox

[Agentノード](../nodes/agent-node.md)にアタッチされたPythonスキルも信頼できないコードを実行します。スキルは共有Workflow内や`everyone`可視性のテンプレート内にそのままの形で含まれる可能性があるため、スキルはPythonツールと**同じ**`HEYM_PYTHON_TOOL_SANDBOX`スイッチを経由して実行され、同じようにfail closedで動作します。スキルコンテナは同一の方法で堅牢化されています（非root、全ケイパビリティの削除、`no-new-privileges`、読み取り専用ルートファイルシステム、CPU/メモリ/PID制限、そして**Dockerソケットなし**）。ただし、スキルが正当に必要とする2点のみ意図的に異なります：

- **ネットワークegressが許可されます**（スキルはAPIを呼び出し、`uv`経由で自身の依存関係をインストールします）、そして
- **書き込み可能なworkspaceがマウントされます**。これによりスキルは出力ファイルを生成し、Heym Driveのファイルを読み取ることができます。

workspaceは、Codex runnerが使用するのと同じ名前付きDockerボリューム（`heym-codex-workspaces`、`/app/data/codex-workspaces`にマウント）を通じて、使い捨ての兄弟コンテナと共有されます。この実行自身のサブディレクトリのみが、実行ごとの`volume-subpath`を介して兄弟コンテナにマウントされるため、あるスキルが別の実行やCodexのworkspaceデータを見ることはありません。Docker Composeスタックは常にこのボリュームをマウントします。単一コンテナの`docker run`では、Codexと同様にPythonスキルに対しても`-v heym-codex-workspaces:/app/data/codex-workspaces`を含める必要があります。`auto`/`docker`モードでボリュームが存在しない場合、スキル実行はバックエンドで実行されるのではなく**fail closed**となります。実行ごとのサブパスマウントには**Docker Engine 25.0以降**が必要なため、古いエンジンではアップグレードするか、`HEYM_PYTHON_TOOL_SANDBOX=subprocess`で信頼済みスキルを実行してください。

コンテナには、シークレットではないポータブルな環境変数（プロキシとCAバンドルの設定、ロケール）のみが転送されます。データベースURL、`SECRET_KEY`/`ENCRYPTION_KEY`、プロバイダーAPIキー、OAuthシークレットはallowlistによって除外されます。スキルのファイルパスはworkspace内に留まるよう検証され、出力ディレクトリに仕込まれたシンボリックリンク（`_hitl_request.json`センチネルを含む）は決して追跡されません。必要に応じて`HEYM_SKILL_IMAGE`、`HEYM_SKILL_NETWORK`、`HEYM_SKILL_MEMORY`、`HEYM_SKILL_CPUS`、`HEYM_SKILL_PIDS`、`HEYM_SKILL_USER`でデフォルトを上書きできます。

ツールと同様に、`subprocess`モードはバックエンドプロセス内でスキルを実行し、**セキュリティ境界ではありません**。信頼済みのシングルユーザーまたはローカル開発でのみ使用してください（`run.sh`はネイティブ開発用にこれを選択します）。

## Code Node Sandbox

[Codeノード](../nodes/code-node.md)は、任意のユーザーPythonを任意のサードパーティ依存関係とともに実行するため、3つのSandboxの中で最も厳格であり、唯一**エスケープハッチがありません**。Sandboxモード変数を一切読み取らず、`subprocess`モードも持たず、到達可能なDockerデーモンがない場合はfail closedとなります。バックエンドプロセスでユーザーコードを実行するようフォールバックすることは決してありません。

実行は1つまたは2つの使い捨てコンテナで行われ、いずれもツールおよびスキルSandboxと同様に堅牢化されています（非root、全ケイパビリティの削除、`no-new-privileges`、読み取り専用ルートファイルシステム、CPU/メモリ/PID制限、そして**Dockerソケットなし**）：

- `requirements.txt`が空の場合、**`--network none`の単一コンテナ**がコードを実行します。runnerはコンテナのstdin payloadで到着するため、何もマウントされません。
- 依存関係がある場合、最初のコンテナがネットワークアクセス付きでそれらを実行ごとの`.deps`ディレクトリにインストールし、2番目のコンテナがそのサブツリーを**読み取り専用**でマウントしてコードを実行します。実行コンテナは、ノードの`codeAllowNetwork`オプションが有効になっていない限りネットワークを持ちません。

依存関係は`uv`でインストールされ、`pip`で再試行され、実行間でキャッシュされることはありません。バックエンドがコンテナ内で実行される場合、実行ごとのディレクトリはスキルSandboxが使用するのと同じ`heym-codex-workspaces`ボリューム上に存在し、実行ごとの`volume-subpath`を介してマウントされるため、ある実行が別の実行のファイルを見ることはありません。この形式には**Docker Engine 25.0以降**が必要です。ネイティブバックエンド（`./run.sh`）にはそのようなボリュームはなく、必要ありません。その実行ごとのディレクトリは、兄弟コンテナに直接バインドマウントされるローカル一時パスです。いずれの場合も、結果に関係なくすべての実行後にディレクトリは削除されます。

コンテナには、シークレットではないポータブルな環境変数のみが転送されます。プロキシ設定、CAバンドル、ロケールであり、依存関係のインストールが企業プロキシの背後でPyPIに到達するために必要です。データベースURL、`SECRET_KEY`/`ENCRYPTION_KEY`、プロバイダーAPIキー、OAuthシークレットはallowlistによって除外されるため、新しいバックエンドシークレットは、誰かがdenylistを更新するまで漏洩するのではなく、デフォルトで除外されます。バックエンドの`HOME`がSandbox自身の書き込み可能パスを上書きすることは決してありません。

**Format**ボタンは同じSandboxを使用します。Ruffはソースを実行するのではなく解析して書き換えますが、バックエンドホスト上で実行すると、信頼できないファイルにバックエンドの環境全体を継承するプロセスを与えることになるため、同じ制限と同じallowlist環境を持つ専用の使い捨て`--network none`コンテナを取得します。ホスト上でフォーマットするのではなく、Dockerなしではfail closedとなります。

Sandboxの制限は環境変数ではなく定数です — 512 MBのメモリ、1 CPU、256プロセス、120秒のインストールタイムアウト、60秒の実行タイムアウト。イメージは既存の`HEYM_PYTHON_TOOL_IMAGE` / `HEYM_CODEX_DOCKER_IMAGE`チェーンから解決されます。ノード自体は独自の設定を導入しません。
