# 設定

設定ダイアログでは、プロフィールの管理、永続的な AI 指示の設定、アカウントパスワードの更新、チャット音声の設定、デフォルトの AI クレデンシャルとモデルの設定、および可観測性ステータスの確認ができます。ヘッダー右上隅にある**あなたのアバターと名前**をクリックすると開きます。

## ダイアログを開く

ヘッダー右上の**あなたのアバターと名前**をクリックします。ダイアログが開き、**Profile**、**Security**、**Voice**、**AI Defaults**、**Observability** のタブが表示されます。インスタンス管理者には **SSO** タブも表示されます。

## Profile タブ

### プロフィール画像

Heym は、アカウントのメールアドレスに対応する [Gravatar](https://gravatar.com) の画像を、ヘッダー、[Chat](../tabs/chat-tab.md) および **Chat with Heym** のメッセージの横、[Board](../tabs/board-tab.md) のコメント、共有ダイアログやチームメンバーリストの名前の横に表示します。変更するには Gravatar 上の画像を更新してください。Heym は数時間以内に新しい画像を取得します。Gravatar の画像がない場合、Heym は名前の頭文字を表示します。

画像は Heym サーバーによって取得され、そこにキャッシュされるため、ブラウザが Gravatar に直接アクセスすることはありません。サーバーが Gravatar に到達できない場合、全員に頭文字が表示され続けます。

### 名前

アプリ全体で表示される表示名です。このフィールドは必須で、空のままにすることはできません。

### User Rules

User Rules は、すべての AI リクエスト（Workflow ビルダーとダッシュボードチャットの両方）に自動的に挿入されるカスタム指示です。**Workflow ビルダー**（[AI Assistant](./ai-assistant.md)）では、Workflow JSON を生成するために使用されるシステム Prompt に追加されます。**ダッシュボードチャット**では、システムレベルのコンテキストとして適用されます。一度記述すれば、各 Prompt で繰り返すことなくグローバルに適用されます。

**一般的な用途:**

- 言語やトーン: `Always respond in English. Keep responses concise.`
- コーディングスタイル: `Use async/await patterns. Prefer TypeScript interfaces over types.`
- Workflow の規約: `Include error handling in all workflows. Use descriptive node labels.`
- 応答形式: `Use bullet points. Avoid lengthy explanations.`

**適用される場所:**

| コンテキスト | 説明 |
|---------|-------------|
| **Workflow ビルダー** | Workflow の生成または変更のための [AI Assistant](./ai-assistant.md) リクエスト |
| **ダッシュボードチャット** | すべての [Chat タブ](../tabs/chat-tab.md)の会話 |

User Rules はシステムレベルで挿入されます。Workflow や会話ごとの追加設定なしに、すべての Prompt の前に自動的に実行されます。

### プロフィール変更の保存

**Save Changes** をクリックして適用します。変更はすべての新しい AI リクエストに即座に反映されます。

## Security タブ

### パスワードの変更

Security タブでアカウントのパスワードを更新できます。

**要件:**

| ルール | 要件 |
|------|-------------|
| 最小文字数 | 8 文字 |
| 大文字 | 少なくとも 1 つの大文字 (A–Z) |
| 小文字 | 少なくとも 1 つの小文字 (a–z) |
| 数字 | 少なくとも 1 つの数字 (0–9) |

パスワードは現在のパスワードと異なる必要があります。これらのルールはフロントエンドとバックエンドの両方で適用されます。

**手順:**

1. **Current Password** を入力します
2. **New Password** を入力します（上記のすべての要件を満たす必要があります）
3. **Confirm New Password** に再入力します
4. **Update Password** をクリックします

現在のパスワードが正しくない場合、インラインのエラーメッセージが表示されます。成功すると確認メッセージが表示され、フォームは自動的にリセットされます。

## Voice タブ

Voice タブでは、[Chat タブ](../tabs/chat-tab.md)の読み上げ音声を設定します。**ElevenLabs クレデンシャル**を選択（またはインラインで追加）し、ElevenLabs アカウントから**音声**を選択して、**Save Voice Settings** をクリックします。これにより、メッセージごとの読み上げとインタラクティブ音声モードが有効になります。詳細なフローについては [Chat Voice (TTS & STT)](./chat-voice.md) を参照してください。

## AI Defaults タブ

AI Defaults タブには 2 つのセクションがあります。

### 優先クレデンシャルとモデル

**優先 LLM クレデンシャル**と、そこから**モデル**を選択します。これは、アプリ内のすべての AI 機能（チャット、[AI Assistant](./ai-assistant.md)（ビルダー、アナライザー、Workflow 作成）、ボードマッパー、AI ダッシュボードウィジェット、[docs チャット](../tabs/chat-tab.md)、データテーブル AI スキーマヘルパー、式ビルダー、evals）において、そのサーフェスに独自の保存された選択がない場合の初期デフォルトになります。

各サーフェスが従う選択ルールは次のとおりです:

1. **保存された選択** — そのサーフェスで既に行った選択（たとえばチャット会話の最後のモデル）が常に優先されます。
2. **優先** — 保存された選択がない場合に使用されます。
3. **最初に利用可能なクレデンシャル** — 優先設定を行っていない場合のフォールバックです。

サーフェスごとにクレデンシャルとモデルをいつでも変更できます。優先設定は初期デフォルトを埋めるだけです。クレデンシャルを **No preference** のままにすると、以前の最初のクレデンシャルの動作が維持されます。優先クレデンシャルが後で削除または共有解除された場合、タブに通知が表示され、サーフェスは最初に利用可能なクレデンシャルにサイレントにフォールバックします。

### コーディングパッケージの使用状況

**Codex** 認証情報（共有のものを含む）ごとに、このタブではアクティブなウィンドウごとの残りのレート制限使用量が横棒グラフで表示されます。例えば、プランに応じて **5 hours** ウィンドウや **Weekly** ウィンドウなどが表示されます。各バーには残りのクォータの割合とリセットまでのカウントダウンが表示されます。**Refresh** ボタンでオンデマンドに再取得できます（結果はサーバー側で短時間キャッシュされます）。

**OpenCode** 認証情報ごとに、このタブでは OpenCode Go サブスクリプションのウィンドウ（**5 hours**、**Weekly**、**Monthly**）が同じスタイルのバーで表示され、その認証情報の API key を使用してゲートウェイの認証済み使用状況Endpointから読み取られます。上限に達したウィンドウは琥珀色で **「limit reached」** と表示されます。key が無効であるか、ワークスペースに Go サブスクリプションがない場合は、バーの代わりにその理由がカードに表示されます。

## Observability タブ

Observability タブには、このインスタンスの [OpenTelemetry Tracing](./opentelemetry.md) の読み取り専用ステータスが表示されます。tracing が有効かどうか、OTLP Endpoint、サービス名、サンプラー比率、およびどの span が出力されるかなどです。tracing はバックエンドの `HEYM_OTEL_*` 環境変数を通じて設定されるため、このタブでは何も編集できません。tracing が無効になっている場合、このタブには有効化に必要な環境変数が一覧表示されます。OTLP 認証ヘッダーなどのシークレットはここには表示されません。設定の完全なリファレンスについては [Environment Variables](https://github.com/heymrun/heym/blob/main/ENVIRONMENT-VARIABLES.md) を参照してください。

## SSO タブ

インスタンス管理者（`HEYM_ADMIN_EMAILS` に記載されたアカウント）のみに表示されます。このタブでは、Heym を外部の OpenID Connect プロバイダーに接続し、ユーザーが既に持っているアカウントでサインインできるようにします。issuer URL とクライアント認証情報を入力し、読み取り専用の redirect URI をプロバイダーにコピーして、有効化する前に **Test connection** を実行してください。テストに合格したら、ここからパスワードサインインを無効にできます。完全なセットアップについては [Single Sign-On](./sso.md) を参照してください。

## Instances タブ

インスタンス管理者（`HEYM_ADMIN_EMAILS` に記載されたアカウント）のみに表示されます。このタブには、このデータベースに接続されている Heym インスタンスが一覧表示され、バックグラウンド実行がそれらの間でどのように分割されるかを設定します。各行には、インスタンスの編集可能な名前、ロール、稼働中かどうか、データベースへの計測されたレイテンシ、オン/オフスイッチ、および重みが表示されます。重みは現在作業を引き受けられるインスタンスのシェアであり、100 のパーセンテージではありません。`41 / 26 / 33` で 3 番目のインスタンスがオフの場合、最初の 2 つは実際に 61% と 39% を受け取ります。パネルはその実効的な分割をテーブルの下に表示し、有効なインスタンスに重みがまったくない場合にのみ保存を拒否します。

**Give new instances a share automatically** はデフォルトでオンになっています。参加したインスタンスはそうでなければ重み 0 のまま何も受け取らないため、リーダーは一度だけ均等なシェアを付与し、既存の重みをその比率を保ったまま縮小します。自分で重みを設定したインスタンスには決して触れません。

パネルはまた、過去 24 時間の実行のうち、メインインスタンスでのみ実行できたものがどれだけあるかも報告します。そのシェアが高い場合、その下の重みではその作業を移動できません。メインに残るものと数値の選び方については [Load Distribution](./cluster.md) を参照してください。

## このダイアログに含まれないもの

| 機能 | 場所 |
|---------|-----------------|
| **API key 管理（MCP）** | [MCP Tab](../tabs/mcp-tab.md) – MCP サーバーの API key を表示、コピー、再生成 |

| **メール変更** | 現在サポートされていません |
