# Chatタブ

**Chat**タブは、直接的なLLMチャットインターフェースを提供します。モデルのテスト、質問、既存のWorkflowの実行、または自然言語リクエストからの新しいWorkflowの作成に使用できます。

## セットアップ

1. [credential](./credentials-tab.md)（OpenAI、GoogleなどのAPI key）を選択します
2. ドロップダウンからモデルを選択します（モデルは選択したcredentialから読み込まれます）
3. 入力を開始してメッセージを送信します

[Workflowsタブ](./workflows-tab.md)のチャットボックスから会話を開始することもできます。最初のメッセージが送信され、回答がすでにストリーミングされている状態で、ここに新しい会話が開きます。

## 機能

- **Global Variablesコンテキスト** – [Global Variables](../reference/global-variables.md)がLLMから利用可能なため、保存された値について質問したり参照したりできます
- **Workspaceテンプレートコンテキスト** – ワークスペース内の共有Workflowおよびノードテンプレートがコンテキストとして含まれるため、Chatは利用可能なテンプレートに関する質問に回答できます
- **長時間実行Agent** – ブラウザを閉じてもChatはバックエンドで動作を続けるため、別のデバイスから戻って同じ会話を続けることができます
- **Workflow作成** – ChatにWorkflowの作成やセットアップを依頼すると、エディタアシスタントと同じWorkflow AI Builderエンジンを使用してWorkflowを生成・保存します
- **Kanbanタスク作成** – 自然言語でタスクの追加やカードの作成を依頼できます。Chatは指定されたボードの最初の列に追加します。複数のボードがあり、名前を指定しない場合、Chatはカードを作成する前にボード選択画面を表示します
- **キューされたフォローアップ** – 回答のストリーミング中にも追加のメッセージを送信できます。キューされたメッセージは永続化され、開始前に編集または削除でき、アクティブな応答の後に順番に実行されます
- **プランニングの一時停止** – Chatがプランニングの詳細を必要とする場合、明確化の質問を行い、回答するまでキューされたフォローアップを一時停止します。プランニングの回答が完了すると、キューされたメッセージが再開されます
- **Credentials** – Chatが作成または編集するWorkflowがcredentialを必要とする場合、Chatはどれを使用するかを尋ね、会話内で新しいものを作成することを提案するか、使用せずに続行できるようにします。また、Chatにcredentialの作成や所有しているものの更新を依頼することもできます。会話内でcredentialフォームが開きます。モデルはcredentialの名前とタイプを参照しますが、その値は参照しません（自身が所有するCredentialおよび共有されたCredentialの両方が対象です）。Chatが追加するLLMおよびAgentノードは、共有Credentialを含め、チャット用に選択されたCredentialとモデルで実行されます。ChatがWorkflowを編集する際、既存のLLMおよびAgentノードはそのCredentialとモデルを維持します。詳細は[AI Assistant › Credentials](../reference/ai-assistant.md#credentials)を参照してください
- **Data tables** – Chatが作成または編集するWorkflowがレコードを保存する場合、Chatはどの[data table](./datatable-tab.md)を使用するかを尋ねるか、Workflowに必要な列を持つものを作成することを提案します。また、テーブルとその列を一覧表示することもできます。行の読み取りや書き込みは行いません。詳細は[AI Assistant › Data tables](../reference/ai-assistant.md#data-tables)を参照してください
- **ストリーミング応答** – モデルの出力がストリーミングされる様子を確認できます
- **応答の停止** – 現在ストリーミング中の回答をいつでも中断できます。停止すると、その会話のキューされたメッセージもクリアされます
- **Markdownレンダリング** – 応答はインライン画像を含むMarkdownフォーマットをサポートします
- **画像表示** – 応答に埋め込まれた画像（LLMの画像生成によるものなど）はインラインで表示されます。任意の画像をクリックするとフルスクリーンで表示されます。フルスクリーン表示を閉じるには**Esc**キーまたは戻るボタン（モバイル）を押します
- **メッセージのコピー** – 任意のメッセージをクリップボードにコピーできます
- **チャットのクリア** – 新しい会話を開始します
- **音声入力** – マイクボタンを使用して音声テキスト変換を行います（ブラウザ対応）。録音が停止すると、Heymは送信前にトランスクリプトを軽くクリーンアップできます
- **スケジュールされたWorkflow** – cron Workflowがいつ実行されるか（今日、今週、今月、またはカスタム日付範囲）を尋ねることができます。アシスタントは[Scheduled](./scheduled-tab.md)タブと同じスケジュールデータを使用し、結果を所有するWorkflowに限定したり、共有されているものを含めたりできます
- **Workflow実行履歴** – 1つのWorkflowについて質問できます（「日次レポートは何回実行されましたか？」「失敗しましたか？」「最後に実行されたのはいつですか？」）。ChatはIDでWorkflowを検索し、実行回数、ステータス内訳、最初と最後の実行時刻、平均所要時間から回答します。実行が失敗した理由や何を返したかを尋ねると、Chatはその単一の実行を開いて、入力、出力、ノードごとのエラーを読み取ります
- **ライブ実行ステータス** – 現在何が実行されているかを尋ねると、Chatは件数、Workflow名、各実行の経過時間、どのノードにいるか、ライブ実行への直接リンクを回答します

- **実行コンテキストチップ** – [Execution History](../reference/execution-history.md#ask-ai) の **AIに質問** をクリックすると、選択した Workflow 実行がチップとして添付された新しい会話が開きます。[実行についての質問](#zik-kou-ni-tsui-te-no-zhi-wen) を参照してください

## MCP Client からの Chat の使用

Chat エンジンはブラウザ外からも利用できます。[MCP タブ](./mcp-tab.md)で **Heym Chat Tool** を有効にすると、MCP Client（Claude、Cursor、その他 MCP に対応するあらゆるツール）から、同じエンジンをすべての機能とともに実行する単一の `heym_chat` ツールを利用できるようになります。

これらの会話はこのタブの履歴に保存され、会話一覧ではプラグアイコンで表示されます。会話を開くと、Client が何を要求したか、どのツールカードが Trigger されたかを確認でき、そのスレッドを自分で続けることもできます。確認質問への回答は、そのターンがここから始まった場合でも MCP Client から始まった場合でも同じように機能します。

MCP 経由の場合、Chat は Credential の一覧表示、選択、作成を行いません。Chat が構築する Workflow では Credential フィールドは空のままとなり、返信の中で Credential が必要なノードが示されるので、エディタで設定してください。

データテーブルも MCP 経由で動作します。Chat はテーブルの一覧表示、新規作成、および構築する Workflow への組み込みを行います。テーブルに関する質問は結果内にテキストとして返されるため、同じ `conversation_id` を使って回答してください。

## コンテキスト制限

Chat はコンテキスト内に直近 25 件のメッセージを保持します。それより古いメッセージは、モデルの制限内に収めるために削除されます。

## Workflow の作成

Chat に Workflow の作成、構築、生成、セットアップを依頼すると、生成された名前と説明を持つ新しい保存済み Workflow が作成されます。応答には、生成されたノードとエッジの読み取り専用キャンバスプレビューと、新しいブラウザタブで Workflow エディタを開く **Open workflow** リンクが含まれます。Workflow を実行したい場合は、プレビューカードの **Run** ボタンを使用してください。

同じ Chat 内での追加のフィードバックは、新しい Workflow を作成するのではなく、その Workflow を編集します。たとえば、Chat が Workflow を作成した後に「承認ステップを追加して」「出力形式を変更して」「şöyle yap」と伝えると、Chat は保存済みの Workflow を更新し、プレビューを更新します。

これは、単発の回答ではなく、再利用可能な自動化として作業を完了させたいリクエストに最適です。

## Kanban タスクの作成

Chat に通常の言葉で依頼してください。たとえば、「Fix login bug というタスクを追加して」や「Launch ボードに Update documentation という新しいカードを作成して」などです。同じリクエスト内に説明を含めることもできます。Chat は常に、選択されたボードの最初の列にカードを作成します。

ワークスペースに複数のボードがあり、どれかを指定しない場合、Chat は単一選択のボードピッカーを表示して一時停止します。ボードを選択するとカードの作成が完了します。スラッシュコマンドや特別なメッセージ形式は必要ありません。

## 実行状況の確認

「何が実行中ですか？」「現在アクティブな Workflow はいくつありますか？」「夜間レポートはどのノードにありますか？」など、通常の言葉で質問すると、Chat がリアルタイムの状況を報告します。

- **いくつの**実行が進行中か（実行中と Human レビュー待ちに分けて表示）
- **どの Workflow** に属しているか（名前別）
- **どれくらいの時間** 各実行が続いているか（例: `1m 35s`、`3h 25m`）
- **どのノード** が現在実行中か（キャンバス上のラベル別）、および最後に完了したノード
- **各実行へのリンク**（その実行をリプレイする形でキャンバスを開きます）

[Human-in-the-Loop](../reference/human-in-the-loop.md) または Codex レビューのために一時停止している実行は、実行中ではなくあなたの対応待ちとして報告されます。これはヘッダーのアクティブ実行バッジと同じデータであるため、Chat とバッジの内容が食い違うことはありません。すでに完了した実行については、代わりに最近の実行を尋ねてください。これは [Execution History](../reference/execution-history.md) から読み取られます。

## 実行についての質問

エディターまたは All History の [Execution History](../reference/execution-history.md#ask-ai) で Workflow 実行を選択し、ダイアログのタイトル横にある **AIに質問** をクリックします。Chat はメッセージボックスの上に2つのチップを表示した新しい会話を開きます:

- **Workflow:** Workflow の名前
- **Execution:** 選択した実行のIDの先頭文字

除外する場合は **×** をクリックしてチップを削除します。その後、「なぜこの実行にこれほど時間がかかったのか?」、「ここで何が失敗したのか?」、「これを修正できますか?」といった質問を入力します。残りのチップは完全なIDとともにそのメッセージに添付されるため、Chat は Workflow を検索する代わりに実行の入力、出力、およびノードごとのトレースを直接読み取ります。Workflow を修正する場合、Chat は [Workflowの作成](#workflow-no-zuo-cheng) で説明されているように変更を保存、テスト実行、検証します。

送信されたメッセージでは質問の下にチップが表示されます。これらはそのメッセージのみに属します。同じ会話内の以降の質問は履歴からのコンテキストを維持します。

## アラートに関する質問

Chat は、定義済みの[アラート](./alerts-tab.md)に関する質問に回答できます。

- **何が存在するか** — 「どんなアラートがありますか？」「invoice Workflow にアラートはありますか？」「現在発火しているアラートはどれですか？」
- **どのように設定されているか** — 「コストアラートのしきい値は何ですか？」「それはどのように設定されていますか？」
- **なぜ、いつ発火したか** — 「なぜコストアラートが発火したのですか？」「これは最後にいつ Trigger されましたか？」

「なぜ発火したか」という質問に対して、Chat は発火記録を読み取り、実際に観測された値、しきい値、評価された正確なウィンドウを引用し、さらに詳細な内訳（エラーアラートの場合は失敗した実行 ID とエラーメッセージ、コストアラートの場合はモデル別の支出、実行回数アラートの場合は Trigger ソースの内訳）を提示します。ウィンドウはすでに経過しており、再計算すると異なる結果になる可能性があるため、Chat はウィンドウを再計算せず、アラート発火時に真であった内容を報告します。

## User Rules

[User Rules](../reference/user-settings.md)（Settings で設定）は、システムレベルの指示としてすべての Chat 会話に自動的に注入されます。一度設定すれば、すべての Chat リクエストに永続的な設定が適用されます。

## ツール呼び出しとコンテキストサイズ

アシスタントがツールを呼び出すたびに（Workflow の実行、実行履歴の一覧表示、新しい Workflow の構築など）、会話内に折りたたみ可能なカードが表示されます。カードはツールの実行中に自動展開され、正確な引数を表示します。ツールが完了すると、カードは経過時間とともに1行のサマリーに折りたたまれます。任意のカードをクリックすると、引数とレスポンスのサマリーが再展開されます。

入力欄の下にある小さなリングバッジは、モデルのコンテキストウィンドウに対する現在のコンテキスト使用率をパーセンテージで表示します（例: `12% · ~9.2k`）。バッジにカーソルを合わせると、システム Prompt、AGENTS.md、Workflow ブロック、ユーザールール、履歴、入力中の下書きといった内訳が表示されます。使用率が80%を超えるとリングは琥珀色に、95%になると赤色に変わります。

使用率が上限に近づくと、Heym は Agent ノードが使用するのと同じ仕組みで、古いメッセージを自動的に短いサマリーに圧縮します。何が起きたかを示す「Context compressed」カードがインラインで表示されます。
