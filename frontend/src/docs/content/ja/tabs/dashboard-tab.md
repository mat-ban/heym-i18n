# ダッシュボード

**ダッシュボード**タブは、Grafana スタイルの空間で、チャートウィジェットのグリッドを構築できます。各ウィジェットは、それぞれの背後に隠れた Heym Workflow の出力からレンダリングされます。そのため、Workflow で生成できるあらゆるデータ — データベースクエリ、API 呼び出し、RAG 検索、LLM 出力 — をチャートにできます。複数のダッシュボードを保持し、それぞれを個人またはチームと共有できます。

## ダッシュボード

誰もが最初にタブを開いたときに 1 つのダッシュボードが作成されます。タブ上部のダッシュボードセレクターでダッシュボードを切り替え、その隣の **+** で新しいダッシュボードを作成できます。セレクターには、まず自分のダッシュボードが一覧表示され、次に共有されたダッシュボードが、共有した人の名前とともに表示されます。

タブを再度開くと、最後に使用したダッシュボードが開きます。また、アドレスバーには開いているダッシュボード (`?tab=dashboard&dashboard=<id>`) が含まれるため、リンクを開くとアクセス権を持つ誰もがそのダッシュボードを開けます。

設定ボタン（オーナーのみ）では、ダッシュボードの名前変更、[詳細ページ](#detail-pages)として受け入れるレコード形式の設定、共有の管理、削除ができます。ダッシュボードを削除すると、そのウィジェットとそれらの Workflow も削除されます。自分自身のダッシュボードは常に少なくとも 1 つ保持されるため、最後の 1 つは削除できません。

## ウィジェット

ウィジェットはグリッド上の単一のチャートです。サポートされているチャートタイプ：

- **Bar**（縦または横）
- **Line**
- **Area**（塗りつぶしトレンド、複数シリーズに対応）
- **Pie**
- **Table**（スクロール可能。列の見出しをクリックすると昇順で並べ替えられ、もう一度クリックすると降順になります。1つの列を [ステータスチップ](../nodes/chart-output-node.md#status-chips) としてレンダリングでき、1つの列に新しいタブでURLを開く [リンクボタン](../nodes/chart-output-node.md#link-buttons) を配置でき、行をクリックして [詳細ページ](#xiang-xi-pezi) を開くことができます）
- **Numeric**（単位を任意で指定できる単一の KPI 値）
- **Gauge**（最小〜最大範囲に対する単一の値、例：パーセンテージ）
- **Scatter**（相関プロット用の X/Y ポイント）
- **Proportion**（パーセンテージ凡例付きで割合に分割された 1 本のバー、例：言語の内訳）
- **Gantt**（タスクの日付、完了状況、依存関係）
- **Entity relationships (DB)**（テーブル、フィールド、PK/FK キー、接続）
- **Bar gauge**（赤→緑のグラデーションと値を持つ、行ごとに 1 本の水平ゲージ、例：空きディスク容量）
- **Text**（markdown メッセージ、例：「Last execution at 19:47」のようなステータスノート。markdown が静的な場合は[インタラクティブなチェックボックス](../nodes/chart-output-node.md#interactive-task-lists)を、カスタムまたは降順の番号付けには[明示的な番号付きリスト](../nodes/chart-output-node.md#numbered-lists)をサポート）
- **HITL**（保留中のヒューマンレビュー。ヘッダーには `1/n pending` と表示されます。Workflow 名をクリックすると、キャンバス上でその実行が開きます。**Approve**、**Request changes**、**Reject** で解決できます。ウィジェットタイトルの横の履歴アイコンをクリックすると、このページの履歴ダイアログでその実行が開きます。このウィジェットは上流の行を使用せず、各人が自分のキューを表示します。 代わりに、その Workflow を開くことができる全員に向けて、単一の Workflow のレビューを表示することもできます。[HITL ウィジェット](#hitl-uizietto) を参照してください）

チャートのほかに、**Run a workflow** ウィジェットを使うとダッシュボードから自分の Workflow を実行できます。ファイルのドロップ、入力フィールドの入力、または Run ボタンで実行します（[実行ウィジェット](#run-widgets)を参照）。

各ウィジェットはタブを開いたときにデータを非同期で読み込むため、チャートが表示されていく間もページは応答性を保ちます。

## ウィジェットの追加

1. **Add widget** をクリックし、タイトルを付けてチャートタイプを選択します。ピッカーの下に、そのチャートタイプの例がサンプルデータとともに描画され、期待される行の名前が示されるため、構築する前にタイプを比較できます。
2. ウィジェットが Workflow エディターでスターターグラフとともに開きます。行を生成する [Set](../nodes/set-node.md) ノードが [Chart Output](../nodes/chart-output-node.md) ノードに接続されています。Set ノードを任意のデータソースに置き換えてください。**HITL** ウィジェットは Chart Output ノードのみで構成され、保留中のレビューを読み取るためデータソースは不要です。
3. **Chart Output** に供給するノードが行の配列を生成するように Workflow を構築し、Chart Output ノードのフィールドマッピング（ラベルフィールド、値フィールドなど）を設定します。
4. 保存してダッシュボードタブに戻ると、ウィジェットがレンダリングされます。

**Run a workflow** ウィジェットの場合は、代わりに実行する Workflow を選択します。ピッカーには、ウィジェットがそれぞれの Workflow をどのように実行するかが表示されます。ウィジェットはグリッドに直接追加され、新しい Workflow を構築する必要はありません。

ウィジェットをダブルクリックする（または編集ボタンを使用する）と、いつでもその Workflow を再度開けます。ウィジェットヘッダーの **Clone widget** を使用すると、ウィジェットとその完全な Workflow の両方を複製できます。コピーは元の下に配置され、**(Copy)** とラベル付けされるため、独立して編集できます。

## HITL ウィジェット

新しい HITL ウィジェットは、自身のキューで待機しているすべてのレビューを表示します。1つの Workflow のレビューのみを表示するには、ウィジェットの **設定** を開きます:

1. **Workflow** で対象の Workflow を選択します。リストには、ユーザーが開くことができる Workflow（自身が所有するもの、または自身やチームと共有されているもの）のうち、人を待機しているステップ（人間のレビューを伴う Agent、または Slack の承認、ボタン、フォームのステップ）を持つものが含まれます。横にあるアイコンをクリックすると、その Workflow が新しいタブで開きます。
2. Workflow にそのようなステップが1つだけある場合、自動的に選択されます。複数ある場合、**Select agent** はノード名順にそれらをリストし、先頭に **All agents** が表示されます。Slack ステップには **(Slack)** のマークが付きます。
3. 保存します。ヘッダーの `1/n pending` はそれらのレビューのみをカウントします。自身のキューを再度表示するには **すべてのWorkflow** を選択します。

キャンバス上の Chart Output ノードのプロパティにも同じ選択肢があります。**AI で微調整** を使用して指定することもでき（「請求書承認のみを表示」）、Workflow 名を指定した新しいウィジェットの説明からも設定できます。すべての変更は Workflow の編集であるため、Edit History に表示されます。

- **レビューの表示対象。** Workflow でフィルタリングされたウィジェットは、その Workflow を開くことができる全員にその Workflow のレビューを表示し、Workflow を実行できるのと同様にウィジェットから承認、変更リクエスト、却下を行うことができます。フィルタリングされていないウィジェットは、各ユーザーに自身のキューを表示します。
- **ウィジェットの表示対象。** 選択した Workflow を開くことができないユーザーには、共有されたダッシュボード上であってもウィジェットは一切表示されません。ダッシュボードの所有者がアクセス権を失った場合、または Workflow が削除された場合、所有者には「You no longer have access to the workflow this widget shows」と表示され、**設定** で別の Workflow を選択できます。
- **アクセス可能な選択肢のみ。** 開くことができない Workflow は、設定からでもキャンバスからでもAI経由でも、ウィジェットの保存時に拒否されます。

## 詳細ページ

テーブルウィジェットの行を別のダッシュボードにリンクすると、そのダッシュボードを詳細ページとして機能させることができます。つまり、1 つのダッシュボードですべての顧客、請求書、またはチケットに対応できます。

1. テーブルウィジェットの **Settings** を開き、**Row link** でリンク先のダッシュボードを選択します。
2. 行を識別する値を持つ列である **Record column**（例: `id`）を入力し、必要に応じて行の名前となる **Label column**（例: `name`）を入力します。
3. 保存します。行をクリックする（またはフォーカスして Enter キーを押す）と、リンク先のダッシュボードが `?record=<value>&label=<name>` 付きで開きます。

詳細ダッシュボードでは、各ウィジェットの Workflow がその値を `$page.record` として読み取り（[Chart Output](../nodes/chart-output-node.md#detail-pages-pagerecord)を参照）、グリッドの上には `Dashboard / <label>` とレコードをクリアするボタンが表示されます。戻るボタンで元のテーブルに戻ります。

- **開くことができるユーザー。** 行をクリックできるのは、リンク先のダッシュボードを開く権限がある閲覧者のみです。他のユーザーにはリンクなしの同じテーブルが表示されます。
- **レコード形式。** レコードは URL から渡されるため、詳細ダッシュボード側で受け入れる形式を決定します。設定の **Detail page records** では、ID（英字、数字、`-`、`_`、`.`、最大 128 文字、デフォルト）、数値、UUID、またはメールアドレスのいずれかを選択します。それ以外の値はウィジェットの実行前に拒否され、ウィジェットには「This page does not accept that record」と表示されます。
- **オーナー権限での実行。** 詳細ページでも、ウィジェットはダッシュボードのオーナーとして実行されます。作成者は、ノードが値をエスケープする箇所にのみ `$page.record` を渡すようにし、クエリテキストへ直接埋め込まないでください。
- **キャッシュ。** 各ウィジェットはウィジェットと同じ有効期間（TTL）でレコードごとにチャートをキャッシュし、最近使用された 50 件のレコードを保持します。

## 実行ウィジェット

**Run a workflow** ウィジェットは、Workflow の 1 つを実行し、その結果（ステータス、実行時間、出力）を表示します。表示内容は Workflow が受け取る入力によって異なります。

- **ファイル。** [File Upload Trigger](../nodes/file-upload-trigger-node.md) で始まる Workflow の場合、ファイルをドロップする（またはクリックして選択する）と、ウィジェットはトリガーの使い捨てアップロードリンク経由でファイルをアップロードします。ウィジェットにはトリガーが受け入れるファイル形式とサイズが表示され、それ以外のファイルはアップロード前に拒否されます。Workflow が Text Input ノードでも始まる場合、ドロップゾーンの横にその入力フィールドが表示されます。ファイルを選択し、フィールドに入力して **Run** をクリックすると、両方が送信されます。入力値はウィジェットが発行するアップロードリンクと一緒に送られるため、共有されたアップロードリンクからそれらの値を設定することはできません。
- **入力フィールド。** Text Input ノードで始まる Workflow の場合、ウィジェットにはデフォルト値付きのフィールドが表示され、**Run** をクリックすると入力した値で Workflow が実行されます。Workflow に存在しないフィールドの値は破棄されます。
- **入力なし。** 入力を持たない Workflow には **Run** ボタンが表示されます。

結果の **Wrap** ボタンは、ボックス内の長い出力行を折り返します。出力の JSON レイアウトをそのまま読むにはオフにしてください。

- チャートを更新できるのと同様に、ダッシュボードを開けるユーザーなら誰でもこのウィジェットを実行できます。Workflow へのアクセス権はダッシュボードのオーナーに準じます。ウィジェットを追加するにはあなたとオーナーの両方が実行できる Workflow が必要であり、実行自体はアップロードリンクと同様に Workflow オーナーの認証情報（credential）を使用します。
- 結果はページを離れるまで自分の画面にのみ残ります。他の閲覧者にあなたのファイル、入力値、結果が見えることはありません。実行はトリガー `dashboard` として実行履歴に記録されます。
- ダッシュボードを共有しても、Workflow 自体へのアクセス権は付与されません。**Edit workflow** はすでにアクセス権を持つユーザーに対してのみ開かれ、**Fine-tune with AI** は提供されません。
- ファイルの実行は、すべての File Upload Trigger の実行と同様に、アップロードされたファイルが保存されているメインインスタンス上で実行されます。

## AI でウィジェットを生成する

**AI** をクリックし、必要な指標を説明して（例：「過去 30 日間の Workflow 成功率を棒グラフで」）、LLM クレデンシャルとモデルを選択します。Heym は Chart Output ノードで終わる完全なウィジェット Workflow を生成し、グリッドに追加します。チャートタイプごとの Prompt の例については、[Chart Output](../nodes/chart-output-node.md#example-ai-prompts) を参照してください。

ウィジェットには、リクエストの言語で「未処理案件」のような1〜2語の短いタイトルが付けられます。タイトルにデータテーブルのIDが含まれることはありません。モデルが文形式でウィジェットに名前を付けた場合、Heym はその最初の数語を保持します。

ウィジェット API は、AI なしで **カウントカード** を作成することもできます。`count_column` と `count_value` を指定したデータテーブル (`data_table_id`) 上の `text` ウィジェットは、その値を持つ行数を表示します。ウィジェットのタイトルにはその値が示されます。Heym Work は、データテーブルから作成されたページをステータスごとに1つのカウントカードで開始します。

ウィジェットの **Fine-tune with AI** ボタンを使用すると、新しい指示で既存のウィジェットを修正できます。AI による微調整のたびに、以前の Workflow がウィジェットの **Edit History** にスナップショットされるため、Workflow エディターから変更を確認したりロールバックしたりできます。

## Chat および MCP からの操作

[Chat](./chat-tab.md)、および [`heym_chat` ツール](./mcp-tab.md) を介した MCP クライアントは、ダッシュボードの読み取り、ウィジェットの追加、ウィジェットの名前変更や削除、ダッシュボードのレイアウトの整理を行うことができます。Heym Work は各ダッシュボードをページとして表示するため、同じ回答がそのページにも適用されます。

- **どのようなダッシュボードがあり、何が含まれているか。**「どのようなダッシュボードがありますか？」「営業ダッシュボードには何がありますか？」「収益 Workflow はどのダッシュボードにありますか？」と尋ねます。Chat は、あなたが所有するダッシュボードと共有されているダッシュボードを、アクセス権と各ダッシュボードへのリンク、およびそれらに含まれるすべてのウィジェット（タイトル、チャートタイプ、その背後にある Workflow）とともに一覧表示します。開く権限のない Workflow でフィルタリングされた [HITL ウィジェット](#hitl-widgets) は、ダッシュボード上と同様に非表示のままになります。
- **新しいウィジェット。**「営業ダッシュボードにステータス別のオープンケースのグラフを追加して」と依頼します。Chat はまずダッシュボードに空のウィジェットを配置し、次にウィジェット専用の Workflow を作成し、実行が成功するまでテスト実行とエラー修正を繰り返します（これは [Workflow の作成](./chat-tab.md#workflow-no-sakusei) と同じ方法です）。個別の Workflow が残されることはなく、保存ごとにウィジェットの Edit History に記録されます。ウィジェットのタイトルとチャートタイプは、Chat が保存した内容に従います。
- **既存の Workflow。**「営業ダッシュボードに収益 Workflow を配置して」と依頼します。Chart Output ノードで終わる Workflow は、その Workflow の独自のコピーを持つチャートウィジェットになるため、ウィジェットに対するその後の変更が元の Workflow に影響を与えることはありません。Trigger または Input ノードを持つ Workflow はチャートウィジェットにすることはできません。その他の Workflow は [実行ウィジェット](#run-widgets) になり、これにもダッシュボード所有者が実行できる Workflow が必要です。
- **ウィジェットの名前変更または削除。**「収益ウィジェットの名前を営業に変更して」または「オープンケースウィジェットを削除して」と依頼します。チャートウィジェットの Workflow も新しい名前になります。実行ウィジェットの Workflow は独自の名前を保持します。チャートウィジェットを削除すると、ウィジェットの削除ボタンと同様に、その Workflow も一緒に削除されます。実行ウィジェットの Workflow は残ります。Chat は明確に依頼されたウィジェットのみを削除し、指定した単語が複数に一致する場合は最初にどれかを尋ねます。
- **レイアウトの整理。**「営業ダッシュボードを整理して」、または「これら 3 つのウィジェットを追加して整理して」と依頼します。Chat は、**整理** ボタンと同様に、表示されているウィジェットを順番に配置します。2 行または 3 行のランダムな配置になるため、再度依頼すると別の配置になります。そのサイズの行を取得するには、1 行あたりの数を指定します（「1 行に 3 つ」）。これにより、Heym 内のダッシュボードが整理されます。Heym Work はページの独自の配置を保持し、ページの **整理** ボタンで変更されます。

新しいウィジェットはダッシュボードの既存のウィジェットの下に配置され、すべてのウィジェットと同様にダッシュボード所有者の権限で実行されます。追加、名前変更、削除、整理には、ダッシュボードへの書き込み権限が必要です。新しいウィジェットを作成するには、Workflow を構築できるチャットが必要です（Chat タブ、Heym Work の編集者用 Chat、および `heym_chat`）。

## レイアウトの編集

**Edit** を切り替えて編集モードに入ると、12 列のグリッド上でウィジェットをドラッグしたりサイズ変更したりできます。レイアウトの変更は自動的に保存されます。ウィジェットのタイトルはウィジェットヘッダーからインラインで編集できます。

## キャッシュと更新

各ウィジェットは、最後に計算されたデータをサーバー上に設定可能な time-to-live（TTL）の間キャッシュします。キャッシュが新しい間は、ダッシュボードを再度開くと Workflow を再実行する代わりに保存された結果が提供されます。キャッシュはデータが再計算されるたびにその場で置き換えられ（ウィジェットごとに 1 つのキャッシュ、さらに[詳細ページ](#detail-pages)上のレコードごとに 1 つのキャッシュ）、ウィジェットの Workflow を編集すると自動的に無効化されます。

ウィジェットの **Refresh** ボタン（またはツールバーの **Refresh**）を使用すると、キャッシュをバイパスして即座に再計算できます。

## 共有

オーナーはダッシュボードの設定から、個々のユーザー（メールアドレス指定）または所属する任意の[チーム](teams-tab.md)に対してダッシュボードを共有できます。各共有は**Read**または**Write**であり、個人共有とチーム共有の両方が存在する場合は、より強い権限が適用されます。

| 操作 | オーナー | Write | Read |
|--------|:-----:|:-----:|:----:|
| ウィジェットの表示、更新、自動更新の使用 | ✓ | ✓ | ✓ |
| 詳細ページを開く、実行ウィジェットを実行する | ✓ | ✓ | ✓ |
| ウィジェットの追加、複製、削除、名前変更、サイズ変更、AI生成と微調整、チェックリスト項目のチェック | ✓ | ✓ | |
| エディタでウィジェットのWorkflowを開く | ✓ | ✓ | |
| ダッシュボードの名前変更・削除、レコード形式の設定、共有の管理 | ✓ | | |

**ウィジェットは常にダッシュボードのオーナーとして実行されます。** 誰が閲覧していても、ウィジェットはオーナーの認証情報とグローバル変数を使用し、その実行はオーナーの実行履歴とトレースに表示されます。したがって、チームメンバーは背後にあるアカウントへのアクセスなしに同じデータを閲覧でき、すべての閲覧者がウィジェットごとに1つのキャッシュされた結果を共有します。Write権限のコラボレーターが追加または複製したウィジェットも、オーナーに帰属します。

このため、**Write**はWorkflowを編集用に共有するのと同じ信頼を伴います。Write権限を持つコラボレーターは、あなたの認証情報で実行される内容を変更できます。Write権限は、あなたのWorkflowの編集を許可する相手にのみ付与してください。コラボレーターがWorkflowエディタから開始するテスト実行は、共有されたWorkflowと同様に、そのコラボレーター自身の認証情報を使用します。オーナーとして実行されるのはダッシュボード自体のみです。**Read**はウィジェットのWorkflowへのアクセスを一切許可せず、読み取り専用の閲覧者はチャート自体を受け取りますが、その背後のノードごとの実行詳細は受け取りません。

共有の削除、またはWriteからReadへの引き下げは、即座に反映されます。

## スケジュールとデータベース図

ウィジェットの追加で **Gantt** を選択するとタスクの時間経過に伴う完了状況と依存関係リンクが表示され、**Entity relationships (DB)** を選択するとテーブル、フィールド、およびそれらのリレーションシップがマッピングされます。どちらのタイプも [Chart Output ノード](../nodes/chart-output-node.md#gantt-schedules) を使用し、Heym Work ページでも利用できます。Work がスケジュールやデータベーススキーマのウィジェットを提案するとき、ページを構築する前に提案されたタスクやエンティティからプレビューを描画します。
