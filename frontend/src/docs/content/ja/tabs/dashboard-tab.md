# ダッシュボード

**ダッシュボード**タブは、Grafana スタイルの空間で、チャートウィジェットのグリッドを構築できます。各ウィジェットは、それぞれの背後に隠れた Heym Workflow の出力からレンダリングされます。そのため、Workflow で生成できるあらゆるデータ — データベースクエリ、API 呼び出し、RAG 検索、LLM 出力 — をチャートにできます。複数のダッシュボードを保持し、それぞれを個人またはチームと共有できます。

## ダッシュボード

誰もが最初にタブを開いたときに 1 つのダッシュボードが作成されます。タブ上部のダッシュボードセレクターでダッシュボードを切り替え、その隣の **+** で新しいダッシュボードを作成できます。セレクターには、まず自分のダッシュボードが一覧表示され、次に共有されたダッシュボードが、共有した人の名前とともに表示されます。

タブを再度開くと、最後に使用したダッシュボードが開きます。また、アドレスバーには開いているダッシュボード (`?tab=dashboard&dashboard=<id>`) が含まれるため、リンクを開くとアクセス権を持つ誰もがそのダッシュボードを開けます。

設定ボタン（オーナーのみ）では、ダッシュボードの名前変更、共有の管理、削除ができます。ダッシュボードを削除すると、そのウィジェットとそれらの Workflow も削除されます。自分自身のダッシュボードは常に少なくとも 1 つ保持されるため、最後の 1 つは削除できません。

## ウィジェット

ウィジェットはグリッド上の単一のチャートです。サポートされているチャートタイプ：

- **Bar**（縦または横）
- **Line**
- **Area**（塗りつぶしトレンド、複数シリーズに対応）
- **Pie**
- **Table**（スクロール可能）
- **Numeric**（単位を任意で指定できる単一の KPI 値）
- **Gauge**（最小〜最大範囲に対する単一の値、例：パーセンテージ）
- **Scatter**（相関プロット用の X/Y ポイント）
- **Proportion**（パーセンテージ凡例付きで割合に分割された 1 本のバー、例：言語の内訳）
- **Bar gauge**（赤→緑のグラデーションと値を持つ、行ごとに 1 本の水平ゲージ、例：空きディスク容量）
- **Text**（markdown メッセージ、例：「Last execution at 19:47」のようなステータスノート。markdown が静的な場合は[インタラクティブなチェックボックス](../nodes/chart-output-node.md#interactive-task-lists)を、カスタムまたは降順の番号付けには[明示的な番号付きリスト](../nodes/chart-output-node.md#numbered-lists)をサポート）
- **HITL**（保留中のヒューマンレビュー。ヘッダーには `1/n pending` と表示されます。Workflow 名をクリックすると、キャンバス上でその実行が開きます。**Approve**、**Request changes**、**Reject** で解決できます。ウィジェットタイトルの横の履歴アイコンをクリックすると、このページの履歴ダイアログでその実行が開きます。このウィジェットは上流の行を使用せず、各人が自分のキューを表示します）

各ウィジェットはタブを開いたときにデータを非同期で読み込むため、チャートが表示されていく間もページは応答性を保ちます。

## ウィジェットの追加

1. **Add widget** をクリックし、タイトルを付けてチャートタイプを選択します。ピッカーの下に、そのチャートタイプの例がサンプルデータとともに描画され、期待される行の名前が示されるため、構築する前にタイプを比較できます。
2. ウィジェットが Workflow エディターでスターターグラフとともに開きます。行を生成する [Set](../nodes/set-node.md) ノードが [Chart Output](../nodes/chart-output-node.md) ノードに接続されています。Set ノードを任意のデータソースに置き換えてください。**HITL** ウィジェットは Chart Output ノードのみで構成され、保留中のレビューを読み取るためデータソースは不要です。
3. **Chart Output** に供給するノードが行の配列を生成するように Workflow を構築し、Chart Output ノードのフィールドマッピング（ラベルフィールド、値フィールドなど）を設定します。
4. 保存してダッシュボードタブに戻ると、ウィジェットがレンダリングされます。

ウィジェットをダブルクリックする（または編集ボタンを使用する）と、いつでもその Workflow を再度開けます。ウィジェットヘッダーの **Clone widget** を使用すると、ウィジェットとその完全な Workflow の両方を複製できます。コピーは元の下に配置され、**(Copy)** とラベル付けされるため、独立して編集できます。

## AI でウィジェットを生成する

**AI** をクリックし、必要な指標を説明して（例：「過去 30 日間の Workflow 成功率を棒グラフで」）、LLM クレデンシャルとモデルを選択します。Heym は Chart Output ノードで終わる完全なウィジェット Workflow を生成し、グリッドに追加します。チャートタイプごとの Prompt の例については、[Chart Output](../nodes/chart-output-node.md#example-ai-prompts) を参照してください。

ウィジェットの **Fine-tune with AI** ボタンを使用すると、新しい指示で既存のウィジェットを修正できます。AI による微調整のたびに、以前の Workflow がウィジェットの **Edit History** にスナップショットされるため、Workflow エディターから変更を確認したりロールバックしたりできます。

## レイアウトの編集

**Edit** を切り替えて編集モードに入ると、12 列のグリッド上でウィジェットをドラッグしたりサイズ変更したりできます。レイアウトの変更は自動的に保存されます。ウィジェットのタイトルはウィジェットヘッダーからインラインで編集できます。

## キャッシュと更新

各ウィジェットは、最後に計算されたデータをサーバー上に設定可能な time-to-live（TTL）の間キャッシュします。キャッシュが新しい間は、ダッシュボードを再度開くと Workflow を再実行する代わりに保存された結果が提供されます。キャッシュはデータが再計算されるたびにその場で置き換えられ（ウィジェットごとに 1 つのキャッシュ）、ウィジェットの Workflow を編集すると自動的に無効化されます。

ウィジェットの **Refresh** ボタン（またはツールバーの **Refresh**）を使用すると、キャッシュをバイパスして即座に再計算できます。

## 共有

オーナーはダッシュボードの設定から、個々のユーザー（メールアドレス指定）または所属する任意の[チーム](teams-tab.md)に対してダッシュボードを共有できます。各共有は**Read**または**Write**であり、個人共有とチーム共有の両方が存在する場合は、より強い権限が適用されます。

| 操作 | オーナー | Write | Read |
|--------|:-----:|:-----:|:----:|
| ウィジェットの表示、更新、自動更新の使用 | ✓ | ✓ | ✓ |
| ウィジェットの追加、複製、削除、名前変更、サイズ変更、AI生成と微調整、チェックリスト項目のチェック | ✓ | ✓ | |
| エディタでウィジェットのWorkflowを開く | ✓ | ✓ | |
| ダッシュボードの名前変更・削除、共有の管理 | ✓ | | |

**ウィジェットは常にダッシュボードのオーナーとして実行されます。** 誰が閲覧していても、ウィジェットはオーナーの認証情報とグローバル変数を使用し、その実行はオーナーの実行履歴とトレースに表示されます。したがって、チームメンバーは背後にあるアカウントへのアクセスなしに同じデータを閲覧でき、すべての閲覧者がウィジェットごとに1つのキャッシュされた結果を共有します。Write権限のコラボレーターが追加または複製したウィジェットも、オーナーに帰属します。

このため、**Write**はWorkflowを編集用に共有するのと同じ信頼を伴います。Write権限を持つコラボレーターは、あなたの認証情報で実行される内容を変更できます。Write権限は、あなたのWorkflowの編集を許可する相手にのみ付与してください。コラボレーターがWorkflowエディタから開始するテスト実行は、共有されたWorkflowと同様に、そのコラボレーター自身の認証情報を使用します。オーナーとして実行されるのはダッシュボード自体のみです。**Read**はウィジェットのWorkflowへのアクセスを一切許可せず、読み取り専用の閲覧者はチャート自体を受け取りますが、その背後のノードごとの実行詳細は受け取りません。

共有の削除、またはWriteからReadへの引き下げは、即座に反映されます。
