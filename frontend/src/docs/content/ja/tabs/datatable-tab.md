# DataTable

**DataTable** タブでは、Heym 内で直接構造化データテーブルを作成・管理できます。テーブルは [DataTable ノード](../nodes/datatable-node.md) を介して Workflow 内で使用でき、プログラムによる CRUD 操作が可能です。

## テーブルの作成

1. ダッシュボードから DataTable タブに移動します
2. **Create DataTable** をクリックします
3. 名前と任意の説明を入力します
4. カラムエディターでカラムを追加します

## カラム

各カラムには以下があります：

| プロパティ | 説明 |
|----------|-------------|
| Name | カラムの表示名 |
| Type | `string`、`number`、`boolean`、`date`、または `json` |
| Required | 新しい行にこのカラムを含める必要があるかどうか |
| Unique | 行間で値が一意である必要があるかどうか |
| Default Value | 行がこのカラムを省略した場合に自動入力される値 |

カラムの追加、編集、削除はテーブル詳細ビューのヘッダーから行えます。

## AI によるカラムの生成

手動でカラムを追加する代わりに、テーブルを自然言語で説明する（またはサンプル JSON を貼り付ける）ことで、LLM にスキーマを提案させることができます。どちらのエントリーポイントも同じダイアログを開きます：

- **Generate with AI**（DataTable リストヘッダー）— 説明からまったく新しいテーブルを作成します。
- **AI columns**（テーブル詳細ビュー、カラムコントロールの隣）— 開いているテーブルに追加する*新しい*カラムを提案します。

### 仕組み

1. **LLM credential** と **model** を選択します（デフォルトでは最初の LLM credential とその最新モデルになります）。
2. 説明を入力します — 例えば *「タイトル、著者、ページ数、読了したかどうかを含む書籍のテーブル」* — または JSON サンプル／スキーマを貼り付けます。
3. **Generate** をクリックします。モデルが提案されたスキーマを返します。
4. 生成されたカラムを編集可能なフォームで確認します：各カラムの **name**、**type**、**default**、**unique**、**notEmpty**（必須）を変更したり、不要なカラムを削除したり、手動で **Add column** したりできます。新しいテーブルの場合は、AI が提案した **name** と **description** も編集できます。
5. **Create Table**（新規テーブル）または **Add Columns**（既存テーブル）をクリックして保存します。いつでも **Esc** を押してダイアログを閉じることができます。

### 既存テーブルへの追加のみ

既存テーブルに対してカラムを生成する場合、モデルは現在のカラムをコンテキストとして参照し、**新しい**カラムのみを提案します。既存のカラムとそのデータは変更・削除されることはありません — 生成されたカラムは追加されます。重複する名前（大文字小文字を区別しない）は自動的に除外されます。

> LLM credential（OpenAI、Google、または Custom）が必要です。お持ちでない場合は、先に Settings で追加してください。

## 行の管理

- **行の追加**：追加ボタンをクリックして新しい行を作成します
- **インライン編集**：任意のセルをダブルクリックして値を編集します。Enter を押すか外側をクリックして保存、Escape でキャンセルします
- **行の削除**：行アクションメニューから行を削除します
- **ページネーション**：行は 1 ページあたり 25 件表示され、ページナビゲーションが利用できます

## CSV のインポート／エクスポート

### インポート
1. テーブル詳細ビューで **Import CSV** をクリックします
2. アップロードする CSV ファイルを選択します
3. 最初の 5 行とカラムマッピングをプレビューします
4. 緑色のカラムは既存のテーブルカラムに一致しており、黄色は一致していません
5. Import をクリックして行を一括挿入します

### エクスポート
**Export CSV** をクリックすると、すべての行が CSV ファイルとしてダウンロードされます。

## 共有

テーブルを他のユーザーやチームと共有できます：

1. テーブル詳細ビューから共有ダイアログを開きます
2. メールアドレスでユーザーを追加し、**read** または **write** 権限を付与します
3. チームを追加し、**read** または **write** 権限を付与します
4. 読み取り専用ユーザーはデータを表示できます。書き込みユーザーは行とカラムを変更できます。テーブルの名前変更、説明の変更、共有の管理は所有者専用のままです。

## AI Assistant からのテーブル作成

Canvas [AI アシスタント](../reference/ai-assistant.md#data-tables)、[Chat](./chat-tab.md)、および [MCP タブ](./mcp-tab.md)の `heym_chat` ツールは、構築する Workflow 用にテーブルを選択するか、新しいテーブルを作成できます。名前とカラムを提案し、質問カードを送信するとテーブルを作成します。Canvas アシスタントはテーブルのメタデータから Workflow ノードを設定します。Chat および `heym_chat` は行を検査し、カラムを追加または削除したり、直接行を挿入、更新、削除したりすることもできます。テーブル名またはこのタブのリンクを指定してください。書き込みには所有権または直接/チームの**書き込み**アクセス権が必要です。カラムの追加は既存のデータを保持します。カラムの削除はすべての行からその値を削除します。カラムの削除とすべての行のクリアは、このタブと同様に確認を求めます。

## Workflow での使用

[DataTable ノード](../nodes/datatable-node.md) はテーブルを Workflow に接続します。操作には find、getAll、getById、insert、update、remove、upsert が含まれます。credential は不要です。

## LLM Cost Table（システムテーブル）

ユーザーが作成したテーブルの上に、固定された **System tables** セクションが表示され、**LLM Cost Table** という単一のエントリがあります。これは [Traces](./traces-tab.md) のコストチャートで使用される、モデルごとの価格設定の固定スキーマでユーザーごとに編集可能なビューです。

### データの取得元

Heym は Helicone の公開価格設定 Endpoint（`https://www.helicone.ai/api/llm-costs`）からシードされた、モデルごとの価格設定のグローバルテーブルを保持しています。同期はテーブルまたは Traces を初めて開いたときにバックグラウンドで実行され、24 時間に 1 回のフェッチに制限されています。**Refresh** を押すと即座に再同期を強制できます。Helicone が上流リストから削除したものはローカルでは削除されないため、過去のコスト検索は安定したままです。

### スキーマ（読み取り専用カラム）

| カラム | 意味 |
|---|---|
| Provider | `ANTHROPIC`、`OPENAI`、`GOOGLE`、…（情報提供用、Helicone で使用） |
| Model | `trace.model` と照合されるモデル識別子 |
| Op | マッチ演算子：`equals`、`startsWith`、または `includes` |
| Input $/1M | 100 万 Prompt トークンあたりの USD |
| Output $/1M | 100 万完了トークンあたりの USD |
| Source | `helicone`、`seed`、または `user` |

### 価格のカスタマイズ

- **行を編集**してその価格を上書きします。上書きはユーザー単位で適用され、`Customized` バッジが表示されます。以降の Helicone 同期ではこの上書きは変更されません。
- **デフォルトにリセット**すると上書きが削除され、その行のグローバル値が復元されます。
- **Add Custom Model** をクリックするとダイアログが開き、ユーザー専用の行を作成できます（たとえば、Helicone が一覧に含めていないプライベートなファインチューニング済みモデルなど）。カスタム行には `User added` が表示され、削除すると完全に取り除かれます。

### Traces との照合

Traces ダッシュボードがコストを計算する際、各 `trace.model` を次の順序で照合します。

1. まず上書き設定（モデル名の完全一致）
2. 一致しない場合はグローバルテーブル — `equals` の完全一致が `startsWith`/`includes` より優先され、同一オペレーター内の競合は一致するモデルのプレフィックス/サブストリングが最も長いもので解決されます

どの行にも一致しない場合、そのモデルは Traces ページの **Unpriced models** 通知に表示され、カスタム行を追加するか既存の行を上書きするまでコストへの寄与はゼロになります。
