# Plugin

**Plugin** 노드는 설치된 플러그인이 제공하는 사용자 정의 액션을 실행합니다. 플러그인은 핵심 애플리케이션을 수정하지 않고도 새로운 노드 유형 — 액션, 서드파티 통합, 또는 Python으로 표현 가능한 모든 것 — 으로 Heym을 확장합니다.

## 개요

| 속성 | 값 |
|----------|-------|
| 입력 | 1 |
| 출력 | 1 |
| 출력값 | `$nodeLabel.<keys returned by the plugin>` |

플러그인 **패키지**(zip 하나)는 **여러 노드**를 포함할 수 있으며, 액션과 트리거를 자유롭게 조합할 수 있습니다. 각 노드는 고유한 이름과 설명과 함께 **Plugins** 아래 팔레트에 나타납니다. 노드를 캔버스로 드래그하면 해당 패키지(`pluginId`)와 노드(`pluginNodeKey`)에 바인딩된 Plugin 노드가 생성됩니다.

## 사용 시점

운영자가 필요한 액션을 수행하는 플러그인을 설치한 경우 — 예를 들어 프라이빗 API 호출, 내부 시스템과의 통신, 또는 배포 환경을 위해 작성된 맞춤형 로직 실행 — Plugin 노드를 사용하십시오.

Workflow를 시작하는 트리거 스타일 플러그인에 대해서는 [Plugin Trigger 노드](./plugin-trigger-node.md)를 참조하십시오.

## 구성

노드의 구성 양식은 플러그인의 manifest에서 생성됩니다. 플러그인이 선언한 각 필드(`string`, `number`, `boolean`, `select`)는 자동으로 렌더링됩니다. 비밀 정보가 아닌 문자열 필드는 표현식 입력을 사용하며, `$`로 시작하는 저장된 문자열 구성 값은 플러그인 핸들러가 실행되기 전에 해석됩니다.

비밀 필드(예: API 키)는 UI에서 마스킹되며 로그에 기록되지 않습니다.

## 플러그인 실행 방식

플러그인은 Heym에서 제공되고 운영자가 설치하므로, 플러그인 코드는 **신뢰**되며 내장 노드처럼 프로세스 내에서 실행되어 전체 네트워크 및 라이브러리 접근 권한을 가집니다. 플러그인은 설치 시 인스턴스에 설치되는 pip `dependencies`를 선언할 수 있습니다.

플러그인 설치 및 제거는 이메일이 `HEYM_PLUGIN_ADMIN_EMAILS`에 등록된 운영자로 제한되며, 전체 하위 시스템은 `HEYM_PLUGINS_ENABLED`(기본값 비활성화)로 제어됩니다. 환경 변수에 대해서는 [실행 및 배포](../getting-started/running-and-deployment.md)를 참조하십시오.

## 사용자 정의 아이콘

플러그인은 사용자 정의 SVG 로고를 포함할 수 있습니다. 패키지 루트에 `icon.svg`를 배치하여 모든 노드의 기본값을 설정하거나, manifest에서 노드별로 `"icon": "<file>.svg"`를 지정할 수 있습니다. 아이콘은 팔레트 카드와 캔버스 노드 모두에 표시되며, 아이콘이 없는 노드는 기본 퍼즐 조각 글리프로 대체됩니다.

## AI Builder

설치된 플러그인은 AI 어시스턴트와 채팅 캔버스에 노출되므로, Heym에게 "Acme CRM 플러그인을 사용하여 레코드를 생성해줘"라고 요청하면 올바른 `pluginId`와 `config`를 가진 Plugin 노드를 생성합니다.

## 플러그인 작성

플러그인 패키지를 빌드하려면 zip 레이아웃, manifest 필드, 핸들러 시그니처, 아이콘, 의존성, 런타임 신뢰 모델에 대해 [플러그인 작성](../reference/plugin-authoring.md)을 참조하십시오.
