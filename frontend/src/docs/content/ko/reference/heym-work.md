# Heym Work

**Heym Work**는 Heym을 기반으로 구축된 비즈니스 팀 전용 보조 인터페이스입니다. 사용자는 자신의 언어로 업무를 설명하고 몇 가지 질문에 답하는 것만으로 Heym이 구축하고 검증한 workflow를 이용할 수 있습니다. 팀에 맞춰 제작된 페이지에서 작업하고 검토를 처리하며, 실행자 이름이 표시된 모든 실행 내역을 확인할 수 있습니다. Heym은 백그라운드에서 모든 작업을 수행합니다.

Heym Work는 Heym 옆에서 별도의 컨테이너로 실행되며, Heym 팀이 발급하는 별도의 라이선스가 필요합니다. 자세한 내용을 확인하고 평가판을 신청하려면 [heym.run/enterprise](https://heym.run/enterprise)를 방문하세요. 2분 둘러보기는 [Heym Work 영상](https://youtu.be/5Z2gGo6bcpU)에서 시청할 수 있습니다.

## 비즈니스 팀에 제공되는 혜택

| 영역 | 기능 설명 |
|------|-----------|
| **Chat** | 텍스트 입력 또는 음성으로 작업을 설명합니다. Heym이 필요한 정보를 묻고, workflow를 구축한 뒤 테스트하여 검증됨으로 표시합니다. |
| **Flows** | 편집자는 캔버스 대신 선택 항목을 통해 flow를 빌드합니다. 시작 조건, 선택적 AI 초안, Slack, Google Sheets 및 이메일에서의 작업이 포함됩니다. Slack의 답변으로 실행이 계속되고 승인도 활동에서 대기합니다. [Flows](#flows)를 참조하세요. |
| **페이지** | 고정된 위젯 페이지: 지표 수치, 차트, 상태 칩이 포함된 표, 파일 드롭 영역 및 승인 기능. 표의 특정 행을 클릭하여 전용 세부 페이지를 열 수 있습니다. |
| **승인** | [Human-in-the-Loop](./human-in-the-loop.md) 단계의 검토 항목이 활동 내역과 페이지에 대기하며, 승인, 변경 요청, 반려 옵션을 지원합니다. |
| **활동** | 작업을 시작한 담당자와 실행한 인스턴스가 명시된 모든 실행 기록. |
| **역할** | 소유자, 편집자, 뷰어. 사용자는 Heym에서 이미 사용하는 [Single Sign-On](./sso.md)을 통해 로그인합니다. |
| **산업별 에디션** | 법률, 교육, 금융, 물류, 에너지, 전자상거래 에디션에는 해당 업종 맞춤형 페이지, 샘플 데이터 및 workflow가 사전 탑재되어 있습니다. |

## Flows

**Flows**는 편집자 및 소유자를 위한 Heym Work 메뉴에 있습니다. Flow는 노드가 아닌 선택 항목으로 구성되며 Heym Work는 이를 생성한 사람을 대신하여 Heym API를 통해 일반 Heym 워크플로우로 저장합니다. Heym의 액세스 규칙, 편집 기록 및 트리거 동기화는 편집기에서와 동일하게 적용되며 모든 실행은 다른 실행과 마찬가지로 활동에 표시됩니다.

| 파트 | 선택 항목 |
|---|---|
| **시작 조건** | 요청 시, 일정에 따라, Slack 메시지 수신 시, Google Sheets 탭이 변경될 때(행 추가, 변경 또는 삭제) 또는 이메일이 받은편지함에 도착할 때. 스프레드시트 및 이메일 트리거는 1분, 5분, 15분 또는 60분마다 확인합니다. |
| **AI 초안** (선택 사항) | 모델과 지침은 flow를 시작한 내용을 후속 단계를 위한 텍스트로 변환합니다. 스프레드시트나 이메일에서 시작하지 않는 flow는 먼저 채널이나 스레드에서 최근 Slack 메시지를 읽을 수 있습니다. |
| **다음 단계** | Flow를 시작한 항목에 관계없이 세 가지 도구 중 하나에서 순서대로 작업을 수행합니다. **Slack:** 채널 메시지, 다이렉트 메시지, 양식, 버튼이 있는 메시지, 승인, 스레드 답장, 메시지 업데이트 및 최종 결과. **Google Sheets:** 행 추가 또는 변경된 행 업데이트. **이메일:** 이메일 전송. |

- **답변으로 실행이 계속됩니다.** 승인, 버튼 또는 양식은 누군가 Slack에서 응답할 때까지 실행을 일시 중지합니다. 승인은 활동에서도 대기하며 어느 한 곳에서 결정하면 Slack 메시지에서 버튼이 제거됩니다. 이후의 Slack 단계는 첫 번째 메시지의 스레드에 유지됩니다.
- **단일 연결 카드.** 각 flow는 읽고 보내는 데 사용하는 Slack 워크스페이스, Google Sheets 계정 및 받은편지함을 표시합니다. 이는 Heym 자격 증명입니다: **Slack Bot**(봇 토큰, `xoxb-…`), **Google Sheets**, **IMAP**, **SMTP**. 누락된 자격 증명은 flow 자체에서 직접 추가할 수 있습니다.
- **각 flow에 대해 하나의 Slack 앱.** Slack 앱에서 대화형 요청 URL을 `https://<Heym 주소>/api/slack/interactions/<자격 증명 ID>`로 설정하고 이벤트 구독 요청 URL을 `https://<Heym 주소>/api/slack/events/<자격 증명 ID>`로 설정합니다. Heym Work는 선택한 연결에 대해 두 가지를 모두 표시합니다. 해당 자격 증명의 모든 flow가 이를 공유합니다.
- **Slack 트리거는 수신할 항목을 선택합니다:** 채널 및 DM의 메시지, 봇으로의 다이렉트 메시지, 봇 멘션 또는 단일 채널의 메시지. 봇 자신의 게시물은 flow를 시작하지 않습니다.
- **요구 사항.** Flows에는 Heym 0.0.131 이상이 필요합니다.

Flow가 빌드하는 단계는 캔버스에서 사용할 수 있는 노드와 동일합니다: [Slack](../nodes/slack-node.md), [Slack Trigger](../nodes/slack-trigger-node.md), [Google Sheets](../nodes/google-sheets-node.md), [Google Sheets Trigger](../nodes/google-sheets-trigger-node.md), [IMAP Trigger](../nodes/imap-trigger-node.md), [Send Email](../nodes/send-email-node.md), [Cron](../nodes/cron-node.md).

## Heym Work 연결

최초 명령어 입력부터 홈 화면까지 전체 설정 과정은 [설치 가이드 영상](https://youtu.be/zXGfg1HPSLk)에서 확인할 수 있습니다.

연결 설정은 **설정 → Heym Work**에서 진행합니다. 이 탭은 `HEYM_ADMIN_EMAILS`에 등록된 인스턴스 관리자에게만 표시됩니다.

| 항목 | 기능 설명 |
|------|-----------|
| **Heym Work 주소** | Heym Work가 실행 중인 주소(예: `https://work.example.com`). 로그인 후 이곳으로 이동합니다. **저장**을 누릅니다. |
| **연동 키** | **키 생성**을 누르면 Heym Work가 Heym에 요청할 때마다 사용하는 키가 생성됩니다. 복사 버튼과 함께 1회만 표시되며, Heym은 해시 값만 보관합니다. |
| **Heym Work 활성화** | 연결을 켭니다. 주소와 키를 먼저 입력해야 합니다. |
| **산업 및 팀 에디션** | 법률, 교육, 금융, 물류, 에너지, 전자상거래 에디션과 기업 팀을 위한 IT, 영업, 마케팅, 인사 에디션에는 해당 업무를 위한 페이지, 샘플 데이터 및 워크플로우가 함께 제공됩니다. |

그런 다음 Heym Work 주소로 이동하여 설정을 완료합니다:

1. **라이선스**: Heym 팀에서 발급받은 라이선스 키를 입력합니다.
2. **Heym**: Heym 주소와 연동 키를 입력합니다.
3. **소유자**: Heym Work 소유자로 등록된 계정으로 로그인합니다.

팀에서 사용할 준비가 완료된 홈 화면이 열립니다.

### 키 교체

**키 교체**를 누르면 연동 키가 새로 변경됩니다. 새 키가 Heym Work에 입력될 때까지 Heym Work 작동이 일시 정지되며, Heym Work에 로그인된 모든 사용자가 로그아웃됩니다. 키 유출이 우려되거나 키를 알고 있는 직원이 퇴사할 때 사용하세요.

### 연결 비활성화

**Heym Work 활성화** 스위치를 끄면 연결이 중단됩니다. 이후 Heym Work는 Heym 키를 다시 요청합니다. 어떤 경우에도 Heym 자체는 모든 workflow, 일정 및 웹훅을 차질 없이 계속 실행합니다.

## 보안 모델

- **모든 변경은 Heym을 거칩니다.** Heym Work는 표시할 내용을 Heym 데이터베이스에서 읽어오고, 키로 보호되는 채널을 통해 모든 작업을 Heym으로 전달하며, Heym이 자체 접근 권한 규칙을 적용합니다. Heym Work는 자체 데이터를 별도의 `heym_work` 스키마에 보관합니다.
- **키는 해시 처리되어 저장됩니다.** Heym은 제시된 키의 해시 값을 비교하며, 원본 키를 평문으로 저장하지 않습니다.
- **인증은 Heym에서 처리됩니다.** [SSO](./sso.md)가 활성화되어 있으면 사용자는 회사 ID 제공업체를 통해 Heym으로 로그인합니다.
- **모든 변경 내역이 기록됩니다.** 연결 저장 및 키 교체 시 [감사 로그](./audit.md)에 `work_integration.update` 및 `work_integration.key_rotate` 항목이 기록됩니다.

## 라이선스 안내

Heym Work를 사용하려면 Heym 팀에서 발급한 고유 라이선스 키가 필요합니다. Heym Work는 매일 heym.run으로 라이선스 ID, 설치 ID, 최근 30일 활성 사용자 수, 총 멤버 수, 최근 24시간 실행 횟수, Heym 및 Heym Work 버전을 전송합니다. Workflow 내용, 입력값, 결과물 및 자격 증명 정보는 항상 로컬 서버에만 유지됩니다.

일일 동기화가 30일 동안 실패하면 14일의 유예 기간이 시작되며, 유예 기간이 지나면 Heym Work 인터페이스에서 소유자에게 키 입력을 요청합니다. 평가판은 마지막 날까지 정상 동작하며 Heym 팀이 연장하면 다시 활성화됩니다(설치당 1회 평가판 허용). Heym 자체는 전 과정 동안 중단 없이 계속 실행됩니다. 인터넷 연결이 불가능한 격리망 환경에서는 enterprise@heym.run을 통해 오프라인 라이선스를 발급받아 사용할 수 있습니다.
