# Виведення діаграми

Вузол **Виведення діаграми** є термінальним вузлом workflow [віджета дашборда](../tabs/dashboard-tab.md). Він приймає рядки, сформовані вихідними вузлами, та перетворює їх на стандартизований payload діаграми, який відображає дашборд.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 0 (термінальний) |
| Вихід | Стандартизований payload діаграми |

Розмістіть цей вузол **останнім** у workflow віджета дашборда. Вузол перед ним має формувати масив об'єктів-рядків, наприклад:

```json
[
  { "month": "Jan", "revenue": 120 },
  { "month": "Feb", "revenue": 150 }
]
```

Якщо є лише прикладні/зразкові дані (без реального джерела), сформуйте ці рядки за допомогою вузла **Set**, використовуючи `$array(dict(...), dict(...))` — наприклад `$array(dict(month="Jan", revenue=120), dict(month="Feb", revenue=150))`. **Не** використовуйте `${...}` або прості літерали об'єктів `{...}`; Heym створює об'єкти лише за допомогою `dict(key=value)`.

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `label` | string | Ідентифікатор вузла (camelCase) |
| `chartType` | string | `pie`, `bar`, `line`, `area`, `table`, `numeric`, `gauge`, `scatter`, `proportion`, `barGauge`, `text` або `hitl` |
| `orientation` | string | `vertical` або `horizontal` (лише для стовпчикових діаграм) |
| `dataPath` | string | Шлях через крапку до масиву рядків у вихідних даних попереднього вузла (наприклад, `data` або `result.items`). Залиште порожнім для автоматичного визначення. |
| `labelField` | string | Ключ рядка, що використовується як категоріальна мітка (pie/bar/line) |
| `valueField` | string | Ключ рядка, що використовується як числове значення (pie/bar/line/numeric/gauge) |
| `series` | array | Необов'язкове визначення кількох серій `[{ "name": "Sent", "field": "sent" }]` для bar/line (перевизначає `valueField`) |
| `columns` | array | Необов'язковий список стовпців для `table` (типово — ключі першого рядка) |
| `xField` / `yField` | string | Ключі рядків для числових осей X та Y (scatter) |
| `min` / `max` | number | Числовий діапазон для `gauge` (типово `0` / `100`) |
| `unit` | string | Необов'язкова одиниця виміру, що відображається поруч зі значенням `numeric` або `gauge` |
| `text` | string | Повідомлення у форматі Markdown для типу діаграми `text`. Залиште порожнім і встановіть `valueField`, щоб відобразити динамічне повідомлення, отримане з вихідних даних попереднього вузла. |
| `title` | string | Необов'язковий заголовок діаграми |

## Типи діаграм

- **bar / line / area / pie** — категоріальні діаграми, що керуються `labelField` + `valueField` (або `series` для багатосерійних bar/line/area). `area` — це заповнена діаграма тренду.
- **table** — необроблені рядки, відображені як таблиця з прокруткою за допомогою `columns`.
- **numeric** — одне значення KPI з першого рядка з необов'язковою `unit`.
- **gauge** — одне значення, показане в діапазоні `min`–`max` (наприклад, відсоток). Використовує `valueField`.
- **scatter** — точки X/Y з `xField` та `yField` для графіків кореляції.
- **proportion** — одна горизонтальна смуга, розділена на частки з відсотковою легендою (наприклад, розподіл за мовами). Використовує `labelField` + `valueField`.
- **barGauge** — один горизонтальний індикатор на рядок із градієнтом від червоного до зеленого та значенням (наприклад, вільний дисковий простір). Використовує `labelField` + `valueField`, необов'язкові `unit` та `max` (типово — найбільше значення рядка).
- **text** — повідомлення у форматі markdown (наприклад, статусна нотатка на кшталт "Last execution at 19:47"). Розмістіть markdown у `text` для статичного повідомлення або залиште `text` порожнім і встановіть `valueField`, щоб відобразити рядок, сформований попереднім вузлом. Підтримує заголовки, напівжирний/курсивний текст, [списки](../nodes/chart-output-node.md#interactive-task-lists), посилання та інлайн-код.
- **hitl** — карусель Ваших перевірок, що очікують на розгляд. У заголовку відображається `1/n pending`; стрілка вліво вимкнена на першій картці, а стрілка вправо — на останній. Назва workflow відкриває відповідний запуск на canvas. Кнопки **Approve**, **Request changes** та **Reject** завершують перевірку, а значок історії поруч із заголовком віджета відкриває цей запуск у діалозі історії на тій самій сторінці. Цей тип діаграми ігнорує рядки, отримані від попередніх вузлів, тому workflow віджета складається лише з вузла Виведення діаграми. Кожен авторизований користувач бачить перевірки для workflow, якими він володіє.

### Інтерактивні списки завдань

Використовуйте синтаксис списків завдань у форматі GitHub-flavored markdown у статичному полі `text`:

```markdown
- [x] Option 1
- [ ] Option 2
- [ ] Option 3
```

На [Дашборді](../tabs/dashboard-tab.md) прапорці відображаються як клікабельні елементи керування (сумісні з темним і світлим режимами). Перемикання прапорця оновлює поле `text` workflow віджета та зберігається між оновленнями.

**Інлайн-редагування:** двічі клацніть мітку елемента завдання, щоб відредагувати її на місці. Натисніть Enter або клацніть поза полем, щоб зберегти; натисніть Escape, щоб скасувати. Повністю очистіть мітку, щоб видалити цей елемент зі списку.

**Посилання в елементах завдань:** якщо мітка містить markdown-посилання (`[title](url)`), клацання по посиланню відкриває URL без перемикання прапорця. Клацніть в іншому місці рядка, щоб перемкнути прапорець.

**Лише статичний текст:** інтерактивність потребує синтаксису списків завдань GFM (`- [ ]` / `- [x]`). Звичайні динамічні статусні повідомлення без елементів завдань залишаються доступними лише для читання. Якщо markdown надходить із `valueField`, перше перемикання копіює його в статичне поле `text`, щоб зміни зберігалися.
### Нумеровані списки

Віджети тексту відображають markdown із **явно збереженими номерами рядків**. Додайте на початок кожного рядка номер, який потрібно показати (наприклад, `9.`, `8.`, `7.`). Heym не перенумеровує рядки за вас.

**Чому явні номери?** Стандартні впорядковані списки markdown (`1.`, `2.`, `3.`) перетворюються на HTML-списки `<ol>`, які лише збільшують лічбу **вгору** від першого числа. Список, записаний як `9.` / `8.` / `7.`, у звичайному рендерері markdown відобразився б як `9`, `10`, `11`. Додавання на початок кожного рядка потрібного номера дозволяє цього уникнути.

**Спадні списки (наприклад, найновіші спочатку):** сформуйте markdown у циклі workflow та обчисліть номер для відображення для кожного елемента:

```
${loop.total - loop.index}. [${item.title}](https://example.com/watch?v=${item.id})
```

Типовий підхід:

1. Отримайте або сформуйте масив елементів (наприклад, HTTP → `body.videos`).
2. Виконайте [цикл](./loop-node.md) над масивом; усередині тіла використайте [Variable](./variable-node.md) з `.add()`, щоб додати один нумерований рядок за кожну ітерацію.
3. Після гілки **done** циклу виконайте [Set](./set-node.md) `join("\n")` над накопиченим масивом (або еквівалентом) в один рядок markdown.
4. Спрямуйте **Chart Output** `valueField` на цей рядок (або задайте статичний `text`).

Приклад виразу рядка всередині циклу (мітка `processVideos`, елементи з `title` та `id`):

```
$processVideos.total - $processVideos.index + ". [" + $processVideos.item.title + "](https://www.youtube.com/watch?v=" + $processVideos.item.id + ")"
```

Отриманий markdown:

```markdown
9. [Latest video](https://www.youtube.com/watch?v=abc)
8. [Previous video](https://www.youtube.com/watch?v=def)
1. [Oldest video](https://www.youtube.com/watch?v=xyz)
```

Для простого висхідного списку, що починається з 1, або додайте на початок кожного рядка номер (`1.`, `2.`, `3.`), або використайте цикл із `$loop.index + 1`. Використовуйте [марковані списки](#interactive-task-lists) (`- item`), коли номери не потрібні.

## Як розв'язуються дані

1. Якщо задано `dataPath`, вузол прямує цим шляхом із крапками у вихідні дані вище за потоком.
2. Інакше він шукає масив: список верхнього рівня, масив `data` або перше поле зі значенням-списком.
3. Для `table` кожен рядок стає рядком таблиці з використанням `columns` (або ключів першого рядка).
4. Для `numeric` та `gauge` значення береться з `valueField` у першому рядку (або з першого числового поля).
5. Для `scatter` кожен рядок стає точкою `[xField, yField]`.
6. Для `text` повідомлення береться з `valueField` у першому рядку, якщо його задано, інакше — зі статичної конфігурації `text` (або з першого рядкового поля першого рядка).

## Приклад

```json
{
  "type": "chartOutput",
  "data": {
    "label": "revenueChart",
    "chartType": "bar",
    "orientation": "vertical",
    "dataPath": "data",
    "labelField": "month",
    "valueField": "revenue",
    "title": "Monthly revenue"
  }
}
```

Gauge (одне значення проти діапазону):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "cpuGauge",
    "chartType": "gauge",
    "dataPath": "rows",
    "valueField": "value",
    "min": 0,
    "max": 100,
    "unit": "%"
  }
}
```

Scatter (точки X/Y):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "correlation",
    "chartType": "scatter",
    "dataPath": "rows",
    "xField": "x",
    "yField": "y"
  }
}
```

Proportion (одна смуга, розділена за часткою + легенда з відсотками):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "languages",
    "chartType": "proportion",
    "dataPath": "rows",
    "labelField": "name",
    "valueField": "value",
    "title": "Most Used Languages"
  }
}
```

Area (заповнений багатосерійний тренд):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "memCpu",
    "chartType": "area",
    "dataPath": "rows",
    "labelField": "time",
    "series": [
      { "name": "Memory", "field": "memory" },
      { "name": "CPU", "field": "cpu" }
    ],
    "title": "Memory / CPU"
  }
}
```

Bar gauge (градієнтний gauge для кожного рядка зі значеннями):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "freeDisk",
    "chartType": "barGauge",
    "dataPath": "rows",
    "labelField": "name",
    "valueField": "value",
    "unit": "GB",
    "title": "Free disk space"
  }
}
```

Text (статичне повідомлення markdown — рядки вище за потоком не потрібні):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "statusNote",
    "chartType": "text",
    "text": "**Last execution** at `19:47` — all checks passed ✅",
    "title": "Status"
  }
}
```

Text (динамічний — рядок повідомлення формується вище за потоком і отримується через `valueField`):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "lastRun",
    "chartType": "text",
    "dataPath": "rows",
    "valueField": "message"
  }
}
```
## Приклади AI prompt

Під час генерації віджета за допомогою **AI** prompt, подібні до наведених нижче, чітко відповідають кожному типу:

- **Bar** — «Покажіть місячний дохід за останні 6 місяців як вертикальну стовпчикову діаграму з прикладом даних.»
- **Line** — «Побудуйте графік щоденних активних користувачів за останні 14 днів як лінійну діаграму.»
- **Area** — «Покажіть використання пам'яті та CPU за останні 24 години як діаграму з областями з двома серіями. Використайте приклад даних.»
- **Pie** — «Розподіліть статус виконання (success, error, cancelled) як кругову діаграму.»
- **Table** — «Покажіть топ-10 Workflow за кількістю виконань як таблицю з прокруткою зі стовпцями name та runs. Використайте приклад даних.»
- **Numeric** — «Покажіть загальну кількість виконань Workflow за сьогодні як єдиний KPI з одиницею виміру "runs". Використайте приклад даних.»
- **Gauge** — «Покажіть поточне використання CPU як індикатор від 0 до 100 відсотків.»
- **Scatter** — «Побудуйте залежність затримки запиту від розміру payload як точкову діаграму з прикладом даних.»
- **Proportion** — «Покажіть мої найуживаніші мови як смугу пропорцій: Kotlin 49.64%, JavaScript 23.73%, TypeScript 11.64%, Java 8.92%, Python 6.06%. Використайте приклад даних.»
- **Bar gauge** — «Покажіть вільний дисковий простір для кожного тому (sda1–sda7) як стовпчиковий індикатор у ГБ. Використайте приклад даних.»
- **Text** — «Додайте текстовий віджет із markdown-чеклістом (один позначений пункт, два непозначені) або перелічіть 5 найновіших навчальних відео у спадному порядку (від 5. до 1.) з посиланнями на YouTube — додайте на початок кожного рядка явний номер (`5. Title`, `4. Title`, …).»
