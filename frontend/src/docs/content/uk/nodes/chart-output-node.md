# Виведення діаграми

Вузол **Виведення діаграми** є термінальним вузлом workflow [віджета дашборда](../tabs/dashboard-tab.md). Він приймає рядки, сформовані вихідними вузлами, та перетворює їх на стандартизований payload діаграми, який відображає дашборд.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 0 (термінальний) |
| Вихід | Стандартизований payload діаграми |

Розмістіть цей вузол **останнім** у workflow віджета дашборда. Для зв'язків сутностей вузол перед ним формує об'єкт графа (див. [Entity relationships](#entity-relationships-db)). Інші діаграми на основі даних використовують масив об'єктів-рядків, наприклад:

```json
[
  { "month": "Jan", "revenue": 120 },
  { "month": "Feb", "revenue": 150 }
]
```

Якщо є лише прикладні/зразкові дані (без реального джерела), сформуйте ці рядки за допомогою вузла **Set**, використовуючи `$array(dict(...), dict(...))` — наприклад `$array(dict(month="Jan", revenue=120), dict(month="Feb", revenue=150))`. **Не** використовуйте `${...}` або прості літерали об'єктів `{...}`; Heym створює об'єкти лише за допомогою `dict(key=value)`.

## Параметри

|-----------|------|-------------|

| `chartType` | string | `pie`, `bar`, `line`, `area`, `table`, `numeric`, `gauge`, `scatter`, `proportion`, `barGauge`, `gantt`, `erDiagram`, `text` або `hitl` |
| `orientation` | string | `vertical` або `horizontal` (лише для стовпчикових діаграм) |
| `dataPath` | string | Шлях через крапку до масиву рядків (або об'єкта графа для `erDiagram`) у вихідних даних попереднього вузла (наприклад, `data` або `result.items`). Залиште порожнім для автоматичного визначення. |
| `labelField` | string | Ключ рядка, що використовується як категоріальна мітка (pie/bar/line) |
| `valueField` | string | Ключ рядка, що використовується як числове значення (pie/bar/line/numeric/gauge) |
| `series` | array | Необов'язкове визначення кількох серій `[{ "name": "Sent", "field": "sent" }]` для bar/line (перевизначає `valueField`) |
| `columns` | array | Необов'язковий список стовпців для `table` (типово — ключі першого рядка) |

| `statusTones` | object | Необов'язкове зіставлення значення статусу з тоном (`success`, `attention`, `failure`, `waiting`, `neutral`) для значень, які не охоплені за замовчуванням |
| `linkColumn` | string | Необов'язковий стовпець `table`, клітинки якого містять URL і відображаються як [кнопка посилання](#link-buttons), що відкриває його в новій вкладці. Це має бути один із відображених стовпців. |
| `linkLabel` | string | Необов'язковий текст кнопки посилання. Якщо залишити порожнім, кнопка показує лише піктограму посилання. |
| `xField` / `yField` | string | Ключі рядків для числових осей X та Y (scatter) |
| `min` / `max` | number | Числовий діапазон для `gauge` (типово `0` / `100`) |
| `unit` | string | Необов'язкова одиниця виміру, що відображається поруч зі значенням `numeric` або `gauge` |
| `text` | string | Повідомлення у форматі Markdown для типу діаграми `text`. Залиште порожнім і встановіть `valueField`, щоб відобразити динамічне повідомлення, отримане з вихідних даних попереднього вузла. |
| `title` | string | Необов'язковий заголовок діаграми |
| `hitlWorkflowId` | string | Лише `hitl`. Показує тільки рецензії цього Workflow. Якщо залишити порожнім, віджет показує всі рецензії. |
| `hitlNodeId` | string | Лише `hitl`. Звужує `hitlWorkflowId` до одного кроку: Agent із перевіркою людиною або крок Slack із затвердженням, кнопками чи формою. |

## Типи діаграм

- **bar / line / area / pie** — категоріальні діаграми, що керуються `labelField` + `valueField` (або `series` для багатосерійних bar/line/area). `area` — це заповнена діаграма тренду.
- **table** — необроблені рядки, відображені як таблиця з прокруткою за допомогою `columns`. Один стовпець може відображатися як [чипи статусу](#status-chips), а рядки можуть відкривати [сторінку деталей](../tabs/dashboard-tab.md#detail-pages).
- **numeric** — одне значення KPI з першого рядка з необов'язковою `unit`.
- **gauge** — одне значення, показане в діапазоні `min`–`max` (наприклад, відсоток). Використовує `valueField`.
- **scatter** — точки X/Y з `xField` та `yField` для графіків кореляції.
- **proportion** — одна горизонтальна смуга, розділена на частки з відсотковою легендою (наприклад, розподіл за мовами). Використовує `labelField` + `valueField`.
- **barGauge** — один горизонтальний індикатор на рядок із градієнтом від червоного до зеленого та значенням (наприклад, вільний дисковий простір). Використовує `labelField` + `valueField`, необов'язкові `unit` та `max` (типово — найбільше значення рядка).
- **gantt** — графіки завдань із датами, прогресом та залежностями; див. [Діаграми Ганта](#gantt-schedules).
- **erDiagram** — сутності бази даних, поля, ключі та зв'язки; див. [Entity relationships](#entity-relationships-db).
- **text** — повідомлення у форматі markdown (наприклад, статусна нотатка на кшталт "Last execution at 19:47"). Розмістіть markdown у `text` для статичного повідомлення або залиште `text` порожнім і встановіть `valueField`, щоб відобразити рядок, сформований попереднім вузлом. Підтримує заголовки, напівжирний/курсивний текст, [списки](../nodes/chart-output-node.md#interactive-task-lists), посилання та інлайн-код.
- **hitl** — карусель Ваших перевірок, що очікують на розгляд. У заголовку відображається `1/n pending`; стрілка вліво вимкнена на першій картці, а стрілка вправо — на останній. Назва workflow відкриває відповідний запуск на canvas. Кнопки **Approve**, **Request changes** та **Reject** завершують перевірку, а значок історії поруч із заголовком віджета відкриває цей запуск у діалозі історії на тій самій сторінці. Цей тип діаграми ігнорує рядки, отримані від попередніх вузлів, тому workflow віджета складається лише з вузла Виведення діаграми. Кожен авторизований користувач бачить перевірки для workflow, якими він володіє. Виберіть **Workflow** (і **Select agent**, якщо він має кілька кроків перевірки) у властивостях вузла або в налаштуваннях віджета, щоб натомість показувати рецензії цього Workflow усім, хто може його відкрити; див. [віджети HITL](../tabs/dashboard-tab.md#hitl-widgets).

### Діаграми Ганта

Виберіть **Gantt** (`gantt`) для графіків проєктів і часових шкал завдань. Вкажіть `dataPath` для масиву завдань, наприклад `tasks`. Рядки використовують фіксовані назви полів:

```json
{
  "tasks": [
    { "id": "design", "label": "Design", "start": "2026-10-01", "end": "2026-10-05", "progress": 100 },
    { "id": "build", "label": "Build", "start": "2026-10-05", "end": "2026-10-14", "progress": 40, "dependencies": ["design"] }
  ]
}
```

`start` та `end` приймають дати або мітки часу ISO. Значення без часового поясу використовують UTC; зміщення часових поясів перетворюються на UTC. `end` має бути не раніше ніж `start`. Поле `progress` є необов'язковим (0–100, за замовчуванням 0); `dependencies` містить ідентифікатори наявних завдань. Ідентифікатори мають бути унікальними. Наведіть курсор на завдання, щоб переглянути повні дати, прогрес і залежності. Великі діаграми прокручуються всередині віджета. Приймається щонайбільше 500 завдань.

Для тестових даних зіставлення Set із назвою `tasks` може використовувати `$array(dict(id="design", label="Design", start="2026-10-01", end="2026-10-05", progress=60))`. Підключіть його до Chart Output із `chartType: "gantt"` та `dataPath: "tasks"`. Зіставте вихідні стовпці з цими фіксованими назвами за допомогою вузла Set; `labelField` та `valueField` не використовуються.

### Entity relationships (DB)

Виберіть **Entity relationships (DB)** (`erDiagram`) для схем баз даних і зв'язків між сутностями. Вкажіть `dataPath` для **об'єкта** графа, наприклад `graph`, що містить обидва масиви:

```json
{
  "graph": {
    "entities": [
      { "id": "customers", "label": "Customers", "fields": [{ "name": "id", "type": "uuid", "key": "PK" }] },
      { "id": "orders", "label": "Orders", "fields": [{ "name": "customer_id", "type": "uuid", "key": "FK" }] }
    ],
    "relations": [
      { "source": "customers", "target": "orders", "sourceField": "id", "targetField": "customer_id", "cardinality": "one-to-many", "label": "places" }
    ]
  }
}
```

Поля мають `name`, необов'язковий `type` та необов'язковий `key` (`PK`, `FK`, `PK/FK` або порожньо). Зв'язки посилаються на наявні ідентифікатори сутностей; необов'язкові поля `sourceField` та `targetField` прив'язують з'єднання до вказаних полів. `cardinality` приймає `one-to-one`, `one-to-many` (за замовчуванням), `many-to-one` або `many-to-many`. Ідентифікатори сутностей та назви полів усередині кожної сутності мають бути унікальними. Приймається щонайбільше 100 сутностей, 100 полів на сутність і 500 зв'язків.

За допомогою вузла Set побудуйте `graph` через `$dict(entities=array(dict(...)), relations=array(dict(...)))`; використовуйте `chartType: "erDiagram"` та `dataPath: "graph"`. Це візуалізація наданої вами схеми; вона не перевіряє активну базу даних автоматично.

Обидва типи з'являються в меню **Додати віджет** із попереднім переглядом і в селекторі типу діаграми вузла на полотні. Heym Work може пропонувати ці типи під час опису графіка чи схеми бази даних, генеруючи ескізи запропонованих завдань чи сутностей ще до побудови сторінки.

### Інтерактивні списки завдань

Використовуйте синтаксис списків завдань у форматі GitHub-flavored markdown у статичному полі `text`:

```markdown
- [x] Option 1
- [ ] Option 2
- [ ] Option 3
```

На [Дашборді](../tabs/dashboard-tab.md) прапорці відображаються як клікабельні елементи керування (сумісні з темним і світлим режимами). Перемикання прапорця оновлює поле `text` workflow віджета та зберігається між оновленнями.

**Інлайн-редагування:** двічі клацніть мітку елемента завдання, щоб відредагувати її на місці. Натисніть Enter або клацніть поза полем, щоб зберегти; натисніть Escape, щоб скасувати. Повністю очистіть мітку, щоб видалити цей елемент зі списку.

**Посилання в елементах завдань:** якщо мітка містить markdown-посилання (`[title](url)`), клацання по посиланню відкриває URL без перемикання прапорця. Клацніть в іншому місці рядка, щоб перемкнути прапорець.

**Лише статичний текст:** інтерактивність потребує синтаксису списків завдань GFM (`- [ ]` / `- [x]`). Звичайні динамічні статусні повідомлення без елементів завдань залишаються доступними лише для читання. Якщо markdown надходить із `valueField`, перше перемикання копіює його в статичне поле `text`, щоб зміни зберігалися.
### Нумеровані списки

Віджети тексту відображають markdown із **явно збереженими номерами рядків**. Додайте на початок кожного рядка номер, який потрібно показати (наприклад, `9.`, `8.`, `7.`). Heym не перенумеровує рядки за вас.

**Чому явні номери?** Стандартні впорядковані списки markdown (`1.`, `2.`, `3.`) перетворюються на HTML-списки `<ol>`, які лише збільшують лічбу **вгору** від першого числа. Список, записаний як `9.` / `8.` / `7.`, у звичайному рендерері markdown відобразився б як `9`, `10`, `11`. Додавання на початок кожного рядка потрібного номера дозволяє цього уникнути.

**Спадні списки (наприклад, найновіші спочатку):** сформуйте markdown у циклі workflow та обчисліть номер для відображення для кожного елемента:

```
${loop.total - loop.index}. [${item.title}](https://example.com/watch?v=${item.id})
```

Типовий підхід:

1. Отримайте або сформуйте масив елементів (наприклад, HTTP → `body.videos`).
2. Виконайте [цикл](./loop-node.md) над масивом; усередині тіла використайте [Variable](./variable-node.md) з `.add()`, щоб додати один нумерований рядок за кожну ітерацію.
3. Після гілки **done** циклу виконайте [Set](./set-node.md) `join("\n")` над накопиченим масивом (або еквівалентом) в один рядок markdown.
4. Спрямуйте **Chart Output** `valueField` на цей рядок (або задайте статичний `text`).

Приклад виразу рядка всередині циклу (мітка `processVideos`, елементи з `title` та `id`):

```
$processVideos.total - $processVideos.index + ". [" + $processVideos.item.title + "](https://www.youtube.com/watch?v=" + $processVideos.item.id + ")"
```

Отриманий markdown:

```markdown
9. [Latest video](https://www.youtube.com/watch?v=abc)
8. [Previous video](https://www.youtube.com/watch?v=def)
1. [Oldest video](https://www.youtube.com/watch?v=xyz)
```

Для простого висхідного списку, що починається з 1, або додайте на початок кожного рядка номер (`1.`, `2.`, `3.`), або використайте цикл із `$loop.index + 1`. Використовуйте [марковані списки](#interactive-task-lists) (`- item`), коли номери не потрібні.

## Чипи статусу

Таблиця (`table`) може показувати один стовпець у вигляді кольорових чипів. Встановіть **Status column** у властивостях вузла (або `statusColumn` у DSL) на назву стовпця. Кожне значення отримує один із п'яти тонів, а поширені слова отримують його автоматично без налаштування:

| Тон | Слова за замовчуванням |
|------|---------------|
| `success` | success, successful, succeeded, done, complete, completed, approved, active, ok, paid, passed, healthy, resolved, won, delivered, published |
| `attention` | warning, attention, review, needs review, at risk, partial, degraded, overdue, unpaid, expiring |
| `failure` | failed, failure, error, errored, rejected, declined, blocked, lost, expired |
| `waiting` | pending, waiting, queued, running, in progress, processing, scheduled, draft, new, open |
| `neutral` | будь-що інше |

Зіставлення ігнорує регістр, `_` та `-`, тому `IN_PROGRESS` і `in-progress` обидва стають `waiting`. Додайте **Status tones** для інших значень; запис перевизначає стандартний тон для цього значення:

```json
{
  "type": "chartOutput",
  "data": {
    "label": "invoices",
    "chartType": "table",
    "dataPath": "rows",
    "columns": ["invoice", "customer", "state"],
    "statusColumn": "state",
    "statusTones": { "Disputed": "failure" }
  }
}
```

Сервер визначає тон для кожного значення, тому Heym і Heym Work показують однакові кольори.

## Сторінки деталей: `$page.record`

Панель приладів, відкрита з `?record=<value>`, запускає кожен Workflow віджета з цим значенням як `$page.record`. Посилання в рядку таблиці відкриває таку сторінку; див. [Сторінки деталей](../tabs/dashboard-tab.md#detail-pages). На панелі приладів, відкритій без запису, а також у діалозі виразів `$page.record` дорівнює `null`. Вузол із міткою `page` має пріоритет над ним.

Використовуйте його, щоб отримати саме той запис, якому присвячена сторінка, наприклад у вузлі [HTTP](./http-node.md):

```
https://crm.example.com/api/customers?id=$page.record
```

`$page.record` — це саме значення натиснутого рядка, наприклад `V-1002`, а не об'єкт із полями. Щоб знайти цей запис у [DataTable](./datatable-node.md), відфільтруйте стовпець запису за цим значенням: операція `find` із фільтром `{"vendor_id": "$page.record"}`. Шлях на зразок `$page.record.id` нічого не повертає, тому віджет, який створює або налаштовує ШІ, відкидає ці поля і натомість читає `$page.record`.

Значення надходить з URL-адреси, яку може змінити будь-хто. Панель приладів приймає лише значення у своєму форматі запису (за замовчуванням літери, цифри, `-`, `_` і `.`), але все одно ставтеся до нього як до ненадійних вхідних даних: передавайте його туди, де вузол екранує значення, як-от параметр HTTP-запиту або значення фільтра [DataTable](./datatable-node.md) чи ClickHouse, і ніколи не формуйте текст запиту шляхом конкатенації рядків із ним. Віджети все одно виконуються від імені власника панелі приладів, незалежно від того, хто відкриває сторінку.

## Як розв'язуються дані

1. Якщо задано `dataPath`, вузол прямує цим шляхом із крапками у вихідні дані вище за потоком.
2. Інакше він шукає масив: список верхнього рівня, масив `data` або перше поле зі значенням-списком.
3. Рядки безпосередньо з вузла [Data Table](./datatable-node.md) (`{id, data, created_at}`) зчитуються зі своїми стовпцями на верхньому рівні поруч із `id`, тому `labelField`, `valueField` і `columns` називають власні стовпці таблиці.
4. Для `table` кожен рядок стає рядком таблиці з використанням `columns` (або ключів першого рядка). Із `statusColumn` Payload також містить тон кожного значення в цьому стовпці.
5. Для `numeric` та `gauge` значення береться з `valueField` у першому рядку (або з першого числового поля).
6. Для `scatter` кожен рядок стає точкою `[xField, yField]`.
7. Для `text` повідомлення береться з `valueField` у першому рядку, якщо його задано, інакше — зі статичної конфігурації `text` (або з першого рядкового поля першого рядка).

## Приклад

```json
{
  "type": "chartOutput",
  "data": {
    "label": "revenueChart",
    "chartType": "bar",
    "orientation": "vertical",
    "dataPath": "data",
    "labelField": "month",
    "valueField": "revenue",
    "title": "Monthly revenue"
  }
}
```

Gauge (одне значення проти діапазону):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "cpuGauge",
    "chartType": "gauge",
    "dataPath": "rows",
    "valueField": "value",
    "min": 0,
    "max": 100,
    "unit": "%"
  }
}
```

Scatter (точки X/Y):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "correlation",
    "chartType": "scatter",
    "dataPath": "rows",
    "xField": "x",
    "yField": "y"
  }
}
```

Proportion (одна смуга, розділена за часткою + легенда з відсотками):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "languages",
    "chartType": "proportion",
    "dataPath": "rows",
    "labelField": "name",
    "valueField": "value",
    "title": "Most Used Languages"
  }
}
```

Area (заповнений багатосерійний тренд):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "memCpu",
    "chartType": "area",
    "dataPath": "rows",
    "labelField": "time",
    "series": [
      { "name": "Memory", "field": "memory" },
      { "name": "CPU", "field": "cpu" }
    ],
    "title": "Memory / CPU"
  }
}
```

Bar gauge (градієнтний gauge для кожного рядка зі значеннями):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "freeDisk",
    "chartType": "barGauge",
    "dataPath": "rows",
    "labelField": "name",
    "valueField": "value",
    "unit": "GB",
    "title": "Free disk space"
  }
}
```

Text (статичне повідомлення markdown — рядки вище за потоком не потрібні):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "statusNote",
    "chartType": "text",
    "text": "**Last execution** at `19:47` — all checks passed ✅",
    "title": "Status"
  }
}
```

Text (динамічний — рядок повідомлення формується вище за потоком і отримується через `valueField`):

```json
{
  "type": "chartOutput",
  "data": {
    "label": "lastRun",
    "chartType": "text",
    "dataPath": "rows",
    "valueField": "message"
  }
}
```
## Приклади AI prompt

Під час генерації віджета за допомогою **AI** prompt, подібні до наведених нижче, чітко відповідають кожному типу:

- **Bar** — «Покажіть місячний дохід за останні 6 місяців як вертикальну стовпчикову діаграму з прикладом даних.»
- **Line** — «Побудуйте графік щоденних активних користувачів за останні 14 днів як лінійну діаграму.»
- **Area** — «Покажіть використання пам'яті та CPU за останні 24 години як діаграму з областями з двома серіями. Використайте приклад даних.»
- **Pie** — «Розподіліть статус виконання (success, error, cancelled) як кругову діаграму.»
- **Table** — «Покажіть топ-10 Workflow за кількістю виконань як таблицю з прокруткою зі стовпцями name та runs. Використайте приклад даних.»
- **Numeric** — «Покажіть загальну кількість виконань Workflow за сьогодні як єдиний KPI з одиницею виміру "runs". Використайте приклад даних.»
- **Gauge** — «Покажіть поточне використання CPU як індикатор від 0 до 100 відсотків.»
- **Scatter** — «Побудуйте залежність затримки запиту від розміру payload як точкову діаграму з прикладом даних.»
- **Proportion** — «Покажіть мої найуживаніші мови як смугу пропорцій: Kotlin 49.64%, JavaScript 23.73%, TypeScript 11.64%, Java 8.92%, Python 6.06%. Використайте приклад даних.»
- **Bar gauge** — «Покажіть вільний дисковий простір для кожного тому (sda1–sda7) як стовпчиковий індикатор у ГБ. Використайте приклад даних.»
- **Text** — «Додайте текстовий віджет із markdown-чеклістом (один позначений пункт, два непозначені) або перелічіть 5 найновіших навчальних відео у спадному порядку (від 5. до 1.) з посиланнями на YouTube — додайте на початок кожного рядка явний номер (`5. Title`, `4. Title`, …).»

## Кнопки посилань

Стовпець у `table` можна перетворити на кнопки, що відкривають посилання. Вкажіть **Link column** у властивостях вузла (або `linkColumn` у DSL) для стовпця, клітинки якого містять URL, і за потреби **Link button text** (`linkLabel`). Кожна клітинка стає кнопкою, що відкриває свій URL у новій вкладці. Без тексту кнопки вона показує лише піктограму посилання:

| Значення клітинки | Відкриває |
| ----------------- | --------- |
| `https://jira.example.com/browse/T-1` | Інший сайт у новій вкладці |
| `/dashboards` | Сторінку всередині Heym у новій вкладці |

Кнопками стають лише адреси `http://` і `https://` та шляхи, що починаються з одного `/`. Будь-яке інше значення, наприклад `javascript:` або `//host`, залишається звичайним текстом, а порожня клітинка нічого не показує.

Кнопка працює поряд із [посиланням рядка](../tabs/dashboard-tab.md#detail-pages): клік по кнопці відкриває її посилання в новій вкладці, а клік будь-де в іншому місці рядка, як і раніше, відкриває сторінку деталей.
