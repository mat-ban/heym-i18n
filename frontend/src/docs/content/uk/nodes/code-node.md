# Code

Вузол **Code** виконує написаний Вами код Python із власним файлом `requirements.txt` та повертає JSON. Кожне виконання отримує цілком новий контейнер, який знищується після завершення запуску, тож одне виконання ніколи не може побачити інше чи вплинути на нього.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | `$nodeLabel.result` (те, що повернула `main`), а також `$nodeLabel.logs` і `$nodeLabel.install` |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `label` | string | Ідентифікатор вузла (camelCase) |
| `codeSource` | string | Вихідний код Python. Має визначати `main(params)` і повертати значення, придатне для серіалізації в JSON |
| `codeParameters` | expression | Об'єкт JSON, що пов'язує дані workflow з кодом. Вирази обчислюються до запуску коду |
| `codeRequirements` | string | Вміст `requirements.txt`, один пакет на рядок. Порожнє значення пропускає встановлення |
| `codeAllowNetwork` | boolean | Чи може сам код звертатися до мережі (типово `false`) |

## Функція `main`

Ваш код має визначати функцію `main` верхнього рівня, яка приймає один аргумент:

```python
def main(params):
    name = params.name
    return {"message": f"Hello, {name}!", "length": len(name)}
```

Інструкції рівня модуля справді виконуються, але виходом вузла стає лише те, що повертає `main`.

Редактор показує номери рядків, а кнопка розгортання поруч із **Format** відкриває більший редактор, який закривається клавішею `Esc` — зміни застосовуються в міру введення, тож зберігати нічого не потрібно. Кнопка **Format** переформатує Ваш код за допомогою Ruff, зберігаючи коментарі. Вона також виправляє пошкодження відступів, які зазвичай спричиняє вставлення: рівномірно зсунутий блок, табуляції впереміш із пробілами та рядок, зміщений на один-два пробіли від свого блоку, — усе це виправляється, а не відхиляється. Справжня синтаксична помилка натомість повідомляється із зазначенням рядка та стовпця. Форматування виконується в тому самому ізольованому контейнері, у якому працює вузол — без мережі, без середовища бекенду — тож для нього потрібен Docker, як і для виконання.

## Читання параметрів

`params` підтримує точкову нотацію, зокрема крізь вкладені об'єкти та списки:

```python
def main(params):
    city = params.user.address.city
    first_order = params.orders[0].id
    return {"city": city, "first_order": first_order}
```

- `params["my key"]` читає ключі, які не є припустимими ідентифікаторами Python
- `params.get("maybe")` повертає `None` замість помилки, коли ключ відсутній
- `params.to_dict()` повертає звичайний словник
- Читання ключа, який ніколи не надавався, спричиняє помилку із зазначенням ключа та переліком доступних

## Вихід

```json
{
  "result": { "message": "Hello, Heym!", "length": 4 },
  "logs": "",
  "install": { "ok": true, "tool": "none", "log": "" }
}
```

- `result` — значення, яке повернула `main`. Наступні вузли читають `$nodeLabel.result.message`
- `logs` — усе, що код надіслав до `print`, захоплене окремо, тож воно ніколи не пошкоджує результат
- `install` — який інструмент встановлював залежності (`uv`, `pip` або `none`) та його вивід

## Залежності

Перелічіть пакети у `requirements.txt` точно так, як робили б це локально:

```
requests==2.32.3
feedparser
```

Пакети встановлюються за допомогою `uv` у тимчасову директорію до запуску коду; якщо `uv` не може обробити пакет, Heym повторює спробу з `pip`. Між запусками нічого не кешується, тож важкі залежності додають кілька секунд до кожного виконання. Якщо залишити `requirements.txt` порожнім, крок встановлення повністю пропускається, і це помітно швидше.

Пакети, які не постачаються з wheel і потребують компілятора C, не встановляться. Причина з'явиться в `install.log`.

## Мережа

| Фаза | Мережа |
|-------|---------|
| Встановлення залежностей | Завжди увімкнена — pip і uv мають дістатися до PyPI |
| Виконання Вашого коду | Вимкнена типово. `codeAllowNetwork` вмикає її |

Коли `codeAllowNetwork` вимкнено, вихідний виклик на кшталт `requests.get(...)` завершується помилкою з'єднання. Це і є задумана типова поведінка: більшість вузлів Code перетворюють дані, які вже отримав інший вузол. Надавайте перевагу отриманню даних вузлом **HTTP** і передаванню тіла через `codeParameters`.

## Пісочниця та обмеження

Ваш код виконується від імені користувача без прав root у контейнері з усіма відкликаними можливостями Linux, увімкненим `no-new-privileges` та кореневою файловою системою, доступною лише для читання. Він не отримує ні Docker-сокета, ні секретів чи середовища бекенду.

| Обмеження | Значення |
|-------|-------|
| Пам'ять | 512 MB |
| CPU | 1 |
| Процеси | 256 |
| Час очікування встановлення залежностей | 120 секунд |
| Час очікування виконання | 60 секунд |

Це фіксовані властивості пісочниці, а не налаштування.

> **Потрібен Docker.** На відміну від інструментів і навичок Agent Python, вузол Code не має локального резервного режиму та змінної середовища, щоб його послабити. Без доступного демона Docker вузол завершується зрозумілою помилкою, а не виконує Ваш код у процесі бекенду. Під час розробки через нативний `./run.sh` запустіть Docker перед використанням цього вузла. Див. [Security → Code node sandbox](../reference/security.md#code-node-sandbox).

## Приклад

Рядки оцінок, створені вхідним вузлом:

```python
def main(params):
    rows = params.rows
    total = sum(r.amount * r.weight for r in rows)
    return {"total": round(total, 2), "count": len(rows)}
```

Якщо для `codeParameters` встановлено значення `{ "rows": "$fetchRows.result" }`, наступні вузли зчитують `$scoreRows.result.total`.
