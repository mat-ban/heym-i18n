# Converter

Вузол **Converter** перетворює дані та файли між форматами без написання коду. Він є технологічно нейтральним, тож із часом можна додавати нові формати. Він конвертує дані CSV, JSON та XML в обох напрямках, запускає Tesseract OCR для вилучення тексту із зображень і PDF-файлів, а також перезаписує збережений файл в іншому форматі.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | `$nodeLabel.result` (розібрані дані для `csvToJson` / `xmlToJson`, текст для `jsonToCsv` / `jsonToXml`, вилучений текст для `imageToText` / `pdfToText`, метадані нового файлу для `fileConvert`) |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `label` | string | Ідентифікатор вузла (camelCase) |
| `conversion` | string | `csvToJson` (текст CSV → масив об'єктів рядків), `jsonToCsv` (масив об'єктів/рядків → текст CSV), `xmlToJson` (текст XML → об'єкт), `jsonToXml` (об'єкт → текст XML), `imageToText` (OCR зображення), `pdfToText` (OCR кожної вибраної сторінки PDF) або `fileConvert` (перезапис збереженого файлу в іншому форматі) |
| `source` | expression | Дані для перетворення. Залиште порожнім, щоб використати перший вхід вузла |
| `delimiter` | string | Односимвольний роздільник полів (типово `,`) |
| `hasHeader` | boolean | Лише `csvToJson` — вважати перший рядок заголовком (типово `true`) |
| `trimValues` | boolean | Лише `csvToJson` — прибирати пробіли навколо назв заголовків і значень комірок (типово `true`) |
| `includeHeader` | boolean | Лише `jsonToCsv` — записувати рядок заголовка (типово `true`) |
| `converterColumns` | string | Лише `jsonToCsv` — необов'язковий порядок стовпців, розділених комами |
| `converterFileId` | expression | Перетворення файлів — файл Heym Drive для читання, наприклад `$Upload.file.id` |
| `converterTargetFormat` | string | Лише `fileConvert` — вихідний формат (`pdf`, `docx`, `html`, `md`, `txt`, `csv`, `epub`, `jpg`, `png`, `bmp`, `webp`) |
| `ocrLanguage` | string | Лише OCR — `auto` (типово), код Tesseract, наприклад `tur`, або `custom` |
| `ocrLanguageCustom` | string | Лише OCR — коди мов, що використовуються, коли `ocrLanguage` має значення `custom`, наприклад `eng+tur` |
| `ocrEncoding` | string | Лише OCR — кодування, до якого нормалізується текст (типово `utf-8`) |
| `ocrNormalizeUnicode` | boolean | Лише OCR — застосувати нормалізацію NFC (типово `true`) |
| `ocrPsm` | string | Лише OCR — режим сегментації сторінки Tesseract (типово `3`) |
| `ocrDpi` | number | Лише `pdfToText` — DPI растеризації сторінки (типово `300`) |
| `ocrPageRange` | expression | Лише `pdfToText` — `3` або `2-5`. Порожнє значення означає кожну сторінку |

## Поведінка

- **`csvToJson`** розбирає вихідний текст CSV. За `hasHeader: true` кожен рядок стає об'єктом із ключами за значеннями заголовка; за `hasHeader: false` кожен рядок стає масивом значень комірок. Поля в лапках, вбудовані роздільники та вбудовані символи нового рядка обробляються згідно з RFC 4180. Провідний BOM UTF-8 (поширений у файлах, експортованих з Excel) видаляється, а дублікати назв заголовків робляться унікальними без перезапису справжнього стовпця (`a, a, a_2` → `a`, `a_3`, `a_2`). Встановіть `delimiter` у `\t`, щоб розібрати значення, розділені табуляцією.
- **`trimValues`** (типово `true`) прибирає пробіли навколо назв заголовків і значень комірок, **зокрема всередині полів у лапках** (`" padded "` → `padded`). RFC 4180 трактує пробіли в лапках як дані, тож встановіть `trimValues: false`, щоб зберегти їх точно.
- **`jsonToCsv`** будує текст CSV з масиву об'єктів (або масивів). Порядок стовпців береться з `converterColumns`, якщо його надано, інакше виводиться з ключів першого об'єкта. Значення, що містять роздільник, лапки або символи нового рядка, автоматично беруться в лапки.
- **`xmlToJson`** розбирає XML в об'єкт. Атрибути використовують префікси `@`, а текст, змішаний з атрибутами, використовує `#text`; повторювані сусідні елементи стають масивами. Розгортання сутностей XML вимкнено.
- **`jsonToXml`** серіалізує об'єкт у документ XML. Об'єкт повинен мати рівно один ключ верхнього рівня, який стає кореневим елементом XML. Використовуйте ту саму умовність `@attribute` та `#text`, що й у `xmlToJson`, щоб створювати атрибути й текст поряд із дочірніми елементами.
- **`imageToText`** запускає Tesseract над одним зображенням (PNG, JPEG, TIFF, WebP, BMP).
- **`pdfToText`** растеризує кожну вибрану сторінку за `ocrDpi` та розпізнає її. Кожна сторінка проходить через OCR, тож цифровий PDF із цілком придатним текстовим шаром усе одно перечитується з пікселів. Це забезпечує однакову поведінку сканованих і цифрових документів ціною швидкості, тож звужуйте `ocrPageRange` для довгих файлів.
- **`fileConvert`** перезаписує вихідний файл в іншому форматі та зберігає результат як **новий** файл Drive. Оригінал ніколи не змінюється. Документи проходять через pandoc, зображення — через Pillow, а JSON у CSV — через засіб запису csv мови Python. Зображення не може стати документом, а документ не може стати зображенням; щоб вилучити текст із зображення, використовуйте `imageToText`.

## Як подати файл на вхід

Перетворення файлів читають із Heym Drive, а не з шляху чи URL, тож файл спершу потрібно зберегти. Три поширені ланцюжки:

- **[File upload trigger](./file-upload-trigger-node.md) → Converter** — спрямуйте `converterFileId` на `$Upload.file.id`.
- **[Drive](./drive-node.md) (`downloadUrl`) → Converter** — отримайте віддалений файл у Drive, потім передайте `$Download.id`.
- **[Agent](./agent-node.md) → Converter** — навичка, що записує файл, надає його як `$reportAgent._generated_files[0].id`.

`converterFileId` також приймає цілий об'єкт файлу (`$Upload.file`) або URL для завантаження з Heym; ідентифікатор файлу вилучається з будь-якого з них. Файл має належати Вам або бути наданим Вам колегою.
## Мови

`auto` (типове значення) спершу запускає визначення орієнтації та письменності Tesseract, а потім обирає найкращу встановлену модель для визначеної письменності. Моделі письменності, як-от `Latin` чи `Cyrillic`, читають усі мови, що пишуться цією письменністю, — саме тому `auto` розпізнає і турецький, і англійський рахунок, не отримуючи вказівок, де який.

Коли мову відомо, її зазначення все одно дає точніший результат. Використовуйте один код (`tur`) або з'єднуйте кілька символом `+` (`eng+tur`) для змішаних документів — більше мов означає повільніше та трохи шумніше розпізнавання, тож тримайте список коротким. Коди працюють лише тоді, коли відповідні мовні дані встановлено на бекенді; вузол показує доступні варіанти, якщо обрано відсутній.

Кожен образ Heym містить `osd`, англійську, турецьку, німецьку, французьку, іспанську, італійську, португальську, нідерландську, російську, арабську, спрощену китайську, японську, корейську, а також моделі письменності Latin, Cyrillic, Arabic, HanS, Japanese і Hangul.

## Кодування

Розпізнаний текст має кодування UTF-8 і зберігає кожен символ, який створив Tesseract. `ocrNormalizeUnicode` (увімкнено типово) застосовує нормалізацію NFC, тож літера, записана як `s` разом із комбінованою седилею, стає єдиною `ş` — варто залишати це увімкненим, адже ці дві форми не рівні під час порівнянь чи пошуку в базі даних.

`ocrEncoding` має значення лише тоді, коли щось нижче за потоком не може зберігати повний діапазон Unicode. Вибір `cp1254` чи `iso-8859-9` зберігає турецький текст неушкодженим, гарантуючи, що результат уміщується в цей набір символів; `latin-1` та `ascii` вужчі й замінюють те, що не можуть представити, символом `?`. Залишайте `utf-8`, якщо цільова система не змушує вас вчинити інакше.

## Виведення

`csvToJson`, `jsonToCsv`, `xmlToJson` і `jsonToXml` повертають `$label.result` та `$label.conversion`. Перетворення OCR додають:

| Поле | Опис |
|-------|-------------|
| `$label.result` | Повний витягнутий текст, сторінки з'єднано порожнім рядком |
| `$label.language` | Модель, яка фактично виконувалася (корисно, щоб побачити, що обрав `auto`) |
| `$label.encoding` | Набір символів, до якого було нормалізовано текст |
| `$label.page_count` | Кількість розпізнаних сторінок |
| `$label.pages` | Масив `{ page, text }` для посторінкової обробки |
| `$label.file` | `{ id, filename, mime_type, size_bytes }` вихідного файлу |

`fileConvert` натомість повертає новий файл:

| Поле | Опис |
|-------|-------------|
| `$label.id` | UUID щойно збереженого файлу |
| `$label.filename` | Ім'я перетвореного файлу, базову назву збережено, розширення замінено |
| `$label.mime_type` | MIME-тип нового файлу |
| `$label.size_bytes` | Розмір нового файлу |
| `$label.download_url` | URL завантаження з Drive для нового файлу |
| `$label.source_file` | Метадані файлу, який було перетворено |

## Приклад

```json
{
  "type": "converter",
  "data": {
    "label": "toRows",
    "conversion": "csvToJson",
    "source": "$userInput.body.text",
    "delimiter": ",",
    "hasHeader": true
  }
}
```

Для вхідних даних `name,age\nAda,36` вузли нижче за потоком отримують доступ до розібраних рядків через `$toRows.result` (`[{ "name": "Ada", "age": "36" }]`).

Перетворення XML на JSON:

```json
{
  "type": "converter",
  "data": {
    "label": "xmlToObject",
    "conversion": "xmlToJson",
    "source": "$webhook.body"
  }
}
```

Для `<person id="1"><name>Ada</name></person>` `$xmlToObject.result` дорівнює `{ "person": { "@id": "1", "name": "Ada" } }`. Щоб створити XML, передайте цей об'єкт другому вузлу Converter із `conversion: "jsonToXml"`.

Читання сканованого рахунку, завантаженого через trigger завантаження файлу:

```json
{
  "type": "converter",
  "data": {
    "label": "readInvoice",
    "conversion": "pdfToText",
    "converterFileId": "$Upload.file.id",
    "ocrLanguage": "tur",
    "ocrEncoding": "utf-8",
    "ocrDpi": 300,
    "ocrPageRange": "1-3"
  }
}
```

Вузол [Agent](./agent-node.md) або [LLM](./llm-node.md) нижче за потоком може потім витягнути структуровані поля з `$readInvoice.result`.

Перетворення звіту агента у форматі markdown на PDF:

```json
{
  "type": "converter",
  "data": {
    "label": "convertDoc",
    "conversion": "fileConvert",
    "converterFileId": "$reportAgent._generated_files[0].id",
    "converterTargetFormat": "pdf"
  }
}
```

Вузли нижче за потоком читають `$convertDoc.download_url`, щоб поділитися PDF, або `$convertDoc.id`, щоб продовжити роботу з ним у [Drive](./drive-node.md).

## Вимоги

OCR викликає зовнішні `tesseract` та `pdftoppm` з poppler, а перетворення документів використовує pandoc. Усі три постачаються з кожним способом запуску Heym, зокрема `run.sh`, docker-compose та єдиним образом релізу, тож налаштовувати нічого не потрібно. Обмеження сторінок, тайм-аути та максимальний DPI — це фіксовані значення платформи, а не налаштування.
