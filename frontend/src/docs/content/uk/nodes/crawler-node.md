# Crawler

Вузол **Crawler** виконує скрапінг вебсторінок за допомогою FlareSolverr з опціональним вилученням HTML через CSS-селектори. Використовуйте його для вебскрапінгу та вилучення вмісту.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | `$nodeLabel.body` (HTML або вилучений вміст) |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `credentialId` | UUID | Облікові дані FlareSolverr з [Облікові дані](../tabs/credentials-tab.md) |
| `crawlerUrl` | expression | URL для скрапінгу (підтримує вирази) |
| `crawlerWaitSeconds` | number | Кількість секунд очікування перед скрапінгом (за замовчуванням: 0) |
| `crawlerMaxTimeout` | number | Максимальний тайм-аут у мс (за замовчуванням: 60000) |
| `crawlerMode` | string | `"basic"` або інші режими |
| `crawlerSelectors` | array | CSS-селектори для вилучення. Кожен: `{ selector, attribute? }` |

## Приклад

```json
{
  "type": "crawler",
  "data": {
    "label": "scrapePage",
    "credentialId": "flaresolverr-credential-uuid",
    "crawlerUrl": "$userInput.body.url",
    "crawlerWaitSeconds": 2,
    "crawlerSelectors": [
      { "selector": "h1" },
      { "selector": ".content", "attribute": "innerHTML" }
    ]
  }
}
```

## Безпека вихідного трафіку

- URL FlareSolverr, збережений в облікових даних, має використовувати `http://` або `https://` і не може розпізнаватися як link-local або cloud-metadata адреса. Заборонений набір — це `169.254.0.0/16`, `fe80::/10`, IPv6-адреси метаданих Alibaba Cloud та AWS, а також форми переходу IPv6, які можуть містити одну з них. Це перелік відомих endpoint, а не гарантія щодо кожного провайдера.
- Loopback- та приватні адреси дозволені навмисно, щоб задокументоване налаштування `http://localhost:8191` та імена сервісів compose, як-от `http://flaresolverr:8191`, продовжували працювати. Наслідок полягає в тому, що це поле також можна спрямувати на будь-який інший сервіс, доступний бекенду за цими адресами, і відповідь повернеться у вихідних даних вузла. Спільний доступ до облікових даних цього не усуває: будь-який автентифікований користувач може створити власні облікові дані FlareSolverr, тож утримання наявних нічого не змінює. Дієві засоби контролю — це довіра до осіб, які можуть створювати workflow, та мережеві правила, що обмежують доступність бекенду.
- Heym фіксує розпізнану адресу перед підключенням, тож відповідь DNS не може перемістити запит на адресу метаданих після перевірки. Проксі середовища вимикаються, поки активний захист, а переадресації не відстежуються.
- Сторінка, яку FlareSolverr потім завантажує для Вас, — це окремий перехід, який FlareSolverr розпізнає самостійно. Heym його не перевіряє, тож обмеження того, куди може підключатися контейнер FlareSolverr, належить до Вашої мережевої політики.
- Довірені self-hosted розгортання можуть скасувати правило метаданих за допомогою `HEYM_HTTP_ALLOW_PRIVATE_URLS=true`. Залишайте значення за замовчуванням на hosted- або мультитенантних розгортаннях.
