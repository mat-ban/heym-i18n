# Decision

Вузол **Decision** ставить моделі прийняття рішень типізовані запитання про поточний стан виконання та повертає ймовірності. Він не генерує текст. Звертайтеся до нього, коли workflow потребує судження, на якому можна побудувати розгалуження — маршрутизація, тріаж, ранжування, верифікація або обмеження кроку, який неможливо скасувати.

Моделі прийняття рішень (також звані моделями *System One*) — це інший тип моделей, ніж LLM. Тут немає prompt, немає системної інструкції, немає temperature і немає виклику інструментів. Ви надсилаєте **state** разом із мапою **questions**, і кожна відповідь повертається як число з розподілом ймовірностей за ним. Оскільки відповідь складається лише з кількох токенів, ці моделі швидші та дешевші порівняно з проханням до [LLM](./llm-node.md) згенерувати JSON і подальшим його парсингом.

Для генерації тексту використовуйте вузол [LLM](./llm-node.md). Для моделі, яка викликає інструменти, використовуйте [Agent Node](./agent-node.md).

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | Відповідь провайдера дослівно — `$nodeLabel.answers.<id>`, `$nodeLabel.model`, `$nodeLabel.usage` |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `credentialId` | UUID | Облікові дані *Decision Model*. Не облікові дані LLM. |
| `model` | string | Назва моделі, наприклад `jev-latest` |
| `state` | expression | Те, що модель має прочитати (типово `$input.text`) |
| `questions` | array | Упорядковані рядки запитань; щонайменше одне |
| `customBodyEnabled` | boolean | Надіслати написане вручну тіло запиту замість форми |
| `customBody` | expression (JSON) | Тіло для надсилання, коли перемикач увімкнено |
| `requestTimeoutSeconds` | number | Максимум секунд очікування (типово: 60) |

### State

**State** — це ситуація, яку оцінює модель. Приймає рядок, об'єкт або масив.

Поле, що містить рівно один вираз, зберігає власний тип, тож `$input` надсилає сам об'єкт, а не його текст. Шаблон із виразом усередині (`Ticket: $input.text`) перетворюється на рядок. Надайте кожному запитанню достатньо інформації для відповіді: вихідний текст, ідентичності, зв'язки, політики та поточні факти.

## Типи запитань

Кожне запитання має `id`, `type`, `instructions` та критерії, що залежать від типу.

`id` — це те, як ваш workflow зчитує відповідь назад. Він **ніколи не надсилається моделі**, тож усе значення має міститися в `instructions`. Написання `id: is_urgent` з `instructions: "Is it?"` не дає моделі жодної опори.

### Noul

Чи виконується умова. Повертає ймовірність того, що відповідь — «так», від 0 до 1.

Критерії необов'язкові: **Yes means** та **No means** описують, що охоплює кожна сторона. Значення близько 0.5 означає, що модель вважає «так» і «ні» приблизно однаково ймовірними — а не «середню інтенсивність».

```json
{
  "id": "is_urgent",
  "type": "noul",
  "instructions": "Does this message convey urgency?",
  "criteriaTrue": "Explicitly time-sensitive or blocking work",
  "criteriaFalse": "No urgency expressed"
}
```

Зчитуйте його за допомогою `$triage.answers.is_urgent.noul`.

### Choice

Обирає один варіант із набору, який ви визначаєте. Повертає обраний варіант, повний розподіл та похідну від нього впевненість.

Додайте варіант, що охоплює «жоден із цих», коли ніщо може не підійти — модель не може обрати варіант, якого ви не запропонували.

```json
{
  "id": "department",
  "type": "choice",
  "instructions": "Which team should handle this request?",
  "options": [
    { "key": "billing", "description": "Payments, invoicing, refunds" },
    { "key": "technical", "description": "Bugs, outages, integrations" },
    { "key": "other", "description": "Nothing above fits" }
  ]
}
```

Зчитуйте його за допомогою `$triage.answers.department.choice`, `.probabilities.billing` та `.confidence`.

### Score

Оцінює стан за впорядкованою рубрикою. Повертає зважене за ймовірністю значення, яке може опинитися **між** рівнями, а також легенду та розподіл.

Рівні йдуть від найнижчого, щонайменше два і щонайбільше десять. Кожен рівень має описувати конкретну ситуацію та бути самодостатнім.

```json
{
  "id": "frustration",
  "type": "score",
  "instructions": "How frustrated is the customer?",
  "levels": ["Calm", "Frustrated", "Very angry"]
}
```

Зчитуйте його за допомогою `$triage.answers.frustration.score`, `.legend` та `.confidence`.

## Generate with AI

**Generate with AI** перетворює просте речення на запропонований шаблон state та набір рядків запитань. Опишіть, що ви хочете оцінити — «triage an incoming support ticket: how urgent it is, which team owns it, and how frustrated the customer sounds» — і перегляньте те, що повернеться, перш ніж додавати це до вузла.

Складання виконує LLM, тож діалог запитує облікові дані LLM. Модель прийняття рішень відповідає на запитання пізніше, коли workflow виконується. Згенеровані id дедуплікуються відносно рядків, які вузол уже містить, тож повторна генерація ніколи не перезаписує наявний ключ відповіді.

Кожна генерація записується на вкладці [Traces](../tabs/traces-tab.md) у джерелі **Decision Questions**, поряд із трасуваннями `decision.systemone`, які записує сам вузол під час виконання.
## Власне тіло запиту

Увімкніть **Власне тіло запиту**, щоб надсилати JSON, який Ви пишете самостійно, замість форми. Використовуйте це для endpoint, контракт якого відрізняється від того, який будує форма.

Редактор початково заповнюється з поточної форми, а вирази всередині нього обчислюються перед надсиланням запиту. Поки перемикач увімкнено, поле State та рядки запитань ігноруються. Відповідь передається без змін в обох випадках, тож інший контракт просто створює іншу структуру для зчитування Вашими виразами.

## Вихідні дані

Вузол повертає саме те, що повернув провайдер. Нічого не перейменовується та не вирівнюється.

```json
{
  "model": "jev-1.13.0",
  "answers": {
    "is_urgent": { "type": "noul", "noul": 0.95 },
    "department": {
      "type": "choice",
      "choice": "billing",
      "probabilities": { "billing": 0.88, "technical": 0.12, "other": 0.0 },
      "confidence": 0.81
    },
    "frustration": {
      "type": "score",
      "score": 1.05,
      "legend": { "0": "Calm", "1": "Frustrated", "2": "Very angry" },
      "probabilities": { "0": 0.0, "1": 0.95, "2": 0.05 },
      "confidence": 0.92
    }
  },
  "usage": { "input_tokens": 296, "output_tokens": 20 }
}
```

## Розгалуження за відповіддю

Вузол [Switch](./switch-node.md) спрямовує потік за обраним варіантом, а вузол [Condition](./condition-node.md) може надсилати випадки з низькою впевненістю туди, де їх побачить людина:

```
Input → Decision (triage) → Condition ($triage.answers.department.confidence > 0.7)
                              ├─ true  → Switch on $triage.answers.department.choice
                              └─ false → Send Email (human review)
```

Типізована відповідь гарантує структуру, а не істинність. Обирайте порогові значення, виходячи з Ваших власних даних і наслідків, а не копіюючи число з прикладу.

## Облікові дані

Створіть облікові дані **Decision Model** на вкладці [Облікові дані](../tabs/credentials-tab.md) із такими полями:

- **Base URL** — endpoint, наприклад `https://api.typesafe.ai`. Heym додає `/v1/systemone`.
- **API Key** — необов'язково. Endpoint, яким не потрібен ключ, можна залишити порожнім.

Під час редагування облікових даних збережений ключ зберігається, якщо поле ключа залишено порожнім; введіть його повторно лише для заміни.

Ті самі облікові дані можуть оцінювати запуски [Оцінювання](../tabs/evals-tab.md): з вибраним **LLM-as-Judge** оберіть їх як суддю, і модель рішень оцінить кожну відповідь щодо очікуваного результату.

Heym блокує вихідні запити до приватних і loopback-адрес за замовчуванням, тож endpoint рішень, який Ви запускаєте самостійно на `localhost` або в приватному діапазоні, потребує `HEYM_HTTP_ALLOW_PRIVATE_URLS=true`.

Моделі рішень не з'являються в таблицях ціноутворення LLM, які синхронізує Heym, тож стовпець **Cost** у [Трасуванні](../tabs/traces-tab.md) залишається порожнім для цих викликів. Кількість токенів усе одно записується, і Ви можете додати власну ціну за допомогою перевизначення ціноутворення.

## Помилки

| Ситуація | Що відбувається |
|-----------|--------------|
| Недійсний API key | Вузол завершується помилкою із зазначенням облікових даних |
| Некоректне запитання | Власне повідомлення провайдера на рівні поля переноситься в помилку вузла |
| Перевищено ліміт або перевантаження | Вузол завершується помилкою із зазначенням, що умова тимчасова — увімкніть [retry](../reference/features.md) для цього вузла, щоб перечекати |
| Дубльований або порожній id запитання | Вузол завершується помилкою до надсилання будь-якого запиту |
