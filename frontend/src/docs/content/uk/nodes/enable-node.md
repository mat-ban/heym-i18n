# Вузол Enable Node

Вузол **Enable Node** знову вмикає інший вузол. Під час виконання він встановлює для цільового вузла значення `active` як `true` та зберігає цю зміну. Це парний вузол до [Disable Node](./disable-node.md): використовуйте його, щоб повторно активувати тригер [Cron](./cron-node.md) або будь-який вузол, який було вимкнено.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | `$nodeLabel.targetNode`, `$nodeLabel.enabled` |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `label` | string | Ідентифікатор вузла (camelCase) |
| `targetNodeLabel` | string | Мітка вузла, який потрібно ввімкнути (наприклад, `hourlyCheck`) |

## Поведінка

- Цільовий вузол зберігається як активний, тому подальші запуски та тригери його враховують. Повторно ввімкнений тригер Cron спрацьовує знову у свій наступний запланований час.
- Якщо цільовий вузол розташований нижче за потоком від Enable Node і ще не виконувався, він також виконується в поточному запуску.
- Увімкнення вузла, який уже активний, нічого не змінює; вихід усе одно повідомляє `enabled: true`.
- Вузол завершується помилкою, якщо `targetNodeLabel` порожній або жоден вузол не має такої мітки.

## Сценарій використання

Запуск тригера [Cron](./cron-node.md) на вимогу. Збережіть вузол Cron вимкненим і додайте до workflow другу точку входу, наприклад тригер [Input](./input-node.md). Запит до цієї точки входу запускає Enable Node, і Cron починає спрацьовувати.

Вимкнений тригер ніколи не запускає виконання самостійно, тому Enable Node має розташовуватися за точкою входу, яка може виконуватися.

## Приклад

```json
{
  "type": "enableNode",
  "data": {
    "label": "startCron",
    "targetNodeLabel": "hourlyCheck"
  }
}
```

Потік: Input → Enable Node (ціль: cron) → Output. Вузол Cron `hourlyCheck` збережено як вимкнений у тому самому workflow, і він запускає власну гілку HTTP-перевірки після ввімкнення.
