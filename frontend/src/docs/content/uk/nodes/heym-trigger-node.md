# Heym Trigger

Вузол **Heym Trigger** запускає workflow, коли сама платформа Heym публікує подію. Це trigger-вузол без вхідних даних для автоматизації Heym за допомогою Heym: журнали аудиту змін, сповіщення про розгортання та зведення про стан інстансу.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 0 |
| Виходи | 1 |
| Вихід | `$nodeLabel.events`, `$nodeLabel.count`, `$nodeLabel.triggered_at` |
| Облікові дані | Не потрібні |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `eventNames` | Масив рядків | Які події слід прослуховувати. Залиште порожнім, щоб отримувати всі події. |

## Події

| Подія | Публікується, коли | Область |
|-------|----------------|-------|
| `heym.started` | Платформа Heym запускається | На рівні інстансу: кожен підписник отримує її |
| `workflow.created` | Створюється workflow | Лише підписники власника workflow |
| `workflow.updated` | Workflow зберігається | Лише підписники власника workflow |
| `workflow.deleted` | Workflow видаляється | Лише підписники власника workflow |

Віджети дашборду внутрішньо зберігаються як workflows, але вони ніколи не генерують події `workflow.*`.

## Доставка здійснюється пакетами

Heym надсилає події кожні п'ять секунд. **Кожна подія, отримана за один прохід надсилання, надходить в одному запуску workflow** як масив.

- Створіть два workflows протягом п'яти секунд один від одного → **один** запуск із двома подіями.
- Створіть один workflow → **один** запуск із масивом з одного елемента.

Форма ніколи не змінюється, тому подальші вирази ніколи не повинні розгалужуватися залежно від того, чи надійшла одна подія, чи багато. Коли потрібно виконати дію один раз на подію, розмістіть вузол [Loop](./loop-node.md) над `$nodeLabel.events`.

## Доставка рівно один раз

Кожна подія закріплюється за вузлом-підписником через унікальне обмеження бази даних, перш ніж її буде доставлено. Це діє для кожного воркера uvicorn, кожного контейнера та кожної машини: запуск Heym на двох серверах не призводить до доставки події двічі. Якщо закріплення неможливо зафіксувати, подія не доставляється взагалі — архітектура відмовляє закрито, а не спрацьовує двічі.

Два різні вузли `heymTrigger`, підписані на одну й ту саму подію, кожен отримують її один раз; вони не конкурують за неї.

## Вікно надсилання

Диспетчер розглядає лише події, опубліковані за **останні п'ять хвилин**. Старіші події залишаються в журналі для перевірки, але ніколи не доставляються. Це обмежує наслідки після простою: відновлення роботи Heym після години офлайну не відтворює нічого, замість того щоб одразу надіслати годину накопичених подій.

Події зберігаються протягом **7 днів**, після чого видаляються.

## Вихідні поля

| Вираз | Опис |
|------------|-------------|
| `$nodeLabel.events` | Масив об'єктів подій, від найстарішої. Завжди масив. |
| `$nodeLabel.events[0].id` | UUID події |
| `$nodeLabel.events[0].name` | Назва події, наприклад `workflow.created` |
| `$nodeLabel.events[0].payload` | Тіло події |
| `$nodeLabel.events[0].workflow_id` | Ідентифікатор відповідного workflow або `null` для `heym.started` |
| `$nodeLabel.events[0].created_at` | Мітка часу ISO, коли подію було опубліковано |
| `$nodeLabel.count` | Кількість подій у цьому пакеті |
| `$nodeLabel.triggered_at` | Мітка часу ISO для виконання workflow |

### Форми payload

`workflow.created`, `workflow.updated`, `workflow.deleted`:

```json
{
  "workflow_id": "…",
  "name": "Nightly report",
  "owner_id": "…",
  "actor_user_id": "…",
  "updated_at": "2026-08-11T09:30:00+00:00"
}
```

`heym.started`:

```json
{ "version": "1.4.2", "started_at": "2026-08-11T09:30:00+00:00" }
```

`workflow.deleted` містить назву, зафіксовану безпосередньо перед видаленням, оскільки рядок workflow вже відсутній на момент читання події.

## Приклад workflow

**Журнал аудиту змін workflow**

```
heymTrigger → heym (getWorkflow) → slack
```

- **Heym Trigger** з міткою `platformEvents`, підписаний на `workflow.created`, `workflow.updated`, `workflow.deleted`
- Вузол **Heym** з `getWorkflow` та `heymWorkflowId`, встановленим у `$platformEvents.events[0].workflow_id`
- Повідомлення **Slack**: `"$platformEvents.count workflow change(s), latest: $platformEvents.events[0].name"`

## Примітки

- `heym.started` спрацьовує **один раз на запуск платформи**, а не один раз на воркер, навіть попри те, що Heym запускає вісім воркерів на контейнер. Контейнери, які запускаються з інтервалом понад п'ять хвилин, публікують по одній події кожен.
- Виконання, запущені в такий спосіб, з'являються в історії з `trigger_source = "heym_event"`.
- Встановіть **Events** у значення «жодного», а не перелічуйте всі чотири, якщо хочете автоматично підхоплювати типи подій, додані в майбутніх версіях.
