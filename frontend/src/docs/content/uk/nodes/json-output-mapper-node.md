# Вузол JSON output mapper

Вузол **JSON output mapper** формує JSON-об'єкт із [mappings](./set-node.md) ключ/значення (та сама модель, що й у [Set](./set-node.md)). Використовуйте його, коли виклики мають отримувати **звичайне JSON-тіло** в корені відповіді.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 0 (sink) |
| Результат виконання | Об'єкт, побудований із `mappings` |

## Параметри

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `label` | string | Ідентифікатор вузла (camelCase) |
| `mappings` | array | Записи `{ "key": "fieldName", "value": "expression" }` (як у Set) |

## Використання як інструмента агента

Не підтримується. Цей вузол є термінальним sink, тому його не можна приєднати до обробника інструментів [Agent Node](./agent-node.md). Використовуйте вузол [Set](./set-node.md), коли агенту потрібно формувати значення під час розмови.

## Поведінка Webhook і виконання

Коли цей вузол є **єдиним** термінальним виходом workflow, **outputs** виконання — це сам відображений об'єкт: ключі з `mappings` з'являються на **верхньому рівні** JSON. Немає **жодного** зовнішнього обгорткового ключа за `label` вузла і **жодного** об'єкта `{ "result": ... }` (на відміну від вузла [Output](./output-node.md)).

Якщо кілька термінальних вузлів формують виходи (наприклад, [Output](./output-node.md) разом із JSON output mapper або кілька гілок), Heym використовує звичайну структуру: кожен термінал позначається своїм `label`.

## Обмеження циклів

Те саме правило, що й для [Output](./output-node.md): не розміщуйте цей вузол усередині гілки ітерації циклу — лише після гілки `done` циклу. Див. [Loop](./loop-node.md).

## Приклад

```json
{
  "type": "jsonOutputMapper",
  "data": {
    "label": "apiPayload",
    "mappings": [
      { "key": "message", "value": "$llm.text" },
      { "key": "ok", "value": "true" }
    ]
  }
}
```
