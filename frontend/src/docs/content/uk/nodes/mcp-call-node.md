# Вузол MCP Call

Вузол **MCP Call** викликає конкретний інструмент [Model Context Protocol (MCP)](https://modelcontextprotocol.io) безпосередньо, без залучення LLM для вибору інструмента. Використовуйте його, коли точно відомо, який інструмент слід викликати, і потрібне детерміноване одноетапне виконання.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 1 |
| Виходи | 1 |
| Вихід | `$nodeLabel.result` |

## Коли використовувати

Використовуйте вузол MCP Call, коли:
- На етапі проєктування точно відомо, який інструмент MCP слід викликати
- Не потрібно, щоб LLM обирала між інструментами
- Потрібна легка детермінована альтернатива вузлу агента для виклику одного інструмента

Натомість використовуйте [вузол Agent](./agent-node.md), коли рішення про вибір інструментів має ухвалювати LLM або коли потрібне багатокрокове міркування.

> Вузол MCP Call **не можна** підключати до вузла агента як інструмент.

## Налаштування з'єднання

Вузол підключається до одного сервера MCP. Виберіть транспорт і заповніть відповідні поля.

### SSE / Streamable HTTP

| Поле | Опис |
|-------|-------------|
| `transport` | `sse` або `streamable_http` |
| `url` | Повна URL-адреса сервера MCP (наприклад, `https://mcp.example.com/sse`). Підтримує DSL-вирази. |
| `headers` | JSON-об'єкт HTTP-заголовків (наприклад, `{"Authorization": "Bearer ..."}`) |
| `timeoutSeconds` | Час очікування на одне з'єднання в секундах (за замовчуванням: 30) |

### stdio

| Поле | Опис |
|-------|-------------|
| `transport` | `stdio` |
| `command` | Виконуваний файл для запуску (наприклад, `npx`) |
| `args` | JSON-масив аргументів (наприклад, `["-y", "@modelcontextprotocol/server-filesystem"]`) |
| `env` | JSON-об'єкт змінних середовища (наприклад, `{"API_KEY": "..."}`) |
| `timeoutSeconds` | Час очікування на одне з'єднання в секундах (за замовчуванням: 30) |

## Вибір інструмента

1. Заповніть поля з'єднання.
2. Натисніть **Fetch Tools** — вузол підключиться до сервера MCP і відобразить список доступних інструментів.
3. Виберіть інструмент зі спадного списку.

**Вибір інструмента є обов'язковим.** Вузол не виконуватиметься без вибраного інструмента.

## Аргументи

Після вибору інструмента вузол відображає одне поле введення для кожного аргументу, визначеного у схемі введення інструмента. Кожне поле приймає:
- Статичне значення: `10`
- DSL-вираз: `$userInput.body.text`

Обов'язкові аргументи позначені символом `*`.

## Вихід

| Поле | Опис |
|-------|-------------|
| `$nodeLabel.result` | Результат виконання інструмента. Якщо відповідь є коректним JSON, це розібраний об'єкт. Інакше — рядок. |

## Приклад

Виклик інструмента `search` на сервері MCP через SSE з передаванням запиту користувача:

```json
{
  "type": "mcpCall",
  "data": {
    "label": "searchCall",
    "connection": {
      "transport": "sse",
      "url": "https://mcp.example.com/sse",
      "timeoutSeconds": 30
    },
    "selectedTool": "search",
    "toolArguments": {
      "query": "$userInput.body.text",
      "limit": "10"
    },
    "timeoutSeconds": 30
  }
}
```

Доступ до результату на наступних етапах:

```
$searchCall.result.items   ← якщо результат є JSON-об'єктом
$searchCall.result         ← якщо результат є звичайним рядком
```

## Примітки

- Вузол обчислює DSL-вирази в `url`, `headers`, `env` та всіх значеннях `toolArguments` перед викликом інструмента.
- `timeoutSeconds` на рівні вузла застосовується до всього виконання; `connection.timeoutSeconds` застосовується безпосередньо до сесії MCP.
- Якщо сервер MCP недоступний або повертає помилку, вузол завершується з помилкою, а повідомлення про помилку стає доступним у трасуванні workflow.
