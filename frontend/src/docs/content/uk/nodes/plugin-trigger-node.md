# Вузол Plugin Trigger

Вузол **Plugin Trigger** є тригерним аналогом
[вузла Plugin](./plugin-node.md). Він надається встановленим плагіном, чий
`kind` дорівнює `trigger`, і продукує початкові дані, з яких запускається workflow.

## Огляд

| Властивість | Значення |
|----------|-------|
| Входи | 0 |
| Виходи | 1 |
| Вихід | `$nodeLabel.<keys returned by the plugin>` |

Тригерний плагін може представляти будь-яке джерело — інший застосунок, сторонній
сервіс або іншу технологію — за умови, що обробник плагіна повертає дані,
з яких має починатися workflow.

## Коли використовувати

Використовуйте вузол Plugin Trigger, коли встановлений плагін визначає тригер, що запускає
Ваш workflow. Для плагінів, які виконують дію посеред workflow, натомість використовуйте
[вузол Plugin](./plugin-node.md).

## Конфігурація

Як і вузол Plugin, форма конфігурації генерується з полів маніфесту
плагіна. Несекретні рядкові поля використовують поле введення виразів, а секретні
поля маскуються.

## Як виконуються плагіни

Код плагінів є довіреним (постачається Heym, встановлюється оператором) і виконується в межах процесу.
Встановлення обмежено `HEYM_PLUGIN_ADMIN_EMAILS`, а підсистема
керується `HEYM_PLUGINS_ENABLED`. Див.
[Запуск і розгортання](../getting-started/running-and-deployment.md).

## Створення плагінів

Щоб створити пакет тригерного плагіна, див.
[Створення плагінів](../reference/plugin-authoring.md) щодо структури zip-архіву,
полів маніфесту, сигнатур обробників, іконок, залежностей і моделі довіри
під час виконання.
