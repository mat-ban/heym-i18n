# Постійна пам'ять агента

Вузли агентів можуть зберігати **граф знань для кожного вузла** у базі даних: сутності (з типами та властивостями) і зв'язки між ними. Коли цю функцію увімкнено, Heym **додає стислий виклад цього графа до системного prompt** під час кожного запуску (якщо граф не порожній). Після успішного запуску **завдання вилучення за допомогою LLM** у фоновому режимі об'єднує нові факти з розмови з графом.

Підагенти та оркестратори за замовчуванням використовують граф, прив'язаний до **їхнього власного вузла Canvas**. Ви також можете **надати іншим агентам доступ на читання або читання й запис** до графа цього вузла (зокрема агентам у **інших Workflow**, якими Ви володієте) — див. [Спільний доступ з іншими агентами](#sharing-with-other-agents).

## Увімкнення

| Параметр | Тип | Опис |
|-----------|------|-------------|
| `persistentMemoryEnabled` | boolean | Якщо `true`, граф цього вузла завантажується до системного prompt і планується вилучення після запуску для графа цього вузла |
| `memoryShares` | array (необов'язково) | Надає іншим вузлам агентів доступ до графа пам'яті **цього** вузла; див. [Спільний доступ](#sharing-with-other-agents) |

Увімкніть цю функцію у властивостях вузла агента (**Persistent memory (graph)**). Рожева іконка **мозку** на вузлі відкриває редактор графа, коли пам'ять увімкнено (або коли відображається модель).

## Редактор графа

У діалоговому вікні сутності відображаються як анімований граф із силовим розміщенням — кольорові кружечки, розмір яких залежить від кількості зв'язків, згруповані за типом сутності — а також засоби редагування та навігації (підгонка вигляду, упорядкування розмітки, комбінації клавіш). Ви можете **додавати, редагувати або видаляти** вузли та ребра вручну; засоби вибору зв'язків Source/Target підтримують пошук для графів із великою кількістю сутностей. Вибір вузла показує його вихідні та вхідні зв'язки, кожен з яких можна натиснути, щоб перейти до відповідного вузла. Зміни застосовуються лише до графа **цього** агента (графа вузла Canvas, мозок якого Ви відкрили).

## Спільний доступ з іншими агентами

У діалоговому вікні графа пам'яті пункт **Share memory with other agents** дає змогу приєднати **партнерів**, які можуть використовувати цей граф під час виконання:

1. Виберіть **Workflow** (будь-який Workflow, який Ви можете відкрити в редакторі).
2. Виберіть вузол **агента** в цьому Workflow.
3. Установіть **Read only** або **Read & write**.

| Дозвіл | Ефект |
|------------|--------|
| Read only | Коли запускається **партнерський** агент, цей граф додається до системного prompt партнера (якщо він має сутності). Вилучення до цього графа з запуску партнера не виконується. |
| Read & write | Така сама поведінка prompt, як і для читання, а після **успішного** завершення партнера звичайне вилучення пам'яті також може **об'єднати дані з цим (власницьким) графом**, використовуючи облікові дані запуску партнера. |

Партнери зберігаються для кожного вузла-власника як записи `memoryShares` з `peerWorkflowId` і `peerCanvasNodeId` (а також `permission`). У старіших Workflow поле `peerWorkflowId` може бути відсутнім для партнерів у **тому самому** Workflow; редактор трактує це як поточний Workflow.

**Спільний доступ між Workflow** визначається під час виконання шляхом сканування Workflow, якими **Ви володієте**. Запуски без контексту автентифікованого користувача визначають лише спільні доступи, визначені в JSON **поточного** Workflow (той самий Canvas).

## Поведінка під час виконання

### Власний граф (`persistentMemoryEnabled`)

1. **Перед викликом LLM** — Якщо граф має сутності, до системної інструкції додається блок, який пояснює, що це факти з попередніх запусків (можуть бути неповними; у разі конфлікту переважає поточне повідомлення користувача).
2. **Після успішного завершення** — Фонове завдання запитує в моделі (з тими самими обліковими даними, що й під час запуску агента) структурований JSON (сутності + зв'язки). Цей payload об'єднується з базою даних (для деяких типів застосовуються дедуплікація та очищення зв'язків, наприклад для ребер на кшталт зв'язків зайнятості).

### Партнер, який отримує спільні графи

Коли запускається агент, система знаходить вузли-**власники** (у будь-яких Ваших Workflow, коли це можливо), чиї `memoryShares` вказують на Workflow і вузол Canvas цього запуску. Для кожного збігу граф цього власника додається як розділ **shared memory** до системного prompt. Партнери з доступом **Read & write** додатково планують цілі вилучення для Workflow/графа **власника**, коли запуск завершується успішно.

Вилучення **не** виконується, якщо запуск завершується помилкою або переходить у стан очікування HITL.

## JSON Workflow (поле `data`)

Зберігається на вузлі агента, як і інші налаштування:

```json
{
  "type": "agent",
  "data": {
    "label": "supportAgent",
    "persistentMemoryEnabled": true,
    "userMessage": "$input.text",
    "memoryShares": [
      {
        "peerWorkflowId": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
        "peerCanvasNodeId": "agent-peer-canvas-id",
        "permission": "read"
      }
    ]
  }
}
```

`permission` має значення `"read"` або `"write"`. Опустіть `memoryShares` або використайте `[]`, якщо спільний доступ не потрібен.

Повну структуру об'єкта вузла див. у [Workflow Structure](./workflow-structure.md).
