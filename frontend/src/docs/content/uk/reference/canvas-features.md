Редактор Workflow надає кілька функцій для налагодження, тестування та впорядкування вузлів: **Run to Node**, **AI на вузлі**, **Data Pin**, **Execution Logs**, **Enable/Disable** та **Extract to Sub-Workflow**.

## Run to Node

Наведіть курсор на будь-який вузол, крім стікера, і натисніть **Run** під ним. Heym виконує цей вузол та його вихідні залежності, залишаючи нижчі вузли та не пов'язані гілки без змін. Це використовує режим тестування canvas, включно з закріпленими виходами та звичайними умовами гілок Workflow.

Якщо вибраний шлях має поля введення, права панель **Run** відкривається та фокусується на першому полі. Введіть значення, потім натисніть **Run to _node label_** або натисніть **Ctrl+Enter** (Cmd+Enter на macOS). Режим загального body фокусується на редакторі JSON body. Шляхи без полів введення виконуються негайно без відкриття панелі. Закріплені вузли Input повторно використовують свій закріплений вихід без запиту введення.

Панель зберігає вибрану ціль для наступних запусків. Виберіть **Run full workflow**, щоб очистити ціль. Кнопки Run вимкнені, поки виконання активне. Ціль всередині циклу зупиняє запуск, коли цей вузол досягається вперше; вибір вузла після циклу запускає повний вихідний цикл.

## AI на вузлі

Наведіть курсор на будь-який вузол, крім наліпки, і натисніть **AI** над ним. [AI Assistant](./ai-assistant.md) відкривається на цьому вузлі та пропонує **Change this node as ...**, **Fix error in this node ...** і **Other**. У режимі Agent асистент змінює лише цей вузол; інші вузли, з’єднання та макет залишаються без змін. Див. [AI Assistant › Зміна окремого вузла](./ai-assistant.md#changing-one-node).

Кнопка прихована у workflow, які доступні лише для перегляду.

## Data Pin

Data Pin дозволяє закріпити вихід вузла з останнього запуску, щоб ви могли тестувати нижчі вузли без повторного виконання закріпленого вузла.

### Де його знайти

- **Панель властивостей** – Виберіть вузол і прокрутіть до розділу **Pinned Data**
- **Бейдж вузла** – Іконка pin з'являється на вузлі, коли дані закріплені

### Дії

| Дія | Опис |
|--------|-------------|
| **Pin** | Закріплює вихід останнього виконання вузла (доступно після запуску) |
| **Clear** | Видаляє закріплені дані |
| **Edit** | Редагуйте закріплений JSON безпосередньо; натисніть Save, щоб застосувати |

### Поведінка в режимі тестування

Під час запуску Workflow у режимі тестування вузли з `pinnedData` пропускають виконання та використовують закріплений вихід. Використовуйте це, щоб:

- Тестувати нижчу логіку без виклику зовнішніх API
- Налагоджувати вирази, які посилаються на вихід вузла
- Ітерувати над Prompt або умовами з фіксованими зразками даних

Автодоповнення виразів у редакторі використовує закріплені дані, коли доступні, для пропонування полів.

## Execution Logs

**Панель Debug** (нижня шухляда) показує логи виконання в реальному часі під час запусків Workflow. Ви
також можете відкрити запущене production-виконання з діалогу History або картки Board. Редактор
приєднується до SSE-потоку цього запуску, відновлює результати завершених вузлів і продовжує
показувати анімації вузлів та логи, коли нові вузли запускаються та завершуються.

### Що він показує

- **Результати вузлів** – Статус кожного вузла (`success`, `error`, `skipped`, `running`), час виконання та вихід
- **Фінальні виходи** – Агреговані виходи з вузлів [Output](../nodes/output-node.md)
- **Прогрес Agent** – Для вузлів [Agent](../nodes/agent-node.md), покрокові виклики інструментів та міркування

### Дії

- **Copy as JSON** – Копіює повний лог виконання в буфер обміну
- **Open in JSON editor** – Відкриває лог у JSON Hero або JSON Editor Online для перевірки
- **Download generated files** – Якщо skill створив файли для завантаження (`_generated_files`), з'являється кнопка Download. Один файл завантажується безпосередньо; кілька файлів відкривають спливаюче вікно вибору.

### Відмінність від вкладки Logs

Панель Debug показує логи **виконання Workflow** (результати вузлів, виходи). [Вкладка Logs](../tabs/logs-tab.md) показує логи **Docker-контейнера** (backend, frontend, database). <!-- pragma: allowlist secret -->

## Enable / Disable

Ви можете вимкнути вузли, щоб вони пропускалися під час виконання. Вимкнені вузли показують бейдж "off" і виглядають затемненими.

### Як перемикати

| Метод | Опис |
|--------|-------------|
| **Панель властивостей** | Виберіть вузол → Іконка Power (верхній правий кут) |
| **Контекстне меню** | Клацніть правою кнопкою на вузлі(ах) → Disable або Enable |
| **Клавіатура** | Виберіть вузол(и) → натисніть **D** (див. [Keyboard Shortcuts](./keyboard-shortcuts.md)) |

### Множинний вибір

Коли вибрано кілька вузлів, Enable/Disable застосовується до всіх них. Контекстне меню показує "Enable", якщо будь-який вибраний вузол вимкнено, "Disable", якщо всі увімкнені.

### Поведінка під час виконання

Вузли з `active: false` пропускаються. Нижчі вузли не отримують даних від пропущених вузлів. Використовуйте це, щоб тимчасово виключити вузли без їх видалення.

Щоб увімкнути або вимкнути вузол зсередини Workflow, а не вручну, використовуйте [Disable Node](../nodes/disable-node.md) та [Enable Node](../nodes/enable-node.md).

## Граф пам'яті Agent

Вузли [Agent](../nodes/agent-node.md) з увімкненою **[persistent memory](./agent-persistent-memory.md)** показують рожевий елемент керування **brain** на вузлі. Натисніть його, щоб відкрити редактор графа пам'яті: entities відображаються як анімований граф із силовим розташуванням, згрупований за типом entity, із доступними для пошуку засобами вибору Source/Target для додавання зв'язків та панеллю connections для переходу між пов'язаними entities. Той самий діалог містить **Share memory with other agents** (workflow → agent → read або read/write) для [cross-agent memory sharing](./agent-persistent-memory.md#sharing-with-other-agents). Поки діалог відкрито, undo/redo основного полотна відкладається, щоб редагування графа вело власну історію.

**Фільтрування графа.** У верхньому лівому куті полотна є засіб керування пошуком, згорнутий до кнопки-скорочення, доки Ви не натиснете її або не натиснете **Ctrl/Cmd+F**. Він зіставляє назву entity, його тип та кожен ключ і значення атрибута, а також тип зв'язку (`parent_of`) та його властивості; знайдений зв'язок притягує обидва свої entities. Усі розділені пробілами терміни мають збігатися. Знайдений entity притягує все своє оточення — кожен зв'язок, у якому він бере участь, та entity з протилежного боку кожного з них — тож збіг ніколи не залишається непов'язаною точкою. Знайдений зв'язок притягує лише два entities, які він з'єднує, і на цьому зупиняється, оскільки пошук за типом зв'язку є питанням про цей зв'язок, а не про все, до чого приєднані його кінці. Усе інше повністю приховується — не приглушується — на полотні та в списку **All edges**, а бейдж показує, скільки із загальної кількості entities залишилося. **✕** усередині поля спершу очищає запит, а потім закриває поле при повторному натисканні. Escape розгортає той самий шлях, починаючи з найглибшого: очищає запит, потім закриває поле пошуку, потім виходить із розширеного подання полотна і закриває діалог лише тоді, коли жодне з них не відкрито. Очищення відновлює повний граф, повертаючи кожен entity на його місце.

**Розміщення entities вручну.** Перетягування entity закріплює його там, де Ви його відпустите, тож автоматичне розташування впорядковує решту графа навколо нього, а не повертає його назад. Перетягування вибраного entity переміщує разом із ним безпосередньо пов'язані entities, зберігаючи форму кластера; перетягування будь-якого іншого entity переміщує лише його. **Tidy layout** (кнопка з паличкою) звільняє кожен закріплений entity та повторно запускає автоматичне розташування.

## Extract to Sub-Workflow

Перетворює вибрані вузли на багаторазовий sub-workflow та замінює їх вузлом [Execute](../nodes/execute-node.md).

### Як використовувати

1. Виберіть один або кілька вузлів на полотні
2. Клацніть правою кнопкою → **Extract to Sub-Workflow**
3. Введіть назву (та необов'язковий опис) для нового workflow
4. Натисніть **Extract**

### Що відбувається

- Створюється новий workflow з вибраними вузлами
- Зовнішні входи (ребра з-поза меж вибраного) стають полями [Input](../nodes/input-node.md) sub-workflow
- Зовнішні виходи (ребра до вузлів поза межами вибраного) зіставляються з [Output](../nodes/output-node.md) sub-workflow
- Вибрані вузли замінюються одним вузлом [Execute](../nodes/execute-node.md), який викликає новий workflow
- Зіставлення входів/виходів зберігаються автоматично

### Варіанти використання

- Повторне використання послідовності вузлів у кількох workflows
- Спрощення складного workflow шляхом групування пов'язаної логіки
- Створення модульних sub-workflows, придатних для тестування

## Run with cURL

Кнопка **cURL** на панелі інструментів редактора (вгорі праворуч) відкриває діалог для створення та копіювання команди cURL для запуску workflow через API.

- Виберіть режим тіла запиту workflow (`Defined` або `Generic`)
- Задайте тип автентифікації (Anonymous, JWT або Header Auth)
- Налаштуйте кешування відповідей та обмеження швидкості
- Увімкніть або вимкніть SSE streaming та налаштуйте повідомлення про запуск для кожного вузла
- Відредагуйте тіло запиту
- У режимі Generic панель запуску на полотні використовує те саме необроблене тіло JSON, що й діалог cURL
- Натисніть **Copy cURL**, щоб скопіювати готову до виконання команду

Повні відомості про діалог дивіться в розділі [Webhooks](./webhooks.md#run-with-curl-dialog), а про протокол подій — у розділі [SSE Streaming](./sse-streaming.md).
