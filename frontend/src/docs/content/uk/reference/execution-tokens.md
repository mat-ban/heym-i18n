# Токени виконання

Токени виконання — це обмежені за областю дії JWT, які надають доступ до endpoint'ів execute та stream одного workflow. Вони дозволяють викликати workflow із зовнішніх систем без розкриття вашого довготривалого токена користувацької сесії.

## Навіщо використовувати токени виконання

Коли автентифікацію workflow встановлено як **JWT**, endpoint зазвичай вимагає дійсної користувацької сесії. Токени виконання дозволяють:

- Передавати викликаний токен зовнішнім скриптам, CI-конвеєрам або інтеграціям без передачі облікових даних вашого акаунта.
- Обмежити ризик — токен дійсний лише для одного конкретного workflow.
- Миттєво відкликати доступ без зміни пароля чи ротації токенів сесії.
- Обирати між короткоживучими токенами (хвилини або години) та довгоживучими токенами (до 10 років).

## Створення токена

Відкрийте діалог **Run with cURL** у редакторі (панель інструментів у верхньому правому куті). Коли автентифікацію workflow встановлено як **JWT Token**, діалог показує менеджер токенів:

1. Оберіть **Short-lived** або **Long-lived (10yr)**.
2. Для короткоживучих токенів введіть тривалість у секундах (мінімум 60).
3. Натисніть **+ New Token**.

Токен створюється негайно, додається до списку та автоматично вибирається, тож команда cURL оновлюється, щоб його включити.

## Список токенів

Кожен рядок токена показує:

| Стовпець | Опис |
|--------|-------------|
| Created | Мітка часу створення |
| Status | **Expires:** дата, **Expired** або **Revoked** |
| Eye icon | Перемикає видимість значення токена |
| Revoke button | Позначає токен як відкликаний (незворотно) |

Натисніть будь-який активний (не прострочений, не відкликаний) рядок, щоб його вибрати. Вибраний токен вбудовується в попередній перегляд команди cURL.

Прострочені та відкликані токени залишаються видимими в списку, але їх не можна вибрати.

## Використання токена

Скопіюйте значення токена зі списку (натисніть значок ока, щоб його показати) та включіть його як `Bearer`-токен:

```bash
curl -X POST \
  -H "Content-Type: application/json" \
  -H "X-Trigger-Source: my-service" \
  -H "Authorization: Bearer <execution-token>" \
  "https://app.heym.ai/api/workflows/{workflow_id}/execute" \
  -d '{"message": "Hello"}'
```

Коли ви використовуєте **Copy cURL** у діалозі з вибраним токеном, токен уже вбудований у команду — ручна заміна не потрібна.

## Область дії токена

Кожен токен містить такі JWT-твердження:

| Твердження | Значення |
|-------|-------|
| `sub` | ID користувача — творця токена |
| `wid` | UUID workflow — токен відхиляється для будь-якого іншого workflow |
| `scope` | `workflow:execute` — відрізняє його від токена користувацької сесії |
| `jti` | Унікальний ID токена, який використовується для пошуку під час відкликання |
| `exp` | Мітка часу закінчення терміну дії |

Бекенд перевіряє все це під час кожного запиту: дійсність підпису, термін дії, відповідність `wid` та те, що `jti` не було відкликано.

## Відкликання

Натисніть кнопку відкликання (коло з рискою) поруч із токеном, щоб його відкликати. Відкликання набуває чинності негайно — наступні запити з використанням цього токена повертають `401`. Рядок токена залишається видимим у списку з позначкою **Revoked**.

Скасувати відкликання неможливо. Створіть новий токен, якщо потрібно відновити доступ.

## API

Endpoint'и керування токенами автентифікуються вашою звичайною сесією.

| Метод | Шлях | Опис |
|--------|------|-------------|
| `POST` | `/api/workflows/{id}/execution-tokens` | Створити токен |
| `GET` | `/api/workflows/{id}/execution-tokens` | Показати ваші токени для цього workflow |
| `DELETE` | `/api/workflows/{id}/execution-tokens/{token_id}` | Відкликати токен |

**Тіло запиту на створення:**

```json
{ "ttl_seconds": 900 }
```

**Відповідь на створення:**

```json
{
  "id": "uuid",
  "token": "<full jwt>",
  "expires_at": "2026-04-30T15:22:00Z",
  "created_at": "2026-04-30T15:07:00Z",
  "revoked": false
}
```

Поле `token` повертається лише один раз під час створення. Збережіть його негайно; наступні запити `GET` повертають той самий рядок, але ви також можете будь-коли показати його в діалозі cURL.

## Область видимості

Кожен користувач бачить лише створені ним токени. Члени команди з доступом до спільного workflow не бачать токенів одне одного.
