# Діалог обчислення виразів

Діалог обчислення виразів — це розширений редактор для полів, що підтримують вирази. Він відкривається за допомогою кнопки розгортання поруч із полем введення виразу та надає Вам більший робочий простір, автодоповнення, попередній перегляд у реальному часі від бекенду та перегляд виводу в одному місці.

## Відкриття діалогу

- Натисніть кнопку розгортання поруч із полем виразу на панелі властивостей.
- Багаторядкові поля показують кнопку всередині поля введення.
- Однорядкові поля показують кнопку праворуч від поля введення.

## Структура діалогу

- Діалог відкривається як центроване модальне вікно розміром приблизно **80vw × 80vh**.
- У заголовку відображається **Evaluate — {field name}**, коли мітка поля відома.
- Редактор зберігає автодоповнення, навігацію між полями та звичайні дії **Apply** / **Cancel**.
- Попередній перегляд оновлюється автоматично приблизно через **300 мс** після того, як Ви припините вводити текст.
- Натисніть `Ctrl` / `Cmd` + `Enter`, щоб застосувати поточний текст до поля та закрити діалог (те саме, що й **Apply**).

## Розділ виводу

Область виводу оновлюється автоматично після того, як Ви призупините введення тексту в редакторі.

### Обчислення

| Тип виразу | Результат |
|---|---|
| Одиничний `$expr` (усе поле) | Власне значення зберігається |
| Одиничний голий шлях із точкою (усе поле, без `$`, без вбудованого символу нового рядка) | Те саме, що `$` + цей шлях (бекенд нормалізує для обчислення) |
| Текст із вбудованими `$refs` | Кінцевий результат завжди є рядком |
| Літеральний текст (без `$`, не одиничний шлях із точкою) | Повертається як є |

**Приклади**

| Вхідні дані | Результат |
|---|---|
| `$input.items` | `[1, 2, 3]` |
| `input.items` (те саме, що `$input.items`, коли все значення є цим шляхом) | `[1, 2, 3]` |
| `Hello $input.name` | `Hello John` |
| `$input.count + 1` | `6` |
| `just text` | `just text` |

Контекст обчислення будується в такому порядку:

- **Закріплені дані** на вузлах вище за потоком
- **Виводи останнього запуску** з Canvas
- `null`, коли дані вище за потоком недоступні

Якщо поточний вузол має залежності вище за потоком, але жодна з них не має закріплених даних або результату останнього запуску, діалог спочатку виконує тестовий запуск для побудови контексту, а потім обчислює поточний текст.

### Вибір шляху виводу

Коли результат бекенду є об'єктом або масивом, область виводу може показувати інтерактивний вибір шляху замість необробленого JSON.

- Двічі натисніть на рядок, щоб додати цей шлях до поточного посилання `$node.path`.
- Одноразово натисніть на рядки, що розгортаються, щоб відкрити або закрити гілки.
- Скористайтеся вбудованим полем пошуку для пошуку ключів, значень і рядків шляхів.

## Автодоповнення

- Введіть `$`, щоб відкрити підказки для вузлів вище за потоком, вбудованих функцій і методів.
- Натисніть `Tab` або `Enter`, щоб вставити вибрану підказку.
- Використовуйте `↑` / `↓` для переміщення списком підказок.

### Приклади відповідей

Коли Ви продовжуєте посилання `$…` точкою, кожен рядок підказки показує відповідь, яку ця підказка видасть, жирним шрифтом праворуч від рядка.

- Введення `$set.listItems.first().toString().u` показує список `upper`, `urlEncode`, `urlDecode` та `unescape`, кожен з обчисленим результатом — тож Ви можете обирати за результатом, а не за назвою.
- Введення `$node.text.toJson()` розбирає рядок JSON в об'єкт або масив. Після `.toJson()` автодоповнення може запропонувати розібрані ключі (наприклад, `repoUrl`), коли доступні виводи останнього запуску або закріплені дані.
- Результати обчислюються на бекенді на основі тих самих закріплених даних і виводів останнього запуску, які використовує попередній перегляд діалогу, тож вони відповідають тому, що видасть поле.
- Обчислюються лише підказки, що є самодостатніми: методи без аргументів (`upper()`, `first()`, `keys()`, `toJson()`) та звичайні властивості (`length`, `year`). Підказки, які спершу потребують аргументів — `map`, `filter`, `sort`, `replace` — залишаються порожніми.
- Рядок залишається порожнім, коли кандидат не видає відповіді: помилка, `null` або метод, що не застосовується до цього значення.
- Відповіді скорочуються до одного рядка. Наведіть курсор на скорочену відповідь, щоб побачити більше.

## Створення за допомогою AI

Кнопка **Build with AI** з'являється у верхньому правому куті діалогу обчислення, коли завантажено Workflow. Вона відкриває вкладене модальне вікно, де Ви можете описати бажаний вираз звичайним текстом і доручити LLM згенерувати його для Вас.

### Як це працює

1. Натисніть **Build with AI** на панелі інструментів діалогу обчислення.
2. Виберіть облікові дані LLM і модель із випадаючих списків.
3. Введіть опис бажаного звичайним текстом — наприклад, *"Get the customer name from the API response"*.
4. Натисніть **Generate**. Модальне вікно звертається до бекенду, який використовує системний Prompt [Expression DSL](./expression-dsl.md) разом із виводами останнього запуску Вашого Workflow як контекст, і повертає один рядок виразу.
5. Згенерований вираз негайно обчислюється на основі тих самих даних Canvas, тож Ви можете побачити результат перед застосуванням.
6. Натисніть **Apply**, щоб замінити вміст редактора згенерованим виразом, або **Regenerate**, щоб спробувати знову.

### Використаний контекст

Генератор отримує виводи вузлів з останнього тестового запуску на Canvas. Якщо Workflow ще не запускався, LLM генерує вираз за найкращою спробою на основі міток вузлів і домовленостей DSL.

### Вимоги

- Облікові дані LLM (OpenAI, Google або Custom) мають бути налаштовані на вкладці [Credentials](./credentials.md).
- Workflow має бути відкритий у редакторі.

## Комбінації клавіш

| Комбінація | Дія |
|---|---|
| Пауза в введенні (~300 мс) | Оновити попередній перегляд від бекенду |
| `Ctrl` / `Cmd` + `Enter` | Застосувати та закрити діалог |
| `Escape` | Спочатку закрити автодоповнення, інакше закрити діалог |
## Вкладені `$` у аргументах методів

Для діалогового / бекенд-оцінювання можна передати інше посилання з вкладеним `$` у викликах на кшталт `.get($other.field)`, коли потрібен динамічний ключ. Також можна використати голий шлях усередині `.get(...)` (наприклад, `other.field`); бекенд розпізнає його так само. Збережені поля workflow мають і надалі відповідати правилам [Expression DSL](./expression-dsl.md); evaluate API також приймає повний голий dot-шлях у рядку для зручності (див. таблицю вище).

## Навігація

Редактори мапінгу Set і Execute можуть показувати кнопки **Prev** / **Next**, щоб переміщатися між полями, не закриваючи діалог.
