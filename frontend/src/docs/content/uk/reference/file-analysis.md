# Аналіз файлів

Аналіз файлів дозволяє Chat, [вузлу Agent](../nodes/agent-node.md) та [вузлу Code](../nodes/code-node.md) відкривати та аналізувати великі файли з [Drive](./drive.md) в ізольованому пісочнику (sandbox) Python. Файли PDF, електронні таблиці, CSV, DOCX та JSON спочатку перевіряються, а потім вибірково зчитуються, тому договір на 200 сторінок або книга з мільйоном рядків ніколи не повинні повністю поміщатися в контекст моделі.

## Як це працює

Кожен виклик виконується в новому контейнері без доступу до мережі. Необхідні файли копіюються в режимі лише для читання, код виконується, а контейнер видаляється. Невелика робоча папка зберігається між викликами однієї сесії, що дозволяє пізнішому кроку продовжувати роботу з результатів, збережених попереднім кроком.

| Шлях | Вміст |
|------|--------|
| `/input` | Файли Drive цієї сесії, лише для читання |
| `/work` | Робочий простір, що зберігається протягом сесії, наприклад `/work/sales.pkl` |
| `/work/out` | Файли, записані сюди, зберігаються в Drive після виклику і повертаються як посилання |

У sandbox попередньо встановлено pandas, openpyxl, xlrd, pdfplumber, pypdf, python-docx та langdetect, а також Tesseract OCR, який використовується [вузлом Конвертер](../nodes/converter-node.md).

## Інструменти

Модель працює з трьома інструментами, а також четвертим у Chat:

| Інструмент | Функція |
|------|----------|
| `list_files` | Перелічує файли Drive, які ви можете відкрити: назва, тип, розмір, дата |
| `inspect_file` | Повертає тип, метадані та структуру файлу з коротким зразком |
| `run_python` | Запускає Python на вказаних файлах і повертає консольний вивід |
| `clear_workspace` | Тільки Chat: видаляє робочу папку розмови |

`inspect_file` зчитує лише те, що необхідно для підсумку:

| Тип | Підсумок |
|-----|-----------------|
| PDF | Кількість сторінок, назва та автор, можливість вилучення тексту, мова, розміри сторінок, текст і таблиці першої сторінки. Відскановані PDF зчитуються за допомогою OCR (до 5 сторінок) |
| XLSX / XLS | Аркуші з кількістю рядків і стовпців, рядки заголовків, типи, pandas `read_hint`, іменовані діапазони, перші рядки |
| CSV / TSV | Кодування, роздільник, кількість рядків, стовпці з типами, перші рядки |
| DOCX | Структура заголовків, таблиці, кількість слів і символів, автор і дата |
| JSON | Кореневий тип, ключі, довжина масиву, глибина вкладеності, зразки записів |

Усередині `run_python` відкрийте файл за допомогою модуля `heym_files`:

```python
import heym_files
import pandas as pd

df = pd.read_excel(heym_files.path("q3.xlsx"), sheet_name="Summary", usecols=["Region", "Amount"])
print(df.groupby("Region").Amount.sum())
df.to_csv(f"{heym_files.out_dir()}/by-region.csv", index=False)
```

## У Chat

Прикріплюйте файли PDF, електронні таблиці, DOCX, CSV або JSON, зображення (PNG, JPG, GIF, WebP) або звичайні текстові файли на [вкладці Chat](../tabs/chat-tab.md), у Heym Work Chat або через інструмент MCP `heym_chat`. Одне повідомлення може містити до 10 файлів. Кожен файл зберігається у вашому Drive; лише його назва та ID потрапляють у повідомлення. Chat перевіряє файл, читає частину, необхідну для вашого запитання, і відповідає таблицями або витягами.

## У workflow

Запуск відкриває лише власні файли: ті, що завантажені через [Trigger завантаження файлів](../nodes/file-upload-trigger-node.md), ті, які його вузли записали в Drive, і ті, які [вузол Drive](../nodes/drive-node.md) отримав за допомогою кроку **Get** у тому самому запуску.

- **Вузол Agent**: якщо вхідні дані або повідомлення агента містять файл, він автоматично отримує вищезазначені інструменти для цих файлів.
- **Вузол Code**: встановіть **Files** на вираз, наприклад `$Upload.file.id`. Файли монтуються та перелічуються в `params.files`.

## Обмеження

| Обмеження | Значення |
|-----------|------|
| Пам'ять на виклик | 2 GB |
| Час на виклик | 120 секунд |
| Робоча папка на сесію | 2 GB |
| Вихідні файли на виклик | 20, до 100 MB кожен |
| Друкований вивід, що повертається моделі | 20 000 символів |
| Файли на виклик | 20 |

## Безпека

- Sandbox не має доступу до мережі, не має доступу до налаштувань чи секретів Heym і працює як непривілейований користувач.
- Файли обробляються виключно всередині sandbox.
- У Chat доступ відповідає Drive: ви відкриваєте власні файли та файли, спільні з вашими командами.
- Відкриття файлу в Chat фіксується в журналі аудиту.
- Вміст файлів розглядається суто як дані; інструкції всередині файлів не виконуються.

## Вимоги

Аналіз файлів вимагає бекенду sandbox на екземплярі Heym (Docker або [Kubernetes](../getting-started/running-and-deployment.md#kubernetes)).
