# Guardrails

Guardrails дають змогу блокувати небезпечні або небажані повідомлення користувачів, перш ніж вони досягнуть вузла [LLM](../nodes/llm-node.md) або [Agent](../nodes/agent-node.md). Коли повідомлення відповідає заблокованій категорії, вузол замість виконання викликає помилку, яку можна перехопити за допомогою вузла [Error Handler](../nodes/error-handler-node.md).

## Увімкнення Guardrails

Відкрийте панель властивостей для вузла **LLM** або **AI Agent** та прокрутіть до перемикача **Enable Guardrails** (іконка щита). Позначення прапорця відкриває розділ налаштування.

## Облікові дані та модель для Guardrail

Коли guardrails увімкнено, **необхідно** вибрати **облікові дані та модель** для перевірки безпеки вмісту. Перевірка guardrail використовує вибрані облікові дані та модель із вузла — без резервного варіанта, без змінних середовища. Використовуйте облікові дані OpenAI або Google для надійної фільтрації вмісту, особливо якщо Ваша основна модель використовує власного провайдера (наприклад, Zhipu, GLM), який може не підтримувати guardrails або повертає помилки API (наприклад, 404).

Workflow не може запуститися, доки не вибрано і Guardrail Credential, і Guardrail Model.

## Заблоковані категорії

Виберіть одну або кілька категорій для блокування. Повідомлення, що відповідає будь-якій позначеній категорії, відхиляється.

| Категорія | Що блокується |
|---|---|
| **Violence** | Насильницький, загрозливий або фізично шкідливий вміст |
| **Hate Speech** | Дискримінація, расизм або фанатизм |
| **Sexual Content** | Відвертий сексуальний вміст або сценарії |
| **NSFW / Profanity** | Груба лексика, нецензурні вирази, відверті образи та дорослий сленг будь-якою мовою |
| **Self-Harm** | Самогубство, самоушкодження або пов'язаний вміст |
| **Harassment** | Особисті напади, образи, цькування або залякування |
| **Illegal Activity** | Інструкції щодо вчинення протиправних дій |
| **Political Extremism** | Екстремістський політичний вміст або насильницька пропаганда |
| **Spam / Phishing** | Спам, фішинг або соціальна інженерія |
| **Personal Data Request** | Вимагання приватної або особисто ідентифікованої інформації |
| **Prompt Injection** | Спроби перевизначити системні інструкції, впровадити шкідливі prompt або маніпулювати поведінкою моделі |

## Чутливість

Налаштування **Sensitivity** визначає, наскільки суворо виявляються порушення:

| Рівень | Поведінка |
|---|---|
| **Low** | Позначає навіть прикордонні або неоднозначні випадки |
| **Medium** *(за замовчуванням)* | Позначає явні порушення; ігнорує прикордонні випадки |
| **High** | Позначає лише крайні, однозначні порушення |

## Як працює виявлення

Виявлення використовує **вибрані облікові дані та модель guardrail**:

- **Облікові дані OpenAI** — використовує [OpenAI Moderation API](https://platform.openai.com/docs/guides/moderation) (безкоштовно, швидко, без витрат token) для п'яти категорій, які вона підтримує нативно (Violence, Hate Speech, Sexual Content, Self-Harm, Harassment). Решта категорій перевіряється за допомогою класифікаційного виклику LLM із використанням вибраної моделі guardrail.
- **Облікові дані Google / власні** — усі категорії перевіряються за допомогою класифікаційного виклику LLM із використанням вибраних облікових даних і моделі guardrail.

Коли Ваша основна модель використовує власного провайдера (наприклад, Zhipu, Cerebras), який може повертати 404 або інші помилки API, виберіть **облікові дані OpenAI або Google** для guardrails.

## Формат помилки

Коли спрацьовує guardrail, вузол викликає помилку з повідомленням:

```
Guardrail violation: message blocked due to prohibited content.
Violated categories: Violence, Hate Speech
```

Поле `output` результату вузла також містить `guardrail_violated_categories` (масив міток порушених категорій), щоб Debug Panel та Execution History могли чітко відображати "Blocked by: X, Y".

Використовуйте опцію вузла **Continue on error** (або [Error Handler](../nodes/error-handler-node.md)), щоб спрямувати workflow до резервної гілки, коли спрацьовують guardrails.

## Приклад Workflow

```
Input → Agent (guardrails: Violence, Illegal Activity, severity: Medium)
          ├── output handle → LLM → Output
          └── error handle  → Error Handler → Set("Sorry, that request was blocked.") → Output
```

## Примітки

- **Без повторних спроб**: порушення guardrail є навмисними блокуваннями і ніколи не повторюються, навіть якщо для вузла увімкнено "Retry on failure".
- Міграція бази даних не потрібна — налаштування guardrail зберігаються в JSON вузла workflow разом з іншими даними вузла.
- Guardrails перевіряють обчислене **повідомлення користувача** (після обчислення виразів шаблону), а не сирий шаблон.
- Встановлення **жодної категорії** при увімкнених guardrails еквівалентне їх вимкненню — перевірка не виконується.
- За **Low** чутливості класифікація LLM виконується завжди (найкраще багатомовне покриття). Облікові дані OpenAI додатково запускають Moderation API.
- За **Medium/High** чутливості облікові дані OpenAI використовують Moderation API для нативно підтримуваних категорій і класифікацію LLM для решти. Облікові дані Google/власні завжди використовують класифікацію LLM.
- Класифікація LLM є **мовно-агностичною** — вона виявляє порушення турецькою, арабською, російською, іспанською та іншими мовами.
