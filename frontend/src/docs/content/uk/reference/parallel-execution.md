# Паралельне виконання

Heym виконує вузли паралельно, коли вони не мають взаємних залежностей, а також дозволяє одночасне виконання кількох запусків workflow.

## У межах одного запуску

### Планування на основі DAG

Виконавець групує вузли за **рівнями виконання**, використовуючи спрямований ациклічний граф (DAG):

1. **Рівень 0** – вузли без вхідних ребер (початкові вузли)
2. **Рівень N** – вузли, всі висхідні залежності яких розташовані на рівнях 0..N-1

Вузли одного рівня не мають взаємних залежностей і виконуються паралельно.

### Пул потоків

- **Спільний пул**: `ThreadPoolExecutor(max_workers=8)` для виконання вузлів
- **Планування**: `wait(..., return_when=FIRST_COMPLETED)` – щойно будь-який вузол завершується, плануються наступні вузли
- **Потокобезпечність**: вихідні дані вузлів зберігаються з використанням блокування (`store_node_output`)

### Субагенти оркестратора

Коли агент-оркестратор повертає кілька викликів інструменту `call_sub_agent` за один хід, вони виконуються паралельно. Див. [Архітектура агента](./agent-architecture.md).

### Вузол Merge

Вузол [Merge](../nodes/merge-node.md) об'єднує вихідні дані з кількох паралельних гілок. Використовуйте його, коли потрібно явно об'єднати результати; інакше паралельні гілки можуть завершуватися окремими вихідними вузлами.

### Цикли

Ітерації циклу виконуються **послідовно**. Вузли тіла циклу переплановуються на кожній ітерації.

### Дострокове повернення

Вихідні вузли з `allowDownstream` можуть повертати результат достроково. Решта наступної роботи виконується у фоновому режимі.

## Одночасні запуски workflow

- **Без блокування на рівні workflow** – Кілька запитів можуть виконувати той самий workflow одночасно
- **Асинхронний API** – Endpoint-и FastAPI використовують `asyncio.to_thread(execute_workflow)`, тому цикл подій залишається чутливим
- **Ізоляція** – Кожен запуск отримує власний екземпляр `WorkflowExecutor` та власний стан

Trigger-и, які запускають workflow ([Webhook](./webhooks.md), [Portal](./portal.md), [Cron](./triggers.md), RabbitMQ, MCP, Editor), кожен незалежно викликає `execute_workflow`.

## Стрімінг

Стрімінг використовує ту саму паралельну модель, але надсилає події в міру завершення вузлів. Редактор і чат-інтерфейс порталу внутрішньо використовують стрімінг для відображення прогресу в реальному часі, а користувачі webhook тепер можуть долучитися до того самого потоку подій через endpoint виконання [SSE Streaming](./sse-streaming.md).
