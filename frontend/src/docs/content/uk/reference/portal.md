# Portal

**Portal** надає доступ до Workflow Heym як до публічних чат-інтерфейсів. Кінцеві користувачі можуть запускати Workflow за URL-адресою без входу в Heym.

## Що це робить

- **Публічна URL-адреса**: `/chat/{slug}` (наприклад, `/chat/my-workflow`)
- **Чат-інтерфейс**: Користувачі взаємодіють через чат-інтерфейс (повідомлення, введення, відповіді)
- **Необов'язкова автентифікація**: Якщо налаштовано користувачів Portal, потрібен вхід; інакше Portal є публічним
- **Стрімінг**: Прогрес виконання вузлів у реальному часі (якщо увімкнено)
- **Зупинка виконань, що виконуються**: Користувачі можуть зупинити активне виконання Portal з нижнього колонтитула чату; активне виконання Workflow також скасовується на сервері
- **Завантаження файлів**: Необов'язкове завантаження файлів (текст, зображення тощо) для кожного поля введення
- **Передача на людський розгляд**: Виконання Portal можуть надавати [посилання на розгляд HITL](./human-in-the-loop.md), коли агент зупиняється для затвердження
- **Відображення зображень**: Результати Workflow, що містять зображення (наприклад, від генерації зображень LLM або скріншотів Playwright), відображаються як мініатюри в чаті. Натисніть на будь-яке зображення, щоб відкрити повноекранний перегляд; натисніть **Esc** або скористайтеся кнопкою "Назад" на пристрої, щоб закрити

## Конфігурація Workflow

| Налаштування | Опис |
|---------|-------------|
| `portal_enabled` | Увімкнути Portal для цього Workflow |
| `portal_slug` | URL-ідентифікатор (наприклад, `my-workflow` → `/chat/my-workflow`) |
| `portal_stream_enabled` | Використовувати потокове виконання |
| `portal_file_upload_enabled` | Дозволити завантаження файлів |
| `portal_file_config` | Конфігурація файлів для кожного поля (типи, обмеження) |

Налаштування в редакторі: Кнопка **Portal** у заголовку Workflow відкриває діалог налаштувань Portal.

## Потік

1. **Інформація**: `GET /api/portal/{slug}/info` – Повертає метадані Workflow та поля введення (без автентифікації)
2. **Вхід** (якщо потрібно): `POST /api/portal/{slug}/login` – Повертає Token сесії
3. **Виконання**: `POST /api/portal/{slug}/execute` – Чат-інтерфейс Portal викликає цей Endpoint (або його потоковий варіант внутрішньо, якщо увімкнено); кінцеві користувачі взаємодіють через чат-інтерфейс, а не викликаючи API безпосередньо.
4. **Зупинка**: `POST /api/portal/{slug}/executions/{execution_id}/cancel` – Викликається, коли користувач натискає **Stop** під час активного виконання Portal

## HITL у виконаннях Portal

Якщо Workflow Portal досягає [Вузла агента](../nodes/agent-node.md) з увімкненим [Human-in-the-Loop](./human-in-the-loop.md), відповідь Portal показує посилання на розгляд замість порожньої відповіді.

- Статус виконання Workflow стає `pending`
- Чат Portal відображає URL-адресу розгляду
- Будь-які вузли, підключені до виходу `review` агента, можуть негайно сповіщати Slack, електронною поштою або іншими каналами
- Рецензент завершує рішення на `/review/{token}` без входу
- Після розгляду Workflow відновлюється зі збереженого знімка

Це дозволяє поєднувати публічні чат-потоки з приватними кроками затвердження людиною.

## Поля введення

Поля введення походять від вузлів [Input](../nodes/input-node.md). API витягує початкові вузли типу `textInput` та їхні `inputFields`. Виконання використовує той самий рушій, що й звичайні запуски; введення передаються як `body.inputs` та `conversation_history` для багатокрокових потоків.

## Автентифікація та сесії

- **WorkflowPortalUser**: Ім'я користувача/пароль для кожного Workflow (коли автентифікація увімкнена)
- **Видалення останнього користувача**: Якщо портал увімкнено, видалення останнього користувача порталу робить портал знову загальнодоступним; діалогове вікно налаштувань спочатку запитує підтвердження
- **PortalSession**: Token сесії з TTL 168 годин
- **Обмеження швидкості**: 3 невдалі спроби входу → 24-годинний бан для кожного Workflow+IP
- Прострочені сесії очищуються за допомогою завдання Cron

## Інтерфейс конфігурації

Вкладки **WebPortalSettingsDialog**:

1. **Загальні**: Увімкнути Portal, встановити slug, скопіювати URL-адресу Portal
2. **Користувачі**: Додати/видалити користувачів Portal (ім'я користувача/пароль)
3. **Опції**: Режим стрімінгу, завантаження файлів, перегляд полів введення
