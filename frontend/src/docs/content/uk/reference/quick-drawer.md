# Швидка панель

**Швидка панель** — це бічна права панель швидкого запуску для workflow. Вона відображається на сторінках, що потребують автентифікації, зокрема на вкладці [Workflows](../tabs/workflows-tab.md) панелі керування, у розділі Docs та в розділі Оцінювання.

## Доступ

- Натисніть фіксований тригер **Quick / Workflows** на правому середньому краї екрана
- Якщо також доступний [Контекстний покажчик](./contextual-showcase.md), його тригер **Page Guide** розташований над Quick Workflows
- Панель відкривається справа та зсуває поточну сторінку ліворуч із легким масштабуванням
- На мобільних пристроях Швидка панель прихована
- Панель не відображається в редакторі workflow, на сторінках входу/реєстрації, порталу або перевірки HITL

## Пошук workflow

Скористайтеся полем фільтра вгорі панелі, щоб шукати workflow за:

- Назвою workflow
- Описом workflow

Пошук не чутливий до регістру та оновлює список негайно.

## Закріплені workflow

Закріплюйте workflow, щоб утримувати їх угорі панелі.

- Закріплені workflow відображаються в окремому розділі над повним списком
- Нові закріплення додаються вгору
- Порядок закріплень зберігається між перезавантаженнями у сховищі браузера

## Запуск workflow

Виберіть workflow, щоб відкрити його форму введення.

- Поля введення відображаються вертикально в порядку панелі
- Натисніть **Run Workflow**, щоб виконати вибраний workflow
- Натисніть **Stop Workflow**, щоб скасувати виконання, що триває, з панелі
- Workflow без полів введення також можна запускати безпосередньо
- Workflow, який починається з [File Upload Trigger](../nodes/file-upload-trigger-node.md), натомість показує зону перетягування: перетягніть туди файл або натисніть, щоб вибрати його. У зоні вказано типи й розмір файлів, які приймає trigger, а інші файли відхиляються ще до завантаження. Кнопка **Run Workflow** залишається неактивною, доки файл не вибрано.

Панель використовує той самий API виконання workflow, що й інші поверхні запуску Heym, тому вихідні дані та поведінка під час виконання залишаються узгодженими.

Зупинка запуску з панелі також скасовує активне виконання на бекенді, зокрема будь-яке завдання браузера Playwright у процесі виконання для цього запуску workflow.

## Перебіг і результати

Після запуску панель показує:

- Потоковий перебіг кроків для вузлів у міру їх запуску та завершення
- Фінальний статус: `success`, `error` або `pending`
- Фінальні вихідні дані в компактній панелі JSON
- Записи в Історії з позначкою `Quick Drawer`

`pending` означає, що workflow очікує на подальшу дію, як-от перевірку людиною.

Запуски зі Швидкої панелі (Quick Drawer) є виробничими запусками, тому workflow із [лімітом одночасності](./webhooks.md#concurrency-limit-and-queued-runs) може змусити їх чекати. Поки запуск перебуває в черзі, статус відображає **Waiting in queue (2/5)**; він змінюється на "running", коли запуск починається, і показує результат після завершення без покрокового перебігу. Запуск, термін очікування якого минув у черзі або який було скасовано під час очікування, завершується зі статусом `error`.

Запуск із файлом відбувається через одноразове посилання для завантаження trigger: панель запитує у workflow посилання, завантажує туди файл і показує результат після завершення завантаження. Запуски з файлом показують кінцевий статус і вихідні дані без покрокового прогресу та також позначаються тегом `Quick Drawer` в історії. Вибраний файл очищується після кожного запуску, оскільки одне посилання приймає лише один файл.

## Сховище браузера

Швидка панель зберігає особисті налаштування в `localStorage`:

- Ідентифікатори закріплених workflow
- Останній вибраний workflow

У цій версії панель **не** зберігає введені значення.

## Обсяг

Швидка панель навмисно є легкою поверхнею виконання.

- Включено: пошук, закріплення, вибір, введення (зокрема файлу), запуск, перебіг, результат
- Виключено: створення workflow, редагування, керування теками та дії на Canvas
