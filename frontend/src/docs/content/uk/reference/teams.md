# Команди

Команди дають змогу одночасно надавати спільний доступ до workflow, облікових даних, глобальних змінних, векторних сховищ і файлів Drive для групи користувачів.

## Огляд

- **Команда** – Іменована група з творцем і учасниками
- **Творець** – Завжди є учасником; може редагувати команду, видаляти команду, додавати учасників
- **Учасник** – Може додавати й видаляти інших учасників (крім творця); має доступ до ресурсів, наданих команді

## Створення команд і керування ними

Створюйте команди на вкладці [Команди](../tabs/teams-tab.md). Додавайте учасників за електронною поштою; вони повинні мати обліковий запис. Творця не можна видалити. Видалення команди скасовує всі надання доступу, пов'язані з командою.

## Модель надання спільного доступу

Спільний доступ до ресурсів можна надавати:

1. **Окремим користувачам** – За електронною поштою (надання доступу між користувачами)
2. **Командам** – Вибравши команду (надання доступу команді)

Обидві моделі діють додатково. Користувач отримує доступ, якщо він:

- Має прямий спільний доступ (надання доступу користувачу), або
- Є учасником команди, якій надано спільний доступ

## Що можна надавати командам

| Ресурс | Місце надання доступу |
|----------|----------------|
| Workflows | Діалог надання доступу в редакторі workflow |
| Шаблони workflow | Діалог надання доступу під час створення/редагування шаблону workflow |
| Шаблони вузлів | Діалог надання доступу під час створення/редагування шаблону вузла |
| Облікові дані | Діалог надання доступу на вкладці «Облікові дані» |
| Глобальні змінні | Діалог надання доступу на вкладці «Змінні» |
| Векторні сховища | Діалог надання доступу на вкладці «Вектори» |
| Файли Drive | Діалог надання доступу на вкладці «Drive» або операції вузла Drive `shareWithMyTeams` / `unshareWithMyTeams` |

Для шаблонів, коли видимість встановлено як **Конкретні користувачі**, також можна вибирати команди. Усі учасники вибраних команд отримують доступ до шаблону.
Надання спільного доступу до файлів Drive для команд є доступним лише для читання для учасників команди; власник файлу зберігає права на керування.

## Endpoint-и API

- `GET /api/teams` – Перелік команд, до яких належить користувач
- `GET /api/teams/{id}` – Отримати відомості про команду з учасниками
- `GET /api/teams/{id}/shared-entities` – Повертає об'єкти, надані команді (workflow, облікові дані, глобальні змінні, векторні сховища, файли, шаблони workflow, шаблони вузлів)
- `POST /api/teams` – Створити команду
- `PATCH /api/teams/{id}` – Оновити команду
- `DELETE /api/teams/{id}` – Видалити команду (лише творець)
- `POST /api/teams/{id}/members` – Додати учасника (тіло: `{ "email": "..." }`)
- `DELETE /api/teams/{id}/members/{user_id}` – Видалити учасника

Надання доступу команді для кожного ресурсу:

- `GET/POST/DELETE /api/workflows/{id}/team-shares` – тіло POST приймає `permission` (`read` або `write`, типово `write`); повторне надсилання наявної команди оновлює її дозвіл
- `GET/POST/DELETE /api/credentials/{id}/team-shares`
- `GET/POST/DELETE /api/global-variables/{id}/team-shares`
- `GET/POST/DELETE /api/vector-stores/{id}/team-shares`
- `PATCH /api/files/{id}/team-sharing`
