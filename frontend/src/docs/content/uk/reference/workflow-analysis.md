# Аналіз Workflow

**Аналіз Workflow** — це бічна панель, яка містить один спільний редагований Markdown-документ для кожного workflow. Використовуйте її, щоб пояснити, що робить workflow, та фіксувати ідеї щодо вдосконалення — а також дозвольте AI згенерувати для Вас перший чернетковий варіант.

Документ є спільним: кожен, хто має доступ до workflow, може читати та редагувати його. Він зберігається разом із workflow і видаляється автоматично, коли workflow видаляється.

## Відкриття панелі

1. Відкрийте workflow у редакторі.
2. Натисніть **Analyze** (іконка Sparkles) на панелі інструментів редактора.
3. Панель відкриється ліворуч. Палітра вузлів (ліва панель) згортається, поки вона відкрита; повторне відкриття палітри вузлів закриває панель аналізу.

Панель доступна лише для збережених workflow. Для абсолютно нового незбереженого workflow спочатку збережіть його.

## Документ

Панель показує єдиний Markdown-документ із двома режимами перегляду, які перемикаються кнопками **Edit** (олівець) та **Preview** (око):

| Режим | Призначення |
|------|---------|
| **Edit** | Звичайний редактор Markdown (textarea). |
| **Preview** | Відрендерений Markdown. |

У заголовку вказується, **хто останнім редагував** документ і коли.

### Збереження

Натисніть **Save**, щоб зберегти зміни. Кнопка Save активна лише за наявності незбережених змін.

Оскільки документ є спільним, збереження використовує оптимістичну конкурентність:

- Якщо хтось інший зберіг новішу версію від моменту відкриття панелі, Ваше збереження буде відхилено, і з'явиться попередження із зазначенням іншого редактора.
- Потім Ви можете обрати **Reload (discard mine)**, щоб прийняти серверну версію, або **Overwrite**, щоб примусово зберегти Вашу версію замість їхньої.

## AI-аналіз

Виберіть **Credential** та **Model** LLM угорі панелі (список моделей завантажується з вибраного credential — див. [Credentials](../tabs/credentials-tab.md)). Потім запустіть аналіз:

- **Analyze my workflow** — відображається, коли документ порожній. Він потоково записує згенерований AI Markdown-звіт безпосередньо в редактор як незбережену чернетку. Перегляньте та відредагуйте його, потім натисніть **Save**.
- **Reanalyze** — відображається, коли документ уже має вміст. Він потоково записує свіжий звіт в окремий **preview**, залишаючи Ваш поточний документ без змін. Оберіть **Accept**, щоб замінити вміст редактора новим аналізом, або **Discard**, щоб залишити те, що було.

Обидві дії спочатку **запускають workflow** (коли він валідний і може бути запущений) і включають результати виконання до prompt аналізу, тож звіт відображає, як workflow поводиться насправді. Якщо workflow не може запуститися, аналіз виконується на основі його статичної структури.

Згенерований звіт охоплює три розділи, у такому порядку: **Improvement areas** (конкретні пропозиції, включно з аспектом **security**, коли workflow торкається credentials, введення користувача, зовнішніх запитів або розкриття даних), **Purpose** workflow та **What it does** (покроковий огляд вузлів).

Розділ **Improvement areas** завжди виконує п'ять явних перевірок:

1. **Error coverage** — якщо на canvas немає вузла [Error Handler](../nodes/error-handler-node.md) і не налаштовано error workflow, звіт звертає на це увагу та рекомендує додати обробку помилок.
2. **Time saved** — якщо не встановлено оцінку зекономленого часу на один запуск, звіт рекомендує налаштувати її, щоб метрика **Time Saved** у [Analytics](../tabs/analytics-tab.md) могла заповнюватися.
3. **Network nodes** — для вузлів, які виконують мережеві виклики (наприклад, [HTTP](../nodes/http-node.md) та інтеграційні вузли), звіт рекомендує специфічну для вузла обробку помилок (retry та/або continue-on-error) на цих вузлах.
4. **Alerts** — коли для workflow не налаштовано жодних [alerts](../tabs/alerts-tab.md), звіт рекомендує налаштувати сповіщення перед переходом у prod.

5. **Evals**: якщо workflow містить вузол [Agent](../nodes/agent-node.md) без набору агента, звіт рекомендує створити **Agent Suite** (або **Prompt Suite**) у [Evals](../tabs/evals-tab.md#agent-suites); якщо містить вузол [LLM](../nodes/llm-node.md), рекомендується **Prompt Suite** для тестування цього промпту на різних моделях.

### Запуск Analyzer із Properties

Коли workflow має вузли на canvas, але ще не має документа аналізу, у панелі [Properties](./canvas-features.md) рівня workflow (яка відображається, коли жоден вузол не вибрано) з'являється кнопка **Run Analyzer**. Вона відкриває цю панель Аналізу Workflow, щоб Ви могли вибрати credential і модель та згенерувати звіт.

Кожен запуск аналізу записується в [Traces](../tabs/traces-tab.md) під джерелом **Workflow Analysis**.

Якщо жодного LLM credential не налаштовано, кнопка Analyze вимкнена — додайте його на вкладці [Credentials Tab](../tabs/credentials-tab.md).
