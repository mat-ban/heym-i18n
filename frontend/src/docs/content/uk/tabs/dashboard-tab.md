# Dashboard

Вкладка **Dashboard** — це простір у стилі Grafana, де Ви будуєте сітки з віджетів-графіків. Кожен віджет рендериться з виводу власного прихованого Heym workflow, тож будь-які дані, які Ви можете отримати у workflow — запити до бази даних, виклики API, RAG-пошук, вивід LLM — можуть стати графіком. Ви можете мати кілька dashboard і ділитися кожним із них з людьми або командами.

## Dashboards

Кожен починає з одним dashboard, який створюється під час першого відкриття вкладки. Використовуйте селектор dashboard угорі вкладки, щоб перемикатися між dashboard, а **+** поруч із ним — щоб створити новий. Селектор спершу показує Ваші власні dashboard, а потім ті, якими з Вами поділилися, з позначенням імені людини, яка ними поділилася.

Вкладка знову відкриває dashboard, який Ви використовували останнім, а адресний рядок містить відкритий dashboard (`?tab=dashboard&dashboard=<id>`), тож посилання відкриває саме цей dashboard для будь-кого, хто має до нього доступ.

Кнопка налаштувань (лише для власників) дозволяє перейменувати dashboard, вказати, які записи він приймає як [сторінка деталей](#detail-pages), керувати спільним доступом і видалити його. Видалення dashboard прибирає його віджети та їхні workflow. Ви завжди зберігаєте принаймні один власний dashboard, тож останній видалити неможливо.

## Віджети

Віджет — це окремий графік на сітці. Підтримувані типи графіків:

- **Bar** (вертикальний або горизонтальний)
- **Line**
- **Area** (заповнений тренд, підтримує кілька серій)
- **Pie**
- **Table** (з можливістю прокручування; клацніть заголовок стовпця для сортування за зростанням і клацніть знову для сортування за спаданням. Стовпець може відображатися як [чіпи стану](../nodes/chart-output-node.md#status-chips), стовпець може містити [кнопки посилань](../nodes/chart-output-node.md#link-buttons), які відкривають URL-адресу на новій вкладці, а рядки можуть відкривати [сторінку деталей](#storinki-detaley))
- **Numeric** (одне значення KPI з необов'язковою одиницею виміру)
- **Gauge** (одне значення відносно діапазону min–max, наприклад відсоток)
- **Scatter** (точки X/Y для графіків кореляції)
- **Proportion** (один стовпець, розділений на частки, з легендою у відсотках, наприклад розподіл за мовами)
- **Bar gauge** (один горизонтальний індикатор на рядок із градієнтом від червоного до зеленого та значенням, наприклад вільне місце на диску)
- **Text** (повідомлення у форматі markdown, наприклад примітка про стан на кшталт "Last execution at 19:47"; підтримує [interactive checkboxes](../nodes/chart-output-node.md#interactive-task-lists), коли markdown статичний, та [explicit numbered lists](../nodes/chart-output-node.md#numbered-lists) для власної або спадної нумерації)
- **HITL** (Ваші незавершені human reviews. У заголовку показано `1/n pending`. Назва workflow відкриває цей запуск на canvas. **Approve**, **Request changes** і **Reject** завершують його. Іконка історії поруч із назвою віджета відкриває цей запуск у діалозі історії на цій сторінці. Віджет не використовує рядки з upstream, і кожна людина бачить власну чергу. Натомість він може показувати перевірки одного Workflow для всіх, хто може відкрити цей Workflow; див. [Віджети HITL](#vidzheti-hitl))

Окрім діаграм, віджет **Run a workflow** запускає один із ваших workflow безпосередньо з dashboard: для перетягнутого файлу, з його полями введення або за допомогою кнопки Run; див. [Віджети запуску](#run-widgets).

Кожен віджет завантажує свої дані асинхронно, коли Ви відкриваєте вкладку, тож сторінка залишається чутливою, поки графіки наповнюються.

## Додавання віджета

1. Натисніть **Add widget**, дайте йому назву та виберіть тип графіка. Під селектором діалог показує приклад цього типу графіка із зразковими даними та називає рядки, які він очікує, тож Ви можете порівняти типи, перш ніж щось будувати.
2. Віджет відкривається в редакторі workflow із початковим графом: вузол [Set](../nodes/set-node.md), який створює рядки, з'єднаний із вузлом [Chart Output](../nodes/chart-output-node.md). Замініть вузол Set на будь-яке джерело даних. Віджет **HITL** — це лише вузол Chart Output; він читає Ваші незавершені reviews і не потребує джерела даних.
3. Побудуйте workflow так, щоб вузол, який живить **Chart Output**, створював масив рядків, а потім налаштуйте зіставлення полів вузла Chart Output (поле мітки, поле значення тощо).
4. Збережіть, поверніться на вкладку Dashboard, і віджет відрендериться.

Для віджета **Run a workflow** натомість виберіть workflow, який він запускає; селектор показує, як саме віджет запускатиме кожен із них. Віджет додається безпосередньо до сітки; створювати новий workflow не потрібно.

Двічі клацніть віджет (або скористайтеся його кнопкою редагування), щоб будь-коли знову відкрити його workflow. Скористайтеся **Clone
widget** у заголовку віджета, щоб продублювати і віджет, і його повний workflow. Копія
розміщується під оригіналом і позначається **(Copy)**, тож Ви можете редагувати її незалежно.

## Віджети HITL

Новий віджет HITL показує кожну перевірку, що очікує у вашій власній черзі. Щоб показати лише перевірки одного Workflow, відкрийте **Налаштування** віджета:

1. У полі **Workflow** виберіть Workflow. Список містить Workflow, які ви можете відкрити – ваші власні або надані вам чи вашій команді –, які мають крок, що очікує людину: Agent із людською перевіркою або крок Slack для затвердження, кнопок чи форми. Піктограма поруч відкриває цей Workflow на новій вкладці.
2. Якщо Workflow має рівно один такий крок, він вибирається автоматично. Якщо їх кілька, **Select agent** перелічує їх за назвою вузла, причому **All agents** стоїть першим; кроки Slack позначені як **(Slack)**.
3. Збережіть. Індикатор `1/n pending` у заголовку підраховує лише ці перевірки. Виберіть **Усі Workflows**, щоб знову відобразити власну чергу.

Такий самий вибір доступний на полотні у властивостях вузла Chart Output. Його може здійснити **Точне налаштування за допомогою AI** («показувати лише затвердження рахунків»), а також опис нового віджета, який називає Workflow. Кожна зміна є редагуванням Workflow, тому вона з'являється в Edit History.

- **Хто бачить перевірки.** Віджет, відфільтрований за Workflow, показує перевірки цього Workflow усім, хто може відкрити цей Workflow, і вони можуть схвалювати, запитувати зміни або відхиляти безпосередньо з нього, як вони могли б запустити Workflow. Нефільтрований віджет показує кожній особі її власну чергу.
- **Хто бачить віджет.** Той, хто не може відкрити вибраний Workflow, взагалі не бачить віджет, навіть на спільній інформаційній панелі. Коли власник панелі втрачає доступ до Workflow або його видалено, власник бачить «You no longer have access to the workflow this widget shows» і може вибрати інший у **Налаштуваннях**.
- **Лише доступні варіанти.** Workflow, який ви не можете відкрити, відхиляється під час збереження віджета, чи то з налаштувань, з полотна або через AI.

## Сторінки деталей

Табличний віджет може пов'язувати свої рядки з іншим dashboard, який тоді працює як сторінка деталей: один dashboard, що обслуговує кожного клієнта, рахунок-фактуру або тікет.

1. Відкрийте **Settings** табличного віджета й виберіть потрібний dashboard у полі **Row link**.
2. Введіть **Record column** — стовпець, значення якого ідентифікує рядок (наприклад `id`), і за потреби **Label column**, який задає йому назву (наприклад `name`).
3. Збережіть. Натискання на рядок (або фокусування на ньому й натискання Enter) відкриває пов'язаний dashboard із параметрами `?record=<value>&label=<name>`.

На детальному dashboard кожен workflow віджета зчитує це значення як `$page.record` (див. [Chart Output](../nodes/chart-output-node.md#detail-pages-pagerecord)), а сторінка показує над сіткою `Dashboard / <label>` із кнопкою для очищення запису. Кнопка Назад повертає до таблиці, з якої ви перейшли.

- **Хто може її відкрити.** Рядки клікабельні лише для глядачів, які мають доступ до пов'язаного dashboard. Інші бачать ту саму таблицю без посилань.
- **Формат запису.** Запис надходить з URL-адреси, тому детальний dashboard сам визначає, що він приймає. У його налаштуваннях **Detail page records** має одне зі значень: ідентифікатори ID (літери, цифри, `-`, `_` і `.`, до 128 символів; за замовчуванням), числа, UUID або адреси електронної пошти. Будь-яке інше значення відхиляється до запуску віджета, а віджети показують повідомлення «This page does not accept that record».
- **Все ще запуск від імені власника.** На сторінці деталей віджети так само виконуються від імені власника dashboard. Розробники мають передавати `$page.record` лише туди, де вузол екранує (escape) його, і ніколи безпосередньо в текст запиту.
- **Кешування.** Кожен віджет кешує свою діаграму для кожного запису окремо на той самий час життя (TTL), що й сам віджет, і зберігає 50 останніх використаних записів.

## Віджети запуску

Віджет **Run a workflow** запускає один із ваших workflow і показує результат: статус, час виконання та вихідні дані. Те, що він відображає, залежить від вхідних даних workflow:

- **Файл.** Для workflow, який починається з вузла [File Upload Trigger](../nodes/file-upload-trigger-node.md), перетягніть на нього файл (або натисніть, щоб вибрати), і віджет завантажить його через одноразове посилання для завантаження цього тригера. Віджет показує типи та розмір файлів, які приймає тригер, і відхиляє інші ще до завантаження. Коли workflow також починається з вузла Text Input, віджет показує його поля поруч із зоною перетягування: виберіть файл, заповніть поля, і **Run** надішле обидва. Значення передаються разом із посиланням на завантаження, яке генерує віджет, тому спільне посилання на завантаження не може їх задати.
- **Поля введення.** Для workflow, який починається з вузла Text Input, віджет показує його поля зі значеннями за замовчуванням; **Run** запускає workflow із вашими значеннями. Значення для полів, яких немає у workflow, відкидаються.
- **Нічого.** Workflow без вхідних даних отримує кнопку **Run**.

Кнопка **Wrap** у результаті переносить довгі рядки виводу всередині блока; вимкніть її, щоб переглядати JSON-розмітку виводу.

- Будь-хто, хто може відкрити dashboard, може запустити віджет, так само як будь-хто може оновити діаграму. Доступ до workflow визначається власником dashboard: для додавання віджета потрібен workflow, який можете запустити і ви, і власник, а сам запуск використовує облікові дані власника workflow, як і будь-яке посилання для завантаження.
- Результат залишається на вашому екрані, доки ви не залишите сторінку; інші глядачі не бачать ваших файлів, значень чи результатів. Запуск з'являється в історії виконань із тригером `dashboard`.
- Надання спільного доступу до dashboard ніколи не надає доступу до самого workflow. **Edit workflow** відкриває його для людей, які вже мають доступ, а **Fine-tune with AI** не пропонується.
- Запуски з файлами виконуються на головному екземплярі, де зберігаються завантажені файли, як і будь-який запуск File Upload Trigger.

## Генерування віджета за допомогою AI

Натисніть **AI**, опишіть метрику, яку хочете (наприклад, "workflow success rate over the last 30 days as a bar chart"), і виберіть credential для LLM та модель. Heym генерує повний workflow віджета, що завершується вузлом Chart Output, і додає його до сітки. Дивіться [Chart Output](../nodes/chart-output-node.md#example-ai-prompts) щодо прикладів prompt для кожного типу графіка.

Віджет отримує короткий заголовок із одного чи двох слів мовою вашого запиту, наприклад «Відкриті справи». Заголовок ніколи не містить ідентифікатора таблиці даних; коли модель називає віджет цілим реченням, Heym зберігає його перші слова.

API віджетів також може створити **картку лічильника** без AI: віджет `text` над таблицею даних (`data_table_id`) з `count_column` та `count_value` показує, скільки рядків мають це значення; заголовок віджета вказує значення. Heym Work розпочинає сторінки, створені з таблиці даних, з однієї картки лічильника на кожен статус.

Скористайтеся кнопкою **Fine-tune with AI** віджета, щоб доопрацювати наявний віджет новою інструкцією. Кожне AI-доопрацювання зберігає знімок попереднього workflow у **Edit History** віджета, тож Ви можете переглянути або відкотити зміни з редактора workflow.

## Редагування макета

Увімкніть **Edit**, щоб перейти в режим редагування, де Ви можете перетягувати віджети та змінювати їхній розмір на сітці з 12 стовпців. Зміни макета зберігаються автоматично. Назви віджетів можна редагувати безпосередньо в заголовку віджета.

## Кешування та оновлення

Кожен віджет кешує свої останні обчислені дані на сервері протягом настроюваного часу життя (TTL). Поки кеш свіжий, повторне відкриття dashboard віддає збережений результат замість повторного запуску workflow. Кеш замінюється на місці щоразу, коли дані обчислюються заново (один кеш на віджет, плюс один на запис на [сторінці деталей](#detail-pages)), і він автоматично інвалідується, коли Ви редагуєте workflow віджета.

Скористайтеся кнопкою **Refresh** віджета (або **Refresh** на панелі інструментів), щоб обійти кеш і перерахувати негайно.

## Спільний доступ

Власники надають спільний доступ до dashboard з його налаштувань — окремим користувачам (за email) або будь-якій [team](teams-tab.md), до якої вони належать. Кожен спільний доступ має рівень **Read** або **Write**; якщо хтось має і особистий, і командний доступ, застосовується вищий рівень.

| Дія | Owner | Write | Read |
|--------|:-----:|:-----:|:----:|
| Перегляд віджетів, їх оновлення, використання auto-refresh | ✓ | ✓ | ✓ |
| Відкриття сторінок деталей, запуск віджетів запуску | ✓ | ✓ | ✓ |
| Додавання, клонування, видалення, перейменування та зміна розміру віджетів; AI-генерація та fine-tune; позначення пунктів checklist | ✓ | ✓ | |
| Відкриття workflow віджета в редакторі | ✓ | ✓ | |
| Перейменування або видалення dashboard, встановлення формату запису, керування спільним доступом | ✓ | | |

**Віджети завжди виконуються від імені власника dashboard.** Хто б не переглядав, віджет використовує credentials та глобальні змінні власника, а його запуски з'являються в історії виконань і traces власника. Тому колеги бачать ті самі дані без доступу до акаунтів, що стоять за ними, і кожен глядач отримує один кешований результат на віджет. Віджети, які додає або клонує співробітник із правом запису, також належать власнику.

Через це **Write** несе таку саму довіру, як надання спільного доступу до workflow для редагування: співробітник із правом запису може змінити те, що виконується з Вашими credentials. Надавайте його лише тим, кому Ви дозволили б редагувати Ваші workflow. Тестовий запуск, який співробітник запускає з редактора workflow, використовує його власні credentials, як і будь-який спільний workflow; лише сам dashboard виконується від імені власника. **Read** не надає жодного доступу до workflow віджетів, а глядачі з доступом лише для читання отримують сам графік, але не деталі виконання за вузлами, що стоять за ним.

Видалення спільного доступу або зниження його з write до read набуває чинності негайно.
