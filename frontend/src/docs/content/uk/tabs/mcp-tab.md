# Вкладка MCP / A2A / A2A

Вкладка **MCP** налаштовує інтеграцію з Model Context Protocol (MCP), а також як сервери [Agent2Agent](https://github.com/google/A2A) (A2A 1.0), яким інші агенти можуть делегувати завдання. MCP дає змогу AI-клієнтам (Claude, ChatGPT, Gemini, Cursor та будь-якому інструменту, сумісному з MCP) викликати Ваші Workflow у Heym як інструменти.

Heym підтримує два режими: **сервер за замовчуванням**, який надає доступ до всіх Workflow із увімкненим MCP за одним Endpoint, та **іменовані сервери**, які надають кожній логічній групі Workflow власну виділену URL-адресу та API-ключ.

Обидва режими можуть надавати два типи інструментів: окремі **Workflow** та **інструмент чату Heym** — увесь рушій [вкладки Chat](./chat-tab.md) за одним інструментом `heym_chat`.

## Сервер MCP за замовчуванням

Сервер за замовчуванням завжди доступний за адресою `{origin}/api/mcp/sse`. Усі Workflow з увімкненим MCP з'являються тут як інструменти.

### API-ключ MCP

- Ключі зберігаються як SHA-256 дайджести, тому Heym не може показати Вам наявний ключ. Вкладка повідомляє, чи встановлено ключ, а не який він.
- **Згенерувати** / **Перегенерувати** – Новий ключ відображається один раз, одразу після створення. Скопіюйте його тоді ж; після перезавантаження вкладки він остаточно зникає.
- Використовуйте цей ключ під час підключення Claude Desktop, Cursor або інших MCP-клієнтів до Heym
- Загубили ключ? Перегенеруйте його. Попередній ключ негайно перестає працювати.

### Способи підключення

- **API Key** – Використовуйте API-ключ MCP для програмних підключень. Вкладка може скопіювати готову до використання JSON-конфігурацію та містить кнопку **Add to Cursor** для налаштування Cursor в один клік.
- **Claude** – Вкладка показує URL-адресу сервера MCP та кроки налаштування для Claude. Залиште поля OAuth Client ID та Secret порожніми; Claude реєструється автоматично та автентифікується через Heym OAuth.
- **ChatGPT** – На вкладці показано URL сервера MCP і кроки налаштування для застосунку ChatGPT. Увімкніть режим розробника (Developer mode), створіть застосунок із цим URL та оберіть OAuth; ChatGPT реєструється автоматично.
- **Gemini** – На вкладці показано URL сервера MCP і кроки налаштування для власного застосунку Gemini: на gemini.google.com перейдіть до **Settings → Connected Apps → Add a custom app**, вставте URL і залиште **Advanced features** закритим; Gemini автоматично реєструється та автентифікується через Heym OAuth. Після підключення Heym також працює в мобільному застосунку Gemini.

### Перемикач MCP для Workflow

Кожен Workflow можна надати як інструмент MCP:

- **Увімкнено** – Інструменти Workflow стають доступними всім клієнтам, підключеним до сервера за замовчуванням
- **Вимкнено** – Workflow не надається

Картки Workflow показують опис і попередній перегляд назв полів введення, щоб Ви могли побачити, що очікує кожен інструмент, перш ніж увімкнути його.


### Запуски в черзі та heym_execution_status

Workflow з [лімітом одночасності](../reference/webhooks.md#concurrency-limit-and-queued-runs) може бути зайнятий, коли клієнт викликає його. Виклик негайно повертає результат, який не є помилкою:

```json
{
  "status": "queued",
  "execution_id": "6f1c0c2e-...",
  "queue": { "position": 2, "size": 5, "running": 1, "limit": 1 },
  "next_step": "Call heym_execution_status with this execution_id every 5-10 seconds until status is success, error, cancelled or expired."
}
```

Клієнт опитує інструмент `heym_execution_status` за допомогою цього `execution_id`. Він повертає те саме тіло, що й [URL стану](../reference/webhooks.md#status-url): `queued` із поточною позицією, `running`, потім `success` або `error` із результатами. Він знаходить лише запуски workflows, наданих тим самим сервером. Інструмент відображається на сервері за замовчуванням та на кожному іменованому сервері лише доти, доки принаймні один із його workflows має ліміт одночасності. Коли черга заповнена, виклик повертає помилку „Concurrency queue is full“.
## Агент Heym

Розділ **Heym Capabilities** перетворює рушій вкладки Chat на єдиний інструмент MCP з назвою `heym_chat`. Увімкніть його на сервері за замовчуванням, на будь-якому іменованому сервері або на обох — кожна поверхня має власний перемикач і вибір моделі.

Коли його увімкнено, `heym_chat` з'являється в `tools/list` поряд з інструментами Ваших Workflow. MCP-клієнт надсилає одне повідомлення природною мовою, і далі рушій Heym бере керування на себе, маючи ті самі можливості, що й вкладка Chat:

- Створювати Workflow, тестувати його з прикладами вхідних даних, виправляти помилки й завершувати роботу, коли запуск проходить успішно (див. [Режим побудови](#build-mode))
- Переглядати та запускати Ваші наявні Workflow
- Надавати аналітику, останні виконання та майбутні розклади Cron
- Пояснення, де робочі процеси зазнають невдачі та чому вони повільні: процеси, які виконувалися найчастіше, мали найбільше помилок і є найповільнішими, а також типи вузлів з найбільшими витратами часу, помилками та викликами за останні 1, 3 або 6 годин, 24 години, 7 або 30 днів чи за весь час
- Надавати історію запусків одного Workflow: скільки разів він запускався, кількість за статусами, коли він запускався, а на запит — вхідні дані, вихідні дані та помилки окремих вузлів одного запуску
- Надавати інформацію про те, що виконується прямо зараз: скільки виконань активні, їхні назви Workflow, як довго кожне виконується, на якому вузлі кожне перебуває зараз, та посилання на живий запуск
- Перелічувати дошки, створювати картки та читати деталі карток на [вкладці Board](./board-tab.md)
- Перелік інформаційних панелей (сторінок Heym Work) та їхніх віджетів, визначення панелі, де розташовано робочий процес, додавання нового віджета та створення його процесу, розміщення існуючого процесу як віджета, перейменування чи видалення віджетів або впорядкування макета (див. [Dashboard › З Chat та MCP](./dashboard-tab.md#from-chat-and-mcp))
- Перевірка таблиць даних і рядків, створення таблиць, додавання або видалення стовпців, вставка, оновлення або видалення рядків та підключення таблиць до робочих процесів
- Створення, редагування та запуск наборів оцінювання промптів та агентів ([Eval suites](./evals-tab.md#from-chat-and-mcp)), включно з базовим рівнем агента: звітним, побудованим на основі запусків або вказаним числами. Результат містить посилання Evals для кожного збереженого набору.
- Створення або оновлення облікових даних на спеціальній сторінці Heym (див. [Облікові дані](#облікові-дані))
- Читати команди та глобальні змінні, а також шукати в документації
- Схвалювати, редагувати або відхиляти очікувані перевірки human-in-the-loop

Можливості, додані до вкладки Chat пізніше, автоматично стають доступними через `heym_chat` — немає окремого перемикача для кожної можливості, який потрібно синхронізувати.

Ці можливості виконуються всередині `heym_chat`: `tools/list` показує `heym_chat` та ваші інструменти робочих процесів, але ніколи внутрішні інструменти чату, такі як інструменти наборів оцінювання.

### Режим побудови

`heym_chat` завжди запускає рушій Chat у режимі побудови (build mode). За один виклик асистент може зберегти новий Workflow, запустити його з реалістичними прикладами вхідних даних, прочитати звіт про виконання, виправити те, що завершилося помилкою, і запустити його знову — до п'яти тестових запусків за виклик. Коли останній запуск останнього збереження проходить успішно, він завершує роботу підсумком з одного речення, а відповідь закінчується рядком `Verified: the latest test run of the saved workflow passed.`

Коли виклик створює або редагує workflow, відповідь містить повне посилання на редактор для кожного з них, наприклад `https://heym.example.com/workflows/<id>`, а посилання у відповіді асистента також є повними. Вони використовують вашу налаштовану адресу Heym (`FRONTEND_URL`) і відкриваються для користувачів, які ввійшли в Heym і мають доступ до цього workflow.

- Тестові запуски є реальними запусками. Їхні побічні ефекти відбуваються насправді, і вони відображаються в історії запусків Workflow як і будь-який інший запуск.
- Збереження проходять шляхом редактора: зміна графа зберігає попередній граф в історії редагувань (**Edit History**) Workflow.
- Щоб змінити Workflow, побудований раніше, продовжуйте гілку з тим самим `conversation_id`. Асистент оновлює цей Workflow замість створення нового і змінює лише ті Workflow, які Ви можете редагувати.
- Коли п'ять тестових запусків вичерпано, асистент зупиняється і пояснює, що саме все ще не працює.

Таблиці даних — інша річ. Таблиця не містить секретів, тому `heym_chat` може перелічувати Ваші таблиці, запитати, яку з них має використовувати Workflow, та створити нову з її стовпцями. Він ніколи не читає та не записує рядки.

### Облікові дані

`heym_chat` бачить облікові дані, які вам належать, і ті, якими з вами поділилися, за назвою та типом, так само, як і вкладка Chat. Коли створюваному workflow потрібні облікові дані, він запитує, які використовувати, у вигляді запитання в результаті. Дайте відповідь із тим самим `conversation_id`.

Щоб додати облікові дані або оновити власні, асистент відкриває форму облікових даних Heym на сторінці Heym, `/credentials/setup/<id>`. Ви входите в Heym, вводите ключ або підключаєте обліковий запис і зберігаєте. Значення передається безпосередньо в Heym: клієнт MCP та його модель дізнаються лише назву та тип даних. Не вставляйте ключі в клієнт MCP; замість цього запитайте форму.

| Клієнт | Що відбувається |
|--------|-----------------|
| Підтримує отримання URL MCP | Клієнт пропонує відкрити сторінку Heym. Виклик очікує під час заповнення форми (до десяти хвилин), а потім продовжує роботу з новими даними. |
| Будь-що інше | Результат містить посилання та просить клієнта знову викликати `heym_chat` із `wait_for_credential_form`. Цей виклик чекає до п'яти хвилин під час заповнення форми, а потім відновлює розмову. Якщо клієнт не чекає, збережіть форму та дайте відповідь із тим самим `conversation_id`; наступний виклик знатиме, що форму збережено, і які дані створено. |

Сторінка відкривається лише для облікового запису Heym, який створив запит, тому переслане посилання марне для інших. Форма залишається відкритою протягом 24 годин і її можна відхилити на сторінці. Після збереження або відхилення крок у розмові вкладки Chat показує результат.


### Credential і модель

`heym_chat` запускає рушій на Вашому акаунті Heym, тому йому потрібен власний LLM credential:

| Поле | Поведінка |
|-------|----------|
| **Credential** | Виберіть будь-який доступний Вам credential OpenAI, Google або Custom. Попередньо заповнюється з бажаного credential у [Settings](../reference/user-settings.md), якщо Ви не вибрали жодного. |
| **Model** | Завантажується з вибраного credential. Попередньо заповнюється з Вашої бажаної моделі, якщо credential збігається. |

Якщо будь-що з цього відсутнє, інструмент усе одно з'являється в `tools/list`, але кожен виклик повертає помилку з проханням завершити налаштування на цій вкладці.


Вузли LLM та Agent у workflow, створеному `heym_chat`, запускаються з цими обліковими даними та моделлю, включно з обліковими даними, якими з вами поділилися, тому тестові запуски працюють без додаткових налаштувань. Коли `heym_chat` редагує workflow, вузли LLM та Agent, які вже мають облікові дані, зберігають їх разом зі своєю моделлю.
### Аргументи та історія

| Аргумент | Обов'язковий | Опис |
|----------|----------|-------------|
| `message` | Так | Інструкція або запитання природною мовою. |
| `conversation_id` | Ні | `conversation_id` з попереднього результату `heym_chat`, щоб продовжити це обговорення. |
| `wait_for_credential_form` | Ні | З `conversation_id`: зачекайте, поки користувач збереже або відхилить форму облікових даних, відкриту гілкою, а потім надішліть `message`. |

Кожен виклик записується в історію Вашої [вкладки Chat](./chat-tab.md) як звичайна розмова, позначена іконкою вилки в списку розмов. Повідомлення, картки інструментів і паузи для уточнення виглядають точно так само, як розмова, яку Ви розпочали самостійно, і Ви можете відкрити обговорення та продовжити спілкування в браузері. Кожен результат повертає свій `conversation_id`, щоб MCP-клієнт міг продовжити те саме обговорення, а не відкривати нове під час кожного виклику.

Коли асистенту потрібне уточнення, він зупиняється та повідомляє про це; дайте відповіді, використовуючи той самий `conversation_id`.

### Увімкнути A2A

Поки Агент Heym увімкнений, картка відображає прапорець **Увімкнути A2A**. Позначте його, і інші агенти зможуть надсилати завдання Агенту Heym через протокол Agent2Agent (A2A 1.0). Потім картка показує URL-адресу **Agent Card** та кінцеву точку **JSON-RPC endpoint**, кожна з кнопкою копіювання, а також команду `curl` для завантаження картки. A2A використовує той самий ключ та OAuth-вхід, що й MCP. Вимкнення агента також вимикає A2A. Див. [A2A](../reference/a2a.md) щодо методів, станів завдань та прикладу.

### Прогрес

Тривалий виклик `heym_chat` повідомляє про дії агента як про прогрес MCP (`notifications/progress`), тими самими формулюваннями, що й вкладка Chat, наприклад `Тестування робочого процесу · спроба 2/5`. Клієнти, які скидають тайм-аут при отриманні повідомлення про прогрес, продовжують очікувати, поки агент працює.

## Іменовані MCP-сервери

Іменовані сервери дають змогу сегментувати workflows на ізольовані MCP Endpoint. Кожен сервер має власний URL та API Key, тож різні AI-клієнти, команди або сценарії використання можуть підключатися саме до тих workflows, які їм потрібні.

### Створення іменованого сервера

1. Введіть назву в полі внизу вкладки MCP (наприклад, **CRM Tools**)
2. Натисніть **Create** — одразу з'явиться картка нового сервера
3. Натисніть на картку, щоб розгорнути її

### Налаштування окремого сервера

Кожна картка сервера показує:

| Налаштування | Опис |
|---------|-------------|
| **SSE Endpoint** | Унікальний URL: `{origin}/api/mcp/servers/{uuid}/sse` |
| **API Key** | Незалежний ключ, який показується один раз під час генерації або повторної генерації. Скопіюйте його негайно; він зберігається у хешованому вигляді й не може бути показаний пізніше |
| **How to connect** | **Copy JSON** копіює готовий до вставлення MCP-конфіг; **Add to Cursor** встановлює його одним кліком |
| **Heym Capabilities** | Увімкніть або вимкніть Агента Heym (`heym_chat`) для цього сервера та виберіть його credential і модель |
| **Увімкнути A2A** | Власний перемикач A2A цього сервера з власною Agent Card за адресою `{origin}/api/a2a/servers/{uuid}/agent-card.json` |
| **Увімкнути A2A** | Власний перемикач A2A цього сервера з власною Agent Card за адресою `{origin}/api/a2a/servers/{uuid}/agent-card.json` |
| **Assigned Workflows** | Увімкніть або вимкніть, які з Ваших workflows цей сервер надає |

### Призначення Workflow

Призначення Workflow виконується окремо для кожного сервера й не залежить від перемикача сервера за замовчуванням. Workflow може бути увімкнений на сервері за замовчуванням і одночасно на кількох іменованих серверах або на жодному з них.

Перемикання Workflow переміщує його на початок списку призначених, тож рядок, який Ви щойно змінили, залишається видимим, а не зникає під час прокручування.

### Автентифікація

Іменовані сервери підтримують ті самі методи автентифікації, що й сервер за замовчуванням:

- **X-MCP-Key header** – Передайте API Key сервера безпосередньо (API-клієнти, Cursor). Лише header: ключі не приймаються як query-параметр `?key=`, оскільки URL-адреси потрапляють до логів доступу, логів проксі та історії браузера.
- **Claude, ChatGPT і Gemini OAuth** – Додайте URL сервера до конекторів або власних застосунків клієнта; залиште credentials порожніми, і клієнт зареєструється через OAuth автоматично. Bearer Token має передаватися в header `Authorization`, а не як `?token=`.
- **Session token** – Видається під час SSE-рукостискання; прив'язаний до конкретного сервера, тож Token з одного іменованого сервера не може отримати доступ до іншого. Цей короткочасний параметр `?session=` не зачіпається.

### Видалення іменованого сервера

Натисніть іконку **X** у заголовку картки сервера. Видалення прибирає сервер та всі його призначення Workflow; самі workflows не зачіпаються.

## SSE Endpoint

| Сервер | Endpoint |
|--------|----------|
| За замовчуванням | `{origin}/api/mcp/sse` |
| Іменований | `{origin}/api/mcp/servers/{server-uuid}/sse` |

Обидва Endpoint підтримують транспорт SSE (GET, MCP spec 2024-11-05) та транспорт Streamable HTTP (POST, MCP spec 2025-03-26). Claude, ChatGPT і Gemini використовують OAuth 2.1 / PKCE для безпечного входу в обох випадках.
