# Вкладка Traces

Вкладка **Traces** показує трасування виконання LLM. Переглядайте request/response payload, час виконання, виклики інструментів і налагоджуйте поведінку вузлів [Agent](../nodes/agent-node.md) та [LLM](../reference/node-types.md), а також агреговані метрики (виклики, tokens, вартість, затримка, відсоток помилок) за будь-який часовий проміжок.

## Заголовок зі статистикою

Сторінка відкривається зведенням статистики над списком traces, обчисленим за вибраний часовий діапазон та інші активні фільтри:

- **KPI-картки** – Total Calls, Total Tokens, Total Cost (USD), Avg Latency, Error %
- **Tokens by Model** – Кільцева діаграма обсягу tokens за моделлю
- **Cost by Model** – Кільцева діаграма витрат у USD за моделлю. Моделі без ціноутворення показують посилання "Configure pricing" на [LLM Cost Table](./datatable-tab.md#llm-cost-table-system-table)
- **Calls Over Time** – Діаграма з накопиченням площі успішних і невдалих викликів за інтервал (5 хв / 1 год / 6 год / 1 день, обирається автоматично залежно від діапазону)
- **Повідомлення про моделі без ціноутворення** – З'являється під діаграмами, коли деякі трасовані моделі не мають рядка ціноутворення, з посиланням на LLM Cost Table

## Часовий діапазон

Єдиний селектор **Time range** у верхній частині панелі фільтрів керує як заголовком зі статистикою, так і списком traces. Варіанти: Last 1 hour, Last 24 hours, Last 7 days (за замовчуванням), Last 30 days, All time. Зміна діапазону скидає пагінацію та одночасно перезавантажує діаграми й список.

## Список traces

- Пагінований список останніх traces у вибраному часовому діапазоні
- Кожен trace показує: workflow, node, credential, часову мітку, тривалість
- Натисніть на trace, щоб відкрити детальний перегляд
- Використовуйте **Prev / Next** у діалозі деталей, щоб переміщатися між traces, не закриваючи його

## Фільтрування

- **Time range** – 1h / 24h / 7d / 30d / All; фільтрує діаграми та список разом
- **Credential** – Фільтр за використаним credential (API key)
- **Source** – Фільтр за workflow або джерелом виконання
- **Search** – Пошук за моделлю, workflow, credential або міткою node
- **Refresh** – Перезавантажити поточну сторінку traces

## Деталі trace

Коли Ви відкриваєте trace:

- **Steps** – Хронологія згори донизу, яка читає trace як упорядкований ланцюжок: System → User → Assistant → Tool → Answer. Кожен крок можна згорнути; розгортання показує читабельні деталі (текст повідомлення або аргументи й результат інструмента), а далі JSON цього кроку. JSON-вміст у кожному типі події—включно з викликами MCP і payload JSON-RPC—за замовчуванням відкривається у розгортуваному дереві, з розгорнутим першим рівнем. Використовуйте **Tree / Raw**, щоб перемикатися між форматованою структурою та оригінальним текстом. Некоректний JSON залишається видимим як звичайний текст. Кроки інструментів показують свою тривалість і бейдж MCP/Skill, де застосовно, а також бейджі pending / timeout / cancelled, коли встановлено статус виклику інструмента. Крок Answer може показувати агреговані бейджі `tool_metrics` (кількість викликів за статусом і загальна тривалість інструментів). Коли trace фіксує кожен виклик моделі, як це робить повідомлення Dashboard Chat і маршрутизований agent, крок **LLM** стоїть перед інструментами, які запросив виклик, а **Duration Breakdown** розкладає кожен виклик моделі, інструмент і рішення маршрутизації на одній хронології. Повідомлення Dashboard Chat — це один trace, скільки б раундів інструментів воно не зайняло. Traces без ланцюжка повідомлень (наприклад, генерація зображень) показують мінімальну хронологію Request → Response.
- **Request** – Повний request payload, надісланий до LLM, з поданнями JSON **Tree / Raw**
- **Response** – Відповідь моделі, включно з викликами інструментів, якщо вони є, з поданнями JSON **Tree / Raw**
- **Tool metrics** – Коли присутні у відповіді, компактне зведення кількості викликів інструментів (`success` / `error` / `pending` / `timeout` / `cancelled`) і загальної тривалості інструментів
- **Timing breakdown** – `llm_ms`, `tools_ms`, `mcp_list_ms` для аналізу продуктивності
- **Tool calls** – Назва інструмента, аргументи, результат, статус і витрачений час
- **Skills included** – Skills, передані моделі в request
- **Go to Workflow** – Перейти безпосередньо до пов'язаного workflow з діалогу деталей trace

## Копіювання та експорт

- Копіюйте request або response JSON у буфер обміну; копіювання завжди використовує повний raw payload незалежно від активного подання
- Використовуйте для налагодження або надсилання до служби підтримки

## Обслуговування

- **Clear All** – Видалити всі збережені traces після підтвердження
- Елементи керування пагінацією показують поточний видимий діапазон (наприклад, `1-25 of 240`)
