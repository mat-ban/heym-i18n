# AI 助手

**AI Assistant** 是一个从 Debug 面板打开的聊天面板，初始位置在编辑器右下角。拖动其标题栏可移动面板，拖动边缘或角落可调整其宽度或高度。面板不会缩小到低于 360×480 像素。其位置和大小会在此浏览器中记住。标题栏中的 **Reset position and size** 可将面板恢复到右下角。使用自然语言创建或修改工作流——描述你想要的内容，AI 会生成节点和边并应用到画布上。

如需编辑器之外的产品文档帮助，请使用 [Chat with Heym](./chat-with-heym.md)。该界面针对页面感知的产品帮助进行了优化，而非用于工作流生成。

## 打开面板

1. 在编辑器中打开一个工作流
2. 找到底部的 **Debug 面板**（执行结果区域）
3. 点击面板工具栏中的 **AI** 按钮（Sparkles 图标）
4. AI Assistant 面板会在右下角打开。拖动其标题栏可移动面板，或拖动边缘或角落可调整其宽度和高度。

在编辑器任意位置按 `Ctrl + I` / `Cmd + I` 可打开或关闭面板——即使焦点位于文本输入框中，该快捷键也有效。请参阅 [Keyboard Shortcuts](./keyboard-shortcuts.md)。

要对单个节点进行操作，请在画布上悬停在该节点上并点击其上方的 **AI**。面板将聚焦于该节点打开。请参阅[修改单个节点](#changing-one-node)。

## 关闭面板

点击 **X** 按钮，按 `Ctrl + I` / `Cmd + I`，或切换 Debug 面板工具栏中的 **AI** 按钮。标题栏用于拖动面板，而非关闭面板。

## 配置

发送消息前，请选择：

| 设置 | 描述 |
|---------|-------------|
| **Credential** | 来自 [Credentials](../tabs/credentials-tab.md) 的 LLM 凭证（API key） |
| **Model** | 模型名称（例如 `gpt-4o`、`gemini-2.5-flash`） |

在 [Credentials Tab](../tabs/credentials-tab.md) 中添加凭证。模型列表会从所选凭证中加载。

## Agent 模式与 Ask 模式

面板有两种模式，可通过面板标题栏中的 **Agent / Ask** 切换按钮进行切换。

| 模式 | 默认 | 行为 |
|------|---------|-----------|
| **Agent** | ✓ | 构建并修改画布。AI 会生成一个工作流 JSON 块，并在响应完成后自动应用到画布。 |
| **Ask** | | 仅回答问题。绝不会改动画布。可用于询问你的工作流、Heym 功能，或在不触发画布更新的情况下获取建议。 |

可随时切换模式。切换模式不会清空对话。

在 Agent 模式下，消息字段下方的 **YOLO mode** 复选框会让助手运行并修复其构建的内容。请参阅 [YOLO Mode](#yolo-mode)。

## 使用聊天

- 在输入框中输入你的请求（例如“创建一个接收用户输入并将其发送给 LLM 的工作流”）
- 按 **Enter** 发送（Shift+Enter 换行）
- AI 会流式输出其响应。在 **Agent** 模式下，如果响应中包含 \`\`\`json 代码块中的工作流，则会自动解析并应用到画布。在 **Ask** 模式下，画布绝不会被修改。
- 使用 **Clear** 重置对话
- 将鼠标悬停在某条消息上并点击其复制图标，可复制其显示的文本，包括任何工作流 JSON
- 拖动消息框上方的分隔线可加高消息框。输入区域最高可增长到面板的 60%，页面重新加载时会恢复为默认高度

## 工作流自动应用

当 AI 响应中包含 \`\`\`json 代码块中的有效工作流 JSON 块（包含 `nodes`，以及可选的 `edges`）时，Heym 会：

1. 从响应中解析 JSON
2. 用新的节点和边替换当前画布
3. 整理节点布局
4. 将工作流标记为未保存

如果解析失败，会出现一个 **Retry** 按钮以重新生成响应。

## 修改单个节点

在画布上将鼠标悬停在节点上，然后点击其上方的 **AI**。面板以 Agent 模式打开，聚焦于该节点，并显示其正在修改的节点：

| 节点状态... | 面板显示 |
|---|---|
| 当前运行中没有结果 | **Modifying Node:** 在紧凑的一行中显示节点的图标和名称。助手仅根据节点的配置进行编辑；如果需要查看输出，请先运行该节点 |
| 当前运行中有结果 | **Modifying Node: (Has Node Output)** 位于节点本身上方：图标、名称和类型、上次状态和持续时间，以及失败时的错误信息。助手在编辑节点时可以看到该输出和错误 |

将鼠标悬停在标签上以查看面板处于哪种状态。

无论面板处于哪种状态，助手还会读取节点标头中书本图标后面的节点文档页面。它使用该页面来了解节点的选项并回答有关它们的问题。

在消息下方，三个选项可启动请求：

| 选项 | 作用 |
|---|---|
| **Change this node as ...** | 在消息框中填入 *将此节点更改为*，以便您补全句子 |
| **Fix error in this node ...** | 填入 *修复此节点中的错误。* 助手将读取此节点在上次运行中的错误 |
| **Other** | 聚焦到空白消息框 |

编辑文本并按 **Send**。助手仅返回此节点，Heym 会就地对其进行更新：节点保留其 id、类型和名称，因此其他节点中诸如 `$checkLinkedIn.result` 之类的表达式仍可正常工作。其他节点、连接和布局保持不变，并且 **Undo** 可恢复之前的配置。

如果请求无法在节点内容纳，例如需要另一种节点类型或新节点，助手会指出需要更改的内容，而不是进行编辑。点击节点卡片上的 **X** 关闭节点聚焦即可重新编辑整个工作流。关闭面板也会清除聚焦。

[YOLO 模式](#yolo-mode)适用于聚焦节点：助手更改该节点，运行工作流并修复该节点，直到运行通过。在 **Ask** 模式下，聚焦会告诉助手您的问题涉及哪个节点，且画布不会被更改。

## YOLO Mode

**YOLO mode** 让助手测试其构建的内容。勾选消息字段下方的 **YOLO mode** 复选框，然后发送你的请求。该复选框仅在 Agent 模式下出现。默认关闭，页面重新加载时会重置为关闭状态。将鼠标悬停在其旁边的信息图标上可查看简短说明。

开启 YOLO mode 后，助手在应用工作流后不会停止：

1. 它将工作流应用到画布。
2. 在首次运行前，它会请求测试输入。该卡片会列出工作流的输入字段，并填入助手建议的值。编辑它们并按 **Run**。后续运行会复用这些值。仅当输入字段发生变化或助手需要不同的测试数据时，该卡片才会再次出现。
3. 它会像 **Run** 按钮一样在画布上运行工作流：先保存未保存的更改，节点会亮起，运行会出现在 Debug 面板和 [Execution History](./execution-history.md) 中。
4. 它会读取结果。如果运行结果符合你的要求，它会以 **Verified** 和简短摘要结束。如果不符合，它会修复工作流并再次运行。

每条消息最多运行 **5 次**。可随时按 **Stop** 结束循环并停止正在进行的运行。

每条回复都会在步骤发生时显示它们：
- `Applying changes to canvas`；
- `Running workflow · attempt 2/5`，并为每个节点显示一行 `Executing <node>`；
- 最终结论。

每次运行后，会显示一行简短信息，例如 *Attempt 1 result sent · error in 1.2s*，表示结果已发送回助手。
### 运行其他工作流

在 YOLO 模式下，当助手需要其他工作流的结果时，它也可以运行这些工作流。例如，它可以在从 [Execute](../nodes/execute-node.md) 节点调用某个工作流之前，先检查该工作流返回的内容。这些运行会显示为 `Running workflow "<name>"...` 步骤，并以触发源 `ai_assistant` 记录在 Execution History 中。正在编辑的工作流始终在画布上进行测试。

### 何时提前停止

| 情况 | 会发生什么 |
|---|---|
| 助手需要一项决策、信息、凭证或数据表 | 它会通过常规的问题卡片进行询问。回答后循环继续。 |
| 运行等待[人工审核](./human-in-the-loop.md) | 循环停止。批准审核后，再发送一条消息。 |
| 工作流等待文件上传 | 循环停止。YOLO 模式无法测试由上传触发的运行。 |
| 工作流的较新版本已在其他地方保存 | 循环停止。解决保存冲突后，再发送一条消息。 |

> **运行是真实的。** 工作流中的邮件、消息和 API 调用在每次尝试时都会实际发送，DataTable 节点会写入真实的数据行。每次运行都会保存工作流，因此较早的版本会保留在 [Edit History](./edit-history.md) 中。

## 语音输入

在支持的浏览器上，**Voice** 按钮可启用语音转文字。点击开始录音，再次点击停止。转写后的文本会先发送给 AI 进行语法修正，然后再由你发送。

## Agent 节点与 AI Assistant

| | Agent 节点 | AI Assistant |
|---|------------|---------------|
| **用途** | 工作流内部的 LLM 节点；在执行期间运行 | 用于通过自然语言构建工作流的聊天 UI |
| **位置** | 画布节点 | 调试面板 → 浮动面板 |
| **时机** | 运行时 | 编辑时 |

有关使用工具和 MCP 执行 LLM 调用的工作流节点，请参阅 [Agent 节点](../nodes/agent-node.md)。

## 工作原理（AI Builder DSL）

AI Assistant 由一种**工作流 DSL**（领域特定语言）驱动，用于描述节点、边和表达式。当你发送消息时：

1. 你的消息、[User Rules](./user-settings.md) 以及当前工作流（如果有）会被发送到后端。
2. 后端会构建一个**系统提示词**，其中包含：
   - 完整的工作流 DSL（节点类型、表达式语法、规则、示例）
   - 你的 User Rules，作为“User Custom Rules”附加
   - 当你正在编辑现有工作流时，包含当前工作流 JSON
   - 如果你使用 Execute 节点，包含可用工作流的列表
   - 你自己凭证的名称、类型和 id（绝不包含其值）
   - 你可以使用的数据表的名称、id、描述和列（绝不包含其数据行）
3. 模型返回单个工作流 JSON 块（包含 `nodes` 和 `edges`）。前端会解析它并将其应用到画布。

### 凭证

当工作流需要凭证时，助手会在构建之前询问。如果你有合适类型的凭证，它会将这些凭证与 **Create a new credential** 一起列出；如果你没有，它会询问是否创建一个。每个问题也都允许你在没有凭证的情况下继续。

选择创建一个凭证会在面板中打开凭证表单，并预置正确的类型和建议的名称。这些值会直接发送到 Heym；助手只会获知名称和类型。OAuth 凭证（Google Sheets、Google Drive、BigQuery、Linear、Notion）会在弹窗中连接，如果弹窗被拦截，还会显示一个指向授权页面的链接。凭证保存后，卡片会显示其名称，创建按钮会关闭；按下 **Submit answers**，助手就会将新凭证放到节点上。

你也可以单独请求一个凭证（“create a GitHub credential”），或请求更改你拥有的凭证（“update my sheet credential”、“reconnect my Google Sheets”）。助手会用同一张卡片作答：创建会打开一个空表单，更新会在该凭证上打开表单，并将其密钥掩码显示。

助手优先使用专用节点。当没有节点覆盖某项操作时，例如向 Google Sheet 添加一个标签页，它会使用 HTTP 请求，并为所选凭证写入表头行。请参阅 [HTTP › Authenticating with Credentials](../nodes/http-node.md#authenticating-with-credentials)。

工作流无需这些信息也能继续的澄清问题，会在其输入中标注 **Optional**，并且可以跳过。

DSL 强制使用 camelCase 标签、统一的表达式规则以及节点特定字段。如果字段值是单个 `$expr`，后端会保留其原生类型；如果该值混合了普通文本与 `$refs`，则结果为字符串。单 `$` 规则仍然适用：括号内不能有 `$`。[Settings](./user-settings.md) 中的 User Rules 会被注入到这个系统提示词中，因此你的偏好会应用到每个由 AI 生成的工作流。

如果当前工作流包含 Agent skills，AI Assistant 只会在该工作流上下文中包含每个 skill 的 `SKILL.md`。附加的 `.py` 文件和二进制 skill 资源会在请求前被剥离，因此即使 skills 包含大型实现，构建器也能保持在模型上下文限制之内。
### 数据表

当工作流保存、存储或查找记录，而您尚未指定其他存储时，助手会使用 [DataTable](../nodes/datatable-node.md) 节点。如果您指定了某个表的名称，且该表具有工作流所需的列，助手会使用该表。否则，它会询问使用哪个表。卡片会列出符合条件的表，每张表都附有描述和列类型，此外还有 **Create a new table**，其中包含建议的名称和列。与您共享的表也会被提供；您只能读取的表仅会以只读方式提供。

选择新表并按下 **Submit answers**：卡片会创建该表，助手会将其 id 放到节点上，并使用其确切的列名。您也可以单独请求创建表，例如“为我的 leads 创建一张表”。

助手可以看到表名、描述和列，但永远看不到行。它永远不会更改现有表的列：如果某张表缺少工作流所需的列，它会指出该列并改为提供一张新表。请在 [DataTable tab](../tabs/datatable-tab.md) 中添加列。
