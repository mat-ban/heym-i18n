# HTML 輸出對應器

**HTML 輸出映射器**節點會將單一 HTML 範本渲染為頁面。當呼叫端是**瀏覽器**而非 API 用戶端時，請使用此節點——Workflow 會以 `text/html` 而非 JSON 回應。

## 概觀

| 屬性 | 值 |
|----------|-------|
| 輸入 | 1 |
| 輸出 | 0（終端節點） |
| 執行階段輸出 | `{ "html": "…", "statusCode": 200, "contentType": "text/html; charset=utf-8" }` |

## 參數

| 參數 | 類型 | 說明 |
|-----------|------|-------------|
| `label` | string | 節點識別碼（camelCase） |
| `html` | string | 頁面範本。`$nodeLabel.field` 表達式會就地內插。 |
| `statusCode` | number | 回應的 HTTP 狀態碼（預設為 `200`） |
| `contentType` | string | 回應內容類型（預設為 `text/html; charset=utf-8`） |

## Webhook 與執行行為

當此節點是 Workflow 的**唯一**終端輸出時，execute Endpoint 會以渲染後的頁面、設定的狀態碼及設定的內容類型回應——沒有 JSON 封裝、沒有 label 包裝。

有兩種情況會關閉此行為：

- **第二個終端節點。** 當圖中有另一個作用中的終端節點時，Heym 會退回至一般的逐 label JSON 對應，頁面會以字串欄位的形式送達。
- **`X-Simple-Response: false`。** 該標頭會要求包含 `status`、`node_results` 及計時資訊的完整封裝，這正是編輯器畫布所使用的格式。當你在對頁面 Workflow 進行除錯時，請送出此標頭。

## 將頁面提供給瀏覽器

在 cURL 對話框中將 Workflow 的**請求方法**設為 `GET`，讓單純的瀏覽器導覽能觸及此 Workflow。`GET` 請求不帶 body，因此輸入來自查詢字串：

```
curl -X GET "https://your-host/api/workflows/<workflow-id>/execute?name=Ada"
```

使用 `$input.query.name` 讀取這些值。完整的請求方法契約請參閱 [Webhooks](../reference/webhooks.md)。

若 Workflow 沒有 Trigger 節點，且其唯一終端節點為此節點，則會在 [Workflows 分頁](../tabs/workflows-tab.md)中顯示 **WEB** 標籤。

## Agent 工具使用方式

不支援。此節點是終端節點，因此無法附加至 [Agent Node](./agent-node.md) 的工具控制代碼。同樣的規則也適用於 [JSON 輸出映射器](./json-output-mapper-node.md)。

## 迴圈限制

與 [Output](./output-node.md) 相同的規則：請勿將此節點放在迴圈迭代分支內——只能放在迴圈的 `done` 分支之後。請參閱 [Loop](./loop-node.md)。

## 範例

```json
{
  "type": "htmlOutputMapper",
  "data": {
    "label": "reportPage",
    "html": "<!doctype html><html><body><h1>$llm.text</h1><p>Generated by Heym</p></body></html>",
    "statusCode": 200,
    "contentType": "text/html; charset=utf-8"
  }
}
```
